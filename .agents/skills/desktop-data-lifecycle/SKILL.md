# デスクトップデータの保存と復旧

利用者が保持・削除・復元したいものを、ファイルとDBの実際の寿命へ対応付ける。
特定のDB、ファイル形式、履歴保持量、バックアップ方式は固定しない。

## 変更するデータの責務

既存仕様とコードから、対象データの正本、外部原本、管理コピー、一時物、再生成物を特定する。
各データの所属、参照関係、保持・削除条件、バックアップ対象を必要な範囲で整理する。
複数の対象から利用する登録素材などは、親の削除と独立した寿命が必要か確認する。
DB行を消したことと、音声・画像・ログ・コピー等を消したことを同一視しない。

## 確定と回収の境界

- ファイル生成とDB更新が別の確定になる場合、どこで成功と表示し、中断をどう識別・回収するかを決める。
- 再送で二重追加・上書き・削除しないよう、操作ID、固定入力、結果照合を既存方式に合わせる。
- 非同期処理の開始後に手動編集が進む場合、公開時に版・内容の競合を照合する。明示した置換範囲を超えて新しい編集を上書きしない。
- 正本の保存・検証・参照確定を確認してから、役目を終えた一時物を整理する。
- 外部の取り込み元を管理領域の一時物として削除しない。失敗時の未救出データも一律整理しない。
- 削除対象は管理範囲と実体を特定する。拡張子や内容一致だけで外部・別実体へ対象を広げない。
- 所有が不明なデータやリンクは推測で回収せず、保持と診断へ回す。正常完了領域の整理例外は仕様で範囲を限定する。

削除・回収・保存先変更は、使用中の資産と競合しないようにする。
重い全量検証を細かな操作のたびに繰り返したり、ファイルI/O中に広範囲のDBロックを保持したりしない。
検証を削る前に、重複読取りと排他範囲を確認する。

## バックアップと移行

バックアップの目的が現在内容の利用、過去版の復元、処理再現のどれかを確認し、含める情報を決める。
内部履歴や一時的な操作権限を、目的なくすべて可搬化しない。
参照の付替え、共有資産、ID衝突、同名データ、音声・画像の欠損、未完了データの扱いを確認する。
復元で既存データを置換するか追加するかは、製品の契約に従う。

旧形式の対応元、更新方向、失敗時の保持、旧版への戻し方を明示する。
互換性不要の指定は、利用中のデータを無断で削除・初期化する許可とは解釈しない。
一部の不正データによる停止は必要な範囲へ限定し、正本を守りながら診断・復旧の入口を確保する。

## 保存形式変更時の初回起動移行

アプリが管理する永続データ形式を変更するときは、以下を既定方針とする。利用者が別方式を明示した場合はその指定に従う。

- 通常の読取り・書込み・業務処理・UIへ、旧形式対応の分岐や旧新両形式の常設読取りを増やさない。通常処理は新形式へ統一する。
- 旧形式の読取り・新形式への変換・整合性確認を専用の移行モジュールへ隔離し、起動時の呼出しと移行ID・完了記録も識別できるようにする。
- 改修後アプリの初回起動で、対象保存領域の形式版と移行状態を確認し、必要な旧データを自動移行する。当該データの通常利用は必要な移行の完了後に開始する。
- 新規データと移行済みデータは変換をスキップする。起動ごとに完了状態を判定し、完了済みの変換を繰り返さない。
- データの保存・検証・参照の切替を確認してから完了を記録する。中断後は未完了分を再開でき、再実行でも二重変換・二重追加を起こさないようにする。
- 完了まで元データや必要な退避を保持する。失敗・非対応形式を、新規の空データや移行成功として扱わない。必要な進捗と診断・再試行の入口を用意する。
- 移行コード、旧形式の型・読取り器、その起動時登録を、通常処理へ変更を波及させず後日切り離せる構造にする。移行元のサポート終了と撤去条件を記録し、既存の確定済み移行を無断で書き換えない。

旧バックアップを受け入れる仕様がある場合も、復元の入口で新形式へ変換してから通常処理へ渡す。
利用者が選ぶ外部入力形式の対応とは区別し、外部原本や保存領域外のファイルを起動時に一括変換しない。

## 検証と出力

変更した確定境界について、正常完了、中断、再開、競合、結果不明を選んで確認する。
バックアップは作成成功だけでなく、目的とする内容の往復と既存データへの影響を確かめる。
実データを使う場合は、許可されたコピーや隔離領域を優先する。
[ライフサイクルと故障時の観点](references/lifecycle-review.md)を必要に応じて使い、保持・削除・互換範囲と証拠を報告する。
