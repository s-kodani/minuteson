# デスクトップUIの品質確認

利用者の主要操作が、実際のデスクトップ環境で理解でき、完了できるかを確認する。
既存のデザインシステムと依頼された見た目を出発点にする。

## 対象と状態を絞る

変更する画面、主要操作、対応ウィンドウと、関連する通常・待機・失敗・取消・復旧状態を特定する。
見た目の小さな変更に、全画面の再設計や総合テスト一式を追加しない。
既存の部品・余白・色・スクロール・フォーカス規則が使えるか先に確認する。

## 操作と情報量

- 主要操作と補助操作を区別し、同じ設定や操作を複数箇所で別管理しない。
- 説明は利用者の判断に必要な量と場所へ置く。ツールチップ等に移す場合も、必須の注意やエラーを隠さない。
- 内部工程の確認や一時物の破棄など、アプリ内で完結できる作業を不要なユーザー操作にしない。
- 無効な操作には、その理由と再開する条件を分かる方法で示す。無関係な処理で操作可否が点滅しないか確認する。
- 最小の対応画面・倍率で主操作を使えるか確認する。スクロール禁止を一律の要件にはしない。

## 文言と通知

通知の追加、発生条件・文言・履歴の変更、バックグラウンド処理やネイティブ処理のエラーを画面へ出す変更では、実装前に[通知の判断メモ](references/interaction-review.md#通知の判断メモ)を使う。
利用者が作業や結果への影響を把握する必要があるか、次に何ができるかを発生条件ごとに確認し、表示先と件数を決める。
利用者向けには起きたこと、作業やデータへの影響、次の操作を簡潔に伝え、調査に必要な技術詳細は内部ログに残す。

## 入力とネイティブ境界

影響する経路で日本語等のIME変換、保存、取消、画面移動、終了を確認する。
ポップアップ・ダイアログの開閉では、フォーカス、Escape、復帰先、表示範囲を確認する。
再描画やフォーカス変化だけで、編集中の値を確定・破棄したり補助ウィンドウを点滅させたりしない。
表示・最小化・非表示・完全終了は製品の仕様に従い、すべて同じ操作として扱わない。

## 確認と報告

スクリーンショット、既存のUIテスト、実アプリの操作を変更に応じて選ぶ。
OSの枠・フォーカス・トレイ・DPIが関係する場合、ブラウザーモックの成功を実機成功に読み替えない。
必要な項目だけ[確認観点](references/interaction-review.md)から選ぶ。
実装した動作、確認した画面・環境、残る未確認を報告する。画像の作成だけで実装済みとしない。
