# UI変更の確認観点

変更した操作に関係する行だけを使う。すべてのテーマや環境の総当たりを毎回要求しない。

| 領域 | 確認する振る舞い |
|---|---|
| 配置 | 最小の対応画面、倍率、長い名前、空表示、多数項目でも主要操作に到達できる |
| スクロール | 固定領域とスクロール領域が意図どおりで、二重スクロールや操作欄の隠れがない |
| 入力 | IMEの変換中と確定後、貼り付け、Undo、保存失敗、移動、再表示で入力を失わない |
| 保存 | 編集中・保存待ち・保存済み・結果不明を適切に表示し、失敗時に再試行できる |
| ポップアップ | マウスとキーボードで開閉でき、画面端で切れず、必要な内容を選択できる |
| モーダル | 二重に開かず、閉じた後にフォーカスが戻り、取消で元の作業を継続できる |
| 非活性 | 実際に競合する処理を理由に制限し、理由と解除条件が伝わる |
| 補助ウィンドウ | 主画面の最小化・復帰やフォーカス移動で再入・ちらつき・操作不能にならない |
| 外観 | OSの切り抜きと描画の角丸、枠、倍率、テーマが整合する |
| 通知 | 同じ原因を重複表示せず、一時遅延・確定失敗・解消を区別する |

## フォームと操作列の共通規則

- 単一選択の`select`は`app/src/prototype-alignment.css`の共通規則を使う。新画面のクラスを共通CSSへ列挙する方式に戻さない。画面別CSSでは配置・幅を扱い、背景の一括指定で共通の矢印を消さない。録音画面など既存の明示的な専用デザインは保持する。
- 説明文とアイコンボタンを上下中央に揃える場合は、同じ操作グループに入れて`align-items:center`を指定する。フィールドのラベルを含む行全体の中央とは区別する。
- 共通コントロールの変更では、既存画面との計算済みスタイル比較と、要素の中心座標の差を既存のブラウザーテストで確認する。幅の縮小、ライト／ダーク、キーボードフォーカス、強制カラーモードのうち影響する状態を確認する。
- 新規セレクトが既存画面名に依存せず共通の外観を得ることも確認する。今回の自動確認は`app/tests/lifecycle-browser-check.js`で行う。
- ナビゲーションのアイコンは既存の`ActionIcon`を使い、フォント依存の記号や別の線幅を持ち込まない。

## 通知の判断メモ

新規通知や通知整理で、必要なものだけ残す。

| 発生条件 | 利用者への影響 | 必要な行動 | 表示先・履歴 | 解消条件 |
|---|---|---|---|---|

例：定期同期が短時間遅れた場合と、同期できず編集が保存されていない場合は別の状態。
前者の抑制が、後者の通知まで消す実装になっていないか確認する。

## 結果の伝え方

- 実画面とモックを区別する。例示データの画像は、その旨を記載する。
- OS固有部分の未確認を、共通画面のテスト件数で埋め合わせない。
- 修正を利用中アプリへ反映するために、再ビルドや更新が必要なら記載する。
