# ローカルAI評価の観点

モデル、ランタイム、プロンプト、処理枠を変更するときに使う。

## 分けて確認する契約

| 層 | 観察する結果 |
|---|---|
| 資材準備 | 正しいファイル集合を取得・検証・配置でき、中断後に重複導入しない |
| 実行互換 | 同梱する実エンジンが読み込み、所定の入出力を返す |
| アプリ統合 | 正規化・公開・編集保護・再開・取消までつながる |
| 内容品質 | 代表入力で、用途に必要な正確さ・形式・欠落の基準を満たす |
| 性能 | 準備と入力処理を含む総時間、ピーク資源、応答性を測れる |

## 入力と判定

短い正常例に加え、実際に問題となる長さ、空・無音等の入力、専門語、難しい例を必要な範囲で選ぶ。
既存の失敗入力は、利用許可と匿名化を確認して回帰へ使う。

| 入力・版 | 期待する性質／正解 | 判定方法 | 実行条件 | 結果・採否理由 |
|---|---|---|---|---|

文章生成では形式遵守と内容の正確さを分ける。正しいJSONやMarkdownでも要約として有効とは限らない。
担当者・期限・決定事項等を扱う用途では、入力にない情報の創作も確認する。
出力速度だけでなく、入力読込み・分割統合を含む完成までの時間を比較する。

## 残す実行条件

モデル・ランタイム・入力の識別値、プロンプトと設定の版、OS・CPU・メモリ、実際の実行方式、工程別時間、最大メモリ、内容レビュー。
ハッシュや容量の正本は既存の資材定義に置き、スキルや複数の文書へ一覧を複製しない。
反復抑制や再試行の調整は、正常例の品質低下や処理時間の増加も比較して採否を決める。
