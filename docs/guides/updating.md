# アプリ更新とデータの保持

## アプリ内の更新確認

WindowsのMicrosoft Store版とmacOS通常版は、正常な起動準備の完了後と24時間ごとに新版を確認します。「設定 → このアプリについて」からも確認できます。成功した確認結果は30分間再利用し、通信失敗を「更新なし」と表示しません。Windows EXE版、QA版、開発実行は対象外で、確認通信を行いません。

新版がある場合は、録音状態に関係なくメイン画面の各画面へバナーを表示します。Windows・macOSとも本文を押し下げず、ワークスペース右下（音声プレーヤーがある場合はその上）へ浮かせて表示します。入力や録音・解析を中断せず、バナーを閉じるとその起動中は再表示しません。アプリ情報画面では引き続き結果を確認できます。失敗した再確認では前回の更新情報と確認時刻を保持し、失敗した旨を表示します。

Store版はStore APIで現在の利用者に利用可能な更新を確認し、「Microsoft Storeを開く」で更新とダウンロードの画面へ進みます。開く前の確認画面で「Storeを開いてアプリを終了」か「Storeを開くだけ」を選べます。起動中（常駐中を含む）はStoreが更新版のインストールを延期するため、一度アプリを終了するまでインストールは完了しません。終了を選んだ場合も、トレイの「終了」と同じく録音・解析・保存と編集内容の確認を通り、作業を強制終了しません。配信の遅れやStore側のキャッシュがあるため、結果だけで最新版・取得済み・適用済みとは断定しません。macOS通常版（Apple Silicon）はGitHub Releasesの正式版に添付された`latest.json`をTauri Updaterで確認し、新版の署名付きアーカイブをバックグラウンドで取得します。取得・署名検証が完了すると「再起動して更新」が使えます。取得失敗は「再試行」で再確認・再取得でき、30分のキャッシュによって再試行を妨げません。

確認時はMicrosoft StoreまたはGitHubへ通信します。macOSは認証なしで公開された更新情報とアーカイブを取得し、会議・音声・モデル情報は送信しません。macOS通常版の適用・終了・再起動は「再起動して更新」を押したときにだけ実行します。録音・解析・保存・モデル処理・取り込みなどの作業中は適用を拒否します。編集途中の内容は通常の終了時と同じ保存確認を通り、保存できなければ更新しません。適用中は新しい作業の開始を防ぎ、ワーカーを正常停止してからアプリを置換・再起動します。

「あとで」でバナーを閉じても取得済みの更新は設定画面から適用できます。取得済みデータはメモリ上だけに保持し、未適用で終了した場合は次回起動で再確認・再取得します。自動更新には`/Applications`または利用者の`~/Applications`に配置された書き込み可能な通常版が必要です。DMG上・一時配置・権限不足では配置方法を案内します。

## 更新前

録音・テスト・取り込み・解析・書き出し・データ操作の終了を待ち、アプリでバックアップを保存します。会議名・件数、発言と話者、Markdown、用語と全体モデル設定、選択している保存先を確認します。起動時の案内や未確定の保守操作がある場合は先に状態を確認します。

ウィンドウを閉じただけで常駐している場合があるため、アプリの明示終了で保存と停止を待ちます。強制終了を通常の更新手順にしません。

## アプリの置換

| 配布経路 | 更新方法 |
| --- | --- |
| macOS通常版 | 自動取得後「再起動して更新」。更新機構のない旧版からの初回移行はDMGで入れ替える |
| Windows EXE | 同じ通常版の新しいインストーラーで更新する |
| Windows Store | Microsoft Storeの更新を使う |
| QA | 同じQA識別子のアプリ／インストーラーを正常終了後に更新する |

通常版とQA版の識別子は異なります。EXE版とStore版の移行にはバックアップ・追加復元を使い、DBを直接共有しません。

Storeの同一版・異なる署名からの切替は[ローカル検証手順](distribution-store.md#原本と同じ内容のローカル検証)に従います。

Store版のパッケージは`UpdateWhileInUse=defer`を宣言します。Windows 11 24H2以降では、録音・解析中に限らず起動中の更新適用を延期する方針です。トレイ常駐も起動中に含まれます。作業と保存の完了後に明示終了し、Storeの再試行や次回起動時の適用を確認してください。OS更新やシステム再起動の終了を防ぐ設定ではありません。この設定を初めて導入する旧版からの更新は、既存版での保護を実機確認前に保証しません。

## 初回起動と確認

保存先の所有・配置・履歴とDB形式を検査します。会議DBは現行の保存形式だけを受け入れ、対象外のDBは元のファイルを保持して起動時の案内を表示します。現在の形式は[保存仕様](../spec/storage.md#現行形式)を参照してください。

1.0.7では履歴専用DBを版2へ移行し、同じ録音の保存・回復履歴を1件へまとめます。会議DBと音声形式はこの移行では変更しません。移行に失敗した場合は元の履歴を保持して履歴エラーを表示するため、DBや履歴ファイルを削除せず内容を確認してください。詳細は[履歴移行の仕様](../spec/storage.md#録音保存の履歴移行)を参照してください。

起動検証に失敗した場合はアプリ・DB・台帳を保全し、[障害対応](troubleshooting.md)で段階と診断を確認します。DB、WAL、台帳、設定の個別削除で回避しません。

## macOS更新配信の設定

GitHub Actionsのリポジトリ変数`TAURI_UPDATER_PUBLIC_KEY`にTauri公開鍵の内容を設定します。`release-macos`環境のSecretsには`TAURI_SIGNING_PRIVATE_KEY`と必要に応じて`TAURI_SIGNING_PRIVATE_KEY_PASSWORD`を設定します。公開鍵は署名前のビルド時にTauri設定へ埋め込み、署名ジョブでも同じ公開鍵であることを確認します。秘密鍵は署名ジョブだけに渡します。AppleのDeveloper ID署名・公証とは別の鍵です。

初回の鍵はTauri CLIの`signer generate`で作成し、秘密鍵は安全な永続保管先に保存してください。鍵の紛失・変更は既存インストールの更新に影響します。ソースには秘密鍵を保存しません。鍵未設定の正式ビルドは失敗します。

署名・公証・staple済みアプリから`MinutesOn_<version>_aarch64.app.tar.gz`、その`.sig`、`latest.json`を生成します。更新署名には版数を含め、独立した検証ツールで署名・版数・公開鍵の一致を検証します。これらのファイルはDMGと同じソース・版数の成果物としてハッシュ検証・Release添付・来歴証明の対象になります。下書きには自動添付しますが、公開操作は従来どおりGitHubで行います。公開時にはReleaseを正式版かつ最新に設定してください。

ローカルで公証付き配布物を作る場合も、上記の環境変数と既存のApple署名設定に加えて、先に`cargo build --locked -p mon-update-verify`で検証ツールを用意します。アプリへの公開鍵の注入は`mon_macos_release.py`が行います。単に`tauri build`を直接実行した成果物は更新配信に使わないでください。

配布検証では異なる版数の署名・公証済みアプリで、正常な取得と再起動、作業中の適用拒否、会議・設定・モデルの保持を確認します。開発版やブラウザーの合成IPCテストはこの実機検証の代わりにはなりません。
