# ADR 0012 起動時の案内と明示操作の分離

公開前の版では、モデルの操作を[設定画面](../spec/models.md)に集約しました。

## 背景

起動時に機能変更や必要な更新を案内する入口が必要です。モデルの更新には取得・実行・設定変更と利用条件の確認が伴い、一般のお知らせの既読だけで実行や完了を判定できません。復旧画面や録音等と競合するモーダルの追加も避ける必要があります。

## 決定

ネイティブ側が案内のID・revision・種類・優先度と適用対象を解決し、メイン画面だけへ読み取り用の候補を返します。同梱の一般案内と、現在の管理状態から判定する更新案内を共通の一覧・詳細画面で表示します。外部配信や任意コード実行の仕組みは追加しません。復旧案内を優先し、初期読み込み後に一度だけ自動表示します。他の操作中は通知一覧を入口にします。

一般案内の「確認しました」はIDとrevisionに結び付いた既読を既存の端末設定へ記録します。DB schemaとバックアップ形式は変えません。「後で」・閉じる・Escはネイティブプロセス内の延期とし、画面再生成で繰り返し表示しません。次のプロセス起動では必要性を再判定します。通知一覧からの再表示は可能にします。

更新案内の既読を更新完了として保存しません。機能側が同じモーダルへ条件確認を埋め込み、実行直前に現在の選択・対象パッケージ・公式レシピ・開示ハッシュを照合します。モデル確認欄は毎回未選択です。実行は既存のモデル準備と適用処理を使い、成功後の実際の状態から案内を解消します。閲覧や延期だけで通信・配置・互換性実行を始めません。

最初の適用対象は、使用中の公式管理コピーのモデルデータが一致する旧議事録ランタイムです。モデルデータの再利用と旧コピーの保持を案内し、利用者が「今すぐ更新」を確定してから処理します。開始済みジョブの実行条件は固定したままです。

## 理由

案内の提示・延期と機能の処理状態を分けることで、お知らせを増やしても機能ごとの実行境界を維持できます。既存の利用条件確認・排他・取消・中断回復を共有し、通知専用の更新経路を増やしません。

## 影響

新しい案内はネイティブ定義と種類に対応する表示を追加します。モデルの条件確認履歴を永続化したり、既読を実行許可として扱ったりしません。複数画面への表示権限追加や、遠隔配信・必須更新は別の設計判断とします。
