# macOSの手動更新とデータの保持

対象はmacOS 15以降・Apple Siliconの通常版MONである。現時点では署名・公証済みDMGによる配布と実機更新を検証していない。本手順を公開済みインストーラーの存在や更新完了の証明としない。Windowsの更新は保留である。

## 更新前

1. 更新元から、版・対応OS・署名者・配布条件と更新内容を確認する。提供元の署名／公証とハッシュを確認し、端末内で計算したハッシュだけを真正性の証明にしない。出所不明のアプリを起動したり、Gatekeeper・隔離属性を無効にしたりしない。
2. 録音・5秒テスト・音声取り込み・解析・書き出し・バックアップ・復元・削除・保存先変更を終了する。画面を閉じただけでなく、MONの明示終了を使い、停止／保存の完了を確認する。強制終了を通常の更新手順にしない。
3. 正常に保存できる状態で手動バックアップを作り、会議数・日時・名前とアーカイブの検査結果を確認する。バックアップは追加復元用であり、現在のDBを上書きする巻戻し用ではない。AIモデル、実行依存ファイルと端末内の起動設定はバックアップに含まれないため、配置先・準備状態と選択した保存先を別に確認する。モデルや設定を更新のために削除しない。
4. 起動設定・台帳・保存先に異常がある、未完了保守がある、バックアップを検査できない場合は更新を保留する。DB・WAL・台帳の個別コピーや削除、空の保存先への置換で異常を解消したことにしない。

## アプリの置換と初回起動

配布手順に従ってアプリだけを置き換える。会議保存先、モデル、設定・起動用設定を初期化しない。通常版の識別子は`jp.mon.desktop`であり、QAの`jp.mon.desktop.qa`は別領域を使う検証版で、通常版の更新先ではない。QAの設定や本番DBを互いへコピーしない。

更新後の初回起動では保存先と移行履歴を検証する。未対応の新しい移行・改変された履歴・段階の欠落は拒否し、自動的なDB初期化や旧形式への変換は行わない。対応する移行待ちの全段階と履歴は1つのSQLiteトランザクションで確定する。SQLまたは確定の失敗時は途中の新段階を成功扱いにしない。この保護は移行トランザクションのDB内容が対象であり、ファイルシステムの全バイトや、その後の起動時回復まで一括で巻き戻す保証ではない。

通常起動後には、既存の未完了ジョブ・録音・取り込み等の回復処理が状態を更新する場合がある。起動後に表示された会議の保存先、件数、現在／直前の解析・議事録、手動編集・下書きと設定を照合する。許可された音声で再生・編集保存・再起動後の読戻しも確認する。ソース単体テストやQAバンドルの署名検査はこの実機更新検査の代わりにしない。

## 起動・移行に失敗した場合

表示された段階と原診断、確定した保存先を保持し、終了する。診断の再読込はメモリに保持した情報だけで、修復・回収・保存先切替や移行の再試行ではない。原因確認後の明示再起動だけが再び通常の起動検証を行う。共有する診断に個人情報がないか確認する。詳細は[起動拒否時の案内](verification/storage-startup-attention-2026-10-10.md)を参照。

DBを移行した後にアプリだけを旧版へ戻すと、その版が未対応の移行履歴を拒否することがある。旧版で開くために履歴を削除・書き換えたり、DBを直接上書きしたりしない。復旧が必要なら、保持したデータと検査済みバックアップを基に、対応版・隔離した保存先で確認する。現行の追加復元は既存会議を残して別会議として追加するものであり、自動的なダウングレードや完全な環境巻戻しではない。

## 残る配布・更新の検証

Developer ID署名・公証済みDMGの構築／確認、初回モデルダウンロード（手動導入とは別に未実装）とモデル・エンジンの配布条件、実機での通常版のアプリ置換、起動設定・保存先・モデルと会議全体の保持、Gatekeeper、失敗・中断・再起動後の統合、先行試用を確認する。資格情報の準備や公証サービスへのアップロードは別途承認と準備が必要で、本手順の追加によって実行したものではない。
