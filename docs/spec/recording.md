# 録音と音声取り込み

アプリとOSの境界、プロセス・スレッド・キューは[録音構成図（draw.io・3ページ）](../diagrams/current-recording.drawio)を参照してください。PNG版は[全体構成](../diagrams/current-recording-01-overview.png)、[macOS](../diagrams/current-recording-02-macos.png)、[Windows](../diagrams/current-recording-03-windows.png)です。

## 録音範囲と入力

マイクとPC音声を別トラックで取得します。全体録音は全出力機器の音声を対象とします。Windowsは各出力機器のWASAPIループバックを直接取得し、共通のQPC時刻で重ね合わせます。macOSは録音ヘルパー自身のプロセスツリーを除外します。アプリ選択録音は指定したアプリのプロセスツリーに限定し、取得失敗時に全体録音へ切り替えません。

Windowsの全体録音は、Teamsデスクトップ版の音声がプロセス単位のループバックでは無音になる[Microsoftのサンプルへの報告](https://github.com/microsoft/Windows-classic-samples/issues/414)を踏まえ、アプリ選択録音とは取得方式を分けます。既定の一般・メディア出力と、実際に再生中の出力を開きます。録音ヘルパー自身のループバックセッションは再生中の根拠にしません。使っていないBluetoothの通話出力を録音側から開き、再生プロファイルへ干渉することを避けます。OSの出力変更通知と100 ms間隔の確認で経路を追従し、終了する出力の受信済み末尾を保存してから新しい出力を開きます。継続中の出力は再起動しません。出力機器間の合成待ちは250 ms、バッファは10 msのブロック100個までとし、音声が届いていない区間を無音で補いません。実際の取得失敗は入力の切断・再取得として扱います。

Bluetoothなどの切り替えでは、各出力機器の受信位置より先の区間を確定せず、次のパケットが埋めるブロック末尾を待ちます。機器ごとに公平に読み出し、受信済みデータが残る間は待機せず読み出しを続けます。遅れた時計が確定済み区間に重なる場合は、入力ごとの時刻基準を補正してパケット全体を保持し、前半を切り捨てません。補正後の時刻は推定として記録し、元の時刻・補正先・フレーム数を上限付きで診断へ残します。合成バッファの上限では受信済み音声を保存キューへ送り、バッファを捨てたり入力を再起動したりしません。無期限の待機やメモリ増加は行わず、入力が戻るまでの実際の未取得区間と、取得済み音声の時刻補正を区別します。PCMの不正や実際の保存不能は引き続きエラーとして扱います。

macOSでは、確認済みの再取得によりPC音声のサンプルレート等が変わっても、以前の変換器に残る末尾を排出し、新しい形式から共通の保存形式へ変換して継続します。終了した入力からの遅延コールバックや、同じ取得中に所属を確認できない形式変化は引き続き採用しません。

macOSの通常録音でも、受信済み音声の時刻が確定済みの時刻より前へ戻った場合は、同じ取得元の時刻基準を補正し、受信フレームを切り捨てず保存します。補正は接続ごとに保持し、元の時刻・補正先・フレーム数を最大16件の診断と件数に残します。推定時刻を示す `timingEstimated` と保守的な時刻の不確かさをmanifestへ記録し、保存済みの時計区間を書き換えません。保持した音声の論理終端が実際の入力停止時刻を超える場合も、元の停止観測は `observedCaptureEnd` に残します。実際の未取得区間、不正なPCM、古い接続からの音声、同じ取得中のフレームカウンター巻き戻り、保存不能は引き続き区別します。正常な保存完了には両入力の停止確認を必要とします。

WindowsのマイクはWASAPIの開始成功だけでは接続済みにせず、最初の音声パケットの受信を確認してから取得を引き渡します。開始後または取得中に3秒間パケットが届かない場合は、取得クライアントを停止・解放し、既存の再取得処理で現在の通話用既定入力または固定指定の入力を取得し直します。無音を示すパケットも正常な受信として扱います。再生がない間はパケットが来ないことがあるPC音声には、この判定を適用しません。既に受信した音声は保存キューから排出して保持します。

macOSの通常録音では、マイクの構成確認が完了して音声を受け付け始めた後、最初の音声が3秒間届かない場合と、受信後に3秒間途絶えた場合に、既存の再取得処理で入力を取り直します。エンジンの稼働フラグだけで接続を維持せず、無音のPCMも正常受信として扱います。再接続完了は新しい接続で音声を受け付けてから判定し、古いコールバックで期限や状態を更新しません。初期権限待ち、PC音声、5秒テストにはこの期限を適用しません。既存の入力状態・履歴を使い、発生回数は `microphoneFlowTimeouts` に記録します。

マイクは自動選択と機器の固定指定を使い分けます。自動選択で会議アプリの使用入力を特定できない、または候補が複数ある場合はOS既定入力へ戻して選択理由を表示します。Windowsでは通話用の既定入力（eCommunications）と機器一覧の既定表示を一致させます。固定指定では別機器へ無断で切り替えません。機器の切断・再取得や取得できなかった区間は現在の状態・保存後の履歴・内部ログへ反映し、録音中・終了後の中断／復帰通知は表示しません。接続状態は通知台帳の保存・受付・表示確認を待たず、取得元の新しい状態から判定します。古い報告や不正な履歴を接続済みとは扱いません。前回の音声保存を検証・復旧した正常完了も通知せず、会議を更新して内部ログへ記録します。録音自体の停止や保存失敗の通知は維持します。

通常録音では、マイク・PC音声の異常PCM（非数値・無限値・異常振幅）、形式や入力カウンタの不整合を保存失敗と区別します。不正なデータは変換器や保存待ちの集計を更新する前に拒否し、正常に受理した音声を保持して対象入力だけを再取得します。復旧待ちでも他方の入力は録音を継続し、両入力が取得できない場合もユーザーが停止するまで録音セッションを維持します。入力異常だけでは文字起こしへ移行しません。

入力異常後の再取得は1・2・4・8・16・30秒の間隔で繰り返し、30秒を上限にします。正常なPCMを3秒間受信すると間隔を戻します。取得試行のタイムアウト後もOS処理の所有を維持し、終了を確認するまで次の取得を重ねません。入力欄と既存の履歴に復旧状況を表示し、中断・復帰の通知は追加しません。欠落した音声そのものは復元できず、時刻不明の区間も推測しません。5秒テストの異常は失敗として扱い、保存容量不足・書込みや同期の失敗・保存待ち上限超過・保存内容の不一致は引き続き録音全体を停止します。

macOSの取得はAVAudioEngine、ScreenCaptureKit／Core Audio Tapsを使い、WindowsはWASAPIを使います。権限・出力経路・会議アプリの実行構成により取得範囲が異なるため、最初に[5秒テスト](../guides/usage.md#録音する)で入力を確認します。

## テストと録音操作

「5秒録音して確認」の音声は一時確認用です。確認画面を閉じると実行と再生を終了してから削除します。PC側が無音でサンプルを受信しないことと、保存の失敗を区別します。

通常録音には固定の4時間停止期限を設けません。メイン画面が非アクティブになるとミニパネルを表示し、入力状態と停止操作を提供します。パネルを隠す操作と録音停止は別です。停止の確定後は、保存処理の終了を待ちます。

## 音声の保存

元の取得フレームと会議時刻の対応を保持します。元音声から復元できない欠損は記録を残して正式WAVの無音区間とし、前後の音声の時刻を詰めません。未確定の録音は保存完了と表示しません。取得・変換とディスクの同期保存を分離し、取得済みから保存確定までの音声を1入力あたり最大120秒、メモリで待機させます。取得PCMの待機には従来の20秒・16 MiB・4,096パケットの上限を残し、変換済み音声の共有バッファにも16 MiB・4,096ジョブの上限を設けます。構築中・書込み中も計上し、保存確定後にだけ解放します。いずれかの上限または書込み不能に達した場合は、音声を捨てて続けず停止して案内し、確定済み音声を保持します。

録音中は、取得した音声を入力ごとに16 kHz・モノラル・PCM16へ変換し、復旧用の分割CAFだけに保存します。約4秒分をまとめて書き込み、音声・時計・ハッシュの照合と同期保存後に確定範囲を公開します。連続CAFは作成しません。通常時の確定間隔は維持しますが、保存先が停止している間はメモリ上の未確定音声が増え、異常終了時に失われる場合があります。停止後は検証済み分割CAFを可逆FLACへ束ね、正式WAVを作成します。

派生FLACの音声区間に欠損・重複がある場合は、同じ保存処理の中で検証済み分割CAFから自動再生成します。再生成には別のブロック長と単純な可逆符号化を使い、全PCM・CRC・MD5・時間を再検証します。元音声や所有証拠に不整合がある場合は推測で採用しません。録音・取り込みの確定失敗は500 ms後に同じ操作を1回だけ再確認し、既に確定済みなら重複登録せずその結果を使用します。回復不能な場合は元音声を保持して保存失敗を知らせ、次回起動待ちの案内は表示しません。異常終了後の未確定音声の救出は維持します。

録音プロセスの終了後、正常終了できなかった場合も、所有・時計・ハッシュを検証できた確定済み音声を同じ会議へ自動保存します。起動時には既存の失敗・中断セッションと、登録後にWAVの保存が残ったセッションも対象にします。片方の入力だけでも音声があれば保存し、確定していない末尾や実際の取得終了時刻は推測しません。正式WAVの検証完了まで保存中として扱い、完了後は「録音済み」と表示します。「録音未完了・要確認」は使用しません。保存できない場合は「音声保存エラー」とし、会議一覧と通知から「保存を再試行」できます。同一セッションの処理は直列化し、再起動や新しい会議の作成を必要としません。両入力の確定サンプル数がゼロと検証できた場合だけ「録音失敗」とします。無音のサンプルも取得済み音声として数え、読めない音声や欠けた証拠をゼロとみなしません。

取り込み中も、原本の管理コピーから復号した小さな区間を順次変換して、同じ低容量形式の中間CAFを直接作成します。高音域・ステレオ情報は中間音声に保持しません。マイクとPC音声の区別、取得時刻と欠損区間は保持します。録音・取り込み後は16 kHz・モノラル・PCM16の会議全体の共通WAVを正式音声として保存し、再生・解析に使います。元音声・時計・欠損・ミックス条件に対応する内容を照合して再利用します。WAV完成後は不要な音声と途中ファイルを整理します。取り込み元のオリジナルは保持します。Windows・macOS共通の削除範囲と回復は[データ管理](storage.md#wav完成後の音声整理)を参照してください。

録音中の音声本体はマイク・PC音声を合わせて約230.4 MB/時、取り込みの中間CAFと正式WAVはそれぞれ約115.2 MB/時です（十進表記。メタデータ等は別途）。取り込みの必要容量には原本の管理コピー、中間CAF、正式WAVと安全余裕を含めます。原本の容量表示は変換前の値を使います。

## 音声ファイルの取り込み

WAV・MP3・AAC/ALAC M4A・FLACを1件ずつ選択またはドロップして会議を作成します。拡張子だけでなく実際の形式を検査し、長さ・容量・保存先の空きと必要容量を表示します。会議名と取り込み時の用語を設定できます。

WAVは対応する整数／浮動小数点PCMを扱い、WAVEFORMATEXTENSIBLEの整数有効ビットは左詰めとして解釈します。FLACはCRC・PCMのMD5を含めて検査します。新規取り込みの復号中間音声は16 kHz・モノラル・PCM16のCAFを使用し、原本の形式・長さ・フレーム数と保存後の形式・フレーム数を別々に検証します。確定済みの既存音声を形式変更だけのために再生成しません。原本を検査した証拠と所有を保持し、取り込み元の利用者ファイルを削除しません。
