# 録音と音声取り込み

Windows・macOSの取得、時刻補正、共通Rustでの変換・統合、単一WAVへの保存を、[録音データフロー設計図（編集用draw.io・1ページ）](../diagrams/current-recording.drawio)にまとめています。[PNG版](../diagrams/current-recording.png)も同じ正本から書き出しています。2026-11-24時点の実装（WindowsのBluetooth再接続修正・受理済み音声の保持・保存時の重複読取り削減を含む）と照合した図です。

![Windows・macOSと共通Rustの録音データフロー](../diagrams/current-recording.png)

図を更新するときはdraw.ioファイルを正本として編集し、PNGを同じ内容で書き出し直します。OS別の時計・取得・保存I/Oと、同じRust実装を使う範囲も同時に照合します。

### 図の共通部分とOSごとの差

緑色は両OSが同じRust実装を使う処理、紫色は同じ保存契約に従うOS別の処理です。取得、入力時計の補正、キューの所有、ファイルI/Oまでが同一実装という意味ではありません。共有Rustも各OSの録音ヘルパー内で実行し、WindowsとMacの音声をOS間で送受信して混ぜる構成ではありません。

| 境界 | Windows | macOS |
| --- | --- | --- |
| マイク取得 | WASAPI、48 kHz・float・1 ch、取得と停止・COM解放を専用スレッドで所有 | 入力専用AUHAL、実デバイスのレート・チャンネル数。出力busは無効 |
| PC音声取得 | PC全体は出力別のWASAPIループバックとEndpointMixer、アプリ指定はprocess loopback | 製品の通常起動は全体・アプリ指定ともCore Audio Taps。全体は自プロセス除外、指定時は確認したプロセスツリーに限定 |
| 入力時計 | QPCを使い、異常時は機器位置・サンプル数・到着時刻で推定。補正下限は自入力の変換末尾と共通WAVの混合出力済み末尾の最大値 | CaptureClockDomainでOSのhost時刻をmach_continuous_timeへ橋渡し。CapturePCMAlignmentは、補正時に自入力の直前PCM末尾と変換出力末尾の最大値を下限にし、接続ごとの補正量を保持 |
| 共通Rustへの接続 | C++のVoicePCM・WavInput・LiveWavからFFIを呼ぶ | SwiftのVoicePCM・LiveWavSessionから同じFFIを呼ぶ |
| 同期保存 | LiveWav保存ワーカー、書込量確認、FlushFileBuffers。公開済みPCMはアプリ側でSHA-256照合 | LiveWavSessionとRawSegmentCommitWorker、fsync、読戻し照合 |

WindowsのPC機器間補正と入力時計の補正は別段です。EndpointMixerはPC側の出力・通知済み進行位置とその機器の直前末尾を守り、Laneは共通WAVの混合済み末尾も守ります。後者にはディスク同期前の保存待ち音声も含みます。macOSの補正下限をWindowsと同一として図示していません。補正では受信パケットを切り詰めませんが、その後のレート変換・モノラル化・平均合成ではサンプル数と値が変わります。

実装の対応箇所は、Windowsが[SystemCapture](../../probes/windows-capture/system_capture.h)・[EndpointMixer](../../probes/windows-capture/endpoint_mixer.h)・[Lane](../../probes/windows-capture/product_capture.h)・[LiveWav](../../probes/windows-capture/live_wav.h)、macOSが[通常起動時のバックエンド選択](../../app/src-tauri/src/recorder.rs)・[AUHAL](../../probes/macos-capture/Sources/MONMacOSCapture/MicrophoneAudioUnit.swift)・[Core Audio Taps](../../probes/macos-capture/Sources/MONMacOSCapture/CoreAudioCaptureStream.swift)・[時計補正](../../probes/macos-capture/Sources/MONMacOSCapture/CapturePCMAlignment.swift)・[LiveWavSession](../../probes/macos-capture/Sources/MONMacOSCapture/LiveWavSession.swift)です。共通実装は[Rust音声変換](../../crates/mon-core/src/media/voice.rs)・[Rust WAVミキサーと確定記録](../../crates/mon-core/src/capture/wav.rs)・[録音FFI](../../crates/mon-capture-ffi/src/lib.rs)です。CLI指定のScreenCaptureKit経路、5秒テスト、旧CAF救出は図の対象に含めません。

### 回復に使う管理ファイル

停止を確認できない場合に保持する「回復用記録」は、次のように、WAV内の検証できる保存範囲を判定するための管理情報を指します。

| ファイル | 回復時に確かめる内容 |
| --- | --- |
| `single-wav-owner.json` | セッションが所有するWAVのファイル実体・識別情報 |
| `wav-*.json` | 保存ブロックの連番、フレーム範囲、PCMのSHA-256、直前の記録とのつながり、入力ごとの取得フレーム数・両入力未取得範囲 |
| `single-wav.json` | 検証済み末尾、最終確定記録、入力の正常終了を確認できたか |

回復処理はこれらと`recording.wav`を照合し、連続して検証できた範囲を採用します。`manifest.json`や時計・入力状態の診断は補助情報であり、音声本体の確定を示す証拠とは区別します。切断中の未取得音声や、ディスクに保存されていない末尾を復元するものではありません。

## 録音範囲と入力

マイクとPC音声を別入力として取得し、録音中に共通の会議時刻へ整列して一つのWAVへ合成します。全体録音は全出力機器の音声を対象とします。Windowsは各出力機器のWASAPIループバックを直接取得し、共通のQPC時刻で重ね合わせます。macOSは録音ヘルパー自身のプロセスツリーを除外します。アプリ選択録音は指定したアプリのプロセスツリーに限定し、取得失敗時に全体録音へ切り替えません。

Windowsの全体録音は、Teamsデスクトップ版の音声がプロセス単位のループバックでは無音になる[Microsoftのサンプルへの報告](https://github.com/microsoft/Windows-classic-samples/issues/414)を踏まえ、アプリ選択録音とは取得方式を分けます。既定の一般・メディア出力と、実際に再生中の出力を開きます。録音ヘルパー自身のループバックセッションは再生中の根拠にしません。使っていないBluetoothの通話出力を録音側から開き、再生プロファイルへ干渉することを避けます。OSの出力変更通知と100 ms間隔の確認で経路を追従し、終了する出力の受信済み末尾を保存してから新しい出力を開きます。切断・形式変更のない出力は再起動しません。出力機器間の合成待ちは250 ms、バッファは10 msのブロック100個までとし、音声が届いていない区間を無音で補いません。実際の取得失敗は入力の切断・再取得として扱います。

Windowsでは機器IDとネイティブ接続の寿命を区別します。Bluetoothを切断・再接続すると同じ機器IDが戻る場合でも、切断前のWASAPIクライアントを流用しません。接続状態・追加・削除・音声エンジンの形式変更を機器ごとに記録し、一覧確認の間に切断・再接続が完了しても失効を保持します。PC音声は対象機器の古い取得サービスとクライアントを解放してから新しく開き、無関係な出力は継続します。マイクは初期化前から寿命を監視し、初期化中・受信中の失効を取得所有スレッドへ伝えて停止・解放します。切断通知そのものではWASAPIを操作しません。単なる出力先の選択、音量・表示名の変更だけで正常な接続を作り直しません。[WASAPIの無効デバイスからの回復手順](https://learn.microsoft.com/en-us/windows/win32/coreaudio/recovering-from-an-invalid-device-error)に従い、古い接続の参照を残したまま再接続しません。

Bluetoothなどの切り替えでは、各出力機器の受信位置より先の区間を確定せず、次のパケットが埋めるブロック末尾を待ちます。機器探索・接続準備を取得処理から分離し、機器ごとに公平に読み出して、受信済みデータが残る間は待機・時刻ベースの確定を行いません。既存の取得元の時計補正はパケット全体を保持し、補正後の時刻を推定として元時刻・補正先・フレーム数とともに診断へ残します。合成バッファの容量圧力だけで未読音声を先行確定せず、上限では確定済み音声を保持して失敗を知らせます。無期限の待機やメモリ増加は行わず、実際の未取得区間、不正なPCM、取得時計の不整合、保存不能を区別します。

Windowsで切断・再接続やBluetoothの受信遅延により、受信したPCMの時刻が既に合成した単一WAVの位置より古くなる場合は、新しく受信した音声の区間全体を未確定側へ補正します。同じ接続中の受信再開にも適用し、PCMを切り捨てたり保存済みWAVを書き換えたりしません。元の時刻・補正先・理由を既存の時計診断へ残し、時刻を推定として扱います。マイクの接続が生きている間の空キューは受信完了の根拠にせず、受信途絶の監視と実際の停止・解放を待ちます。PC音声は出力ごとの取得・停止・解放を所有し、1機器の停止待ちでも正常な出力を継続します。再接続の前には同じ機器の旧取得の終了を確認し、全出力の一時取得キューにも共有の上限を適用します。

macOSでは、確認済みの再取得によりPC音声のサンプルレート等が変わっても、以前の変換器に残る末尾を排出し、新しい形式から共通の保存形式へ変換して継続します。終了した入力からの遅延コールバックや、同じ取得中に所属を確認できない形式変化は引き続き採用しません。

macOSの通常録音でも、受信済み音声の時刻が確定済みの時刻より前へ戻った場合は、同じ取得元の時刻基準を補正し、受信フレームを切り捨てず保存します。補正は接続ごとに保持し、元の時刻・補正先・フレーム数を最大16件の診断と件数に残します。推定時刻を示す `timingEstimated` と保守的な時刻の不確かさをmanifestへ記録し、保存済みの時計区間を書き換えません。保持した音声の論理終端が実際の入力停止時刻を超える場合も、元の停止観測は `observedCaptureEnd` に残します。実際の未取得区間、不正なPCM、古い接続からの音声、同じ取得中のフレームカウンター巻き戻り、保存不能は引き続き区別します。正常な保存完了には両入力の停止確認を必要とします。

WindowsのマイクはWASAPIの開始成功だけでは接続済みにせず、最初の音声パケットの受信を確認してから取得を引き渡します。開始後または取得中に3秒間パケットが届かない場合は、取得クライアントを停止・解放し、既存の再取得処理で現在の通話用既定入力または固定指定の入力を取得し直します。受信途絶・初期化失敗・取得試行のタイムアウトも、異常PCMと同じ1〜30秒の再取得間隔を適用します。開始成功や短い受信だけでは間隔を戻さず、正常PCMの3秒間の受信を必要とします。無音を示すパケットも正常な受信として扱います。再生がない間はパケットが来ないことがあるPC音声には、この判定を適用しません。既に受信した音声は保存キューから排出して保持します。

macOSの通常録音では、マイクの構成確認が完了して音声を受け付け始めた後、最初の音声が3秒間届かない場合と、受信後に3秒間途絶えた場合に、既存の再取得処理で入力を取り直します。エンジンの稼働フラグだけで接続を維持せず、無音のPCMも正常受信として扱います。再接続完了は新しい接続で音声を受け付けてから判定し、古いコールバックで期限や状態を更新しません。受信途絶・初期化失敗・安定化失敗も最初の失敗から1〜30秒の再取得間隔を適用し、開始成功や短いPCM受信だけでは間隔を戻しません。権限待ちや機器の探索、明示停止を新しい取得失敗には数えません。初期権限待ち、PC音声、5秒テストにはこの期限を適用しません。既存の入力状態・履歴を使い、発生回数は `microphoneFlowTimeouts` に記録します。

マイクは自動選択と機器の固定指定を使い分けます。自動選択で会議アプリの使用入力を特定できない、または候補が複数ある場合はOS既定入力へ戻して選択理由を表示します。Windowsでは通話用の既定入力（eCommunications）と機器一覧の既定表示を一致させます。固定指定では別機器へ無断で切り替えません。機器の切断・再取得や取得できなかった区間は現在の状態・保存後の履歴・内部ログへ反映し、録音中・終了後の中断／復帰通知は表示しません。接続状態は通知台帳の保存・受付・表示確認を待たず、取得元の新しい状態から判定します。古い報告や不正な履歴を接続済みとは扱いません。前回の音声保存を検証・復旧した正常完了も通知せず、会議を更新して内部ログへ記録します。録音自体の停止や保存失敗の通知は維持します。

macOSのマイクは入力専用のAUHALを使います。入力のbus 1を有効、出力のbus 0を無効にしてから選択したデバイスへ接続し、録音のために出力ストリームやOSの既定出力・出力形式を設定しません。実際の入力形式を取得して使用し、Bluetoothスピーカーフォンのプロファイル変更後に残る古い形式を強制しません。同じBluetooth機器のマイクを使うことでOSや機器側が通話プロファイルへ切り替わること自体は防げません。

入力の変更通知は再確認の契機とし、制御処理で実デバイスのID・UID、入力形式、PCMの到着を確認します。入力が変わっていない出力側だけの通知では、正常なマイクを停止・再取得しません。確認できない場合は古い接続を無効にして再取得し、新しい接続のPCMを受理してから接続済みとします。停止を確認できない取得は所有を維持し、新しい取得を重ねたり正常な停止として時刻を確定したりしません。

AUHALの設定・起動・停止は専用の直列処理で所有し、音声コールバックからデバイスのUIDや入力形式を問い合わせません。変更通知で確認済みの世代を無効にし、制御側で同じ接続を再確認するまでPCMを採用しません。コールバックのフレーム数は既存のPCM上限内で事前確保した容量で検査し、OSが示したサンプル時刻・ホスト時刻を保持します。時刻がない場合に到着時刻で置き換えません。

入力状態・音量・履歴保存状況は専用の発行処理が現在の状態から更新し、マイクの初期化待ちによって正常なPC音声の状態まで古くならないようにします。停止時は発行処理を終了してから一時的な状態ファイルを整理します。初期化・再取得の失敗段階は、macOSでも内部ログへ先頭16件を記録します。

Windowsでは初期化に加え、古い入力の停止・解放待ちも別スレッドで所有します。その間も受理済み音声の排出、他方の録音、現在の入力状態の更新を続け、古いOS処理の終了を確認するまで代わりの入力は開きません。停止期限を超えても終了を確認できない入力を、正常に停止できた扱いにはしません。

通常録音では、マイク・PC音声の異常PCM（非数値・無限値・異常振幅）、形式や入力カウンタの不整合を保存失敗と区別します。不正なデータは変換器や保存待ちの集計を更新する前に拒否し、正常に受理した音声を保持して対象入力だけを再取得します。復旧待ちでも他方の入力は録音を継続し、両入力が取得できない場合もユーザーが停止するまで録音セッションを維持します。入力異常だけでは文字起こしへ移行しません。

入力異常後の再取得は1・2・4・8・16・30秒の間隔で繰り返し、30秒を上限にします。正常なPCMを3秒間受信すると間隔を戻します。取得試行のタイムアウト後もOS処理の所有を維持し、終了を確認するまで次の取得を重ねません。入力欄と既存の履歴に復旧状況を表示し、中断・復帰の通知は追加しません。欠落した音声そのものは復元できず、時刻不明の区間も推測しません。5秒テストの異常は失敗として扱い、保存容量不足・書込みや同期の失敗は引き続き録音全体を停止します。Windowsの保存内容の不一致は、録音中は書込み確認の取得時にアプリ側で検出し、確認が行われない間は停止後の検証で検出します（録音中に自動停止はしません）。macOSは保存ワーカーの読戻し照合で検出して停止します。PCの高負荷やディスクの遅れで取得PCMの待機が20秒・16 MiB・4,096パケットの上限に達した場合は、受理済みの音声を保持したまま対象入力だけを同じ間隔で取得し直し、取得できなかった区間は欠落として無音で記録します。録音全体は停止しません。

macOSの取得は入力専用AUHAL、ScreenCaptureKit／Core Audio Tapsを使い、WindowsはWASAPIを使います。権限・出力経路・会議アプリの実行構成により取得範囲が異なるため、最初に[5秒テスト](../guides/usage.md#録音する)で入力を確認します。

## テストと録音操作

「5秒録音して確認」の音声は一時確認用です。マイクとPC音声をそれぞれ16 kHz・モノラル・PCM16の短いWAVへ保存し、個別に再生します。確認画面を閉じると実行と再生を終了してから削除します。PC側が無音でサンプルを受信しないことと、保存の失敗を区別します。

通常録音には固定の4時間停止期限を設けません。メイン画面が非アクティブになるとミニパネルを表示し、入力状態と停止操作を提供します。パネルを隠す操作と録音停止は別です。停止の確定後は、保存処理の終了を待ちます。

ミニパネルの波形は、マイクとPC音声それぞれの受信済み測定値だけを棒で表示します。1秒を超えて古い測定値、未受信、確認不可、切断中は棒を追加せず、右端に空白を流します。空白の長さは途切れた時間に比例し、過去の棒は左へ流れ、64本分の時間（Windowsでは約16秒）で消えます。新しい録音では空の波形から始めます。

入力レベルと接続状態・入力履歴の読み取りが3秒以上応答しない場合は、その要求を待たずに読み直します。続けて応答しない場合は待ち時間を6秒、12秒と延ばし、応答待ちの要求は1画面・1種類につき4件までにします。PCの時計が戻った場合は表示中の値を捨て、時計を作り直したあとに公開された新しい測定値から表示を再開します。読み取りの失敗・停滞・応答なし・時計の逆行とその復旧は内部ログへ記録し、入力レベルはメイン画面とミニパネルを区別します。ログに会議の内容や音声は含めません。

## 音声の保存

元の取得フレームと会議時刻の対応を保持します。元音声から復元できない欠損は記録を残して正式WAVの無音区間とし、前後の音声の時刻を詰めません。未確定の録音は保存完了と表示しません。取得・変換とディスクの同期保存を分離し、取得済みから保存確定までの音声を1入力あたり最大120秒、メモリで待機させます。取得PCMの待機には従来の20秒・16 MiB・4,096パケットの上限を残し、変換済み音声の共有バッファにも16 MiB・4,096ジョブの上限を設けます。構築中・書込み中も計上し、保存確定後にだけ解放します。取得PCMの待機上限に達した場合は、受理済みの音声を捨てず、対象入力だけを取得し直して録音を続けます。未保存音声の120秒・メモリ上限や書込み不能に達した場合は、音声を捨てて続けず停止して案内し、確定済み音声を保持します。

WindowsのPC全体録音では、各出力の合成後のキューが満杯になった場合、受理済みPCMを保持して空きを待ちます。取得側のキューの上限超過と混同せず、待機後も各入力の未読範囲を追い越さずに順次排出します。停止時も録音側が排出を続けてから取得処理の終了を確認します。まだ録音へ採用していない準備結果の取消・破棄では、空き待ちを解除してOS資源を解放します。

録音中は、取得した音声を入力ごとに16 kHz・モノラル・PCM16へ変換し、共通Rustミキサーで単一の`recording.wav`へ合成します。区間ごとに実際に取得できた入力数で平均し、片入力のみの区間はその音量を維持します。ゼロ値PCMを受信した入力も取得済みとして数えます。通常の録音中に分割CAF・中間FLAC・別の完成WAVは作成しません。

取得・変換・合成と保存を別の処理所有者へ分けます。入力の接続世代・連番とFIFOの処理完了を確認し、未読・変換中の音声をタイマーや保存処理が追い越して確定しません。未受信の観測も受理済みPCMの後に処理し、取得した無音とは区別します。既存の250 msの合成待ちと750 msの無通信猶予を用い、追加の一律4秒の整列待ちは設けません。OSから届く古い時刻の音声は、取得側の時計補正で全フレームを保持し、共通WAVミキサーの接続世代・連番・時刻順序の検査を通して保存します。

約4秒分の出力PCMを書き込み、同期保存してから、所有・時計原点・ブロックハッシュ・入力別の取得範囲・欠損範囲を記録したチェックポイントと確定位置を公開します。Windowsの保存ワーカーは書込み量・同期結果・ファイル実体を確認し、同じPCMの直後の読戻しは行いません。アプリ側は公開された範囲を読み、チェックポイントのSHA-256と照合してから受理します。内容不一致はその段階で検出し、検証できない音声を会議へ登録しません。macOSの保存ワーカーの読戻し照合は維持します。保存先が停止している間はメモリ上の未確定音声が増え、異常終了時に失われる場合があります。停止後は末尾を排出してWAVヘッダーを確定し、形式・ハッシュ・DB登録を検証します。正常停止では既存PCMの全体再ミックスや再書込みは行いません。

音声本体の確定に必要な所有・連番・バイト範囲・PCMハッシュの証拠と、補助統計・入力別時計マップ・UTC・終了manifestを区別します。現行の単一WAVでは補助情報の欠損や不整合だけで検証済みPCMの保存を止めず、不明な時刻や欠損情報を補作しません。停止時の正常な末尾も補助情報の作成結果と独立して保存し、入力停止を確認できない場合は正常終了を示す印を付けず確定済み範囲を保持します。入力時刻の補正・接続世代・FIFO・不正PCM・容量上限・実際の書込みと同期の検査は維持します。

WAVのPCM開始位置は80バイトに固定し、通常RIFFの予約領域を必要時にRF64の`ds64`へ切り替えます。録音・取り込みの確定失敗は500 ms後に同じ操作を1回だけ再確認し、既に確定済みなら重複登録せずその結果を使用します。回復不能な場合は保存済み音声を保持して保存失敗を知らせ、次回起動待ちの案内は表示しません。[ADR 0014](../adr/0014-direct-wav-recording.md)に保存方式の判断を記載します。

WAVの確定記録は最大65,536件とし、旧CAFの32,768分割の上限とは分けます。4秒ごとの保存でも4GiB境界を越えられる範囲です。管理記録32MiBの上限は維持し、音声の欠損記録などが先に上限へ達した場合は、確定済み音声を保持して既存の保存失敗処理へ接続します。

録音プロセスの終了後、正常終了できなかった場合も、所有・連番・範囲・PCMハッシュを検証できた確定済み音声を同じ会議へ自動保存します。確定記録やPCMの途中に不整合がある場合は、その直前までの連続した正常部分を保存し、不整合の先や未確定末尾を読み飛ばして採用しません。元音声と不整合の記録は保持します。起動時には既存の失敗・中断セッションと、登録後にWAVの保存が残ったセッションも対象にします。片方の入力だけでも音声があれば保存し、確定していない末尾や実際の取得終了時刻は推測しません。正式WAVの検証完了まで保存中として扱い、完了後は「録音済み」と表示します。「録音未完了・要確認」は使用しません。保存できない場合は「音声保存エラー」とし、会議一覧と通知から「保存を再試行」できます。同一セッションの処理は直列化し、再起動や新しい会議の作成を必要としません。両入力の確定サンプル数がゼロと検証できた場合だけ「録音失敗」とします。無音のサンプルも取得済み音声として数え、読めない音声や欠けた証拠をゼロとみなしません。

正常停止、異常終了後の回復、保存の再試行は、録音セッションごとに1件の「録音の保存」として表示・記録します。停止中から保存完了まで同じジョブIDを使い、保存処理が発行する最新の工程を表示します。回復中・再試行中であることも工程内で伝え、別のジョブや件数へ重ねて計上しません。起動時の対象確認後は録音ごとの待機・実行状態へ引き継ぎます。

履歴の種別は`recording_save`、IDは`recording_save:{sessionId}`です。再試行では最初の開始時刻を保持して同じ履歴の結果を更新します。成功は正式WAVの検証・保存・必要な整理の完了で確定し、セッションの`saved`だけでは履歴を成功へ補完しません。保存中の終了操作は実際の保存完了を待ち、保存失敗や確認対象の変更を未確認のまま通過させません。保存失敗通知は同じセッションで重複させず、正常完了を通知する場合の本文は「録音を保存完了しました。」とします。成功通知の発生条件と件数は増やしません。音声本体の一部だけを救出した場合は、保存済みとして扱い、保存できなかった部分があることを同じセッションの通知・履歴に1件で伝えます。補助情報だけの不整合で全PCMを保存できた場合は内部ログに診断を残し、新たな成功通知や部分保存の警告を増やしません。

既存の回復用IPC名は維持します。表示用スナップショットには開始経路`origin`（`stop`・`startup`・`retry`）と対象セッション`targetSessionId`を持ち、起動時の一括対象確認では対象セッションを`null`とします。読取り失敗を正常な空状態として扱わず、古い応答から完了済みジョブを復活させません。既存履歴の統合は[保存仕様](storage.md#録音保存の履歴移行)を参照してください。

取り込み中も、原本の管理コピーから復号した小さな区間を順次変換して、16 kHz・モノラル・PCM16のWAVへ直接保存します。高音域・ステレオ情報は保存用音声へ保持しません。同じWAVを正式音声として検証・登録し、再生・解析に使います。元音声・時計・欠損・合成条件に対応する内容を照合して再利用します。WAV完成後は不要な管理コピーと途中ファイルを整理し、取り込み元のオリジナルは保持します。旧CAF・FLACの未完了データは専用の移行・救出処理で検証して正式WAVへ渡します。完成済みWAVは再生成しません。Windows・macOS共通の互換性と整理は[データ管理](storage.md#現行形式)を参照してください。

録音・取り込みの音声本体は約115.2 MB/時です（十進表記。メタデータ等は別途）。取り込みの必要容量には原本の管理コピー、保存用WAVと安全余裕を含めます。原本の容量表示は変換前の値を使います。

## 音声ファイルの取り込み

WAV・MP3・AAC/ALAC M4A・FLACを1件ずつ選択またはドロップして会議を作成します。拡張子だけでなく実際の形式を検査し、長さ・容量・保存先の空きと必要容量を表示します。会議名と取り込み時の用語を設定できます。

MP3では、先頭のID3v2と末尾のID3v1・APEv2を音声範囲から除外します。末尾のAPEv2はフッター付きが対象で、音声直後に置かれ、ID3v1を併用する場合はその直前に置かれます。APEv2の長さ・ヘッダーとフッターの整合性・項目の境界を検査します。Lyrics3v2などの未対応の末尾タグ、不正なタグや追記データ、途中で切れたMPEGフレームがある場合は取り込みを拒否します。

WAVは対応する整数／浮動小数点PCMを扱い、WAVEFORMATEXTENSIBLEの整数有効ビットは左詰めとして解釈します。FLACはCRC・PCMのMD5を含めて検査します。原本の形式・長さ・フレーム数と、直接保存したWAVの形式・フレーム数を別々に検証します。確定済みの既存音声を形式変更だけのために再生成しません。原本を検査した証拠と所有を保持し、取り込み元の利用者ファイルを削除しません。

FLACのSTREAMINFOで、既知の最大フレームサイズが最小サイズより小さい場合は、その2項目だけを読み取り用ヘッダー上で「不明」として復号を続けます。元ファイルとそのハッシュは変更しません。旧録音の復旧・取り込み・再生で共通の読取り処理を使い、音声本体のCRC・PCMのMD5・実フレーム数などの検証は維持します。
