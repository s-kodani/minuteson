# 保存とバックアップと復旧

## 保存する情報

主要テーブルのキーと関連は[データモデルとER図](data-model.md)を参照してください。

会議情報・解析・編集・処理履歴をSQLiteで管理します。録音・取り込みが正常完了した会議の音声本体は、16kHz・16bit・モノラルのWAV 1ファイルです。Windows・macOSで同じ保存・整理仕様を使います。会議の時間欠損を隠して音声を連結しません。

### WAV完成後の音声整理

WAVの同期保存・形式・ハッシュ検証とDB確定後に、元の連続CAF・分割CAF、中間FLAC、取り込み元の管理コピーと復号CAFを整理します。録音中の二重保存と取り込み時の中間CAFは維持します。外部の取り込み元オリジナルは変更・削除しません。

正常完了した録音・取り込みの専用作業領域と、そのWAVの出力作業領域では、空・破損した途中ファイルなど、管理記録と対応付けられない残骸も対象です。会議全体や外部フォルダーを拡張子だけで一括削除せず、リンク先も走査しません。最終WAV、登録文書、JSON・ロック等の管理記録、通知・時刻情報は保持します。未完了録音・部分救出の作業領域はこの一括整理に含めず、未救出の音声を保持します。解析用一時音声は従来のライフサイクルで管理します。

旧FLAC変換の出力先も、入力トラックや実体を確認できる変換計画から特定して整理します。設定から保存先を移動した場合は、アプリが検証したコピー前後の実体対応を使って削除を再開します。同じ内容の別ファイルへの差し替えは削除対象として引き継ぎません。

削除前に対象・実体・容量・ハッシュを整理台帳へ固定し、削除直前に再確認します。使用中の音声は処理終了後に整理します。失敗時も完成WAVを保持し、次回起動で残りから再開します。更新後の初回起動では従来の整理済み会議も再確認しますが、正常なWAVは再生成しません。初回整理の入口と処理は通常経路から独立しています。判断の理由は[ADR 0009](../adr/0009-completed-wav-cleanup.md)を参照してください。

会議データとAIモデルの保存先は別です。設定から会議保存先を変更してもモデルは移動しません。通常版・QA版・Windows Store版はアプリ識別子で保存設定を分離します。具体的な保存先はアプリの表示とOSのアプリ領域を確認し、他端末の固定パスを流用しません。

## ボイス登録音声

登録した区間は`voices/<人物ID>/<登録区間ID>.wav`に16kHz・モノラル・PCM16で独立保存します。人物名・声の特徴量は`voice_people`／`voice_samples`、音声のパス・SHA-256・容量・保存状態は`voice_sample_audio`で管理します。会議や会議音声を削除しても登録音声は残り、登録区間・人物の削除で対応する音声も削除します。

既存登録分は元音声が残っていれば起動後に自動保存し、バックアップ前にも同じ処理を行います。元音声がすでにない場合は特徴量のみ保持します。保存失敗時は元会議・会議音声の削除を開始せず、ボイス一覧の「音声保存・削除を再試行」から再試行します。ファイル操作の中断は端末内の`voice_audio_operations`で回収し、この作業記録はバックアップに含めません。

## バックアップと追加復元

全会議を一つの`.monbackup`に保存します。対象は会議情報・会議音声・現在の編集済み文字起こし（話者・時刻を含む）・現在のMarkdown議事録、共通と会議ごとの用語一覧、登録人物・声の特徴量・独立した登録音声WAVです。用語の読み・注記・有効状態・順序も保持します。過去の解析版・編集操作・ジョブ履歴・チェックポイント、モデル本体と設定、プロンプト、端末設定、内部ログは含めません。利用中DBの履歴は削除しません。会議音声は保存済みの共通WAVをそのまま収録し、無音区間と再生時間を保持します。原入力の時計マッピングや未完了処理の回復記録は引き継ぎません。

文字起こしの話者から登録人物・声への紐付きをIDで保持し、候補・自動識別・確認済み・却下の状態と表示名の編集を引き継ぎます。声の登録・照合で使う現在の音声上の話者区間も、話者不明・重複関係・信頼度を含めて保存し、発言の編集済み割当てから作り直しません。複数会議が同じ人物を参照する場合、復元後も同じ新規人物を参照します。同名の既存人物とは統合せず、削除済み人物は再作成しません。元会議が削除済みでも独立保存済みの登録音声は復元できます。音声が元からない登録は特徴量のみ保持し、保存未完了・破損は復元成功として扱いません。

会議音声は通常のRIFF WAVと長時間録音用のRF64 WAVに対応します。取り込みが失敗・取消となった会議も、保存済みの会議情報を復元し、他の会議の復元を妨げません。未確定の音声や取り込み処理の履歴は復元しません。

追加復元は現在のデータを置き換えず、全会議・用語・人物をまとめて確定します。現在の文字起こしを一つの解析版として作成し、録音・取り込み元は既存テーブルに必要最小限の情報だけ作成します。DBはschema 38のままで、新しいテーブルやmigrationは追加しません。共通用語は完全一致を省き、同じ用語で内容が異なる場合は既存を保持して競合を報告します。会議ごとの用語は追加した会議に所属します。

バックアップと復元はジョブ一覧で工程別の会議数・バイト数と停止状態を確認できます。実行中もジョブ一覧へ移動できます。データ操作は同時に一つだけ実行し、書き込みを保護します。完了・失敗・取消の結果は閉じるかアプリを終了するまで表示し、永続的なジョブ履歴や自動再実行は作成しません。

準備・検査・追加確定の各段階で、参照・内容ハッシュ・所有・容量を照合します。同一の復元バッチの再送で二重追加せず、利用者が別の復元として選ぶ場合は別会議として扱います。既存の会議・モデル選択・設定は保持します。

会議削除と音声だけの削除を区別します。削除対象・範囲を確認し、対象の所有と同意を照合してから進めます。他の保存先まで一括削除しません。正常完了した専用作業領域の残骸は、上記のWAV完成後の整理で扱います。登録済み声の音声・特徴量と内部ログには、それぞれ独立した保存・削除の操作／期限があります。

## 現行形式と対応する更新元

| 対象 | 現行／対応範囲 |
| --- | --- |
| DB | schema 38。新規初期化と、履歴を検証した34／35／36／37からの限定的な前進更新 |
| バックアップ出力 | format 8・schema 38（現在内容の型付きデータと音声） |
| 追加復元 | format 8・schema 38のみ。旧format 5／6／7は受け付けません |

35→36の前に`before-followup-intents.sqlite3`、36→37の前に`before-pcm-import.sqlite3`、37→38の前に`before-voice-audio.sqlite3`を残します。過去のmigrationとchecksumは変更せず、過去会議に新しい解析意図を一律追加しません。その他の旧形式を一律変換しないため、未対応版・改変・履歴欠落は拒否します。正本は[更新処理](../../app/src-tauri/src/storage/schema_upgrade.rs)と[バックアップ形式検査](../../app/src-tauri/src/storage/backup/archive.rs)です。

## 異常時と排他

会議DB・配置台帳・起動設定・ファイルの所有と実体を確認し、起動検証に失敗した場合は通常操作を開始せず診断を表示します。診断の再読込みはメモリに保持した結果を読み、保存先の再検査・修復・削除を行いません。

診断画面には、別の明示操作として「起動をやり直す」と「データを初期化」があります。初期化の確認では対象の保存先と退避の有無を選びます。会議・音声・文書・モデル・設定が対象となり、退避を選んでもモデル本体・取得途中のモデルは削除されます。退避フォルダーは通常のバックアップ形式とは異なります。[画面遷移](screens.md#起動と診断)と[障害対応](../guides/troubleshooting.md)を確認してください。

処理の所有・操作ID・入力・内容ハッシュ・版を固定し、結果不明の操作を別IDで無断再送しません。解析結果と後続処理意図を原子的に記録します。会議削除・モデル削除・全体保守は専用の所有を区別し、競合する実処理との相互排他を維持します。取消・アプリ終了時は所有する実処理の終了を待ちます。

起動中の会議DBへ診断用の外部SQLite接続を追加しません。アプリ内で確認するか正常終了後に調べます。復旧手順は[障害対応](../guides/troubleshooting.md)を参照してください。

## ログとプライバシー

「内部ログ」で処理経過とAIエンジンの診断を確認できます。自動更新の一時停止、日時・処理・ID・本文検索、表示中ログのコピーに対応します。会議データと別に最大30日・合計200 MiBを保存し、上限を超えると古いログを削除します。会議本文やローカルパスが含まれる場合があり、会議削除後も保持期限まで残ります。ログはバックアップ対象外です。
