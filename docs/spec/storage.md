# 保存とバックアップと復旧

## 保存する情報

主要テーブルのキーと関連は[データモデルとER図](data-model.md)を参照してください。

会議情報・解析・編集・処理履歴をSQLiteで管理します。録音・取り込みが正常完了した会議の音声本体は、16kHz・16bit・モノラルのWAV 1ファイルです。Windows・macOSで同じ保存・整理仕様を使います。会議の時間欠損を隠して音声を連結しません。

### WAV完成後の音声整理

通常録音は録音中から単一WAVへ追記し、取り込みも直接作成したWAVを正式音声として登録します。新規処理では分割CAF・中間FLAC・復号CAF・重複する完成WAVを作成しません。WAVの同期保存・形式・ハッシュ検証とDB確定後に、取り込み元の管理コピーと役目を終えた途中ファイルを整理します。

旧形式の未完了録音・取り込みは専用の移行・救出処理で従来の所有・時計・ハッシュを検証し、正式WAVへ直接渡します。旧分割CAFから新たな中間FLACを作ったり、旧取り込みを新しいCAFへ変換し直したりしません。正式WAVの確定まで旧音声を保持し、途中で停止した場合は未完了分から再開します。元の連続CAF・分割CAF・中間FLAC・復号CAFは確定後の整理対象です。完成済みの音声は形式変更だけのために再生成せず、外部の取り込み元オリジナルは変更・削除しません。

単一録音WAVの実体は録音開始時の所有予約で固定します。録音中は出力PCMの範囲・ハッシュ・時計原点・入力別の取得範囲・欠損範囲をチェックポイントへ記録し、同期保存と読戻し検証が済んだ範囲だけを確定位置へ反映します。音声本体の所有・連番・範囲・PCMハッシュを保存の根拠とし、補助統計・時計・終了manifestの不整合だけでは検証済みPCMを拒否しません。実際の取得終了時刻やUTCを証明できない場合は不明のまま保存します。

異常終了後はプロセス終了と実体対応を確認してから、確定済みの正常な範囲を検証します。途中の確定記録やPCMが不正なら直前までの連続した先頭部分を救出し、不整合の先や確定位置が示していない末尾は採用しません。先頭部分を別WAVへ保存する場合も、元WAV・確定記録・manifestと未救出範囲は保持し、正常完了領域の一括整理へ含めません。旧分割CAFも未確定のネイティブ録音に限って入力ごとの正常な先頭部分を救出しますが、入力を合成するために必要な時計マップは引き続き検証します。復元済み履歴や完成済み音声を救出の権限として書き換えません。

同じ保存処理内では、検証済みのファイル実体・検証時点・内容ハッシュをDB登録と完了確認へ引き継ぎ、同じPCMを理由なく全量再検査しません。実体・内容・参照が変われば再利用せず、別の再試行や再起動後は保存済みハッシュに対して独立に照合します。検証結果をプロセスをまたぐ信頼済みキャッシュにはしません。

音声取り込みの保存中は、取り込み音声の検証、保存用WAVの作成、保存内容の検証、保存結果の登録、中間ファイルの整理を通知します。WAV作成だけは出力フレーム数に基づく工程内の進捗率を表示し、全工程の進捗率や残り時間は推定しません。WAV作成が100%でも保存完了とはせず、検証・登録・整理の成功後に完了を通知します。

正常完了した録音・取り込みの専用作業領域と、そのWAVの出力作業領域では、空・破損した途中ファイルなど、管理記録と対応付けられない残骸も対象です。会議全体や外部フォルダーを拡張子だけで一括削除せず、リンク先も走査しません。最終WAV、登録文書、JSON・ロック等の管理記録、通知・時刻情報は保持します。未完了録音・データ復元の作業領域はこの一括整理に含めず、復元できなかった音声を保持します。解析用一時音声は従来のライフサイクルで管理します。

設定から保存先を移動した場合は、アプリが検証したコピー前後の実体対応を使って削除を再開します。同じ内容の別ファイルへの差し替えは削除対象として引き継ぎません。

削除前に対象・実体・容量・ハッシュを整理台帳へ固定し、削除直前に再確認します。使用中の音声は処理終了後に整理します。失敗時も完成WAVを保持し、次回起動で残りから再開します。判断の理由は[ADR 0009](../adr/0009-completed-wav-cleanup.md)を参照してください。

会議データとAIモデルの保存先は別です。設定から会議保存先を変更してもモデルは移動しません。通常版・QA版・Windows Store版はアプリ識別子で保存設定を分離します。具体的な保存先はアプリの表示とOSのアプリ領域を確認し、他端末の固定パスを流用しません。

## ボイス登録音声

登録した区間は`voices/<人物ID>/<登録区間ID>.wav`に16kHz・モノラル・PCM16で独立保存します。人物名・声の特徴量は`voice_people`／`voice_samples`、音声のパス・SHA-256・容量・保存状態は`voice_sample_audio`で管理します。会議や会議音声を削除しても登録音声は残り、登録区間・人物の削除で対応する音声も削除します。

会議・会議音声の削除前に、登録音声の保存記録とファイルを検証します。登録音声の削除が保留中の場合は、ボイス一覧に「再試行」を表示します。削除保留は登録人物が0人になっても、アプリを再起動しても端末内の作業記録から表示します。ファイル操作の中断は端末内の`voice_audio_operations`で回収し、この作業記録はバックアップに含めません。

## バックアップと追加復元

全会議を一つの`.monbackup`に保存します。対象は会議情報・会議音声・現在の編集済み文字起こし（話者・時刻を含む）・現在のMarkdown議事録、共通と会議ごとの用語一覧、登録人物・声の特徴量・独立した登録音声WAVです。用語の読み・注記・有効状態・順序も保持します。過去の解析版・編集操作・ジョブ履歴・チェックポイント、モデル本体と設定、プロンプト、端末設定、内部ログは含めません。利用中DBの履歴は削除しません。会議音声は保存済みの共通WAVをそのまま収録し、無音区間と再生時間を保持します。原入力の時計マッピングや未完了処理の回復記録は引き継ぎません。

文字起こしの話者から登録人物・声への紐付きをIDで保持し、候補・自動識別・確認済み・却下の状態と表示名の編集を引き継ぎます。声の登録・照合で使う現在の音声上の話者区間も、話者不明・重複関係・信頼度を含めて保存し、発言の編集済み割当てから作り直しません。複数会議が同じ人物を参照する場合、復元後も同じ新規人物を参照します。同名の既存人物とは統合せず、削除済み人物は再作成しません。元会議が削除済みでも独立保存済みの登録音声は復元できます。音声が元からない登録は特徴量のみ保持し、保存未完了・破損は復元成功として扱いません。

会議音声は既存の44バイトRIFF WAV、新しい80バイトの予約領域付きRIFF WAV、長時間録音用のRF64 WAVに対応します。保存記録との照合は検証済みのデータ位置とフレーム数を使います。登録した声の短い独立WAVの形式は変更しません。取り込みが失敗・取消となった会議も、保存済みの会議情報を復元し、他の会議の復元を妨げません。未確定の音声や取り込み処理の履歴は復元しません。

バックアップ作成時は管理音声のハッシュと形式を確認し、確定前に出力ファイルを先頭から読み戻して、目録、各ファイルのハッシュ、全体容量を照合します。読み戻しの結果からバックアップ全体のハッシュも計算します。

追加復元は現在のデータを置き換えず、全会議・用語・人物をまとめて確定します。現在の文字起こしを一つの解析版として作成し、録音・取り込み元は既存テーブルに必要最小限の情報だけ作成します。共通用語は完全一致を省き、同じ用語で内容が異なる場合は既存を保持して競合を報告します。会議ごとの用語は追加した会議に所属します。

バックアップと復元はジョブ一覧で工程別の会議数・バイト数と停止状態を確認できます。実行中もジョブ一覧へ移動できます。データ操作は同時に一つだけ実行し、書き込みを保護します。

バックアップの正常完了は通知トーストと通知一覧に表示し、設定画面や進行中のジョブに完了カードを残しません。処理結果はジョブ一覧の「履歴」で確認できます。通知には同じ操作で確定した保存先・会議数・容量と、音声削除済み会議がある場合の制約を表示します。Windowsの拡張長パスは通常のドライブ／UNC表記にして表示し、実際の保存先は変更しません。長いパスも通知の詳細で確認できます。通知一覧はアプリ終了まで保持します。失敗・取消・要確認状態と、復元後に会議一覧を開く操作は画面に残します。ジョブ一覧は「進行中」「履歴」で切り替えます。履歴には全種類の処理結果を新しい順に50件ずつ表示し、種類と結果で絞り込めます。履歴は端末の専用SQLiteへ直近90日間保持し、通常バックアップには含めません。終了日時が未確定の場合は最終確認日時を保持期限の基準にし、実行中・再開待ちは期限整理から除外します。会議の削除時は関連履歴も削除し、削除操作は件数・日時・結果だけ残します。データ初期化では履歴も消去します。過去の記録から確認できる結果は取り込みますが、未保存の結果や日時は補作しません。履歴表示は処理の再実行や復旧の権限には使いません。

準備・検査・追加確定の各段階で、参照・内容ハッシュ・所有・容量を照合します。同一の復元バッチの再送で二重追加せず、利用者が別の復元として選ぶ場合は別会議として扱います。既存の会議・モデル選択・設定は保持します。

会議削除と音声だけの削除を区別します。削除対象・範囲を確認し、対象の所有と同意を照合してから進めます。他の保存先まで一括削除しません。正常完了した専用作業領域の残骸は、上記のWAV完成後の整理で扱います。登録済み声の音声・特徴量と内部ログには、それぞれ独立した保存・削除の操作／期限があります。

削除可否は、操作メニューを開いた会議や表示中の会議詳細など、操作に関係する会議について取得します。削除の確認と実行では、ネイティブ側でその時点の処理状態と対象を照合します。

### 録音保存の履歴移行

履歴専用DBは版2を使います。旧版は初回起動時に専用のトランザクションで移行し、同じ会議・セッションの「録音の保存」と「録音の回復」を`recording_save:{sessionId}`の1件へ統合します。旧IDから取り出したセッションIDを検証し、別会議の履歴は統合しません。

開始時刻は最も早い値、結果・終了時刻・詳細は最新の観測を採用します。同時刻の場合は確定結果を優先し、その次に元の保存履歴を優先します。不整合や移行失敗ではロールバックして元データを保持し、履歴のエラー表示へ伝えます。移行が完了したDBを再移行せず、通常処理では統合後の種別だけを使います。90日保持・絞込み・ページ送り・会議削除時の履歴整理の方針は維持します。

会議DBからの履歴補完は起動完了後にバックグラウンドで進めます。保存の完了証拠とWAVの内容を確認した結果は履歴専用DBへ記録し、次回の補完では同じ録音の記録とファイルが変わっていないことを確認して再利用します。ファイルの変更や未確認の記録があればWAVを照合します。履歴の記録は音声の利用・復旧・削除を許可する証拠には使いません。

音声データと会議DBの保存形式は、この履歴移行では変更しません。

## 現行形式

| 対象 | 現行形式 |
| --- | --- |
| DB | schema 40。単一のSQLで新規初期化し、版・チェックサム・実際の構造を照合。既存schema 39からは取り込み確定条件のトリガーだけを専用移行 |
| バックアップ出力・追加復元 | 出力はformat 8・schema 40。旧format 8・schema 39も同じ表・列契約を検証して追加復元 |
| 履歴専用DB | version 2。旧保存・回復履歴を録音セッションごとに統合 |
| 録音manifest | version 5。単一WAVの確定証拠。旧version 4は専用の救出入口で検証 |
| 取り込みmanifest | version 4。保存用WAVを直接公開。旧version 2／3は専用移行で検証 |
| 録音FFI | ABI 1。既存の公開型・関数を維持してWAV用の関数を追加 |

会議DBに公開前の旧形式が見つかった場合は、既存のDB・音声を保持して起動時の案内を表示します。履歴専用DBの旧版は上記の専用移行で扱います。文字起こしの下書きは会議ごとに現在の内容を1件保存します。解析版を置き換えるときは同じトランザクションで旧下書きを削除し、現行処理が参照する解析版と操作記録を保持します。

### 1.0.7との互換性

既存DBの取り込み確定トリガーはCAFのメディア種別だけを認めるため、schema 40でCAFとWAVを認める条件へ更新します。旧schema 39のSQLチェックサムと実構造が一致する場合だけ、1トランザクションでこのトリガーと版の記録を移行します。テーブル・列・既存データは変更せず、他の過去版を受け入れる汎用移行は追加しません。旧macOS版のLFと旧Windows版のCRLFは、既知のチェックサムとSQL定義の組として検証します。新規DBはLFの定義を使い、既存Windows DBの移行ではSQLの改行形式と削除履歴の照合を維持します。

1.0.8は1.0.7の完成済みWAVとformat 8・schema 39のバックアップを読み取り、旧未完了CAF・FLACと取り込みmanifest version 2／3を専用処理で救出します。新規録音と旧録音の合成条件は区別し、完成済み音声や旧録音の救出結果へ新しい区間別平均を遡って適用しません。移行失敗では元音声と未完了状態を保持し、空データや移行成功として扱いません。

旧macOSの録音manifestは、ファイルや録音フォルダーに他者の読取り権限ビットが残る場合があります。旧形式の読取りに限り、保存先とファイルの所有、リンク数、実体、他者の書込み権限がないこと、内容ハッシュを照合して受け入れます。元ファイルの権限は変更せず、新規manifest・WAV・確定記録は所有者専用の権限で保存します。

新版で作成したデータ・バックアップを1.0.7で利用することは保証しません。旧版には短い会議WAVを44バイトヘッダーとしてサイズ判定する処理があり、新しい80バイトRIFFやmanifestを拒否する場合があります。DBはschema 40へ移行し、バックアップの外側の形式は8を維持します。新版で旧データを利用する方向と、新版同士のバックアップ往復を対象とします。旧format 5／6／7や過去のDB schema全般の対応は追加しません。

旧版へ戻す必要がある場合は更新前のバックアップを保持し、旧版で使用する領域へ復元します。新版利用後の保存領域を旧版で無理に開いたり、新版のデータを削除・初期化したりしません。本体と録音ヘルパーは同じ配布候補の組合せを使い、必要な保存契約に対応しないヘルパーは取得開始前に拒否します。同じ1.0.8の検証候補同士でも、移行の要否はアプリ版数ではなくmanifest・保存証拠の版と移行記録から判定します。

## 異常時と排他

保存先・会議DBの実体、排他と対応スキーマを確認します。DBを安全に開けない場合は起動時の案内を表示します。「起動できるか再確認」で、準備が完了しているかを再確認します。

起動時は、未完了の削除と保護対象を通常操作の受付前に確認します。会議を特定できた場合はその会議への書込みを保護し、他の会議は閲覧・編集・新規作成できます。削除対象を特定できない記録や共有作業領域の異常では、閲覧を続けながら共有の書込みを停止します。完了履歴は分割して確認し、不正な記録や確認できなかった操作は保持します。音声の異常は会議一覧の診断と音声を使う操作に反映します。

確定した文字起こしが正常で、文字起こしの編集下書き自体の破損や不整合をDBで確認できた場合は、確定本文を通常どおり開きます。下書きの行と本文の形式番号が食い違う場合も対象です。書込みが許可されているときは、DBのロック下で確認した下書きの行だけを削除します。通常の編集を始めると、確定本文を基に新しい下書きを保存できます。通信やDB読取りが失敗した場合、書込みが保護されている場合、下書きの行と本文がともに同じ未対応形式を示す場合は削除を保留します。文字起こし・議事録の本文自体に保存記録の不整合がある場合は、読み取れた本文を確認用に表示します。

診断画面には、別の明示操作として「起動をやり直す」と「データを初期化」があります。初期化の確認では対象の保存先と退避の有無を選びます。会議・音声・文書・モデル・設定が対象となり、退避を選んでもモデル本体・取得途中のモデルは削除されます。退避フォルダーは通常のバックアップ形式とは異なります。[画面遷移](screens.md#起動と診断)と[障害対応](../guides/troubleshooting.md)を確認してください。

処理の所有・操作ID・入力・内容ハッシュ・版を固定し、結果不明の操作を別IDで無断再送しません。解析結果と後続処理意図を原子的に記録します。会議削除・モデル削除・全体保守は専用の所有を区別し、競合する実処理との相互排他を維持します。取消・アプリ終了時は所有する実処理の終了を待ちます。

起動中の会議DBへ診断用の外部SQLite接続を追加しません。アプリ内で確認するか正常終了後に調べます。復旧手順は[障害対応](../guides/troubleshooting.md)を参照してください。

### データ復元

起動時の案内または通常画面の「データ復元」から、確認できたデータを新しい保存先に引き継ぎます。通常画面から開始するときは編集を保存するか、OSの保存画面で指定した退避ファイルへの書き込みが完了してから専用モードで再起動します。退避の取消・失敗があれば編集画面へ戻れます。起動設定の保存先を確認できないときはOSの選択画面で元の会議データフォルダーを選びます。出力は選んだ親フォルダー内の新しい専用フォルダーへ作成します。容量不足の場合は復元画面で別の親フォルダーを選び、内容と必要容量を確認し直せます。

元の保存先の排他を取得し、作業用コピーでSQLiteの回復と検査を行います。確認画面では会議、文字起こし、議事録、音声、登録した声、用語、設定、モデルごとに検査結果と必要容量を表示します。読めた本文と確認済みの音声を独立して引き継ぎます。確認できた文字起こしの下書きは本文に反映し、確認できない編集内容は引き継がず、確定本文を使う旨を文字起こしの行に表示します。取得できない設定は既定値を用い、モデルは検証した素材を新しい登録として独立したモデルフォルダーに保存します。旧ジョブ、削除の同意、旧モデルの実行確認は新しい保存先へ移しません。

新DBの整合性と外部キー、通常の読取り、コピーした音声を検証し、同期保存と復元結果の確定後に起動設定を原子的に切り替えます。確定前の取消は元の起動設定を維持します。中断後の再試行では操作IDと確認済みの計画を使い、切替が確定していれば同じ結果を参照します。元の保存先は、利用者が削除を選ぶまで保持します。旧版の全件検証後に初期化・再登録する方式は廃止しました。旧版ですでに開始した操作の中断記録は、起動時に検証して回復します。

復元由来と部位ごとの利用不可理由は会議DBにも保存します。利用できない音声がある会議を、音声削除済みとして扱わず、通常バックアップの追加復元でも部位ごとの理由を引き継ぎます。「設定」の「データと保存」から復元結果と元の保存先を確認できます。

切替先で起動した後、利用者は復元結果から「元データを削除…」を選べます。旧DBと関連ファイル、復元済みの管理音声のうち、実体と所有を確認できたファイルが対象です。旧DBを削除すると、そのDB内の復元できなかった内容も失われます。元のフォルダー、モデル、台帳、所有を確認できないファイルは元の場所に残ります。

削除の直前に現在の保存先、元の保存先の排他、対象ファイルを照合します。旧DBの関連ファイルは一体として照合し、実体を確認できない場合は処理を中断します。移動・変更などで確認できなくなった音声は個別に削除対象から外し、ほかの確認済みファイルの処理を続けます。処理後は削除対象から外れた音声の件数を表示します。削除が中断した場合は、復元結果から状態を確認し、処理を再開できます。削除対象の記録は切替先と機器内で結び付け、通常のバックアップの追加復元では引き継ぎません。

### データ復元の表示条件と判定一覧

エラーから新たなデータ復元を自動で始める経路はありません。利用者が「データ復元」から復元先を指定して「復元できる内容を確認」を実行すると事前確認が始まります。「復元して保存先を切り替える」を選んだ場合に作成と切替を行います。起動時に復元の操作記録を検証できれば、先に選んだ操作を引き継ぐため専用画面が開きます。操作記録が壊れていても、現在登録されている会議保存先を検証できれば、その保存先で通常起動し、元の操作記録を保持します。現在の保存先も検証できない場合は起動時の案内で案内します。

| 「データ復元」を表示する条件 | 判定に使う証拠 |
| --- | --- |
| 起動設定を確認できない | 安全に読み取った起動設定が壊れているか、初期化済みの記録に対応する起動設定が欠けている。 |
| 会議DBを安全に開けない | 登録情報と実体が一致する保存先で確認したDBのヘッダー不正、SQLiteが返した破損、非対応の会議DBスキーマ。 |
| 会議を閲覧できるが、通常の書き込みを再開できない | 共有の会議DBを確認する起動処理でSQLiteが破損を返したか、削除記録に矛盾する会議IDがあり、ほかの未完了操作を先に処理する経路もない。 |

別のアプリによるロック、接続・アクセス権限・空き容量の問題、初期化・移動・削除・追加復元の確認待ち、切替後の再起動待ちでは、原因に応じた確認方法を案内します。起動時の案内では原因を表示し、通常画面の閲覧専用の案内では現在の状態と再確認の操作を表示します。復元したモデル保存先だけに異常がある場合は、会議一覧を開き、モデルの準備・実行など、その保存先を使う機能で案内します。現在のモデル削除記録を検証できる場合は、「設定」の「導入済みモデル管理」から「残りの削除を確認」を選べます。会議データの書き込みが制限されている間は、新規のモデル削除も制限します。

起動できる状態か読み取れないときは、通信エラーなら最大3回自動で再確認します。受け取った内容を確認できないときや、自動で確認し直しても問題が続くときは「起動できるか再確認」を表示します。起動後に保存先の書込み可否だけを取得できない場合は再確認中と表示し、進行中のモデル準備は継続します。会議単位で範囲が分かる削除、会議一覧の不正行、個別会議の文字起こし・議事録・音声の異常、録音保存の異常、削除一覧・検査用コピー台帳の取得失敗、Windowsの外部プロセス管理の異常は、それぞれの画面や処理に閉じた診断です。バックアップ用の一時領域台帳が開けない場合は、台帳を使う操作を制限します。未完了の追加復元の保護範囲も確認できない場合は、影響範囲を確認するまで会議データへの書込みを止めます。削除の完了履歴が10,001件以上ある場合も、分割走査を続けます。

| 復元を選んだ後の項目 | 事前確認で異常があった場合 |
| --- | --- |
| 会議 | 会議IDを確認できない行は引き継ぎません。会議IDが確認できて会議名・状態・日時などだけが不正な場合は、分かる情報と既定値を使います。走査が途中で失敗した場合は、後続範囲を未検査と表示します。 |
| 文字起こし | 現在の解析版、確定状態、本文の保存証拠、話者・発言・件数を照合します。確定本文を証明できない場合は、その本文を引き継ぎません。下書きだけに異常がある場合は、正常な確定本文を引き継ぎます。 |
| 議事録 | 保存版・本文・ハッシュを検証し、確認できない議事録だけを引き継ぎません。 |
| 音声 | 保存済みの音声記録と所属、形式・長さ・ハッシュを照合します。利用者による削除を確認できた場合は、削除済みの状態を引き継ぎます。確定記録の異常時に検証できる正本のWAV候補が1件ある場合は、そのWAVを使えます。欠損、実体・属性の不一致、候補の重複、検証不能の場合は音声の理由を残して本文の確認を続けます。 |
| 登録した声 | 人物・サンプルの識別子、抽出方式、特徴量、時刻と参照を人物・サンプルごとに確認します。クリップが欠損・破損しても特徴量が正常なら、一部引継ぎとして登録できます。 |
| 用語 | 共通用語と会議用語を個別に検証し、取得・形式の確認に失敗した一覧を引き継ぎません。 |
| 設定 | 表示設定、議事録の指示、マイク、文字起こし、議事録生成、話者分離、話者照合、話者補完を検証します。確認できない設定は既定値を使います。旧実行ファイル・モデルの参照は未設定に戻し、モデル選択や自動話者識別の評価結果は、新登録で必要な確認を行います。 |
| モデル | 登録ID、保存場所、登録記録、素材、本体のハッシュを検証します。確認できない登録は新しい保存先へ追加しません。同じ内容のモデルは一つにまとめます。走査を継続できない範囲は未検査と表示します。 |

排他が取れない、復元元・出力先の実体や容量を確認できない、元の起動設定・DB・確認済みの計画が変化した、引き継げる項目がゼロ、新しいDB・ファイルの検証または同期保存に失敗した場合は、切替を確定しません。

## ログとプライバシー

「内部ログ」で処理経過とAIエンジンの診断を確認できます。自動更新の一時停止、日時・処理・ID・本文検索、表示中ログのコピーに対応します。会議データと別に最大30日・合計200 MiBを保存し、上限を超えると古いログを削除します。会議本文やローカルパスが含まれる場合があり、会議削除後も保持期限まで残ります。ログはバックアップ対象外です。

Windowsの拡張パス接頭辞は、起動時の案内・初期化・確認ダイアログ・通知・進捗詳細・内部ログの表示とログのコピー時に除去し、通常のドライブ／UNC表記で表示します。文章中やエスケープ済み診断のパスも同じ扱いです。ファイル操作に使う値、通知の識別に使う原文、保存済みの診断・ログは変更しません。
