# モデル削除と通知履歴の排他分離

対象ブランチ: `codex/windows-platform-foundation`。`a7139bc` へ fast-forward してから実装した。WindowsとmacOSで同じRust処理を使い、公開IPC・DB・保存形式は変更していない。

## 変更

モデル削除は全体保守の `data_maintenance` から独立した `model_deletion` の所有を取得する。全体保守・会議削除・モデル削除のlease種別と、現在の取消トークンとの一致を検証する。モデル削除用leaseで会議・音声を削除したり、全体保守用leaseでモデルを削除したりすることはできない。

新規の削除確認と、保存済みの同意に基づく再開の両方へ接続した。通常の通知履歴処理は既存・新規とも共存できる。通知処理の停止・最大5秒の完了待ち・会議音声キャッシュの停止・通知履歴キャッシュの全体破棄は行わない。SQLiteの通常のトランザクション直列化は維持する。

AI実行・モデル準備・録音・取り込み・書き出し・全体保守・会議／音声削除とは、同じ状態ロック内で相互排他を取る。モデル削除は同時に1件。終了時の取消と実処理の終了待ちへ接続し、取消後の終了中止で古い所有を復活させない。失敗・panic・正常終了で自身の所有だけを解放する。

起動時の未完了削除に対する認可と再起動要求の特例は維持する。冷再起動後に保存先全体の再起動保護が残る状態は、通常の通知履歴との共存とは分けて扱い、その保護を解除しない。

## 検証

- 新規・再開のモデル削除中も、既存と新規の通知履歴所有が有効であることを合成データで確認する。
- 別種別のlease、失効した所有、二重受付、競合する操作の同時受付、取消・終了・panicからの解放を共通Rustテストで検証する。
- 合成モデルの削除コントローラー試験をWindowsにも有効化し、対象確認・中断・再開・完了・応答再送・ネイティブ／フロント契約を検証する。
- WindowsのRustテストビルド（`cargo test --locked --offline --lib --no-run`）は成功。生成したテストバイナリで解析コントローラー、モデル削除コントローラー、モデル削除の検査／実行を実行し、58成功・2明示除外。実行ログは `.cache/model-deletion-native-tests.log`。除外は明示実行する合成ベンチマークとQAデータ生成であり、通常テストの追加除外はしていない。
- フロント関連32テスト、TypeScript型検査、Viteビルドは成功。
- ヘッドレスEdgeの合成IPC画面で、モデル削除受付10ケース、Windowsタイトルバー付きの設定レイアウト4ケースが成功。未選択／Whisper選択済みの両方で3画面サイズを検証し、本文末尾への到達と外枠・ヘッダー・サイドバーの固定を確認した。記録は `output/playwright/model-isolation/results.json`。
