# M2-03 文字起こしの固定条件再試行

正式評価とWindows固有部分を保留し、失敗・取消から未完区間を再実行する経路を追加した。再解析の品質評価ではなく、保存・再実行・編集保護の検証記録。

## 実装

- 元ジョブは変更せず、新しいジョブに `retry_of_job_id` と親の `attempt + 1` を保存する。操作IDで二重登録を防ぎ、同じ親に未完の再試行がある間は別の再試行を拒否する。一時停止・中断の再開は従来どおり同じジョブID。
- 元の音声manifest、全トラック・CAF、CLI・モデル・VAD、区間計画、固定設定、完了WAV・JSONとチェックポイントを再照合する。現在の設定画面の内容は使わない。別会議・古いジョブハッシュ・改変済みファイルは新規ジョブを作らず拒否する。
- ディスク検証後にDBトランザクションで元の状態・固定入力・チェックポイントを再検査する。新ジョブとチェックポイントの複製は原子的。結果ファイル自体は参照を引き継ぎ、複製・上書きしない。
- 元ジョブのハッシュ形式は維持。再試行のハッシュには新しい操作ID・親ID・試行番号を含め、チェックポイントを新しいハッシュへ結び直す。SQLite移行12で試行・固定区間数の不変性と再試行元の一致を制約する。
- メイン画面専用RPCと「同じ条件で再試行」を接続。保存済み区間数と条件固定を確認し、試行番号・元ジョブを表示する。失敗後の再操作は同じ操作IDを使う。再試行中も文字起こしを編集でき、現在版と下書きを自動切替しない。

## 検証

- `make check`：Python 65件、フロントエンド15件、Rust通常64件、AVFoundation製CAF読出し1件が成功。正式評価前提の不足は7警告のまま。
- DBテスト3件：重複操作、未完再試行の拒否、元状態の競合、同一条件と新ハッシュ、再起動保持、連鎖の試行番号、チェックポイント登録失敗の全体ロールバック、SQL制約と改変検出を確認。
- ワーカー追加テスト2件：124秒・2区間のプロトコル用CLIを2区間目で失敗させ、DB再読込後の再試行で未完の1区間だけ実行。元ジョブ・完了結果ID・現在版・手動編集の保持を確認。元音声・モデル・結果・チェックポイント・会議・期待ハッシュの6種類の不一致では登録しない。
- Playwrightによる公式Tauri IPCモック：確認取消ではRPCなし、模擬エラー後も本文・保存済み下書きと元の失敗ジョブを保持。同じ操作IDで再実行すると保存済み2/3区間・試行2の新ジョブが追加され、未完再試行中は元ジョブの再試行ボタンを隠す。空の現在設定でも固定条件の再試行は可能。画面キャプチャ `output/playwright/analysis-retry.png` を目視確認。ブラウザと開発サーバーは終了済み。実録音は行っていない。

- 既存の公式whisper.cpp v1.9.4・多言語tinyモデル・提供済み30秒CAFを使うignore試験2件が成功。ワーカー試験を拡張し、1区間完了後に一時停止・取消したジョブを再試行。完了WAV/JSONの追加生成なしで同じチェックポイントから候補を作り、元ジョブ・現在版・手動編集を保持した。CLI・モデルのハッシュと再現コマンドは [ワーカー検証記録](m2-03-whisper-worker-2026-10-03.md) に記載。接続試験であり品質指標ではない。
- `npm --prefix app run tauri -- build` 成功、14.36 MiBの開発用`.app`を生成。`codesign --verify --deep --strict`成功。アドホック署名、公証なし。ネイティブ画面の統合操作は未検証。
