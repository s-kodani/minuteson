# 保存区間をまたぐ話者対応付けの基盤

欠損で分かれた保存区間の話者番号を、そのまま同一人物として扱わないための純粋な処理を追加した。特徴量による区間間の対応付けと、他の話者が重ならない音声範囲の選択を独立20件で確認した。実エンジンによる特徴量抽出、ジョブ・再試行・復元・候補公開・自動工程への接続は未完了であり、欠損を含む音声の話者分離全体は完了扱いにしない。

## 音声範囲と重複制約

`diarization/clustering.rs` は、保存区間ごとに独立して変換・検証した16kHz音声のフレーム数と話者区間を入力にする。保存区間の終端を越えるフレーム、重複した入力、逆順や不正な話者番号を拒否する。会議時刻からこのフレーム範囲への変換と、入力音声・モデルの固定条件の照合は、接続するワーカー側に残る。

正の長さで異なる話者が同時に存在した場合だけ、統合禁止の制約を作る。境界が接する発言や、同じ話者の入れ子区間を別人の重複にしない。特徴量には他の話者が重ならない連続範囲だけを選び、欠損や発言の間隔を連結しない。

選択条件 `unambiguous_longest_two_center30_v1` は、各区間内話者について最長の連続範囲を二つまで使う。同じ長さなら元の時刻が早い範囲を優先し、長い範囲は中央の30秒までとする。完全に重なった話者は候補として保持するが、混じった音声から特徴量を作るための範囲は選ばない。短い範囲で実抽出が可能かどうかは、実エンジンの確認が必要である。

## 特徴量による対応付け

入力する特徴量は区間番号・区間内話者番号・実際に使った音声サンプル数を持つ。値の有限性、次元、所属、個数と音声時間を検査し、実サンプル数で重み付けした正規化重心を作る。特徴量がない、または相反する方向で重心を得られない話者は未解決のまま保持する。

対応付けの方式は `run_centroids_cosine_complete_v1` とし、重心のコサイン距離と完全連結法を使う。[sherpa-onnx v1.13.8の公式クラスタリング処理](https://github.com/k2-fsa/sherpa-onnx/blob/v1.13.8/sherpa-onnx/csrc/fast-clustering.cc)も正規化した特徴量のコサイン距離と完全連結法を使うが、今回の入力は区間内話者の重心であり、既存CLIと同じ結果や精度になるとは扱わない。

トラック全体への人数指定または固定した距離閾値で統合を止める。指定人数に合わせて人物を作り足さず、同時発話の制約を破る統合を要求された場合は拒否する。トラック別に呼び出すための処理であり、別トラックや別会議との本人識別には使わない。距離を信頼度や本人識別の確率として公開しない。

保存区間内の話者候補は4096件、特徴量8192件、次元4096、全特徴量の要素数8,388,608までとする。候補の距離は三角行列で保持し、統合した候補の世代を確認して古い距離を無効化する。統合禁止の制約は後続の統合でも保持し、特徴量・距離計算・統合・結果作成中の取消を確認する。上限は安全上の受付制約であり、最大条件での性能確認ではない。

## 検証結果

先行する独立検査は13件成功・1件失敗だった。取消検査が実際の確認回数を超える固定回数を指定していたため、確認回数を成功実行から取得し、各段階と最後の確認で取消を検査する形へ修正した。対応付けの製品処理はこの失敗によって変更していない。

最終ソースを標準ライブラリだけの独立ハーネスへ組み込み、デバッグ版と最適化版の両方で20件成功・失敗0件・ignoredなし、終了コード0を確認した。両方でassertとオーバーフロー検査を有効にした。記録は `/private/tmp/mon-run-clustering-final-debug.log` と `/private/tmp/mon-run-clustering-final-optimized.log`。同じ20件の二つの実行であり、40件へ加算しない。

検査には区間ごとの話者番号の入替え、同じ番号の異なる特徴量、ベクトルの尺度、同時発話の制約の引継ぎ、未解決特徴量、人数指定、空の候補から人物を作らないこと、次元・数値・順序・容量と取消を含む。独立した全候補走査の実装との40組・各3条件の比較、古い距離の排除、欠損や重複をまたがない範囲の選択も20件内で確認した。

`cargo fmt --check` と差分検査は成功した。この基盤追加後の全体Cargo検査、モデル抽出とMac実機の検査は未実施であり、直前の文字起こし段階の全体Rust1,528件の成功とは分ける。独立検査の終了後に再構築可能な検査実行ファイル6,472KiBを整理し、ハーネスとログを保持した。製品targetは38,664KiBで既存releaseのSHA-256も変更前と一致し、実録音・Windows CIは実行していない。

## 残る接続

次に、管理・照合したsherpa-onnxの埋め込みモデルから、選択した保存範囲の特徴量を実抽出する経路を接続する。固定した区間・モデル・音声と途中成果物の照合、再開・再試行・追加復元、元の会議時刻への対応、手動話者割り当てを保持する候補公開と自動工程への引継ぎが必要である。

既存の欠損付き話者分離の拒否と、連続録音の旧固定条件は変更していない。実モデル・認識品質・話者精度・処理性能・Mac実機、正式評価・10話者・Windows固有部分の保留を維持する。M3-01と計画全体は進行中である。
