# Rustテストの時間とキャッシュ容量

通常Rust検査と専用連携検査は、`tools/mon_rust_tests.py`から同じ所有付きキャッシュを使う構成へ変更した。毎回別の一時キャッシュを作る運用はやめ、通常検査の対象、専用子プロセスの扱い、失敗の伝播とDBの耐久条件は維持する。通常開発・リリースのCargoプロファイルは変更しない。

## 実行方法

```sh
make build-rust-tests
make test-rust
make test-rust-focused RUST_TEST_FILTER=recording_segments::tests
make rust-test-cache
python3 tools/mon_rust_tests.py --clean
```

`build-rust-tests`は全Rustテストのビルドだけを行い、実行はしない。全件検査は一度ビルドしてから通常のlibtestスケジューラーで実行する。通常のCargoが構築するライブラリ・バイナリー・統合検査の対象を維持し、最後にdoc testも実行する。重点検査だけはライブラリと指定フィルターに限定し、全件成功とは区別する。`make check`と既存のSwift連携の専用検査も同じキャッシュを使用し、引数なしの`make`も従来どおり全体検査を選ぶ。直接`cargo test`を実行すると、この容量管理を経由しない。

## ビルドと実行の変更

テスト専用の増分ビルドを有効にした。既存のデバッグ情報なし・シンボル除去・コード生成単位256・ルートパッケージの最適化水準1は維持する。テストの`lto`だけを`"off"`とし、大きな中間bitcodeを残すローカルThinLTOを無効化する。`false`でも最適化と複数のコード生成単位があるとローカルThinLTOは実行されるため、`"off"`を明示する。設定の意味は[Cargoのプロファイル仕様](https://doc.rust-lang.org/cargo/reference/profiles.html)に従う。

SQLiteの繰返し処理は、テスト専用の`libsqlite3-sys`を最適化水準2、`rusqlite`を1とした。組込みSQLiteのCビルドは同パッケージの`OPT_LEVEL`を受け取る。実体確認のSHA-256は、同じ`sha2` 0.10.9のテスト用コードだけを最適化水準3にした。このApple Silicon構成では`asm`機能を有効にしておらず、同版のソフトウェア実装を使う。依存機能・計算方法・入力バイト・ハッシュ照合の省略は変更しない。

debug assertと整数オーバーフロー検査は有効のままで、その実際の動作を通常Rust検査へ追加した。合成1MiBのSHA-256が独立にPython hashlibで計算した基準値へ一致する検査も含む。SQLiteのWAL・FULL同期、実DB移行、保存先移動、上限の検査データ、SIGKILL検査は変更・除外しない。失敗の自動再試行は追加しない。

ビルドの標準並列数は最大4ジョブとし、メモリーと同時生成物を抑える。`--jobs`で1〜16へ変更できる。以下の最終プロファイルの初回構築だけは、この標準変更前の10ジョブで測定している。ソース変更後と無変更の再構築は標準4ジョブである。

既存の同じ実行ファイルで長い保存先移動検査2件を比較したところ、1プロセス・10スレッドは88.357秒、2プロセスは88.506秒で、改善はなかった。そのため標準実行は1プロセス・このMacの10スレッドを維持する。複数プロセスは明示指定だけとし、時間短縮の根拠にはしない。

## 容量と排他

キャッシュは`.cache/rust-tests`の1か所、所有記録は対象リポジトリの絶対パスに固定する。増分状態だけで5GiBを超える実測を受け、利用者が8〜10GiBの構築速度優先を選択したため、標準は各実行終了後10,240MiBのソフト予算とする。ビルド開始前の空き容量は2,048MiB以上を要求する。超過時は各パッケージの古い構築世代を先に回収して最新の完了世代を保持し、完了済み実行ファイルより古い非共有の中間オブジェクトを回収してから、古いパッケージ単位の増分を回収する。それで収まらない場合だけ再生成できるdebug成果物を回収する。状態確認は回収しない。

ロックはビルド・全検査・回収まで保持し、子プロセスにも引き継ぐ。中断で子の終了が確認できない場合は回収せず、次の排他的な実行まで残す。シンボリックリンクのキャッシュ、所有不明な非空ディレクトリ、他リポジトリの所有記録、製品targetや広い祖先ディレクトリは拒否する。回収はディレクトリ記述子に対する操作で、リンク先の製品成果物や外部データを削除しない。

10GiBはビルド中も常時守るハード上限ではない。中断時や直接のCargo実行にも即時上限は保証しない。容量優先では`CARGO_INCREMENTAL=0 python3 tools/mon_rust_tests.py --max-cache-mib 4096`を使用できるが、増分構築の短縮は得られない。容量と速度が両立しない場合は設定した容量を優先する。
