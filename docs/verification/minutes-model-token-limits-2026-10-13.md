# 選択モデル別の入力・出力トークン上限

## 仕様と根拠

設定で選べる議事録モデルの定義へ `tokenLimits` を追加した。最大入力、最大出力、共有コンテキストのトークン数と、確認済みのtokenizer方式を保持する。現在のQwen2.5 1.5B Instruct Q4_K_Mは入力32,768、出力8,192、合計32,768とした。入力と出力を同時に最大まで使えるという意味ではなく、共有上限から実入力とテンプレート予約を差し引いて出力を割り当てる。[固定版の公式情報](https://huggingface.co/Qwen/Qwen2.5-1.5B-Instruct-GGUF/blob/91cad51170dc346986eccefdc2dd33a9da36ead9/README.md)。

モデル名やパスではなく、定義のSHA256とサイズが一致するモデルだけに適用する。未確認モデルの新規生成は説明付きで拒否し、別モデルの上限を推測しない。取得レシピのバイト・ハッシュ、ダウンロード対象、既存モデル本体は変更していない。選択情報の不正な数値、入力・出力が合計を超える値、未知の方式、余分なキーをネイティブと画面側の両方で拒否する。

音声認識・話者分離はテキストLLMのトークン予算を使用しないため、この上限を流用しない。設定画面に専門的な値や追加操作を増やさず、従来の選択・未取得ならダウンロード・使用の導線を維持する。現在の議事録公式候補は1つで、複数候補の追加は別の残件である。

## 分割と実行

処理開始時のモデル能力と全体設定をジョブへ固定する。アプリの設定コンテキストとモデル合計上限の小さい方を使う。分割は設定の入力予算、モデルの最大入力、共有コンテキストから出力予約とテンプレート512トークンを引いた量のすべてに収める。system指示と追加の完結指示も入力予算に含める。長い入力はUTF-8境界で分割・段階統合し、無断で切り捨てない。

各推論の出力は、実際のsystemとpromptの安全側の入力上界を共有コンテキストから引き、モデルの最大出力とアプリの8,192上限の小さい方で決める。現在の8,192コンテキスト設定ではモデルの32,768全量を使う変更ではない。入力が増えれば出力予算は減り、モデルの許容量を超える入力は実行しない。

利用者からの確認に対し、公式資料を再照合した。「入力が短いからモデルの出力上限が増える」という意味ではない。共有枠の余裕にかかわらずモデル定義の最大出力は独立して適用する。変更するのはその範囲内のアプリの許可生成量であり、実際に長く出力することや完結を保証しない。llama.cppの `--predict` と `--ctx-size` も別の設定である。[公式実行設定](https://github.com/ggml-org/llama.cpp/blob/master/tools/completion/README.md)。

入力上界は、対応Qwenのバイト単位BPEについてUTF-8バイト数と512のテンプレート予約を使う。これは正確なtokenizer計数ではない。固定実行エンジンの[バイト変換](https://github.com/ggml-org/llama.cpp/blob/edd6e2bbdad5930899a93db8fa73c3b61c7b9bcc/src/unicode.cpp)と[BPE実装](https://github.com/ggml-org/llama.cpp/blob/edd6e2bbdad5930899a93db8fa73c3b61c7b9bcc/src/llama-vocab.cpp)を確認した。別方式を同じ計算として登録しない。

新規ジョブはversion 7で、本文480文字などの一律schema制限を外した。未完成・重複キー・不正JSONを補修して成功とはせず、失敗単位を確定しない。人間の保存済み本文は保持する。既存の固定済みversion 5・6成果物は生成時の条件で照合するだけで、再試行によって新しい上限へ書き換えない。新条件には新しい生成操作が必要。復元で能力情報・schema条件が変化した場合は、出力前のジョブでも拒否する。
