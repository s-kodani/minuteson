# 録音取得の終了証拠と境界欠損

通常録音の両入力について、実際の取得停止後の共通時計を録音セッションに結び付け、保存済みPCMの外側にある先頭・末尾の欠損をDBへ保持する経路を追加した。切断した入力が復帰しなくても、取得処理の終了と両CAFの確定を確認できれば、残ったPCMと欠損を区別して保存できる。停止失敗・取得処理の未終了・壊れたCAFは保存完了にしない。

## 取得終了と保存完了の区別

`CaptureClockDomain` はマイク・PC音声それぞれについて一つだけ終了証拠を作る。証拠は同じ時計インスタンスと入力種類に固定し、外部から時刻を指定して構築できない。同じ入力の終了確認を再実行した場合は最初の証拠を返し、CAFの確定・再読込み・その後のスリープや壁時計変更によって終了時刻を延ばさない。

マイクはエンジン停止と取得の解放後、CAFを閉じる前に証拠を作る。ScreenCaptureKitは未完了の取得処理と実ストリーム停止を待ち、受信キューを排出してから、CAFの確定前に証拠を作る。同時停止要求は一つの停止・CAF確定の完了を共有し、失敗も保持する。Core Audio TapsはIO停止・コールバック解放・書込みキュー排出後に証拠を作り、解放失敗、未開始、先に行った通常cleanupから後の時刻で証拠を作らない。

両入力が閉じるまでは残る入力の取得時刻を認める。両方が閉じた後のPCM観測、時計の逆行、取得時計とスリープを含む時計の対応変更は拒否する。取得の開始・終了と受信・保存処理の時刻を混同しない。

## 保存形式と所有の照合

時間上限なしの通常録音には保存manifest形式版3を使う。`recordingOwnerId` は実際の録音セッションUUID4であり、両入力の取得時計・最後の保存PCMと終了証拠を照合してから形式版を上げる。録音前の私有5秒テストにはこの経路を使わない。

追加する `captureEnd` は、四項目だけの厳密な形式である。

| 項目 | 意味 |
| --- | --- |
| `method` | 固定値 `acquisition_closed` |
| `microphoneClosedUs` | 共通PCM原点からマイク取得終了まで |
| `systemClosedUs` | 同じ原点からPC音声取得終了まで |
| `endUs` | 両取得終了時刻の最大値 |

Rustは所有、形式、数値上限、各入力の終了がその保存PCM終端以降であること、共通終端が両終了の最大値であることを検査する。終了UTCは固定した取得原点UTCと `endUs` から求め、DBの `updated_at` は実際の保存コミット時刻のまま保持する。

既存の形式版1・2は従来の保存PCM終端を維持する。終了証拠のない旧録音へ、壁時計文字列、他方の音声、ファイル更新時刻から新しい末尾を推測しない。旧形式に終了証拠を混在させた記録も拒否する。

## 保存音声と欠損

各トラックの最初の保存PCMより前は `capture_start_gap`、最後の保存PCMから共通取得終端までは `capture_stop_gap` とし、いずれも未回復の `audio_gaps` に記録する。再取得中の内側の欠損 `capture_timestamp_gap` と併存する。CAFのフレーム数、値、形式と時刻補正区間は変更せず、欠損分の無音をファイルへ追記しない。

境界欠損のある音声でも、その内側の連続した保存区間は既存の固定解析入力と区間再生へ渡せる。欠損を横断する区間再生は拒否する。会議全体再生は現在、未回復の欠損を検出すると準備を拒否する。小さな先頭・末尾の欠損もこの制限に含まれるため、欠損表示と既知区間への移動を備えた会議全体再生を次の対応とする。内側に欠損があるトラックを既知区間ごとに解析する経路も残る。

## 残る対応

Mac実機でのマイク・ScreenCaptureKit・Core Audio Tapsの終了時刻、切断・復帰、権限、同期精度と4時間安定性は未検証である。合成時計とPCMの連携は、実機の同期精度や録音品質の証明ではない。

欠損の表示・既知区間へ移動できる会議全体再生と解析、スリープ後の明示復帰、入力形式変更、容量不足、部分CAF救出、異常終了後の回復、実モデル統合、配布と先行試用を維持する。正式評価・10話者・Windows固有部分は保留し、Windows CIを実行しない。M3-01と計画全体は進行中である。
