# 未確定話者名の回復保存と確認画面

2026-10-07に、未確定の話者名を本文と同じ回復保存へ接続し、確認・編集再開・確認付き破棄を画面に追加した。入力の回復保存と確定済みの本文・名前・Undoは別に扱う。名前だけの記録と本文を含む記録の両方を再開できるが、閲覧と編集再開だけでは確定しない。macOS WebViewと実SQLiteを通した強制終了回復は残り、M3-08と計画全体は進行中である。

## 入力と確定と取消

本文と名前は同じ回復要求へまとめ、約300ms後に保存する。名前を含む記録は形式版3、名前を含まない記録は従来の形式版1とする。保存済みの回復記録があっても、確定前の話者ラベルと本文を置き換えない。

一人の名前の確定では他の名前と本文を確定せず、確認した本文保存の版へ残る回復入力を対応付ける。取消では入力開始時の名前だけを戻し、他の確定済み変更を保つ。入力の除去は回復保存の確認を待ち、未確認の応答がある場合は元の入力欄を保持する。別欄で新しい入力が保存待ちになっていても、読戻しで除去を確認した入力欄は個別に閉じられる。

通常の画面移動と終了前の保存待ちは本文と名前を確定してから回復入力を空にする。画面が残る候補確認等では入力開始時の名前を保持するため、後からEscでその名前だけを次の版として戻せる。古い保存・除去応答で新しい入力を消さず、別欄へ移ったフォーカスも奪わない。

## 確認と編集再開と破棄

プレビューは本文と名前を合わせて10件ずつ表示する。名前には話者ID、入力開始時の名前、手動名の有無、未確定値を示し、選択・コピーできる読み取り専用の入力欄を使う。一覧と破棄確認の件数も両入力の合計とする。

編集再開は現在の下書き・版・内容に一致する新しい読戻しを要求し、本文と名前の両配列を一緒に入力欄へ戻す。名前を含む全記録を拒否していた一時的な読み込み保護は外した。現在の画面にない発言や統合済み話者の名前がある場合は部分的な再開を拒否し、記録を保持して手動コピーを案内する。旧下書きや本文更新後の入力は閲覧できるが、自動適用・旧解析版の採用はしない。

確認付き破棄は本文と名前を同時に空にし、確認した回復版とハッシュを証拠に残す形式版2へ進める。名前だけの入力も対象になる。破棄の応答喪失後は元の要求を保持し、結果確認は読取専用とする。明示的な再試行でも同じ確認条件を維持する。

ローカル入力を破棄して再読込する場合も、現在の本文が確認済みの版から変わっていないことと、両入力の回復除去を確認してから画面を置き換える。回復保存が未確認の最後のキー入力は終了時に失われる可能性を画面に明示する。
