# 5秒録音の自動削除とモデル再利用（Mac・Windows共通）

## 変更内容

- 録音テストの確認画面を閉じると、同じrun IDの停止、再生要求・トークンの解放、一時音声の削除、空状態の確認を順に待つ。終了要求の同時実行は共有し、開始受付が不明な場合は既存の照合で確定する。開始要求は再送しない。
- 画面移動、再生成、再テスト、取消、バックグラウンド化、アプリ終了から共通の終了処理を利用する。手動の破棄ボタンと録音テスト専用の終了確認を撤去した。削除失敗時は確認画面に原因を残し、「閉じる」で再試行できる。
- 配布レシピのハッシュに加え、公式マニフェスト全体から既存のネイティブ検査形式に一致する`packageReviewHash`を画面内で導出する。モデル・実行ファイル・ライブラリ・通知文が同じダウンロード済みコピーを再利用し、内容が違う場合は更新する。IPC・DB形式と保存済みの取得由来は変更しない。
- モデル本体が同じコピーは1行にまとめ、個別の使用状態・詳細・削除操作を展開表示する。通常版とint8版は別項目とし、既存ファイルの自動削除は行わない。

## Windowsでの確認

- フロントエンド単体テスト：891成功、1スキップ。
- 関連ブラウザー検証：14スイート成功。モーダルの閉じる・Esc・背景クリック、録音の各段階、再生・再生準備中の終了、削除失敗と再試行、取消、コピー別削除、設定の再適用、文字起こし再生成を確認した。
- Rust録音テスト：27成功、Swift生成音声を必要とする1件はスキップ。Windowsの合成5秒音声、所有権の引継ぎ、プロセス終了、音声検証と一時ファイル削除を含む。
- 通常版・int8版の実モデル：隔離した保存先へのコピーで、準備と設定適用の成功を確認した。
- 実際に重複したWindowsパッケージの取得記録：配布レシピのハッシュが異なり、全パッケージの検査ハッシュが一致すること、および新しい判定で再利用可能になることを確認した。

ブラウザー内のMac/Windows分岐確認は合成IPCであり、Mac実機の検証を意味しない。検証では実際の会議データ・設定の変更やマイクからの録音は行っていない。

## Mac側の後続確認

利用者の指定により、Mac実機でのネイティブ確認とQAビルドは後続作業とする。

```sh
npm --prefix app test
npm --prefix app run test:browser -- --only capture-test,capture-test-pc-only,capture-test-unreceived,capture-test-quiet,capture-test-recovery,close,recording-compact,recording-preparation,model-management,model-reuse,applied-model-status,transcription-regeneration,simple-models,vad-settings
python3 tools/mon_rust_tests.py capture_test
npm --prefix app run tauri:qa:build
```

実機では、5秒録音の完了後と実行中に確認画面を閉じ、録音・再生が終了し、再度のテストや保存済み会議の文字起こし再生成へ進めることを確認する。再生準備中、再生中、バックグラウンド化、アプリ終了も対象とする。モデル管理では複数コピーの集約表示と個別操作を確認し、配布情報だけが変わった同一内容のパッケージが追加配置されないことを確認する。
