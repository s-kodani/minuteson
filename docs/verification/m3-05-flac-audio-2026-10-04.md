# FLAC音声保存と共通読出しの検証

音声取り込みに必要なFLAC保存・検証・区間読出しをRustの共通音声層へ追加した。管理FLACを既存の再生とAI入力用WAV変換に使えることを、合成音声と独立したデコーダーで確認した。取り込み画面、取り込みジョブ、WAV・MP3・M4Aの復号はまだ接続していないため、M3-05は進行中とする。録音プローブと録音確定の保存形式も引き続きCAFである。

## 保存形式と元音声の保護

4096フレームずつ読み、24ビット整数PCMに量子化してFLACフレームを保存する。元音声、サンプルレート、チャネル数、指定区間のフレーム数は変更しない。量子化はfloat32共通入力に対して行い、正の1.0は符号付き24ビットの最大値になる。FLACはこの整数PCMを可逆圧縮するが、元の浮動小数点音声や32ビット整数音声とのビット単位の一致を保証しない。

同じ保存先フォルダーに専用の一時ファイルを作り、最後にSTREAMINFO、総フレーム数、PCMのMD5を確定する。ファイルを同期し、SHA-256、全音声の復号、CRC、MD5、形式とフレーム数を再検証してから、既存ファイルを上書きしない方式で公開する。取消と公開前の失敗では、その一時ファイルだけを片付ける。元音声と既存の保存先ファイルは残す。

公開後の親フォルダー同期だけが失敗した場合は、通常の未保存エラーと区別して`published=true`を返す。再試行でも公開済みファイルを上書きしない。今後の取り込み・録音保存側はこの結果を回復処理へ渡す必要があり、永続化した変換ジョブやDB確定までを今回の実装範囲には含めない。

## 検証と区間読出し

既存の管理パス、保存時サイズ、SHA-256、DBの形式・時間・フレーム数照合を維持し、拡張子ではなく音声の署名でCAFとFLACを識別する。FLACでは全区間を最初に復号し、時刻の連続性、CRC、実フレーム数、存在するPCMのMD5も照合する。PCMのMD5が省略された音声でも、外部のSHA-256とフレーム検証は省略しない。これらは保存記録との一致を確認するもので、録音者や内容の真正性を証明するものではない。

メタデータのヘッダー、配置、長さ、総量を検査する。利用しない画像・コメント・キュー・ファイル付属の索引はデコーダーへ渡さず、STREAMINFOと音声だけの仮想読出しにする。小さいブロック内に巨大な入れ子の長さやbase64画像を含む場合も、そのフィールドからメモリを確保しない。これらのタグの意味の検証・表示は行わず、原本ファイルも書き換えない。

検証済みの圧縮区間の位置・長さ・開始フレームを索引に持ち、任意位置は該当フレームから読み出す。短い最終ブロックや単一フレームの音声も扱い、プレビューのたびに会議の冒頭から復号しない。全会議のPCMや復号済みコピーは保持せず、復号用の1ブロックと要求区間を保持する。ただし索引は圧縮区間数に応じて増えるため、長時間時の実メモリ測定は残る。

受け入れ範囲は8,000〜384,000 Hz、1〜8チャネル、4〜32ビット、4時間以内。メタデータは16 MiB以内かつ4096ブロック以内、取得した圧縮区間は4 MiB以内かつ200万区間以内とする。宣言時間がない場合も実フレームを数えて時間上限を検査する。異常な区間数などは拒否し、途中の音声を正常終了として扱わない。開く際のハッシュ照合と全復号中は取消を確認し、再生前後はファイル変更も検査する。

## ローカル検証

新規の通常Rustテスト11件で次を確認した。使用した音声は合成音声と公開例で、提供された会議音声の認識品質は測定していない。

- ステレオ全サンプルの往復、非連続シーク、FLACブロック境界、末尾、短い最終ブロック、部分保存、24ビット量子化。
- 取消、未公開の一時ファイルの片付け、既存ファイルと元音声の保持、範囲外の拒否。
- 保存直後の親フォルダー同期失敗を、公開済みとして区別すること。
- SHA-256、CRC、PCMのMD5、総フレーム数、切り詰め、メタデータ長、宣言時間の改変の拒否。
- 宣言フレーム数がない音声の計数、検証後の変更の拒否、復号中の取消。
- 過大な画像・コメント内の長さとbase64画像を、音声デコーダーへ渡さないこと。
- [RFC 9639の独立した例](https://www.rfc-editor.org/rfc/rfc9639.html#appendix-D.1)の左右サンプルとの一致。
- 再生バッファ境界をまたぐPCM、文字起こし用の部分WAV、話者分離用の全トラックWAVが既存CAF経路と一致すること。
- 管理ファイルをDB経由で読み、分割FLAC境界をまたいで再生できること。解析版・本文は変わらず、DBのフレーム数が不一致なら拒否すること。

明示的に指定したFFmpeg 8.0.1による別実装の試験1件も成功した。Rustで保存したFLACをFFmpegで復号し、FFmpegで保存したFLACをRustで復号して、合成ステレオ20,013フレームの全PCMと一致した。FFmpegはこの試験だけに使い、製品の実行時依存には追加しない。この試験は通常のテストではignoreとし、再実行時は次を使う。

```sh
MON_FLAC_FFMPEG=/opt/homebrew/bin/ffmpeg cargo test --locked --offline --manifest-path app/src-tauri/Cargo.toml independent_ffmpeg_flac_round_trip -- --ignored
```

`make check`は成功。Python 65件、フロントエンド61件、Swift 5件、Rust 208件が成功し、Rustの外部エンジン・独立FFmpeg等9件は通常実行ではignoreのまま。別実行のAVFoundation製CAF読出し1件と、上記FFmpeg試験1件も成功した。macOSのlocked・offlineビルドで18.00 MiBの開発用アプリを生成し、`codesign --verify --deep --strict`に成功した。アドホック署名で公証なしのため、実画面・実録音・配布の検証結果とは区別する。

## 依存と残件

FLACの復号は[Symphonia](https://github.com/pdeljanov/Symphonia) 0.5.5のFLAC機能だけを有効にし、保存は[flacenc](https://github.com/yotarok/flacenc-rs/) 0.5.1を固定して並列機能を無効にした。今回のCargo.lockに含まれる直接追加依存のライセンス表記は、SymphoniaがMPL-2.0、flacencがApache-2.0、md-5 0.10.6とcrc 3.4.0がMIT OR Apache-2.0である。推移依存も含めた告知・ライセンス本文・ソース提供方法の同梱確認は配布整備の残件とし、配布可能性を証明したとは扱わない。

原本の管理領域へのコピー、他形式の復号、容量確認、取消・異常終了からの回復、取り込み用のDB状態遷移、単一の`imported`トラックとしての固定入力、音声選択・ドロップ画面、自動解析への引継ぎが残る。録音からFLACへの保存確定も別途接続する。macOS WebViewの統合操作、4時間・16GB端末の速度とメモリ、認識品質、Windowsのビルド・実機確認は未検証のままとする。Windows CIは停止を維持し、今回の検証には使わない。
