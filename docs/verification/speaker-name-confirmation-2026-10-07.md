# 話者名の確定保存と取消

仕様14.13に合わせ、話者名の入力と確定済みの表示名を分離した。名前の確定ボタンとEnterで保存し、キャンセルとEscで入力開始時の名前へ戻す。2026-10-07時点で、通常の保存・画面移動・失敗時の入力保持は単体テストと模擬IPCブラウザーで確認した。未確定の話者名の異常終了時回復とmacOS WebViewの統合は残る。

## 入力と確定

入力中は下書きの名前と発言の話者表示を変更せず、保存状態を未保存とする。一人の名前を確定しても、他の話者名や開いている発言本文は確定しない。確認した名前を同じ話者IDの表示と絞り込み候補へ反映する。空の名前は明示的なnullとして保存し、元の名前を再表示しない。

保存中の新しい入力を古い応答で置き換えず、保存後も新しい値には次の確定を求める。確定・取消ボタンを除去した後は名前欄へフォーカスを戻すが、別の欄への移動は妨げない。確定・取消の重複実行を防ぎ、IME入力・keyCode 229・繰り返しキーは保存操作にしない。名前欄の通常Undoはブラウザーの入力履歴を使い、保存済み下書きのUndoとは区別する。

## 画面移動と保存失敗

通常の画面移動・終了の保存待ちは、話者名と本文の保存結果を待つ。画面が残る場合は入力開始時の名前を保持し、後の取消を新しい下書き版として保存する。他の話者名・本文・割り当てと、確認済みの編集履歴は消さない。

保存失敗時は名前を保持し、画面移動を止める。取消前に下書きを読戻し、所有・解析版・ロック版・内容ハッシュ・本文が保存前の状態と一致した場合だけ取消を許可する。保存済みの応答を失った場合は、読み取りだけの結果確認を先に求める。結果確認で新しい名前を送信しない。

保存の明示再試行も、すでに確定した要求だけを解決する。後から入力した話者名や未確定の本文を、別の保存の再試行で巻き込まない。再読込による破棄は確認を求め、取消・読込失敗では入力を保持する。

## 残る対応

未確定の話者名は画面内メモリーに保持し、通常の画面移動・終了では保存を待つ。本文用の回復記録には名前の入力を混ぜていない。強制終了・再起動後の未確定名の回復はまだ対応しておらず、画面にも明示した。名前専用の回復形式と、所有・版・ハッシュを照合する確認・再開・破棄、バックアップと復元への接続は引き続き実装する。

Rustコードは変更せず、この追加ではRust全体を再実行していない。targetは約38MiBで、本番MON・MON QA・Windows CIを起動していない。表示設定・固定プレーヤー・ミニ画面、macOS実機・配布・先行試用と計画全体は進行中である。正式品質評価・10話者・Windows固有部分は保留する。
