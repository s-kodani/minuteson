# 復元された音声利用不可記録の確認と新しい同意

復元時の同意なし音声利用不可記録を、共有操作コントローラーと音声削除画面へ接続した。元記録を開く段階では削除できず、現在の対象を確認して別の操作IDへ移り、新しい同意を得た場合だけ限定削除する。元の全操作列、復元バッチとID台帳、本文・文書・履歴は保持する。検証範囲はネイティブ合成Storageとブラウザ模擬IPCであり、macOS WebViewの実機統合は残る。

## 元記録と新しい操作

一覧は、専用型で厳密に読戻せた復元記録だけに対象確認を許可する。subtypeや一覧の表示は操作の振分けに使うだけで、共有保守leaseや削除許可を作らない。不正な記録は会議IDを採用せず、エラーと通常書込停止を残す。

元記録の確認段階は `restored_unavailable` として表示し、同意・保存済み方針・処理済み数・削除完了を付与しない。削除・未登録音声を含む削除・保持中止を受付時にも拒否する。再検査だけでは新しい操作を作らず、会議からの新規確認も既存の復元記録へ戻す。

利用者が再出現した音声の確認を選んだときだけ、現在の対象一覧と別の操作IDを作る。この段階ではDBに同意を保存せず、音声を削除しない。確認画面では、復元時の利用不可記録と実際のネイティブ削除完了記録を区別し、新旧の操作IDを併記する。復元元を実際の削除完了と表示しない。後続のネイティブ削除を参照する場合は、その実際の完了を表示する。

新しい同意は現在の確認IDと検査済み一覧へ限定する。未登録音声を含める場合は別チェックを必要とし、再検査後は両チェックを解除する。保存後は新しい操作IDと固定方針から続行し、元記録へ同意を追加したり、保存済みの未登録方針を変更したりしない。

## 中断と書込保護

同意保存直後の未開始操作だけを保持中止できる。この保持は元記録の再出現を解決しないため、元の確認待ちと音声、通常書込停止を維持する。開始済みの部分削除には保持による復元を表示しない。元記録の確認画面を閉じても、元記録と書込停止は残る。

冷再起動時に通常回復を保留したStorageは、未解決の確認待ちがある間、対象確認を続けられるが通常書込はできない。すべてを検証付きで解決した後も、保留した通常回復を行うため手動再起動を必要とする。検査不能な音声対象は確認画面の成功状態にせず、確認待ちとエラーを維持する。

確認後に対象が変わった場合は同意を保存せず、明示的な再検査を要求する。受付応答が不明な場合は同じtoken・確認ID・actionの要求を再送し、新しい同意や別操作へ置き換えない。成功通知は現在の会議と操作に一致する検査済み結果からだけ表示する。
