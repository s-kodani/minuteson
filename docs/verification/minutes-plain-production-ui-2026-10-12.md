# 議事録のプレーンMarkdown画面への切替

実施日: 2026-10-12。対象は製品React画面と合成データ。実録音、使用中QAの操作、既存会議DBの読取り・変更、モデル実行、OS許可変更、CIは行っていない。

## 今回の変更

本番の議事録画面を、一つのMarkdown本文のプレビューとプレーンテキスト編集・明示保存へ切り替えた。高度編集、根拠の発言、生成候補の比較・採用、直前版の復元は表示しない。プレビューの白い枠は内容領域の幅を使い、編集・操作アイコンを32px高さに揃える。生成の細かい操作は三点ボタンからモーダルで開く。

初回生成はMarkdown専用ジョブへ接続し、成功本文を直接プレビューする。既存本文の再生成は明示確認を必要とし、旧版コピーは作らない。生成開始時の本文保存条件を固定し、後から人間が保存した本文は古い生成結果で上書きしない。文字起こしやモデル設定の変更だけでは再生成しない。

編集中の入力は自動保存せず、会議を離れる・終了する・明示再生成する際は保存、破棄、取消を選ぶ。タブだけの切替は両画面が保持されるため、変換中以外は入力をそのまま保持する。文字起こし側の保存ガードは迂回しない。変換中の保存・離脱、応答が不明な保存の安易な破棄、確認中の追加入力、保存先の競合を拒否して入力を保持する。応答喪失時は同じ操作の明示再試行を使う。

- 本番画面では明示保存・保存失敗・応答喪失・追加入力・離脱の取消と破棄・再生成の取消と成功・生成中の人間保存・自動再生成なし・初回生成を確認した。

## 途中の失敗と修正

最初の単体検査は旧高度編集UIを前提とする期待値とテスト用読込み拡張子で失敗し、新しい要求に対応する検査へ更新した。ブラウザでは未保存入力のタブ切替に離脱確認が出る問題を再現し、タブと会議離脱を区別して修正した。編集アイコン40pxと三点アイコン32pxの不一致も寸法検査で検出し、共通の32px設定へ修正した。確認モーダルの×ラベルと閉じた子モーダルを含む選択条件も検査側で訂正した。

旧`detail-tabs`検査は、既に撤去された「編集を開始」等を待つ初期条件で失敗し、今回は移植していない。全既存ブラウザ検査が成功したとはしない。ブラウザには開発サーバーのHMR WebSocketに対するローカルネットワーク拒否が3件あり、製品例外とは区別する。初回のCLI取得はネットワーク解決に失敗し、既存キャッシュのCLIを利用した。
