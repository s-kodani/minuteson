# M2-03 / M2-05 解析設定・候補採用UI（2026-10-03）

正式評価とWindows固有部分は保留したまま、保存済み録音に対する既存whisper.cppワーカーをメイン画面へ接続した。実録音やmacOS WebViewでの一連の操作を証明する検証ではない。

## 保存と参照整合性

- SQLite移行10は既存下書きID・本文・ハッシュ・版番号・編集操作を保ち、版ごとに下書きを保持する。仕様10.9の「種類ごとに一つ」は活動中下書きの部分UNIQUEで維持し、非活動下書きは復元用に残す。全生成履歴の公開は追加しない。
- 採用・復元では現在下書きのID＋lock_version、会議lock_version、確認した候補／直前版のID＋内容ハッシュを同一DBトランザクションで照合する。候補の親が現在版と違う場合も拒否する。
- 版ごとの編集履歴を切り替え、旧基底に対する保存・取り消しは拒否する。復元後はその版の本文・話者変更とUndoチェーンを再利用できる。
- SQLite移行11は標準／高精度のCLI・モデル・任意VAD・スレッド数・GPU設定をJSON＋SHA-256＋lock_versionで保存する。モデル本体は取り込まず、開始時に既存ワーカーが実ファイルのハッシュを固定する。
- 新コマンドはメイン画面だけで使用できる。候補プレビューは候補または現在／直前版に限定し、別会議参照・改変を拒否する。
- 採用・復元のDBコミット成功後だけ版変更の再照合イベントを送る。通知の失敗を保存失敗として扱って再採用させることはしない。

Rust追加5テスト（既存59件中）は、版ごとの編集保持と復元・Undo・再起動、確認ID／ハッシュ／下書きの競合、古い親からの採用拒否・直前版置換確認、実際のv9 DBからの移行と外部キー、設定永続化・競合・改変を検証する。直前版の誤ったID／確認ハッシュでも現在版は変わらない。

## 画面操作

設定には編集保存と同じ逐次保存キューを使用する。保存中の追加入力を古いレスポンスで上書きせず、失敗時は入力を保持する。会議切り替え・候補確認・採用・復元・通常終了は未保存編集を待つ。

ジョブ一覧はイベントを再読込要求として扱い、DBの状態を再取得する。3秒ごとの再照合は同時取得をまとめ、遅い読込の積み上がりと別会議への古いレスポンス反映を防ぐ。区間保存数を表示し、時間・話者品質の推定値は出さない。一時停止・中断の再開・取消は既存バックエンド経路へ渡す。

候補／直前版はネイティブdialogで現在版と並べる。本文は各列50発言ずつ表示し、現在・直前の保存済み編集も適用して表示する。発言が行単位で対応するという誤解を避ける注記、処理条件・内容ハッシュ、話者分離と時刻の未検証表示を付ける。採用／復元の最終確認では版番号と復元範囲を表示する。Escapeと閉じる操作は呼出元へフォーカスを戻す。

Playwright CLI＋通常React画面＋Tauri公式IPCモックで確認した操作:

1. 未設定では開始不可。CLI・モデルの絶対パスと用語ヒントを入力し、設定保存後に標準プロファイル・新操作ID付きの開始要求が一度送られる。
2. 待機ジョブの一時停止、保存済み1/3区間の再開、取消確認の拒否では実行を保持し、承認時に取消状態を表示。
3. 本文編集直後の候補確認は保存を待ち、現在版プレビューに編集本文を表示する。
4. 採用競合を模擬するとダイアログ内にエラーを表示し、現在版・編集・候補を保持。再試行成功後に新しい編集画面を読み込む。
5. 新版にも編集を保存し、直前版プレビューの両列にそれぞれの編集を表示。復元すると元の編集本文を再表示し、新版編集も保持。
6. 確認後の候補ハッシュ変更では、採用コマンド自体を送らずエラー表示（送信数0、現在版不変）。
7. 設定保存エラーでは会議Bへの切り替えを拒否して会議Aと入力を保持し、明示再試行で保存する。
8. Escapeで閉じると「内容を確認」へフォーカスが戻る。不具合を修正後、再読込して確認。
