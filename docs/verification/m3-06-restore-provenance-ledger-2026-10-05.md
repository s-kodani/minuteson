# 復元由来とバッチ台帳の検証

2026-10-05に、計画M3-06の旧ID保持と二重追加防止に向け、復元由来の保存形式、復元専用DBへの構築、端末内バッチ台帳の予約処理を追加した。由来情報は再バックアップに含め、端末内の処理状態は持ち運ばない。ライブDBへの追加公開と、再起動後に保存済みID対応を読み戻して復元を続ける経路は未接続であり、利用者向け復元機能の完成ではない。

## DB移行と持ち運ぶ情報

v21は、v20の会議・音声・版・下書き・編集履歴・用語を変更せず、`restore_provenance`、`restore_batches`、`restore_identity_maps`を追加する。由来情報には対象の領域と新ID、元アーカイブ、旧会議範囲と旧ID、復元バッチ、日時を保存する。旧IDは情報として保持し、復元先の主キーに再利用しない。

バックアップには31テーブルの論理データとして由来情報を含める。再復元では由来レコード自身のIDと、現在の会議・対象IDを対応付け直すが、過去のアーカイブ・旧ID・バッチ・日時は保持する。過去の旧IDもID発行前に予約する。同じ元会議を別操作で取り込んだ複数会議に同じ過去の由来が残ることを許す。削除済み対象の履歴IDも情報として保持し、実体の行を新規作成しない。

端末内のバッチとID対応テーブルは論理バックアップから除外する。別端末へ処理中・公開済み状態をコピーしない。v20の30テーブルのバックアップも受理し、復元専用DBは現在の信頼済み移行で作る。アーカイブのSQLや任意のテーブル名を実行しない。

## 台帳の予約と整合確認

バッチIDに、アーカイブmanifestの指紋、順序を固定した全ID対応のSHAと件数、作成時刻を結び付ける。元キーと新キーの対応はディスク上のレジストリから逐次保存し、全件をメモリに保持しない。

同じバッチと同じ計画の予約は既存行を再確認して返し、行を重複追加しない。アーカイブまたはID対応が異なる場合、件数・各対応が欠損または変更された場合は拒否する。予約処理は呼出し側のトランザクション内に専用savepointを持ち、途中取消でも自身の部分記録を残さない。

信頼済みトリガーでバッチの固定条件とID対応の変更・削除、公開済みバッチへのID追加、公開済みから未公開への逆戻りを拒否する。公開状態への変更を会議追加と同じトランザクションで行う製品経路はまだない。予約や台帳状態の単体検査だけでは、会議の二重追加防止が完成したとは扱わない。

## 由来の照合

領域・UUID・キーの長さと型、会議所属を確認する。現存する対象が別会議に属する場合は拒否し、現在の実体がない履歴キーとは区別する。既に構築した由来行も、元の型付き行と新しい参照が完全一致することを確認する。一時DBには会議データの全ID対応を追記し、通常の由来検査を再実行する。由来レコード自身の由来を再帰的に増やすことはしない。取消・拒否時は今回所有する領域だけを回収する。

## ローカル検証

追加Rustテスト11件が成功した。合成音声の取り込み・手動編集・共通用語と、実ワーカーを偽CLIへ接続して作った完了済み文字起こし・話者分離・議事録・書き出し履歴を使った。実録音、実モデルの品質評価、Windows検証は行っていない。

- v20からのDB移行で会議・下書き・議事録・音声計画・用語を保持した。実際に構成したv20バックアップの読取りと、現在の専用DBへの構築も通った。
- 全ての旧ID・新ID対応、複数会議と共通用語の所属、元データの保持を確認した。完了済みのネイティブ処理履歴は成果物とチェックポイントの全構築段階を通した後、由来追加後も通常DB検査に合格した。
- 再バックアップと再復元で過去と今回の会議由来を保持し、端末内バッチ状態と対応表はコピーされなかった。同じ過去の由来を持つ別会議と削除済み対象も保持した。
- 台帳予約の再実行・再読込、固定条件と対応の改変拒否、公開後の変更拒否、取消後に外側のトランザクションを確定しても部分予約が残らないことを検査した。台帳の公開状態テストは会議公開の実装・検証ではない。
- 未対応領域、別会議の対象、構築先の旧由来の変更を拒否し、取消・拒否時の所有領域だけの回収を確認した。元の検査用DBの読取り専用設定は解除していない。

確定コードの`make check`は終了コード0で成功した。Python 65件、フロントエンド64件、Swift 9件、Rust通常329件と別実行のAVFoundation製CAF検査1件が成功し、環境依存のRust 11件は除外された。型・書式検査とビルドを含み、評価設定の不足はエラー0件・警告7件だった。既存の旧DB移行試験は、データが空のテスト専用台帳だけを除いた旧版の構成と、最新移行数に合わせて更新した。移行本体のチェックサムや不適合版の拒否は緩めていない。ログは`/tmp/mon-restore-ledger-verified-check.log`に保存した。
