# 話者分離ジョブと編集保護の検証

2026年10月4日、sherpa-onnxの全トラック実行を固定入力・共有ジョブ管理・候補保存へ接続した。開始時に保存済みの修正本文、話者名、手動割り当てをコピーし、現在版と下書きを上書きしない。提供済み30秒音声と実エンジンで候補保存まで通ったが、文字起こしは保存処理検査用の合成データであり、話者精度を評価した結果ではない。正式評価とWindows固有部分は保留を維持する。

## 実装と保存の範囲

`start_diarization` はメイン画面専用のAPIとし、保存済み現在版・本文ハッシュ・会議の更新番号・下書きIDと更新番号を照合する。同じ操作IDの要求は条件一致時だけ既存ジョブを返す。修正を適用した内部入力コピーとジョブを一トランザクションで作成し、公開版・下書きを変更しない。

全保存トラックを対象とし、人数は各トラックへの指定または自動推定として固定する。CPU、モデル、実行ファイル、同梱ランタイム、閾値、窓移動比率、最小区間長も固定する。開始後の話者名・本文編集や、再試行時の設定画面の値は固定入力に反映しない。トラック間の同じクラスタ番号を同一人物とは扱わない。

1. 共有スケジューラーが話者分離を取得し、録音・他の推論と同時実行しない。
2. 音声・マニフェスト・モデル・ランタイムを再照合し、全トラックを順番に16 kHzモノラルWAVへ変換して実行する。
3. トラックごとに入力WAV、元の標準出力、由来・条件付き結果JSONを管理ファイルへ登録し、再読込・照合後に途中保存する。
4. 再開と失敗・取消からの同条件再試行は、全保存結果を先に照合し、未完トラックだけ実行する。取消されたトラック内の途中クラスタリング結果は流用しない。
5. 公開直前にも全入力・結果を再照合し、候補版とジョブ成功を一トランザクションで保存する。開始後に現在版が変わった場合も親版を付け替えず、既存の採用APIが古い親の候補を拒否する。

元の認識本文、修正本文、発言時刻、確認できた発言の対応ID、既存話者名を保持する。元の音声認識の信頼度もそのまま引き継ぎ、新しい話者区間の信頼度はエンジンから取得しないためNULLとする。手動割り当ては自動推定より優先し、明示的に選択された「話者不明」も次の再解析へ引き継ぐ。本文だけ修正された未割り当て発言は、初回の話者推定対象から除外しない。

同一トラックの異なる話者区間が実際に交差する場合だけ、複数話者の割り当てにする。発言中の逐次的な話者交代や、重複前後に別の話者を含む場合は、本文を推測分割せず話者不明として残す。元の話者区間を独立して保存するため、文字起こしの手動割り当てを保持した場合も推定区間は失わない。区間と分割確認を表示する画面は今回の実装に含めていない。

SQLite v17は固定入力の明示的な手動割り当てを保持するテーブルと、話者分離結果の由来を検査する制約を追加する。ジョブ作成後の割り当て追加・変更・削除、別入力を指す結果、開始時点から結果を持つジョブを拒否する。既存移行のSQLとチェックサムは変更しない。

## 自動テスト

新しいジョブ・保存テスト13件は合成CAFと模擬CLIを使う。これらは条件引継ぎ・保存・中断を検査するもので、推定品質の証拠にはしない。

- 入力コピーと開始の原子性、同じ操作IDの重複防止、古い現在版・下書き・会議状態・誤トラックの拒否。
- 本文・名前・手動割り当てと明示的な不明の保持、本文だけ修正した発言への推定、認識信頼度と生の区間の保持。
- 2トラックの独立した話者ID、各トラックへの3人指定、指定数と実際に出力されたクラスタ数の区別。
- 1トラック保存後のアプリ再起動・再開と、2トラック目失敗後の再試行で完了分を再実行しないこと。
- 原音、モデル、保存WAV、標準出力、JSONの差し替えを再開・再試行前に拒否し、新しい推論を行わないこと。
- 有効なファイルハッシュを持つ別由来の結果も拒否すること。
- 候補保存とジョブ成功のロールバック、途中保存のDB失敗後に未確定結果を再利用しないこと。
- 録音・通常終了の停止要求で未完の子プロセスを終了・回収し、完了トラック数を増やさないこと。
- 候補採用後も旧版下書きを保持し、次の再解析へ明示的な不明と話者名を引き継ぐこと。開始後の現在版切替で候補の親版を変えず、古い親の採用を拒否すること。
- v16からv17へ移行した現在版、下書き、共通・会議別用語、既存ジョブの固定条件・ハッシュ・外部キーの保持。

`make check` はPython 65件、フロントエンド39件、Swift 5件、Rust 174件に合格した。Rustの実エンジンなど8件は通常実行から除外し、AVFoundation製CAFの読出し1件を別枠で実行した。評価前提不足7件は警告のまま残す。話者分離の接続部はワーカーから利用され、前回の未使用警告はなくなった。

全体テストの再実行で、既存の議事録停止テストが模擬プロセスの準備前に250msのタイムアウトへ達した。単独実行の成功も確認したうえで、一時停止ケースはPIDの書込完了を待って要求し、その要求から回収までを検査する形へ分離した。タイムアウトケースの250msと本体の処理は変更せず、並列テスト中の起動待ちを停止応答時間と混同しないようにした。

開発用macOS `mon.app` のビルドは17.15 MiBで成功した。親アプリと同梱録音プローブの `codesign --verify --deep --strict` も成功した。アドホック署名・公証なしであり、配布や実画面の動作を保証しない。録音は行っていない。

## 実エンジンでの接続確認

前回の[ネイティブ接続検証](m2-05-sherpa-adapter-2026-10-04.md)と同じCLI、両モデル、ONNX Runtime、提供済み30秒CAFを使用した。保存処理を検査する会議・マニフェスト・文字起こしはテスト用であり、実録音の登録からTauri画面までの一連の検証ではない。元ファイルは変更せず、音声を外部へ送信していない。

macOS 27.0 build 26A428、Apple M1 Max、arm64、32 GiBで、CPU・2スレッド、自動人数、閾値0.5、窓移動比率0.1、最小発話長・結合ギャップ0秒として実行した。実モデルに正解データは与えていない。

## 続く実装と未検証事項

人数・対象トラック・エンジン条件の設定、開始・同条件再試行、生の話者区間・重複区間・分割確認の表示を画面へ接続する。既存の候補比較・確認付き採用・直前版復元に統合する。録音後の工程引継ぎとモデル準備も残り、M2-05・M3-03全体は完了扱いにしない。

全体の話者データ件数上限は100件で、保護した既存話者と新規の推定話者を合算する。多人数や繰り返し再解析でこの上限を超える場合は、候補保存が明示的に失敗する。既存話者の整理・統合と安全な件数管理は続く実装で扱う。人数の受付上限を検証済み人数とは表示しない。

日本語の話者精度、重複検出精度、10話者、必須16GB端末、4時間の推論メモリ・処理時間、トラック間のエコー照合、macOS WebViewの実操作、強制終了後の解析子プロセス対策、モデル配布許諾と同梱・準備UIは未検証または残件とする。Windows固有部分は保留し、Windows CIのpush・PR自動実行停止を維持した。
