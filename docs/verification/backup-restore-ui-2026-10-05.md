# バックアップと追加復元の画面検証

M3-06のネイティブ操作へ設定画面の「データと保存」を接続した。上書き確認、件数・容量・共通用語の復元確認、取消、結果確認、完了通知、復元した会議の一覧と由来表示を追加した。下書き保存を待ってから選択と公開を開始する。ブラウザの模擬IPCで20ケースを確認したが、実NSSavePanel・NSOpenPanelとmacOS WebViewを通す一連の操作は未検証であり、M3-06全体は進行中である。

## 編集と操作状態の保護

画面が送る公開要求はネイティブ側の選択トークン、確認ID、操作種別だけであり、画面から保存先パスや復元先IDを指定しない。録音・取り込み・解析・モデル準備・Markdown出力・終了が処理中なら停止や完了を待つ案内を表示する。利用可否の読取りは案内用で、実際の開始時はネイティブ側が共有排他を再検査する。

ファイル選択と公開前は共通の編集保存を待つ。保存に失敗した入力は保持し、データ操作を開始しない。処理中と受付結果が不明な間は画面の編集・新規処理・会議切替を保護する。状態の読込みが失敗した場合も新しい変更操作を停止し、検証済みの再読込みで復帰する。録音停止はデータ状態の読込み失敗だけでは無効化しない。

状態と結果は単調増加するrevisionで受理する。古い通知を採用せず、同じ版の異なる内容や不正な容量・結果を拒否する。イベントに加え、1秒間隔の重複なしポーリングとフォーカス時の再読込みを行う。公開要求の応答を失った場合は同じ要求を保持し、新しい操作へ置き換えない。利用者の「同じ操作の結果を確認」は同じトークンと確認IDを使用する。選択応答だけを失った場合は読取りで確認内容を回復し、復元の公開には引き続き明示確認が必要である。

未確定の受付を再試行せずに閉じたい場合は「同じ操作を取り消して確認」を使い、ネイティブ側で選択の破棄または実処理の取消を行う。受付拒否と応答喪失を画面だけで区別しなくても、未公開物の整理と公開済み結果の保持を維持したまま元の操作へ戻れる。

取消要求後もネイティブ側の終端通知まではbusyを維持する。確認ダイアログは見出しにフォーカスを置き、Escapeで未公開の確認内容を破棄する。取消の片付けと操作可能状態への復帰を待って、呼出元ボタンへフォーカスを戻す。通常終了前にも状態を検査し、処理中や確認待ちなら取消・破棄を確認して既存の終了待ちへ渡す。

## 確認内容と復元結果

新規バックアップ出力は保存パネルの選択後に進める。既存出力を置き換える場合は保存先を表示し、追加の上書き確認を要求する。未完成ファイルを利用可能とは表示せず、終端の実結果がある場合だけ完了通知を出す。公開後の結果が未確定なら実ファイルの確認を案内し、同じ操作を自動で再上書きしない。

追加復元では会議タイトル、件数、余裕を含む必要容量、空き容量、共通用語の追加・完全一致重複・既存を保持する競合を表示する。容量不足では公開ボタンを無効化する。同じバックアップの再検証は同じバッチを保持して確認IDを更新する。別操作として明示的に選び直した場合は別バッチとして新しい会議を追加する。

結果の会議IDで今回の復元一覧を絞り込み、全会議表示へ戻れるようにした。復元由来は専用の読取りAPIで取得し、「バックアップから復元」を表示する。既存のMeetingシリアライズ、形式版2、SQLite移行27、準備済み復元の指紋は変更していない。コントローラーの実SQLite復元テストにも由来一覧の照合を追加した。

共通用語の結果は確認画面の予定値ではなく公開結果を表示する。台帳に過去の件数がない場合は「記録不明」とし、ゼロや推測値に置き換えない。共通用語エディターは入力を保護するため自動再読込みせず、保存後の手動再読込みを案内する。バックアップにAIモデル本体・一時PCM・ログ・端末固有設定は含まれず、独自暗号化・クラウド同期ではないことも説明する。

## ブラウザ操作の検証

Playwright CLIと開発専用の`app/tests/data-save-browser-fixture.js`を使用し、`app/tests/data-save-browser-check.js`の20ケースが成功した。実ファイルの選択や書込み、録音、個人の会議データの変更は行っていない。模擬のJavaScript確認プロンプトは検証内で受諾し、HTMLの上書き・追加復元ダイアログは実際のボタン操作で確認した。

- 収録範囲と除外範囲の説明、新規出力の一度だけの開始、処理中の保護、終端前の成功表示なし。
- 上書き対象の確認、Escapeでの取消とフォーカス帰還、明示確認後だけの公開。
- 復元前の件数・容量・競合確認、既存会議の保持、由来と今回の一覧、全会議への帰還、別操作の別会議追加。
- 容量不足の拒否と同じバッチの再検証、不正アーカイブの拒否。
- 確認構築と公開の取消で実処理完了を待つこと、遅い確認通知でダイアログが再出現しないこと、確定が取消に勝った場合の成功保持。
- 公開応答とイベントを失っても読取りで回復して二重公開しないこと、未受付の要求の明示再送で確認IDを保つこと。
- 未受付か不明な要求を明示取消し、公開や再送なしで確認画面から戻ること。
- 実結果のない不正な完了通知を拒否すること、未確定バックアップの自動再上書き禁止、過去の用語件数を推測しないこと。
- 選択応答の喪失後も確認を回復して明示公開だけを行うこと、処理中の案内、読込み失敗時の保護と再読込みでの復帰。
- 編集保存の失敗時に入力を保持して選択しないこと、遅い保存の完了を待って選択すること。

1200×900と900×650の確認画面を画像で確認した。後者のダイアログは780×約545pxで、水平はみ出しはなく、件数・容量・競合・確定と取消のボタンを読めた。開発サーバーのHMR WebSocketにはローカルネットワーク制約による接続エラーが出たが、各試行のページ再読込みと上記20ケースは成功した。ネイティブWebViewの描画証明ではない。

共通のデータ状態読込みを追加した影響を確認するため、既存のモデル再配置・同条件再試行の模擬IPCブラウザ検証15ケースも再実行し、すべて成功した。ほかの既存画面の全ブラウザ操作を再実行したわけではない。
