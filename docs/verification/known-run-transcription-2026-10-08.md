# 欠損を含む録音の保存区間別文字起こし

未回復の欠損を含む録音について、保存済み区間だけを文字起こしする経路を追加した。欠損分の無音を作らず、区間を連結せず、結果は元の会議時間へ戻す。実行・再開・再試行と追加復元で、取得時計・音声ファイル・欠損・区間の固定条件を照合する。話者分離の区間別対応と実モデル・Mac実機の統合は残る。

## 固定した入力と保存区間

欠損を持つ新しい文字起こしジョブには形式版3を使う。既存の `source` に加えて、`knownInput` に会議時間、入力ごとの欠損、会議時間軸に対応する保存区間を固定する。欠損の開始・終了、理由と回復状態を保持し、取得時計の空白には全範囲を覆う未回復の証拠を要求する。部分だけの証拠、回復済みのラベル、壊れた時計対応から解析用の無音を作らない。

欠損は入力別1024件・合計2048件までとし、元の時間、入力所属、理由の文字・容量、固定順序を照合する。重なる欠損を合わせて保存区間を切り出す。開始は入力の会議時間格子で切り上げ、欠損直前の終端は切り下げる。欠損にかかる部分フレームは除外する。完全に利用不能の入力や未確定・破損した他方入力を、空の成功や別入力だけの正常な解析へ置き換えない。

欠損のない連続音声は従来の形式版2を維持し、`knownInput` と単位の `runIndex` は省略する。既存形式版1・2の固定条件、120秒単位と用語の固定条件を変更しない。旧形式で会議時間が未設定または0の連続音声は、既存の保存トラック時間を使う。欠損を持つ入力には正の保存済み会議時間を要求する。旧 `recorded_audio_plan` と欠損を横断する厳密な区間再生の拒否は維持する。

## PCM読出しと会議時刻への対応

保存区間ごとに120秒の主区間を作り、前後2秒の文脈をその保存区間の端点へ制限する。入力間や欠損の前後を一つのWAVへ連結しない。全保存ファイルの管理パス・ハッシュ・物理フレーム数・形式・連番を検証し、準備する音声は一つの入力区間ずつとする。

時計対応を通すPCM読出しでは、出力範囲だけでなく補間の前後参照も固定した保存区間の内側へ制限する。物理的に連続するCAFに欠損ラベルがある場合も同じ制約を適用する。元のCAFを書き換えず、欠損の前後のPCMを借りない。

認識結果は保存区間の最初の会議時間フレームと解析窓の位置から元の会議時刻へ対応付ける。文脈の中点による単位所有を維持し、結果の終端は保存区間までとする。候補には区間別解析の方式・区間数・未回復欠損数を記録し、詳細な固定条件はジョブに保持する。現在版・手動本文・話者の編集を自動採用や上書きで置き換えない。

## 再試行と追加復元

再試行では同じ音声と欠損の固定条件を照合し、完了済みWAVと認識JSONだけを引き継ぐ。補間境界を含めて同じWAVを再生成できることを確認し、欠損の理由・回復状態・会議時間・取得時計が変わった場合は新しい試行を受け付けない。

候補の公開トランザクションでも、固定した音声メタデータと欠損をDBから読み直す。保存区間の外側や欠損を横断する発言は公開しない。

追加復元では音声資産・トラック・会議・ジョブのIDを既存の対応付けで変える。欠損と保存区間はトラックの固定順序への参照を使い、元の時刻・フレーム・解析窓を変更しない。復元時にモデルを実行せず、保存済みJSON・途中成果物の由来を照合する。

## 検証状況

最初のコンパイルは内部型の公開範囲と追加検査のモジュール参照、続くコンパイルは検査が存在しないジョブ結果フィールドを参照して失敗した。内部型の限定再公開、明示的な検査ファイル参照と `output_analysis_id` へ修正した。記録は `/private/tmp/mon-known-analysis-transcription1.log` と `/private/tmp/mon-known-analysis-transcription2.log`。成功には算入しない。

先行重点検査は10件成功・11件失敗・1件ignoredだった。欠損前後の非ゼロPCMと会議時刻、途中停止からの再試行、補間参照、追加復元の検査は成功した一方、会議時間が0の旧連続録音を拒否する互換性問題を検出した。欠損のない旧録音の時間の扱いを維持し、欠損を含む入力の正の会議時間の要件は残した。記録は `/private/tmp/mon-known-analysis-transcription3.log`。

互換性修正後の重点23件は終了コード0で成功し、実モデル用の既存1件はignoredだった。両入力の異なる形式・時間格子と会議時刻の保持、公開トランザクションでの欠損変更・欠損横断の拒否も確認した。記録は `/private/tmp/mon-known-analysis-transcription4.log`。これは他方入力の未確定状態を明示的に拒否する最終ガードの追加前である。

最終ガードと追加検査を含む重点検査は終了コード0で、24件成功・失敗0件・実モデル用の既存1件ignoredだった。記録は `/private/tmp/mon-known-analysis-transcription5.log`。

同じ最終製品ソースの全体 `make check` も終了コード0となった。通常Rust1,528件は880.41秒で成功し、環境依存・子プロセス専用49件は通常実行ではignoredだった。Swift101件中100件成功・既存1件skip、フロントエンド504件と型検査・ビルド、Python65件と形式検査、CAF全4800フレーム、SwiftとRustの専用連携9件が成功した。重点24件は通常Rustの件数に含み、重複加算しない。記録は `/private/tmp/mon-known-analysis-full-check1.log`。既存のリンク時警告は残る。

検査終了と所有プロセスの終了を確認し、専用一時領域 `/private/tmp/mon-known-analysis-native.Kv9C1c/debug` のRust生成物2,219,332KiB（約2.1GiB）を削除した。検証ログは保持し、生成物は再構築できる。製品targetは38,664KiB（約38MiB）のままで、保持した実行ファイル・アプリ・両配置の録音ヘルパーのSHA-256は変更前と一致した。WindowsワークフローはGitHub上でも `disabled_manually` を確認し、実録音・Windows CIは実行していない。

## 残る対応

欠損を含む音声の話者分離と自動工程の後続接続は未完了である。区間ごとのクラスタ番号を同一人物と扱わず、人数指定・既存の話者名と手動割り当てを保持する必要がある。現時点では欠損のあるトラックの既存話者分離は拒否を維持し、文字起こしの候補を話者分離までの成功として表示しない。

合成CAFと偽CLIの検査は認識品質・処理性能・MacネイティブWebViewの統合の証明ではない。実モデル統合、Mac実機、スリープ・入力形式変更・部分救出・容量不足、配布と先行試用は残る。正式評価・10話者・Windows固有部分の保留を維持し、M3-01と計画全体は進行中とする。
