# 録音前の5秒テスト画面と個別再生

中央の録音準備画面へ、5秒テストの開始確認・取消・入力レベル・結果再確認・マイクとPC音声の個別再生を接続した。会議を保存せずに入力を確認でき、通常録音の前に毎回テストする必要はない。Macアプリでの実録音は未検証であり、強制終了後の私有テスト音声の回収も残る。

## 開始条件と結果の固定

開始確認ではマイク・PC音声の取得範囲と一時保存、参加者の同意、OS権限、解析とモデル準備の停止待ちを説明する。アプリ選択ではプロセスの起動時刻まで固定し、ブラウザの他のタブの音も含む可能性を示す。編集保存後に機器・権限・アプリ・取り込みの所有を読み直し、対象が変わっていた場合は開始しない。

開始要求は新しい所有IDで一度だけ送信する。応答喪失後は状態を読むだけで照合し、開始を再送しない。結果がない場合も停止済みとは推測せず、競合する録音を止める。同時取消・解放は読取り後にも操作中の状態を確認し、二つの要求を同時に送らない。

テスト中は入力と通常録音の操作を固定し、専用の所有IDで入力レベルを読む。接続だけで振幅や保存成功を表示しない。取消の受付後も、取得プロセスの停止を確認するまで進行中として扱う。結果のマイク・アプリ名は固定し、準備画面で入力を変更した後は古い結果からの再生を停止して無効にする。

## 個別再生と一時音声の解放

検証済み音声は利用者が再生を押したときだけ準備する。既存の再生準備IDへ登録し、ネイティブの再検証と受取確認後に、所有トークンでPCMを読む。応答の形式・トラック・フレーム数・サンプルレート・チャンネル・物理長さを検証済み結果と照合する。

マイクとPC音声は別々に再生し、受信して保存した長さを表示する。取得していない時間を無音で埋めず、同期精度やエコー除去の合格結果とは扱わない。再生切替・入力変更・閉じる操作で以前の再生を止める。再生準備の取消受付だけで解放済みとせず、実処理の終了とトークン解放を待つ。解放失敗は共有の再生停止処理に保持し、明示的な再試行が成功するまで一時音声を破棄しない。

新しいテストと通常録音の開始確認では、前のテスト音声を破棄することを説明する。再生停止・同じ所有の終端確認・一時音声解放の後にだけ次の開始へ進む。通常録音の会議作成はその後であり、解放失敗で空の会議を作らない。アプリ終了の確認も、進行中テストの停止と私有音声の解放を待ち、停止が未確認のまま終了しない。

## 残対応

強制終了後のテスト音声は、所有証拠に基づく起動時回収を追加する。一時領域を検索して一括削除する方法では代替しない。画面喪失後の再生準備の回収と、終了しないIPCの扱いも残る。

今回の画面検証は模擬IPCと無音の合成PCMであり、Tauriの実ウィンドウ・実際の権限操作・マイクとPC音声の取得・音声出力の合格を示さない。実機での同期・エコー・切断・スリープ復帰・長時間安定性、残るUI・配布・先行試用を含め、M2-04・M3-08と計画全体は進行中である。正式評価・10話者・Windows固有部分の保留とWindows CI停止を維持する。
