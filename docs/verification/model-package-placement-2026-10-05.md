# 検査済みモデルの手動配置

2026-10-05に、設定画面の事前検査からOSのアプリデータ領域へコピーする処理を追加した。対象はモデル手動導入の配置段階である。実行ファイル・モデルは起動せず、互換性検証やAI準備完了とは扱わない。

## 配置と記録

確認ダイアログでモデル名・容量・元ファイルの保持・互換性未検証・途中配置の保全を示す。確認したmanifestの生バイトSHAと、申告構成・全ファイルの実測容量/SHAを一つの確認ハッシュへ束ねる。配布元のSHA指定がない場合も、配置前に再検査して確認ハッシュの一致を要求する。ローカルSHAは配布元の真正性やライセンス許諾を証明しない。

保存先は会議保存先ではなく `app_data/models/<操作UUID>` とする。空き容量は素材の合計にmanifest用64KiBと16MiBの余裕を加えて確認する。コピー開始前にSQLite v23の既存モデル表へ意図・構成・検査証拠を確定する。パッケージフォルダーとファイルは新規作成限定で、開いたディレクトリに対する相対操作とリンク拒否を使用する。ディレクトリは0700、実行ファイルは0700、その他は0600とし、ファイル・親ディレクトリを同期する。既存物の権限変更・上書き・削除はしない。

64KiB単位で取消・容量・SHAを確認し、元のファイルと親フォルダーの差し替えを検出する。コピー後も全構成を再検査し、一致した場合だけファイル行の配置完了を一括記録する。`model_files.ready` はこのコピーの照合完了だけを意味する。`model_packages` は常に `unavailable` とし、応答の `ready` もfalseで、解析設定・会議・既存ジョブを変更しない。

同じ操作IDへの再要求は、記録内容と配置済み実ファイルを再照合して結果を返し、重複コピーしない。欠損・改変・未完了の同じ操作は上書きせず拒否する。再配置は再検査後の新しい操作で行い、以前の途中配置は残す。意図の予約時には会議等の既存ID・追加復元の予約IDとの衝突も拒否する。

## 取消と再起動

事前検査と配置は共有ガードで全体1件に制限する。開始要求より先に取消が届く場合も、直近128件の取消済みIDを保持して遅れた開始を抑止する。録音中の配置を拒否し、配置中に録音が始まれば取消判定で中断する。画面切替・取消後の古い応答は成功通知に使わない。

中断したファイルは削除しない。再起動時の `preparing` 記録は `unavailable` にし、自動コピー・実行・再開を行わない。結果の応答を受け取れなくても、配置記録の再読込で最後に記録したコピー結果を確認できる。記録表示は現在のディスクの健全性や動作互換性の検証ではなく、表示容量も途中コピー済み容量ではない。
