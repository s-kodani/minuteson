# 保存先引継ぎの旧形式受入れの削除

保存先変更の削除履歴について、旧形式版1の受入れ・検査用変換・旧全行ハッシュへの読取り切替・旧形式の会議参照を保護する専用経路を削除した。現行履歴の同意ハッシュは省略不可にする。現行の初回移動・再移動・同意・所有対応・排他を維持し、旧データを新しい形式へ変換して使い続けることはしない。

## 変更範囲

引継ぎ履歴の `immutableHash` を省略可能な値から必須の文字列へ変更した。初回移動のsource version 2と、過去の移動先の実体対応を含む再移動のsource version 3は、現行処理が作成する異なる状態なので両方を維持する。destination version 1も現行の初回コピーの状態であり、削除対象の旧source version 1とは別である。

冷起動では必須の同意ハッシュを毎回照合し、稼働中の固定コピーの全行ハッシュ検査は残す。旧source version 1の全行ハッシュだけを使う代替読取りと、それを作成する検査専用ヘルパーを除去した。旧形式を別の所有付きコピー経由で新形式へ引き継ぐ成功検査2件と専用ファイルも削除した。削除したソースはGit履歴から復元できる。

新しい検査は旧0・1と未知4の拒否、必須ハッシュの欠落・null・不正形式・内容不一致、現在の進捗時刻の更新、DB側の同意書換え拒否を確認する。所有ルートの検査は従来の削除開始前・DB確定前にも残す。旧形式の参照保護だけの一覧取得・拒否案内は不要になる。

旧構造化議事録、旧ジョブ、DB行だけの削除記録などの残る専用処理は別の整理対象で、互換処理全体の削除完了ではない。現行の会議・音声・モデルや保存された同意は今回削除していない。
