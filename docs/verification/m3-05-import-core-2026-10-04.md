# 音声取り込みの保存と回復の検証

WAV・MP3・AAC/ALAC M4A・FLACのファイル取り込み基盤を追加した。原本を管理領域にコピーし、解析用FLACとmanifestを保存してから、単一の取り込みトラックと自動解析工程を原子的に登録する。合成音声の実復号、保存、再起動後の再生を確認した。後続の[取り込み画面と解析設定の検証](m3-05-import-ui-2026-10-04.md)で選択・ドロップ・開始・取消を接続したが、macOS WebViewの統合確認は残り、M3-05は進行中のままとする。

## 対応形式と原本の保持

拡張子ではなく音声の内容を判定する。macOSの同梱ヘルパーはAudioToolboxでRIFF PCM WAV・AAC/ALAC M4A・FLACを復号する。M4AはISO BMFFの箱を読み、単一音声かつ動画なしの条件を検査する。箱の内容を丸ごと読み込まず、4096個を上限に長さと階層を確認し、音声・動画トラックを識別する。FLACの原本はRust側でもCRC・実フレーム数・存在するPCMのMD5を検査する。

MP3はSymphonia 0.5.5のLayer IIIデコーダーで読む。使用しないID3を復号器へ渡さず、長さと総量16 MiBの上限を確認する。MPEG 1・2・2.5のフレーム境界と形式の連続性を検査し、遅延・末尾パディングは検証後に除去する。途中で切れた音声、自由ビットレート、途中の形式変更や未対応の追加タグは拒否する。すべてのMP3・M4A変種を保証する検証ではなく、M4AのAAC試験はAAC-LCで行った。RF64 WAVやHE-AAC等は今回の確認範囲に含めない。

復号時は8,000〜384,000 Hz、1〜8チャネル、4時間以内、実フレーム数と宣言値の一致、有限のPCMを検査する。検査・コピー前後で元ファイルのサイズ・ハッシュ・変更状態を照合する。管理コピーは新規作成だけを許可し、元ファイルを移動・削除・変更しない。元ファイルの絶対パスは永続的な解析入力として保存しないため、外部の原本を移動しても管理音声を再生できる。

変換中はfloat32 CAFを使い、共通のRust保存器で24ビットFLACにする。FLACの量子化とビット単位の一致に関する制限は[共通FLAC層の検証記録](m3-05-flac-audio-2026-10-04.md)と同じである。原本コピーは変換物とは別に、そのまま保持する。ステレオを含む入力も単一の`imported`トラックとして扱い、チャネルから本人・マイク・PC音声を推定しない。

## 保存状態と中断回復

SQLiteの19段階目の移行で、操作ID、元サイズ・ハッシュ、形式・フレーム数、確定manifestへの参照を追加した。既存の取り込み行は保持し、古い行に検証済みの由来を捏造しない。録音の準備・実行・停止と、進行中の取り込みは同時開始を拒否する。同じ操作IDによる再開始は、他の実行が所有するコピーを削除しない。

開始前と原本コピー後に、原本・中間CAF・FLAC・128 MiBの余裕を含めた保守的な容量見積もりを検査する。コピー、復号、FLAC保存、DB確定の段階と処理量を呼出元に返す。後続の画面へ進捗表示を接続したが、空き容量不足の実機再現は未検証である。

コピーと変換が完了したら、原本・FLACのサイズとSHA-256を記載したmanifestを同期し、上書きせず公開する。原本・FLAC・manifestの3資産、音声トラック、チャンク、会議の`imported`状態、自動解析工程を同じDBトランザクションで確定する。検証または解析工程の登録が失敗した場合、資産やトラックだけが登録された状態にしない。

manifest公開前の取消・失敗では、未登録で所有を確認したコピー・中間音声・変換物だけを整理する。未知のファイル、リンク、登録済みの資産があれば削除せず保持する。これは試験用の取り込み領域でも確認し、外部の原本と既存会議は変更していない。

manifest公開後の保存失敗は音声を保持し、次回起動で再検証する。完了した原本とFLACが固定条件に一致する場合だけ、保存と解析工程への引継ぎを確定する。壊れた完了物はエラーを記録して残し、音声を途中までの正常結果として扱わない。未完了物は中断として記録する。自動回復と終了操作の停止待ちは後続の取り込みコントローラーへ接続した。実画面での終了確認は別途必要である。

## 解析と議事録への引継ぎ

取り込み音声は録音と同じ管理manifest・トラック検査を使い、文字起こしと話者分離へ渡す。話者表示は「取り込み音声 話者N」とし、本人扱いにしない。候補は自動採用せず、議事録も自動開始しない。利用者が採用した本文・話者から、専用の変更不能な入力版を作って議事録生成へ渡す。

プロトコル用の模擬エンジンで、保存から文字起こし、未採用候補の話者分離、明示採用、議事録用固定入力までを検査した。他の会議の状態・ジョブを変更しないことも確認した。この試験は実エンジンの認識品質や生成品質を測ったものではない。

## ローカル検証結果

新規の通常Rustテスト14件は、取り込みの保存・回復11件、MP3の上限とフレーム検査2件、解析から固定議事録入力への引継ぎ1件。Swiftの新規4件は、誤った拡張子のWAVの内容判定と全ステレオPCM、上書き拒否と取消、非有限PCMと不正音声の拒否、M4Aの動画・複数音声・箱の長さ検査を確認した。

`make check`は成功し、Python 65件、フロントエンド61件、Swift 9件、Rust 222件が成功した。外部エンジン等11件は通常実行でignoreのまま。別実行のAVFoundation製CAF試験1件も成功した。旧v12・v14〜v18の移行試験を含め、既存の下書き、heads、ジョブ、用語と設定の保持を検査した。

FFmpegを試験だけの独立実装として使い、次の3件も成功した。製品の実行時依存にはFFmpegを追加しない。

- WAV・MP3・AAC M4A・ALAC M4A・FLACの4秒ステレオ音声を、意図的に異なる拡張子で検査・コピー・FLAC保存し、外部原本を移動後、再起動したDBから再生する試験。動画入りM4Aと不正音声は登録前に拒否した。
- 44.1 kHzステレオVBR・16 kHzステレオCBR・8 kHzモノラルVBRのMP3を、別実装の復号と全PCM照合する試験。2秒のフレーム数が一致し、サンプル差は0.001未満、末尾の切り詰めは拒否した。
- 既存のRustとFFmpegによるFLACの双方向照合試験。

macOSの圧縮音声デコーダーは、この作業環境の制限付き実行では`configure PCM failed: 1718449215`となった。録音・権限要求なしのファイル試験を制限外で行うと成功した。M4Aの誤った拡張子はAVURLAssetの自動判定では開けなかったため、AudioToolboxへの内容による形式指定と、箱のトラック検査に置き換えた。エラーを成功扱いにしたり、試験音声を簡単な形式に置き換えたりしていない。

locked・offlineのmacOSビルドで18.34 MiBの開発用アプリを生成し、`codesign --verify --deep --strict`に成功した。そのアプリに同梱された署名済みヘルパーで、上記5形式の取り込み試験も成功した。アドホック署名・公証なしであり、実画面の操作や配布の検証とは区別する。

再実行には次を使う。圧縮音声の試験にはmacOSのデコーダーサービスを利用できる環境が必要である。

```sh
make check
MON_IMPORT_HELPER=/absolute/path/MONCaptureProbe.app/Contents/MacOS/mon-macos-capture MON_IMPORT_FFMPEG=/opt/homebrew/bin/ffmpeg cargo test --locked --offline --manifest-path app/src-tauri/Cargo.toml native_import_all_formats -- --ignored
MON_IMPORT_FFMPEG=/opt/homebrew/bin/ffmpeg cargo test --locked --offline --manifest-path app/src-tauri/Cargo.toml ffmpeg_mp3_variants -- --ignored
MON_FLAC_FFMPEG=/opt/homebrew/bin/ffmpeg cargo test --locked --offline --manifest-path app/src-tauri/Cargo.toml independent_ffmpeg_flac_round_trip -- --ignored
```
