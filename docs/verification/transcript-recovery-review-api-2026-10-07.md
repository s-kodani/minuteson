# 未確定本文の回復記録一覧と確認付き破棄

2026-10-07に、会議内の旧下書きも含めて未確定本文の保存記録を発見する一覧と、確認した記録だけを破棄するメイン専用APIを追加した。保存済み本文、解析版の採用状態とUndo履歴は変更しない。入力画面からの回復保存と復元操作はまだ接続しておらず、現在の入力は引き続き画面内メモリーに保持する。計画全体は進行中である。

## 会議別の一覧と詳細

一覧は1ページ20件とし、下書きIDの順で次ページを取得する。会議に属する文字起こし下書きだけを対象にし、非アクティブな旧下書きと入力のない保存記録も含める。各記録の型・内容ハッシュ・版番号・発言と話者の所属を検査し、本文を一覧に含めず、詳細取得に必要な所有IDと保存情報を返す。空の記録でも破損を隠さない。

詳細には保存時の基底だけでなく、その下書きの現在の版番号・内容ハッシュと、現在採用中の解析版に対応する有効な下書きかどうかを返す。保存記録と旧下書きの内容が一致しても、現在版として扱えるとは限らない。画面から編集を再開する際には現在の解析版・下書き・保存時の内容を改めて照合する必要があり、一覧取得だけで復元や採用は行わない。

## 確認した記録だけの破棄

破棄要求は会議・下書き・解析版の所有、確認時の下書き版番号とハッシュ、回復記録の版番号とハッシュ、操作IDを固定する。確認後に下書きか入力が更新された場合は、古い確認による破棄を拒否して保持する。旧下書きも対象にできるが、その有効化、旧解析版の採用、確定本文の保存は行わない。

破棄は回復表の入力を空にし、版番号を一つ進めた記録を保存する。確認した旧記録のハッシュと版番号を形式版2の破棄証拠として保持し、遅れて届いた古い保存要求による入力復活を拒否する。証拠に本文や所有IDは含めない。通常保存は形式版1を維持し、新しい省略可能フィールドを出力しないため、従来の形式版1の正本バイト列とハッシュは変わらない。

応答を失った同じ破棄要求は、保存済みの破棄証拠・操作ID・確認条件が完全に一致する場合に限り、保存済みの結果を返す。その後の下書き変更を巻き戻さず、さらに新しい回復保存があれば古い要求を拒否する。通常保存と破棄で同じ操作IDを使っても別種類の成功結果に置き換えない。書込み停止中や旧保存先では再試行も拒否し、読み取りだけを許す。

## バックアップと追加復元

形式版2も回復記録の通常検査とバックアップに含める。追加復元では会議・解析版・下書き・操作と基底内のIDを再対応付けし、基底と記録の内容ハッシュを再計算する。破棄証拠の旧ハッシュは元記録の履歴として保持するだけで、新しい所有や削除許可として使わない。復元後の所有IDであっても、元の破棄要求を再実行する権限にはならない。
