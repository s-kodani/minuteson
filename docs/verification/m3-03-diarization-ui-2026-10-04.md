# 話者分離の人数指定と推定区間確認の画面検証

2026年10月4日、固定編集入力を使う話者分離ワーカーへ人数・条件設定、開始・同条件再試行と区間確認画面を接続した。現在版・候補版・直前版で音声と割り当てを比較できる。保存処理の検査とブラウザの模擬IPC操作は通ったが、macOS WebViewでの一連の操作や推定品質を証明するものではない。正式評価・Windows固有部分の保留は維持する。

## 設定と処理操作

標準・高精度の各プロファイルにCLI、区間モデル、埋め込みモデル、依存ランタイムの絶対パスとCPU条件を保存する。専用の設定キーで他エンジンの設定から分離し、JSONハッシュ・版番号・DB取引で検査する。設定を700ms後に自動保存し、開始・会議切替・通常終了では既存の保存キューを待つ。保存失敗時は入力を保持し、開始や画面移動を止める。明示的な保存再試行と設定再読込を用意し、未保存入力を破棄する再読込は確認を要求する。

人数の初期値はトラックごとの自動推定とする。指定する場合は1～100の整数を要求し、空欄・小数・範囲外を黙って自動推定へ変えない。3人の指定は今回のトラック条件であり、会議全体の参加者総数や検証済み人数を意味しない。プロファイル名も品質保証とはしない。

開始前に本文・話者名等の保存を待ち、最新の現在版・内容ハッシュ・会議版・下書き版を読み直す。人数とエンジン条件は開始時の固定条件として候補へ保存する。一時停止・再開・取消と保存済みトラック数を表示する。同条件再試行は元ジョブの固定条件と保存結果を使用し、現在の設定画面を使用しない。応答不明・失敗後の再送は同じ操作IDを保持する。

## 推定原区間と再生

発言の実効話者割り当てと、保存された推定区間を別々に表示する。複数話者を手動で選んだことだけを重複発話とは表示しない。区間の交差がある場合だけ「発言重複」、同じ発言内で話者が順に交代する場合は「分割を確認」とする。本文や単語時刻を推測して分割しない。明示的な話者不明を含む手動割り当ての保持も表示する。

メイン画面専用の区間参照は会議・解析版・発言IDと内容ハッシュを照合する。現在版、直前版と公開候補だけを許可し、内部入力スナップショット、別会議・別版、公開対象でなくなった過去版、改変した子区間は拒否する。最大50発言の概要、1発言につき原区間と交差区間を各50件ずつ返す。隣接区間や同一話者の二重区間は追加の重複話者と扱わない。信頼度がない出力に値を作らない。

候補比較にも発言全体の音声再生を追加した。原区間がない文字起こし候補でも採用前に聞ける。原区間または交差区間の再生は、その発言の先頭を基準としてフレーム位置を計算する。準備失敗、比較画面の終了、別の発言の再生では以前の再生トークンを閉じる。音源分離やトラック間の人物同定は行わない。
