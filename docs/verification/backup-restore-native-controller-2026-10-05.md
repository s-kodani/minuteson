# バックアップと追加復元のネイティブ操作検証

M3-06の確認処理を、メイン画面専用のTauriコマンド、macOSのファイル選択、バックグラウンド処理、取消と終了待ちへ接続した。確認待ちでは通常の編集を許可し、検証・作成・公開の実処理中は解析ワーカーと同じ開始排他を保持する。設定画面のボタンと確認モーダル、下書き保存の接続は未実装であり、アプリから一連の操作を完了できる状態とは扱わない。

## 操作と状態の保持

`DataController`は、選択のトークン、単調増加するrevision、工程、確認内容、結果、再試行可否を保持する。`get_data_operation`で状態を読めるため、コマンドの応答や`data-operation-changed`イベントを取り逃しても同じ操作を確認できる。4コマンドすべてにメイン画面の検査を置き、公開側にはパスやSQLを受け取らせず、ネイティブ側が保持する確認済みの選択だけを使う。

`select_data_operation`は選択処理をネイティブ側の独立した非同期タスクへ渡し、最初のbusy状態を返す。macOSではバックアップにNSSavePanel、追加復元にNSOpenPanelを使用する。ダイアログの実際の応答後、専用ワーカーで以前の選択を片付け、検証を進める。コマンドの受信側が失われても処理と開始排他を残す。Windowsの選択操作は保留のエラーを返し、Windows実装やCIは再開しない。

`start_data_operation`は選択トークンと確認IDを照合する。同じ確定要求の処理中・成功後は状態だけを返し、再上書きや二重追加を開始しない。再確認の成功後は確認IDが更新されるが、応答を取り逃した同じ再確認要求は更新済みの状態を返す。古い選択や別の確認IDは拒否する。

復元処理の失敗時は確認済みの選択とバッチを保持し、同じバッチで再確認・再試行する。公開のDB確定後にメモリ上の結果を失った場合も、台帳を読んで公開済みの会議IDを返せる。以前の共通用語併合件数を推測して作り直さず、不明のまま返す。バックアップのrename後の未確定エラー、またはバックアップ公開中のpanicでは同じ操作の自動再試行を禁止し、結果の確認を要求する。

## 取消と開始排他

`AnalysisController`にデータ操作の所有付きガードを追加した。録音開始・取り込み・AI処理・モデル準備・Markdown書き出し・終了処理との開始判定を同じ状態ロックで行う。動いている解析をバックアップのために暗黙に止めず、停止・完了後に再試行するエラーを返す。録音や取り込み側もデータ処理中の開始を拒否する。実処理後のガード解放で解析ワーカーを再起動するが、録音・取り込み・終了の判定は引き続き優先する。

取消はフラグを立てるだけで、処理中の排他やbusy状態を先に解除しない。ワーカーの終了と専用領域の片付けを待って状態を確定する。確認待ちの取消でも、大きな専用コピーの削除はバックグラウンドで行い、その間は次のデータ操作と終了待ちを遮断する。DB確定やバックアップ公開が成功した後の取消では、成功結果を取消に変えない。

通常終了では、まず共有の終了判定を確定して新規開始を止める。その後、データ操作、音声取り込み、解析の順で取消・終了を待つ。データ操作の待機上限は15秒で、超過時はアプリを開いたままエラーを返す。取消が届いたダイアログも実際の応答までbusyを保持するため、利用者はパネルを閉じてから終了を再試行する。終了失敗時は開始判定を戻すが、作業中のガードは実処理が終わるまで残す。

Markdown出力にも共有の開始ガードを追加し、バックアップ開始との競合を閉じた。出力の保存パネルと実際の公開が終わるまで独立タスクがガードを所有し、受信側の切断では解放しない。通常終了の完了処理も独立タスクに保持し、close応答の喪失だけで開いたアプリに終了判定が残ることを防ぐ。

## 自動検証の範囲

操作コントローラーの追加7件は、実ファイルのバックアップと実SQLiteへの追加復元を使用する。入力の会議は合成データであり、音声品質や長時間性能を測定する試験ではない。

- 保存先を公開後に別アプリ相当の内容へ変更しても、同じ確定要求の再送で再上書きしない。
- 再確認の応答を取り逃した再送は新しい確認内容を返す。復元は既存会議を保持し、同じ公開要求では一度だけ追加する。
- 取消後の待機タイムアウトではbusyが残り、実ワーカーの終端通知後にだけ待機が終わる。古い操作の進捗は採用しない。
- 遅い取消より公開成功を優先する。公開後の未確定状態を模擬注入したバックアップでは再試行しない。実fsync失敗の再現ではない。
- 不正アーカイブと事前取消は既存データを変更しない。
- 復元の構築中panicを模擬注入した後も同じバッチを保持し、再試行できる。
- 実際の復元コミット後、結果通知の欠落を模擬注入しても、台帳から同じ会議IDを返し、再追加しない。実プロセス強制終了の測定ではない。

共有開始判定の追加5件は、全10種の開始拒否条件、データ操作とMarkdownの同時開始、取消後も保持するガードと停止待ち、終了開始後の再入防止、unwind時の解放を検査する。Tauriの実非同期ランタイムでも受信ハンドルを破棄し、ブロッキング処理の完了までデータ操作のガードが残ることを検査する。これはネイティブWebViewの実IPC切断の測定ではない。

## 全体検証

最終ソースの`make check`は終了コード0で成功した。Python 65件、フロントエンド82件、Swift 9件、Rust通常494件、AVFoundation製CAF読出し1件が成功した。Rustの11件はignoredであり、実モデル・実機測定の成功には数えない。今回追加した操作コントローラー7件と共有開始判定5件も通常検査に含む。

Swiftのユーザーキャッシュ書込み不可と、Rustテストバイナリの`__eh_frame`が16MiBを超えるリンカー警告は残る。検査は成功しているが、リリースや例外処理性能の実測成功を意味しない。`git diff --check`も成功した。

## 残る実装と実測

設定の「データと保存」、説明info、上書き確認、会議件数と容量の復元確認、進行・取消・結果表示、完了トースト、復元会議一覧と由来表示を接続する。下書き保存を待ってから選択・確定を開始し、処理中の編集操作を保護する画面側の接続も残る。

macOS WebView、実NSSavePanelとNSOpenPanel、録音・モデル準備・実書き出しとの一連の操作、長時間・容量不足・強制終了は未実測である。構築用一時領域の起動時回収と要確認状態の解決も残る。形式版2とSQLite移行27は変更していない。M3-06と実装計画全体は進行中を維持し、正式評価とWindows固有部分は引き続き保留する。
