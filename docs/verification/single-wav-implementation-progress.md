Implementation (2026-10-27):

- Normal recording keeps independent capture writes. Finalization and import publish one PCM16 mono 16 kHz WAV in bounded buffers. Playback reads that WAV at 16 kHz; ASR, diarization and embeddings pass frame ranges into the same file. No meeting PCM is copied into analysis unit directories.
- Each input is aligned to meeting time once. An absent input contributes silence independently. Only absence of every input produces silence in the mixed result. Sub-sample gaps are handled on the output sample lattice without rejecting valid captures or skipping meeting time.
- Durable output reservations bind source geometry, physical file identity, frame count and completed SHA-256. Publication validates the generated WAV before committing its reference, then retires verified originals. Cancellation, interrupted publication and cleanup are resumable. Changed registered input bytes are retained and rejected.
- Unknown tails of an interrupted prefix recovery remain recovery evidence. Publishing its verified prefix does not declare a known acquisition end or discard unregistered raw tails. The one-file guarantee applies to completed recordings/imports.
- Normal readers require the canonical commit. The old playback modes, runtime mix cache, skip-gap player and production analysis WAV conversion/copy paths are removed. Obsolete normal-stop FLAC publication tests are replaced with single-WAV publication and native-stop tests; prefix-recovery FLAC support remains capture recovery infrastructure.
- `storage/legacy_audio_migration.rs` is the removable schema-34 bridge. It snapshots SQLite before upgrading to schema 35, migrates before startup readiness, preserves published revisions/drafts/vectors/checkpoints and restarts unfinished audio flows using a new coordinator identity. Cancelled old jobs cannot resume; checkpoints remain immutable archival evidence. Normal finalization, pending publication recovery and canonical readers do not depend on the bridge.
- Retired input IDs/hashes remain provenance. Historical transcript/voice previews resolve to the canonical track without rewriting published text or content hashes. New backups carry the WAV and typed superseded-input omission evidence. The new archive magic is MONBAK02; old archives are deliberately unsupported.
- Stored generation/diarization snapshots read their original track references when validating immutable working-content hashes. Only the playback/editor view resolves references to the current WAV. Backup restoration uses the same distinction, so audio retirement does not invalidate historical snapshot proofs.
- Restore-only `backup/retired_audio.rs` checks historical job input metadata against the retained database and typed retirement evidence. It never opens retired audio or admits a job to native execution. This lets old native result JSON/checkpoints survive backups after the canonical source changes.
- Windows root permissions are applied idempotently so reopening an already private store does not invalidate descendant identity proofs used by interrupted deletion recovery.
