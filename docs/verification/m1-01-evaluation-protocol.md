# M1-01 評価条件と手順

- 更新日: 2026-10-03
- 状態: 評価基盤実装済み。Windows実機と評価音声の割り当て待ち
- 設定の正本: `evaluation/config.toml`

## 目的

M1-02〜M1-05を同じ入力と条件で比較できるようにし、実測前の目標値と実測結果を混同しない。測定結果には端末、OS、電源設定、モデル、入力ハッシュ、実行時間、最大メモリ、成否を残す。

## 必須端末

| ID | 条件 | 現在の状態 |
|---|---|---|
| mac-m1-max-local | Apple Silicon、macOS 15以降 | 利用可能。M1 Max / 32GB / macOS 27.0 |
| macos-arm64-16gb | Apple Silicon、macOS 15以降、16GB | 未割り当て。macOSの性能目標の判定に使用 |
| windows-x64-16gb | x64、Windows 11 24H2以降、16GB、独立GPU不要 | 未割り当て |

性能目標の判定には両OSの16GB条件を使用する。32GBの開発Macの結果を、そのまま16GB端末の保証値にしない。
必須端末を`available`へ変更する前に`doctor`で実測した`cpu_model`を設定の`cpu`へそのまま記入し、`power_source`を`AC`または`battery`で固定する。`power_mode`には低電力モードやWindows電源プランなどの詳細を人手で記録する。試行の開始・終了時にCPU型番・給電状態を再取得し、一致しなければ比較対象から除外する。途中の一時的な切替や低電力モード・電源プランの適用そのものはこの二点観測では証明できないため、人手レビューで確認する。

## 必須評価データ

提供者の同意を得て匿名化した、日本語中心・英語製品名や専門用語を含む会議音声を使う。最大10人、短い相づち、重複発話、明示的な決定事項、担当者・期限が明示されたToDoと未確認のToDoを含める。音声、発言単位の文字正解、話者区間、議事録正解を同じデータセットIDで固定し、SHA-256を記録する。

必須データセットは10話者とし、`contains_overlap=true`の正解話者区間に異なる2人以上の同時発話が実際にあることを構造検査で確認する。発言に話者IDがある場合、その発言時刻と同じ話者の区間が少なくとも一部重なることも確認する。正解議事録には決定事項、担当者・期限がともに明示されたToDo、どちらかが未確認のToDoを含める。英語製品名・専門用語の有無は設定で必須とし、固定した`terms.json`に少なくとも1件の正解出現があることを確認する。音声と発言正解の対応は人手でも確認する。

## 指標

| 対象 | 指標 | 判定方針 |
|---|---|---|
| 録音 | 取得成功、欠損、末尾損失、二系統の同期差、重複抑制 | 末尾損失は5秒以内が開発目標。同期・重複の閾値は実測後に確定 |
| 文字起こし | CER、WER、固有名詞・登録用語の一致率 | 用語ヒント有無を同じ音声で比較。合格値は実測後に確定 |
| 話者分離 | 時間加重誤り率、話者数、重複区間の適合率/再現率 | 重複は2人以上が同時に発話する時間区間とし、境界許容幅は現行の自動採点では0 µs。人手レビューでは境界ずれも確認する |
| 議事録 | 決定事項・ToDoの全体および種類別の適合率/再現率、ToDoの担当者・期限一致、根拠IDの適合率/再現率 | 意味が対応しても決定事項とToDoを取り違えた項目は正解に数えず、漏れと誤追加の双方に計上する。根拠IDは対応済み項目内で採点し、対応しない追加項目は項目適合率で誤りとする。不明は未確認にする |
| 性能 | 実処理時間、総待ち時間、最大RSS、ディスク使用量 | 標準は60分音声の解析30分以内、議事録5分以内が開発目標 |

## 評価手順

1. 評価前に設定を検査し、端末・データセットの未確定項目を解消する。
2. 実行記録を作り、設定ファイルと入力のハッシュを固定する。
3. 両OSでMeet（Chrome/Edge）、Zoom/Teams（デスクトップ）を、全体/アプリ選択、ヘッドセット/スピーカーで記録する。
   録音ごとに二系統の音声を `tools/mon_audio.py` で解析し、同じ校正音を両系統へ流した試験では冒頭・末尾の遅延差を記録する。Windowsでは保存マニフェストのQPC時刻で開始差を補正し、タイムスタンプエラー・不連続がある録音を同期合格にしない。
   macOSアプリ選択はScreenCaptureKitとCore Audio Tapsを別々に試し、対象外音声の混入、子プロセスの包含、権限差を比較する。
4. 4時間継続、機器切断・同一機器の再接続、明示スリープ、強制終了を個別シナリオとして実施する。
5. 同じ確定音声を標準/高精度へ入力し、初回/ウォーム実行、用語なし/ありを分けて測る。
6. 自動指標と人手確認を実行記録へ保存する。失敗や未測定を0点・合格として扱わない。
7. M1-06で標準/高精度構成、合格値、未達項目、代替案をまとめる。
