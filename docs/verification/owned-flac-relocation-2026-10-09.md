# 所有付き途中FLACの保存先変更

- 対象: M3-01、M3-07、通常録音と部分救出の途中音声
- 更新日: 2026-10-10（実装・全体検査は10月9日、結果記録は10月10日）
- 状態: 今回の通常変換再開・途中音声の削除確認範囲は全体検査成功。部分救出の移動後の再同意と変換再開、計画全体は進行中
- 正式評価・Windows固有部分・Windows CIは保留

## 今回の実装範囲

保持中のネイティブ移動snapshotから、同じ会議のDB所有セッションの変換計画、実体が一致する出力先、保存済みの実体IDが一致する途中／公開音声を収集する。元の計画とチェックポイントのバイト列はコピー時に書き換えない。元のJSONから現在の任意ファイルを採用する処理ではない。

Sourceは固定したsnapshot、Destinationはその所有付き配置からのみ生成する。どちらもJSONから構築できない。観測データの形式は別の非公開型で読み、冷起動時には選択済みbootstrapの実際の配置ロックと承認を要求する。制御記録はFLAC履歴がある場合だけ版5とし、版3・4の移動も引き続き読み戻す。端末内台帳の版4を変えず、不変な移動由来記録へ元の観測とコピー先の対応を保存する。

冷起動時には保存先・DB・元領域・移動ID・制御記録・計画とチェックポイントのSHAを照合し、コピー先の各実体IDを独立した配置台帳へ照合する。対応記録とそのSHAを改変しても配置した実体の代用にはならない。認めた対応はメモリー内の専用型とし、元の計画のSHAが一致する世代だけに適用する。汎用Storageのopenや単純なコピーからは所有対応を生成しない。

通常録音の停止後・DB登録失敗の再開では、コピーされた途中／公開FLACの実体を再検証し、新しい実体IDをチェックポイントへ同期保存してから、切詰め・再エンコード・renameを行う。変換後は全PCMを原音声の24bit量子化結果へ照合する。元のトラック・区間UUID、原音声の時刻対応と未登録状態を維持し、旧保存先の音声と記録を回収しない。複数回の移動では元の計画のIDと現在の実体を平坦な対応として引き継ぎ、古い計画を一括更新しない。

通常／部分救出の所有付き途中音声を、移動先の読み取り専用の音声限定削除確認へ接続する。元のチェックポイントの実体記録がないファイル、未知ファイル、差替えは保持する。確認だけで音声やsidecarを作成・回収しない。実際の削除には新保存先での明示確認・未登録音声への個別同意と既存の永続削除記録を要求する。JSON・ロック・部分救出履歴と旧保存先は保持する。

## 検査範囲

合成PCM・実SQLite・所有付きの実配置と切替・冷起動を通す。通常録音の同じUUIDによる再開、移動2回、予約済み未所有一時ファイルの保持、所有付き未完成本体の再エンコード、新しい実体IDの保存、汎用openでの採用拒否、音声・出力先の差替え拒否を扱う。改変してSHAを再計算した所有対応についても、独立した配置台帳のIDと一致しなければ通常Storageを開く前に拒否する。移動元の検査の取消・変換排他も扱う。

部分救出のDB保存失敗後の出力は移動先で新たに削除確認できるが、元の救出確認能力は失効させる。新しい確認・不同意では書き込まず、現在は新しい明示同意でも入力ハッシュが一致しない中断救出の再開を拒否する。この残件を成功へ置き換えない。

専用の親検査からのみ起動する子を、作成前、実体記録前、実体記録後、エンコード後、公開後の5点でSIGKILLし、所有付き移動と冷起動後に続行する。実体記録がある3点では、移動後の新実体IDを保存した直後にも専用子をSIGKILLし、次の冷起動がそのローカル記録から続行できることを検査する。実録音・電源断・Mac製品アプリ・正式評価の証明にはしない。

## 残る対応

部分救出では、同意用review hashに実体ID・世代が含まれる。移動後も新しい確認と同意を必須にしたうえで、移動元の入力内容と移動先の検証済み原音声を結ぶ証拠を追加し、古い変換結果と救出記録を安全に引き継ぐ必要がある。今回の所有対応だけで部分救出を自動再開しない。

時計上限・入力形式変更・容量不足、実モデル・残UI・配布、Mac実機・長時間検証も引き続き残る。M3-01・M3-07と計画全体の完了とはしない。
