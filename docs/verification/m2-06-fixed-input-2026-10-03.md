# M2-06 議事録生成の固定入力基盤

仕様8.2、10.8〜10.10の修正済み入力・固定根拠・編集保護に対応する保存処理を追加した。議事録の生成エンジン・画面はまだ接続しておらず、M2-06の完了ではない。

## 実装

- 現在の確定済み文字起こしと、保存済みの本文・話者名・複数話者割り当てを同一トランザクションで読む。期待する解析ID・内容ハッシュ・会議lock_version・下書きID/lock_versionを再照合し、古い画面状態の生成を拒否する。下書きのハッシュだけでなく、JSON形式と全発言・話者IDを基底版と再照合する。
- 修正を反映した `manual_snapshot / internal_snapshot` を作る。話者・発言・区間のIDは新しくし、lineage・時刻・音声トラック・認識原文・信頼度を保持する。本文と話者割り当てには手動修正を優先し、空本文と話者不明も保持する。会議名、登録日時、実際の開始日時を固定し、開始日時不明の場合は未確認のまま残す。
- スナップショットと議事録生成ジョブを原子的に登録する。モデル構成・生成設定・操作IDはジョブへ固定。ジョブ登録失敗や設定上限超過ではスナップショットと子データも残らない。同じ操作IDの再送では既存の固定入力を返し、開始後の編集を取り込み直さない。
- 公開中の現在版・直前版と下書きを変更しない。内部版は候補一覧・通常の解析プレビューに表示せず、議事録ジョブと根拠の技術的な参照先として保持する。
- SQLite移行13で内部解析の本文・話者・区間・割り当て・由来情報を不変にし、ジョブと議事録の固定入力に内部版を許可する。公開版を指す会議のheadsには内部版を設定できない。
- 版全体の内容ハッシュとは別に、生成で使用する本文・話者・時刻・会議情報の作業内容ハッシュを保存。lineageでID再対応の影響を除き、下書き版番号だけの変更で「元データ更新あり」と誤判定しない。入力読出し時に両ハッシュと由来情報を再検査する。
- 解析本文の読出しとジョブ登録を共通化した。既存の確定解析から作った議事録・ジョブも維持する。実エンジン接続前なので、生成開始RPCや利用者向けのボタンは追加しない。

## 検証

追加のRustテスト8件を実装した。

1. 修正済み本文・話者名・単一話者・話者不明・空本文の固定、新IDとlineage、区間参照、公開heads・下書きの保持、編集継続中の固定、DB再起動とジョブ再開。
2. 古い解析ID・ハッシュ・会議・lock_version・下書き版・下書きなし状態の拒否、同一操作IDの競合、過大設定のロールバック。
3. ジョブ登録失敗を注入し、内部版・全子データ・ジョブを一括ロールバック。
4. 内部版と各子テーブルのINSERT/UPDATE/DELETE拒否、内部版の公開headsへの設定拒否。SQL制約を外して本文・由来を改変した場合も、入力読出しと再送を拒否。
5. 内部版の発言IDへ根拠を固定した議事録の採用。元版の発言IDへの誤参照を拒否し、再解析採用後も固定入力・根拠・議事録ハッシュを保持。
6. v12のDBを作り、解析・下書き・従来ジョブと固定ハッシュを保存したままv13へ移行。外部キー整合と新しい固定入力の作成を確認。
7. 同内容保存・Undo・会議名変更の更新判定。空下書きの作成だけでは更新扱いにせず、開始日時不明を捏造しない。
8. 下書きJSONに異なる発言・話者IDや未対応schemaを入れ、ハッシュを再計算しても生成を拒否。

- 最終の `make check` 成功。Python 65件、フロントエンド15件、Rust通常72件、AVFoundation製CAF読出し1件。正式評価前提の不足は7警告で、合格扱いにはしていない。
- 共通の読出し・ジョブ登録を変更した後、既存の実whisper.cpp接続試験2件も成功。文字起こし候補作成と取消からの保存結果引継ぎを回帰確認した。議事録モデルの実行試験ではない。
- `npm --prefix app run tauri -- build` 成功、14.35 MiBの開発用`.app`を生成。`codesign --verify --deep --strict`成功。アドホック署名・公証なし。ネイティブ画面の統合確認は未実施。
