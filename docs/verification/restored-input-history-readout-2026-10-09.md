# 復元された録音入力履歴の読出しと診断

追加復元した録音の取得履歴・停止時診断・通知の保持不足を、DB内の不変記録から読む経路へ接続した。元の取得証拠の所有は保持し、復元先の通知受付権限にはしない。未表示通知の受付・表示確認・終了を保存する復元先の書込み台帳は残件である。

## DB所属と読出し経路

会議IDと録音IDはDBの終了済み録音行と照合する。不変記録の列がNULLの録音だけを通常録音のファイル経路へ進める。記録がある場合は、外側の所属と内側の元証拠を検査し、復元先に音声や録音らしいディレクトリがあっても取得履歴・通知台帳の代わりにはしない。診断のみの記録や破損した記録もファイル経路へ戻さない。

DB列の513KiB制限は、SQLiteで元のバイト長を調べてから文字列を取得する。読出し前後で管理領域・旧保存先の停止状態を確認し、ファイル読込み中にはSQLiteのロックを保持しない。復元記録・音声資産・元の履歴は書き換えない。

取得履歴APIは、独立して保存された元のjournalだけを返す。`ownerId`・版番号・封印状態・両入力の遷移と保持不足は元録音の値であり、復元先録音へのID付替えや現在の取得状態・報告年齢は追加しない。通知台帳の取得報告をjournalの代わりにはしない。

## 停止時診断と通知一覧

保存失敗・不正・未確定の診断を保つ。保存確認済みの診断は、独立したjournalが封印済みで、元所有IDと確定版が一致する場合だけ受け入れる。journal欠落・版違い・未封印は診断を確認できない状態にする。停止時の未確定結果は、その後に一致したjournalを読めても解消しない。旧録音の診断欠落から保存成功は作らない。

保存後通知の一覧を形式版3にし、読めない記録の`unavailable`と、診断を読めるが未表示通知の受付は未対応の`deliveryUnavailable`を分けた。後者のbatchは保持不足と履歴診断だけを返し、noticesは必ず空にする。元の受付・表示確認・終了証拠は新しい通知として提示しない。画面側は形式版1・2の読込みを維持し、形式版3の未対応状態に通知や受付処理を混在させる応答を拒否する。

既存の要確認一覧で保持不足・保存診断と「復元した未表示通知の受付は未対応です」を表示する。読み取り失敗やデータ保守後にも保持不足と失敗診断を消さず、通知の受信・表示・終了の要求を作らない。通常録音の通知受付は従来の書込み台帳を使う。

## 残件

復元先の論理所有に属する書込み台帳と、元証拠を変えない通知の受付・表示確認・終了、応答喪失時の読戻し・再起動と表示確認後の再バックアップは未接続である。診断だけの空batchを配送完了として扱わない。Mac実機の画面・通知表示・実録音・長時間検証と計画全体は進行中であり、正式評価・10話者評価・Windows固有対応は保留する。
