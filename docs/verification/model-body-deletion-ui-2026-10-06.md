# モデル本体削除の確認画面と中断後の操作

2026-10-06に、設定のモデル配置行から本体削除の確認、未登録物への別同意、中断後の再検査・続行・未開始保持を接続した。会議データとモデル構成・ジョブの履歴、現在の設定は残す。画面操作は合成IPCで25ケースを確認し、macOS WebViewと実モデル容量での統合確認は残る。M3-07全体の完了ではない。

## 削除範囲と同意

既存の読み取り専用の対象確認と、本体削除の実行確認を別のボタンにした。実行画面では、他モデル・外部の導入元・バックアップは対象外で、削除した本体をアプリ内で復元できないことを説明する。本体を失った構成は再準備まで利用できない。モデル本体を消しても会議一覧や選択中の会議は削除しない。

対象はサーバー保持の確認IDで50パスずつ取得する。ページの確認ID・位置・件数・モデル領域・SHA・登録と欠落の状態を照合し、不正な一覧では実行を止める。サーバーへ送る要求は操作トークン、確認ID、操作種別だけで、クライアントのパスや保存済み方針を削除権限として送らない。

新規確認と変更後の残り範囲への再同意では、対象と不可逆性の確認に加え、未登録パスを含める別のチェックを必須とする。未登録数にはフォルダーも含む。再検査で確認IDが変わると両方のチェックを解除し、古いページや同意を新しい範囲へ引き継がない。

保存済み範囲の続行では、記録済みの未登録物の方針を読み取り専用で表示する。未開始段階でも新規同意とは区別し、方針を変更する要求ではなく通常の続行要求を送る。変更後の残り範囲を確認する操作は、それだけでは削除も同意保存も行わない。

## 中断と応答喪失

未完了一覧は検証可能な操作と読み戻せない記録を分ける。検証できない記録に実行ボタンを与えない。開始済みの削除は保持・中止で復元したことにせず、未開始の同じ操作だけを保持できる。再同意画面には以前の処理位置と新しい範囲を別に表示する。

対象一覧は確認時に固定した計画で、現在の実在一覧ではない。処理済み表示は逆順に処理する保存済み位置に対応する。フォルダーと欠落パスも進捗に含むため、処理済みパス数を消したファイル数と表現しない。

実行要求の応答を失った場合は、同じ要求の結果確認を明示的に行う。トークン・確認ID・操作種別を差し替えず再送する。対象確認の応答喪失では状態を読み直すだけで、削除へ自動的に進まない。遅れた古い一覧は、新しい確認へ差し込まない。

成功通知は、操作とモデルに結び付いた本体削除・履歴保持の最終結果を検査してから表示する。途中進捗や不正な完了応答を成功としない。確定後はモデル配置・構成記録だけを再読込し、バックアップ成功や会議削除と取り違えない。

## 通常操作の保護

新規の確認と実行前は編集保存と音声再生の停止・解放を待つ。保存や再生解放に失敗した場合、確認・削除を開始しない。待機後には操作種別・トークン・確認ID・接続状態を再確認し、変更があれば古い同意で実行しない。

モデル操作の受付未確定・検査中・削除中は、会議削除、バックアップ、追加復元、保存先変更、編集、録音・解析などの通常操作を保護する。未完了モデル削除による書込停止も共通のロックに含め、一覧取得の失敗では変更を止める。操作状態と確認画面は設定画面のモデル一覧を閉じても失わない位置に保持する。

冷再起動後の操作を解決しても、通常書込みを再起動前に再開しない。手動再起動の案内を表示する。メイン終了の確認文はモデル本体削除専用とし、未完了対象・履歴を保持し、既に消した本体は復元しないと説明する。
