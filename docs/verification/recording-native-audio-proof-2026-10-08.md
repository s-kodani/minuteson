# 録音音声の実体検証とDB確定

2026-10-08に、macOS録音の停止後と起動時回復で、実音声を検証してからDBへ確定する処理を追加した。manifestの保存完了表示だけを採用せず、マイク・PC音声のCAF構造、全フレーム、形式とPCMの有限性を照合する。不一致なら原音声を残し、会議・音声資産・トラック・解析開始条件を保存完了へ変更しない。

## 同じファイルに結び付いた形式とハッシュ

確定済みCAFの構造を既存の読出し規則で読み、宣言されたデータ長が実ファイル内に収まり、端数フレームや未確定長を含まないことを要求する。物理フレーム数、サンプルレート、チャンネル数をmanifestの取得統計へ照合する。

同じファイル記述子で全バイトのハッシュを一度だけ計算し、浮動小数PCMは全サンプルを有限性検査する。ハッシュ読出しの境界をまたぐサンプルも検査する。整数PCMは既存の形式検査で対応するビット幅を限定し、全ビットパターンを有限な音声値として扱う。原PCMを書き換えず、全録音をメモリーへ展開しない。ハッシュ用の64KiBとサンプル検査用の約64KiBの領域を保持し、読出し前後のサイズ・更新時刻を照合する。

二系統の検証後、既存の録音セッション再照合とDBトランザクションへ進む。音声資産・トラック・チャンク、会議の保存完了と自動解析の開始条件を同じトランザクションで確定する。形式・フレーム数・PCM・保存条件の拒否ではDB登録へ進まず、修正された完全な音声を同じ中断セッションから明示的に再検証できる。

## manifestの内容と容量

manifestはハッシュ計算前に256KiBの容量上限を検査し、読込み自体も上限と1バイトまでに制限する。初回検証後に拡大したファイルも、全体を読み込まない。

解析するmanifestの全バイトは、保存する容量とSHA-256へ照合する。同じ容量で内容が変わった場合も拒否し、先に計算したハッシュと別の解析内容をDBへ保存しない。既存の形式版1、録音方式・対象PID・書込み失敗とセッション状態の検査を維持する。

録音関連の重点Rust50件は終了コード0で成功した。追加の録音確定4件と既存の保存・回復・録音優先・終了確認を含み、ログは `/private/tmp/mon-recording-proof-focused-check.log` にある。

## 残対応

録音時の共通単調時計と保存フレームの対応、補正区間の生成・DB確定は未接続である。本対応は時刻補正区間の物理境界を確認するための音声確定側の検査であり、二系統の同期精度を証明しない。録音中の部分確定、デバイス切断・明示スリープ時の欠損と回復、部分CAFの救出、Mac実機統合と4時間録音は残る。正式評価・10話者・Windows固有部分は保留し、Windows CI・MONアプリ起動・実録音は実行しない。計画全体は進行中とする。

現行のアプリは録音ヘルパーへ `--duration 14400` と `--stop-on-file` を渡し、ヘルパーは停止要求がなくても4時間の期限で停止する。DB確定にも4時間と1秒の長さ上限が残る。仕様5.6の「4時間で強制停止しない」へ合わせた終了条件と長さ検査の修正が必要であり、この音声実体検証では解消していない。
