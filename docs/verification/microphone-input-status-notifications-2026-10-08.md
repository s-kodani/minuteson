# マイク取得状態と切断復帰通知

同じマイクを再取得する処理の状態を、中央の録音画面とミニパネルへ接続した。初回接続と切断後の復帰を区別し、接続・復帰から音声の到着や保存成功を推測しない。PC音声の接続表示は開始時の確認に限定し、最新の入力レベルとCAF書込み確認を別々に維持する。

## 現在の録音への状態の接続

通常録音のヘルパーは、実際のマイク再取得状態・取得世代・中断回数・原因を、録音IDと増加する版番号を持つ `input-status.json` へ約100msごとに原子的に出力する。原因がない場合も明示的なnullを出力し、機器名・Core Audioの一時object ID・音声を通知へ含めない。報告の書込み失敗では録音を停止せず、更新の欠如を確認できない状態として扱う。

5秒テストと時間指定の測定プローブではこのファイルを出力せず、私有テストの固定五ファイルの所有・回収条件を変更しない。通常終了ではライブ状態のファイルを除去する。異常終了後に残った報告を、現在の録音状態として再使用しない。

ネイティブ側はヘルパーの起動前に保存先をディレクトリ記述子で固定する。限定したファイル名をリンクをたどらずに開き、16KiBの上限、通常ファイル、共有リンク数、読取り前後のサイズ・時刻・実体、JSONの必須項目と未知項目、録音ID・安全な整数・既知の状態と原因を照合する。同じ版の内容変更、取得世代・中断回数の逆行、停止済み取得の再開、旧世代の接続復帰を拒否する。

メインと録音ミニパネルに限定したAPIは、読取りの前後に現在の録音ID・準備中または録音中の段階・実際の子プロセスの生存を照合する。録音監視も同じ読取り結果を使い、マイクの接続フラグを開始時のtrueへ固定しない。所有または段階が変わった場合に、遅い報告で停止後の状態を更新しない。

## 報告の期限と状態確認の失敗

ネイティブ側はファイルの実際の更新時刻と経過時間を用い、同じ版の再読取りや時刻だけの更新で報告を新しくしない。画面側でも同じ版の最初の期限を保持し、RPCの待ち時間とスリープ中の壁時計の進行を数える。1秒を超えた報告は、現在の接続や復帰の根拠として表示しない。

画面の読取りは一つの所有につき一度に一件とする。確認失敗では接続表示をクリアし、録音IDの変更や停止後に返った古い応答を採用しない。機器切断、再取得中、権限・機器情報・入力形式の変更による再取得不可、確認できない状態、更新が止まった状態を区別する。別機器や現在の既定入力へ切り替える操作は追加しない。

## 通知先と要対応状態

同じバックエンドの録音所有が、中断回数と復帰を区別する通知IDを決める。メイン画面が表示中ならメインへ、そうでなければ表示中のミニパネルへ一つだけ振り分ける。両画面が非表示の場合には新しい通知先を決めない。後続のもう一方の画面からの読取りで、同じ出来事の通知先を変更しない。

通知は新しい報告にある現在の取得状態と照合して表示する。初回の接続を復帰と通知せず、古い報告から復帰成功を作らない。同じWebViewの実行中は、定期読込み、原因の変更、通知の閉鎖、設定画面からの帰還、確認失敗を挟んだ再読込みで同じ通知を再配信しない。中央画面の通知所有は録音ワークスペースの表示切替より長く保持する。

通知を閉じても、録音画面とミニパネルの取得状態は残る。ミニパネルには360×116pxの領域に収まる短い通知と閉じる操作を設け、通常の停止とメイン画面への帰還を維持する。通知は取得の中断・復帰を示すものであり、PC音声が継続していることや欠損のない保存を保証しない。

## 残る検証と対応

画面の検査は合成IPCによる製品React画面であり、Macの独立したWebView・実際のウィンドウ表示判定・機器切断の一連の動作確認は残る。全ての短い中断の履歴配信、通知の配送応答喪失、WebView再作成をまたぐ永続受付も、この段階の一度限りの配信範囲には含めない。

PC音声の取得異常と再取得、復帰しないまま停止した末尾の欠損、スリープ時計の明示復帰、入力形式変更時の音声変換または区間保存、部分CAFの救出、容量不足、異常終了回復、4時間の実機検証は引き続き必要である。正式評価とWindows固有部分は保留し、Windows CIは停止したままとする。M3-01・M3-08と計画全体を完了扱いにしない。
