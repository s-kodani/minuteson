# 議事録Markdownの生成結果保存とテキスト編集部品

2026年10月12日。[簡素化仕様](../minutes-simplification.md)に沿って、生成結果を一つのMarkdown本文として確定する保存処理と、プレーンテキスト編集の画面部品を追加した。本番の生成ワーカーと議事録画面はまだ旧経路を使う。今回の部品検査を議事録の簡素化完了や実AIの統合成功とは扱わない。

## 生成結果と人間の編集

生成開始時に現在本文の版番号とハッシュだけを固定し、完了時に同じ状態か照合する。生成中に人間が本文を保存した場合は、その新しい本文を保持して生成結果の上書きを拒否する。同じ操作の開始応答が失われたときは、既存ジョブの固定条件を検査して同じジョブを返す。開始要求と本文の照合、文字起こしの固定入力作成は一つのトランザクションで行う。

生成結果の本文更新とジョブの成功状態を同じトランザクションで確定する。本文をトリム・項目JSON化せず、生成結果のハッシュ、固定入力、完了位置、稼働状態を確認する。候補、根拠台帳、議事録下書き、編集履歴、旧本文コピーは作らない。空の生成結果は拒否し、意図的に空にした人間の保存本文は受け入れる。書込み・確定の失敗は本文と成功状態の両方を巻き戻す。

ローカル生成アダプターの出力は、通信上の枠として `markdown` 一つだけのJSON文字列を使用する。復号したMarkdown本文はそのまま返し、構造化項目や根拠の発言IDを求めない。既存の実行ファイル・モデル照合、オフライン実行、時間制限、取消処理を再利用する。このアダプターはまだ本番ワーカーへ接続していない。

## プレーンテキスト編集

プレビューと通常のテキストエリアを切り替え、同じ本文を編集する。書式ツールバーや構造化項目編集は置かない。テキストエリアはプレビュー中も保持し、切替時に別の編集欄へ作り直さない。入力だけでは保存せず、「保存」または保存ショートカットで明示保存する。

保存失敗、成功応答だけの喪失、保存待ち中の追記を保持する。同じ保存の再試行は元の操作ID・本文・基底状態を使い、後から入力した本文を勝手に保存しない。Markdown中の再生区間は小数秒を保持したコールバックへ渡す。検証画面では合成コールバックだけを使い、音声は再生しない。
