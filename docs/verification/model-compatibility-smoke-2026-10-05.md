# モデルのCPU互換性確認

2026-10-05に、手動配置したモデルを利用者の確認後に実行するCPU互換性確認を追加した。対象はwhisper.cpp・sherpa-onnx・llama.cppで、既存の推論アダプターを使用する。今回の実装検証は合成モデルとシェル製の模擬エンジン、ブラウザーの模擬IPCによるものであり、実モデルの読み込み成功や品質を実測した記録ではない。

## 実行前の確認と固定条件

事前検査とコピーは従来どおり実行ファイルを起動しない。配置記録の「互換性を確認」からだけ、新しい操作IDで試行する。画面の確認ダイアログで、取り込んだ実行ファイルを利用者の権限で起動すること、配布元とライセンスを利用者が確認すること、ファイルやネットワークへのアクセスを隔離しないことを明示した。申告エンジン版はmanifestの値であり、実行ファイルから版を検証した値ではない。

3種類ともCPU・1スレッドとする。whisper.cppは16kHz・モノラルPCM16の10秒無音を日本語・非翻訳で処理し、JSON形式とモデル・言語の一致を検査する。sherpa-onnxは同じ無音を人数自動・CPUで処理し、固定モデルとクラスタリング条件の応答を検査する。llama.cppは文脈2048・生成上限64・GPU層0・seed42で、固定入力とschemaから `{"ok":true}` を生成する。無音に対する空の認識・話者区間は認める。意味のある音声認識や話者数・議事録品質を検証する試行ではない。

実行前後に配置済みmanifestと全記載ファイルの容量・SHAを再照合する。推論の待ち時間は120秒を上限とし、前後のファイル照合時間は別である。アダプターへの環境変数は初期化し、固定PATH・LANGなど必要な値だけを渡す。ただし、任意の実行ファイルを安全に隔離する仕組みではない。

## 結果の永続化と再試行

SQLiteのv24移行で端末固有の試行表を追加した。実行前に対象パッケージ・構成ハッシュ・操作ID・アダプター版と未完了状態を確定し、結果は成功・失敗・取消のいずれかへ確定する。成功時には固定条件、入力・出力・ログの容量とSHA、所要時間を含むJSONとそのSHAを保存する。完了行の書換えをSQLトリガーで禁止し、読込時にも条件と対象の整合を検査する。

アプリデータ領域の `model-checks/<操作ID>` は新規作成限定の専用領域で、途中ログも保全する。成功した同じ操作IDを再照会すると、配置ファイルと保存済み証拠を再照合して結果を返し、実行しない。失敗・取消を再実行するには新しい明示操作が必要である。過去の操作の応答で新しい試行の状態を上書きしない。

再起動時の未完了試行は中断として記録し、モデル・ログを削除せず、自動実行しない。既存会議・解析ジョブ・設定・プロファイルは変更しない。端末内のパッケージ状態が成功になっても、画面のAI準備完了フラグはfalseのままとし、「CPU互換性確認済み・プロファイル未適用」と表示する。失敗は今回の固定試行の失敗であり、恒久的な不適合を証明しない。

試行中は共有モデル準備ガードとDBの未完了状態を使用して、解析・録音・取り込み・バックアップとの排他を維持する。取消時は既存のアダプターが直接起動した子プロセスを終了・回収してから結果とガードを確定する。これは直接の子プロセスに対する保証であり、任意の実行ファイルが作成する孫プロセスの隔離・終了を保証しない。端末固有の試行表・入力・出力・ログは持ち運びバックアップに含めず、別端末での利用可能性の証拠にしない。
