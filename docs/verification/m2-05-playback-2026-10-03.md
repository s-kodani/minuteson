# M2-05 編集保存・音声再生の接続（2026-10-03）

正式品質評価ではなく、保存済み音声を発言から確認する実装経路の検証。実際の会議録音、macOS WebView経由の音声出力、4時間の長時間再生、Windowsは未検証。

## 実装と自動検証

- 編集保存は最新入力と保存済み版を分離した逐次キューで処理する。保存中の追加編集、保存前の会議切り替え、保存失敗・明示再試行、元に戻す入力、画面破棄後の解除をフロントエンド5件で検証。
- メインの通常終了は未保存編集の保存を待つ。録音中のウィンドウ閉鎖は非表示のみ。明示終了では録音停止・保存を待つ。保存失敗・60秒の待機上限到達時は終了要求を取り消す。Rustウィンドウイベントとの実機統合は未検証。
- 再生要求は会議ID・確定解析版ID・発言IDから元トラックと管理ファイルを解決する。任意のパスをUIから受け付けない。SHA-256、ファイル長、CAFの形式・フレーム数とDB記録を照合し、再生中もサイズ・更新日時を照合する。
- CAFのPCM（32/64-bit float、16/24/32-bit signed integer、両エンディアンと整数の高位寄せパディング）をfloat32へ変換する。未確定データ長、非有限値、破損ヘッダー、未対応形式は拒否する。録音プローブの保存形式を対象とした実装であり、一般の圧縮CAF対応ではない。
- 1要求65,536フレーム、最大8チャンネルをバイナリで転送し、UIは最大3パケットをWeb Audioの時計で予約再生する。全編のPCMをメモリに載せない。トラックの欠損・重複セグメントを無音で補わず、時刻補正済みトラックは接続完了まで明示的に拒否する。
- ネイティブ7件の追加テストは、PCM変換、読出し制限、変更検出、版・会議の境界、セグメント境界、欠損・時刻補正の拒否、外部シンボリックリンクを検証。
- AVAudioFileとAVAssetWriterが生成したCAFの全4,800フレーム×2チャンネルを期待波形と照合。両保存方式とも全サンプルが許容誤差1e-6以内。`make check-caf-playback`で固有の一時ディレクトリへ合成素材を生成し、Rustの統合テストを実行して生成物だけを整理する。実録音権限は使用しない。
- フロントエンド7件の追加テストは、パケット形式、チャンネル順、3パケット上限と連続予約、一時停止と速度変更、読出し中のシーク、エラーと再試行、古い終了通知、末尾シークを検証。

`make check`はPython 65件、フロントエンド12件、Rust通常43件と上記CAF統合1件に対応。Swiftフォーマット、プローブ・フロントエンドビルドも通過。必須評価端末・10話者素材の不足に関する7警告は残す。

`npm --prefix app run tauri -- build`で今回の変更を含むmacOS `.app`を再生成し、親アプリと同梱プローブの`codesign --verify --deep --strict`に合格。アドホック署名・公証なしの開発用成果物であり、この確認だけではmacOS上の画面操作や配布可能性は証明しない。

## ブラウザでの操作確認

Playwright CLIとViteを使用。`app/tests/browser-fixture.js`がTauri公式のIPCモックを設定し、通常のReact画面を起動する。アプリの本番エントリーポイントには含めない。会議内容は作成した模擬テキスト、音声パケットは無音PCM。実音声やユーザーの会議DBは使用しない。

確認した操作:

1. 会議Aを開き、発言から15秒の音声再生を開始。実AudioContextで再生位置が進み、チャンクが順次要求される。
2. 2倍速、一時停止・再開、スライダーのHomeとArrowRightを操作。ArrowRightで4,800フレーム（0.1秒）の位置へ移動。
3. 本文編集後に保存エラーを返し、会議Bへの切り替えが拒否され、会議Aと編集本文が保持されることを確認。
4. 同状態で`main-close-requested`を送り、`finish_main_close`が呼ばれないことを確認。
5. 保存の再試行が成功し、保存済みへ戻ることを確認。会議Bへの切り替え後、編集画面が破棄される。保存済みでの終了要求は`finish_main_close`へ進む。
6. 音声準備時のハッシュ不一致を模擬し、再生エラーが画面に表示されることを確認。

文字起こし編集領域のスクリーンショットを`output/playwright/transcript-audio.png`へ保存して目視確認した。検証生成物はGit管理外。開発サーバーのfavicon 404とブラウザのローカルネットワーク制約によるVite HMR WebSocket失敗は発生したが、今回の画面操作・HTTPモジュール読込には影響せず、アプリ由来の未処理例外はなかった。

再現時は`npm --prefix app run dev -- --host 127.0.0.1`を起動し、Playwrightのルート置換で`index.html`の`/src/main.tsx`を`/tests/browser-fixture.js`に変更して再読み込みする。`window.monBrowserFixture`で保存・再生の失敗を指定し、要求履歴を確認できる。

## 未検証・残件

実録音の権限・同期・エコー・欠損、macOS WebViewからのIPCバイナリと音声出力、長時間時の初回ハッシュ検証待ち時間、時刻補正済みトラックの再生、文字起こし・話者分離ワーカーとモデル導入は未完了。各発言の準備時に参照ファイル全体をハッシュ検証するため、長い録音での操作性能を保証しない。Windows固有処理、正式評価、10話者・16GBの合否はユーザー指示により保留したまま。
