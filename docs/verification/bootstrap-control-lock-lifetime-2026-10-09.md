# 起動設定ロックの所有者終了時の解放

起動設定の排他ロックを、取得に成功した所有者の終了時に明示解放する。子プロセス起動前の一時的な記述子継承が残っていても、終了した所有者のロックだけで次の正規起動を拒否し続けない。設定・ロックファイルの削除や、排他取得の省略は行わない。

## ロックの取得と終了

`O_CLOEXEC` は実行ファイルへの切替時に記述子を閉じるが、継承から切替までの間には複製された記述子が残り得る。共有する開いたファイル記述が残る間は、元の `File` を閉じるだけではロックが解放されない。

`BootstrapLock` は排他取得の成功後だけ作成し、所有者の他のフィールドを終了した後に `unlock` する。取得に失敗した呼出しは解放用ガードを作らず、既に実行中の所有者のロックを解除しない。取得後の初期化エラーでもガードが解放を担う。ロックの実体・権限と初期化記録の検査は維持する。

## 複製記述子を使う回帰検査

合成のロックファイルを使う対照検査は、通常の `File` を閉じても複製が残れば別の記述子から再取得できず、明示解放後は取得できることを確認する。続いて実際の `Bootstrap` のロック記述子を複製し、実行中の重複起動拒否、所有者終了後の再取得、古い複製の閉鎖後も新所有者の排他維持、起動設定バイト列の不変を検査する。

## 全体検査で確認した失敗

修正前の全体 `make check` は終了コード2となり、通常Rust1,620件成功・1件失敗・専用60件ignoredだった。失敗はモデルの元配置と同意を保持して複数回保存先を移動する検査の、起動設定再取得時のロック競合である。同じ修正前バイナリによる単独再実行は成功したため、単独成功を全体成功の代替にはしない。最初の全体ログは `/private/tmp/mon-input-transfer-full-check.log`、単独ログは `/private/tmp/mon-input-transfer-move-failure-repro.log` に保持する。

記述子の複製による検査は継承前後のロック寿命を対象とする。製品アプリ起動・実録音・Mac実機の再起動操作・電源断を証明するものではない。正式評価とWindows固有部分は保留を維持する。

## 修正後の重点検査

対照検査と新しい所有者終了の回帰検査、実際の子プロセスによる排他取得拒否とSIGKILL後の再取得を含む起動設定の重点19件が成功した。形式検査も成功している。ログは `/private/tmp/mon-input-transfer-bootstrap-lock-focus-final.log` に保持する。全体再検査はこの重点成功と区別して扱う。
