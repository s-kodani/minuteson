# 音声だけのファイル削除と中断後の続行

2026-10-06に、保存済みの音声専用同意に結び付くファイル処理を内部接続した。登録音声・確認した既知の残り音声・解析PCMだけを処理し、文書・文字起こし・編集履歴・根拠・manifest・結果ファイルと親フォルダーを保持する。ファイル処理が終わっても保守中のままとし、音声利用不可判定の確定前に通常操作へ戻さない。M3-07と実装計画全体は進行中である。

## 同意と処理範囲

[同意保存と未開始保持](audio-only-deletion-consent-2026-10-06.md)の厳密な読戻しを使用し、元の同意時刻・方針・対象証拠を変更しない。表示用分類から実行許可を作らず、保存済み観測から同じ音声対象を導出する。分類できないファイル、登録された非音声、既知の解析結果とログは保持する。外部原本・外部書き出し・隣の会議は開かず、削除対象にしない。

開始時は実際の共有lease、保存領域とDBの実体、会議と全依存データ、音声以外を含む全管理ファイルを再照合する。保持文書の編集、別の未完了操作、取消済み所有者、開始済み・保持済み記録では新しい同意として採用しない。予約名の衝突を拒否し、登録音声の移動で増える観測1件を安全上限内に収められない場合は開始しない。

## 予約と削除の手順

音声専用の版2進捗に、元の確認ハッシュ、処理位置、移動前・予約後の実体を保存する。進捗は正規JSON・4KiB以内とし、対象外カーソル、未知フィールド、欠落音声の移動、異なる確認ハッシュ、不正な段階遷移を拒否する。原本名を直接unlinkせず、移動前の実体を保存してから同じ親の `.mon-delete-audio-操作ID-位置` へ上書きしない移動を行う。移動後の実体と内容を照合・保存し、予約名だけを削除してから処理位置を進める。

各境界で全体のファイル観測と依存データを再照合し、不可逆操作の直前にもDB・保存領域と共有leaseを確認する。登録音声が消えた元パスは、登録行を保持した欠落として照合する。移動・削除で変わる直接の親の日時・容量だけを許容し、親の実体・権限、正確な名前の一覧、保持ファイルの実体・内容は照合を維持する。フォルダー自体は削除しない。

予約後に停止した場合は同じ予約実体だけを続行する。予約後の削除と処理位置の確定の間で停止しても、保存した予約証拠がある欠落だけを処理済みとして進める。元から欠落していた音声は再作成せず、二重に数えない。元パスの再出現、予約音声の変更、未確定移動対象の消失、文書や未知ファイルの追加・変更・消失、リンク・共有ハードリンク・親や保存領域の置換では対象を保持して停止する。変更物を別同意なしに採用しない。

## ファイル処理後の保護

ファイル処理完了は `cleanup` 状態と `audioFilesRemoved` 段階で保存し、操作全体の完了とは区別する。音声資産・トラック・chunk・由来・文書・下書き・根拠・ジョブの行は変更せず、保持範囲の指紋を維持する。通常SQLと解析・取り込み等の開始を停止したまま、再起動でも通常回復を保留する。未開始保持へ戻したり、消した音声を復元したと表示したりしない。同じファイル処理の再送でも残った範囲を再照合する。

## 検証範囲

一時Storage・SQLite・合成音声と文書、実際の共有leaseだけを使用する。利用者の録音・モデル・マイク・アプリ設定には触れず、画面・ネイティブAPIや実機の音声削除を検証したとは扱わない。

## 残件

履歴を保持した音声利用不可判定と操作完了の確定、音声欠落後の再生・新規解析・固定条件の再試行・キャッシュ再利用の制限、バックアップ・追加復元を接続する。完了済み音声削除の起動時確認はモデル削除と区別した型付き検査を設ける。残り・変更・再出現範囲への別同意、共有操作コントローラー・メイン専用API、編集保存と再生トークン解放を待つ確認・回復画面、実機統合も残る。現在の内部処理は保守中のまま安全に停止するが、音声専用の一覧と回復画面には未接続である。正式評価・10話者・Windows固有部分は保留し、Windows CIの停止を維持する。
