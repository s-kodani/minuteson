# 保存先配置ロックの所有終了と解放

2026-10-08に、保存先移動の配置台帳について、SQLite接続を閉じてから所有者のOSロックを明示解放するガードを追加した。所有者が生きている間の取得拒否、配置台帳・ロックの実体検査、別操作の台帳保護は維持する。ロックファイルを削除したり、取得失敗を無視したりしない。

## 所有者の破棄後に残るロック

通常の `make check` の先行実行では、再移動テスト1件が配置台帳のロック取得に失敗した。同テストの単独実行と関連70件の並列実行は成功し、元の失敗時に記述子を保持していたプロセスは特定していない。

複製されたファイル記述子を保持する追加テストでは、配置所有者を破棄しても、次の所有者が同じロックを取得できない現象を確実に再現した。修正前のログは `/private/tmp/mon-placement-retained-lock-red.log` にあり、追加1件が同じロック取得エラーで失敗している。

Rustのファイルロックは、複製・継承された記述子がすべて閉じるか、明示解放されるまで維持される。元の記述子だけを閉じる処理では、並行する子プロセス起動のexec前に継承記述子が残る場合、所有終了後のロック取得を妨げる可能性がある。[Rust Fileのロック規則](https://doc.rust-lang.org/std/fs/struct.File.html#method.try_lock)

ガードは取得成功後にのみ作り、所有者内ではSQLite接続より後に破棄するフィールドとする。エラーで構築を中断した場合も、後から作ったSQLite接続が先に閉じる。解放失敗時は元の記述子を閉じる従来の処理へ戻り、別の記述子・別所有者のロックを探して解除しない。

## 自動検査

追加テストは、生きている所有者に対する取得拒否、複製記述子を保持したまま所有者を破棄した後の再取得、古い複製記述子を閉じても新しい所有者の排他が続くこと、その新所有者を破棄した後の再取得を検査する。合成の一時保存先だけを使い、実会議・利用者の保存先は操作しない。

同じ追加1件は修正後に終了コード0で成功した。ログは `/private/tmp/mon-placement-retained-lock-green.log` にある。先行した関連70件の成功だけで修正後の全体成功とは扱わず、最終ソースの通常の全体検査を実行している。

## 残対応

Mac実機の保存先変更・再起動・中断回復、電源断、元データへの別同意を伴う削除の統合確認は残る。正式評価・Windows固有部分は保留とし、Windows CIを実行しない。計画全体は進行中である。
