# ネイティブテストのキャッシュ抑制

大きなRustテストを繰り返し構築しても増分キャッシュとデバッグ用オブジェクトが蓄積しにくいよう、テスト専用プロファイルを調整した。通常の開発・リリースプロファイルは変更せず、Rustのassertと整数オーバーフロー検査は維持する。

## テスト専用設定

`app/src-tauri/Cargo.toml` の設定は次のとおりである。

```toml
[profile.test]
strip = "symbols"
debug = 0
incremental = false
codegen-units = 256
debug-assertions = true
overflow-checks = true
```

デバッグ情報を残す設定では、増分ビルドを無効にしても、アプリのテスト用 `.rcgu.o` が約6GiB残ることを確認した。今回のテストはデバッグ情報も無効にし、デバッガーと行番号付きバックトレースには制限がある。テストの最適化水準は0のままとし、除外・検査の無効化・失敗の自動再試行は追加していない。

非増分ビルドで分割数を明示しなかった構築は、arm64リンカーの `B/BL out of range` で失敗した。分割数256を明示した構築は成功した。非増分時の既定分割数と各設定の意味は[Cargo Bookのプロファイル仕様](https://doc.rust-lang.org/cargo/reference/profiles.html)に従う。大きなunwind情報についての既存警告は残る。

## 全体検査と生成物の整理

最終設定を通常の `make check` で使用し、終了コード0を確認した。Rust通常1,184件、フロントエンド174件、Python65件、Swift9件とCAF読出し1件が成功した。環境依存11件と親試験から実行する子プロセス専用21件の区分を維持する。ログは `/private/tmp/mon-audio-renewal-final-check1.log` に保存した。

最終テスト実行ファイル `mon_desktop_lib-20be98c08aea95a9` は927,681,584バイトだった。この構築では同名プレフィックスのデバッグ用 `.rcgu.o` は残らず、増分ディレクトリは0バイトだった。ビルド・テスト終了後、旧デバッグ設定と失敗した構築に由来する `target/debug/deps` 直下の再生成可能な `.rcgu.o` を整理した。整理後も最終実行ファイルの `--list` は成功し、1,216テストを列挙した。

整理後の `target` は約4.8GiBで、依存ライブラリ・最終テスト実行ファイル・配布用アプリを保持する。生成物の整理ではソース・録音・モデル・利用者設定を変更していない。削除済みのデバッグ生成物は再構築で再生成できる。将来の通常開発ビルドや失敗した構築のすべてに容量上限を保証する設定ではない。
