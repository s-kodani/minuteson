# 終了済み録音の入力通知と履歴診断の画面接続

終了済み録音の未表示通知を、メイン画面の起動時と録音終了後に取得する経路へ接続した。会議の選択とは独立して巡回し、マイクとPC音声の中断・復帰を過去の録音の出来事として表示する。現在の機器接続・音声取得・保存成功を示す表示ではない。ミニパネルと録音確認画面は保存後通知を取得しない。

## 履歴の読込みと通知の確認

DB所有の録音を32件ずつ読み、末尾の後に先頭へ戻る。前の位置より小さいIDの録音が後から終了しても、次の巡回で取得する。一度に一つの一覧要求だけを実行し、応答待ちで同じ読込みを重ねない。画面内の所有者は最新利用順で128件に制限し、取得履歴も配送台帳もない旧録音には新しい画面内台帳を作らない。

保存後の配送版、イベント番号、受付世代、固定した状態と表示確認を照合する。ライブ取得報告や取得履歴の版番号とは比較しない。状態のない投影を挟んでも同じイベントの内容や確定済み受付を変更せず、受け取った値や画面への読出し値の変更で履歴の照合基準を上書きできない。

受付、実表示、終了は既存の順序付き通知キューで分ける。受付の操作IDとネイティブの読戻しを照合し、受付成功だけでは表示済みにしない。モーダルの背後、透明、画面外、表示上限で待機している通知は実表示を確定しない。確認済みの中断通知を閉じてから、同じ入力の復帰通知へ進む。

画面再作成時の未表示イベントは新しい受付世代に引き継ぎ、旧画面の遅い応答を拒否する。所有者の解放・会議削除では対応するトーストを解消し、解放後に届いた応答を新しい所有者へ適用しない。「会議を開く」は編集保存を伴う通常の会議移動へ接続し、録音・音声再生・再解析は開始しない。

## 読込み失敗と保守中の表示

配送期限には一覧要求からの経過時間を加える。最後の読込みから1.5秒を超えた通知は表示を止め、遅い応答で期限を新しくしない。読込みの応答待ちと失敗、通知処理の結果確認待ちを別々に案内する。失敗しても未完了の受付枠と履歴の照合基準を保持し、古い受付応答だけで表示を再開しない。

バックアップ・復元・削除などのデータ保守中、保存先変更後の再起動待ち、アプリ終了手順中は配送を止める。停止前に始めた一覧の応答を、保守後の新しい読込みとして採用しない。再開後は新しい一覧の読込みを必要とする。録音や解析の実行だけを理由に保存後通知を停止する構成ではない。

取得履歴の欠落・照合不能、入力別の通知保持不足は会議ごとの要確認一覧に残す。通知を閉じても診断を解消せず、欠損範囲や保存成否は別の音声情報で確認する。一覧は16件ずつ表示し、会議詳細では高さを制限して編集領域を保持する。診断がない空の領域は非表示にして、編集領域の高さを削らない。
