# 録音入力履歴の保存診断

録音入力履歴の書込み待ち・失敗・整合不良を、マイクとPC音声の取得状態、PCM入力レベル、音声ファイルの保存結果と分けて画面へ接続した。停止時に履歴の保存が未確定だった場合も、終了済み録音の要確認一覧に残す。通知を閉じても診断を解消しない。

## 録音中の書込み確認

録音側の履歴ライターから、要求した版と書込み確定済みの版、待機・失敗・整合不良・確定、終了状態を短いロック内でコピーする。ファイル読込みや書込み完了待ちを追加せず、音声のコールバックを待たせない。失敗後の新しい書込みが確定した場合だけ、ライターの失敗状態を解消する。

通常録音の `input-journal-status.json` は独立した形式版1の報告である。取得報告・履歴ファイル・通知配送の版番号と大小を比較しない。報告の更新そのものは履歴や音声の保存確定ではなく、保持したライター結果のコピーにすぎない。既存の取得報告・履歴・配送台帳の形式は変更しない。5秒テストではこの報告を作らず、通常録音終了時に一時報告だけを除去する。

報告の作成・更新・終了時の除去も、開始時に固定したディレクトリのファイル記述子を使う。既存ファイルを採用せず、排他的に作成した実体とサイズ・更新時刻を更新前後に照合する。途中で祖先ディレクトリや報告ファイルが差し替わった場合は、別のファイルを上書き・削除しない。診断報告の更新は同期保存の証拠ではないため、履歴の同期書込みとは区別する。保持する取得履歴は引き続きファイルとディレクトリの同期を必要とし、一時報告の除去処理では削除しない。

ネイティブAPIはメインとミニパネルに限定し、実際の録音所有と子プロセスを読取り前後に照合する。共有データ保守の開始排他を読取り処理の終了まで保持し、録音制御・子プロセスのロックをファイル処理中に保持しない。録音前に固定したディレクトリから許可した名前だけを読み、リンク・外部所有・容量超過・読取り中の変更、別録音の報告、重複した既知項目を拒否する。

画面は接続状態と独立して診断を読み、一度に一つの要求だけを実行する。要求開始からの経過と報告年齢を加え、1秒を超えて止まった報告を新しい結果にしない。同じ報告版の内容変更、履歴の要求・確定版の逆行、終了状態と整合不良の巻戻しを拒否する。読込み失敗では以前の書込み失敗を保持し、新しい確定報告を確認するまで解消しない。別録音へ切り替えた後の遅い応答は採用しない。

メイン画面の通知と要対応状態は別に保持する。ミニパネルは下段に短い保存診断を配置し、上段の接続状態・タイマーを保持する。詳細には音声の取得・保存結果とは別の診断であることを明示する。初回報告待ちの短い時間には警告を作らず、1秒以上の応答待ちは確認不能として案内する。

## 停止後の診断

停止時の限定待機が未確定なら、既存の `inputEventJournalError` と構造化した `inputEventJournalPersistence` を最終manifestに保持する。履歴側の失敗だけで音声側の保存状態を失敗へ変更しない。待機上限の後に書込みが完了しても、その停止時の未確定エラーを成功へ書き換えない。

終了済み録音の一覧形式版2に、配送台帳とは独立した保存診断を追加した。DB所有の終了済み録音から固定したディレクトリ内のmanifestを読み、録音所有、終了状態、閉じた保存結果、容量と実体を照合する。確定を示す構造化結果は、実際の封印済み履歴と確定版が一致することも必要とする。異常終了などで未封印の履歴だけが残った場合は未確定とする。

診断は短い分類にして、任意のエラー文やパスを画面へ渡さない。配送台帳がない録音にも保存診断を表示する。旧形式の診断欠落を保存成功に変換せず、旧APIで項目が省かれても、画面内の既知の保存失敗を解消しない。通知の表示確認や閉鎖も診断の解消条件ではない。
