# モデルのプロファイル適用画面の検証

- 日付: 2026-10-05
- 対象: M2-02 / M3-06のモデル構成操作
- 前提: [モデル適用基盤](model-profile-application-core-2026-10-05.md)

設定画面から、CPU互換性確認に成功した配置モデルを標準または高精度へ適用する経路を接続した。変更するファイルパスと維持する解析条件を表示し、明示確認後にネイティブの原子的保存を呼び出す。今回の画面検証は模擬IPCによるブラウザ操作であり、実モデル・macOS WebView・実会議の品質と速度の確認ではない。

## 利用者向けの操作

モデル配置記録ごとに、標準／高精度への適用内容を確認できる。最新のCPU確認が成功していないモデル、構成の読込に失敗している状態、録音中、他のモデル準備処理中は確認開始を抑止する。保存直前のモデル・試行証拠・設定版の照合と競合拒否はネイティブ処理で行う。

確認ダイアログには、モデル名・版、構成の変更前後の版番号、全ファイルパス、スレッド数・GPU・閾値・コンテキスト・生成予算等を表示する。ファイル以外の値を変更する応答は表示前に拒否する。CPU試行条件と通常解析条件が異なること、通常条件での互換性・品質・速度が未評価であることを示す。モデル適用そのものではエンジンを起動しない。

適用後は対象エンジンの解析設定と、配置・構成記録を再読込する。会議画面の解析・話者分離・議事録の設定は、設定画面から戻った際に再マウントしてDBから読む既存の経路を使う。既存の固定ジョブや同条件の再試行は変更しない。音声取り込みの設定も、音声を選ぶ際の既存の再読込経路を維持する。

構成記録では、選択済みエンジン・不足エンジンと、現在の解析設定・最新CPU成功記録との不一致を表示する。配置記録だけに「プロファイル未適用」と表示する以前の文言は廃止し、実際の構成記録を参照する表示に変更した。三つのエンジンの保存構成が一致しても、実行準備・ファイル健全性・品質を保証する表示にはしない。

## 取消と結果が未確定の場合

保存の応答を失った場合は確認内容と操作IDを保持し、利用者が同じ操作で結果を確認できる。新しい操作IDで自動再送しない。閉じるボタンも「適用せず」と断定せず、構成記録の確認を促す。確認後に条件が変わった場合はネイティブ処理が拒否し、内容の再確認が必要になる。

取消要求だけで操作を再開せず、処理の応答と記録の再読込を待つ。取消と保存確定が競合する場合があるため、取消要求後の遅い成功応答で保存成功のメッセージを出さず、確定した構成記録の確認を促す。画面を離れた場合も処理へ取消要求を送り、以前の画面の遅い確認結果を表示しない。

保存成功が確認できた後に解析設定の再読込だけが失敗した場合は、保存自体の失敗・巻き戻しとは扱わない。保存成功と現在設定の読込未確認を分けて表示する。

## 検証した範囲

フロントエンドの追加テスト8件で、適用対象の資格、構成記録の役割・状態、標準／高精度・モデル・確認操作・現在版との結び付き、数値条件の維持、適用結果と解析設定の読込を検査した。

最新版の`make check`は終了コード0で成功した。Python 65件、フロントエンド77件、Swift 9件、Rust通常437件（11件はignored）、AVFoundation製CAF読出し1件が成功した。ネイティブの実モデル試験がignoredであることを合格には算入しない。今回の変更は画面・状態検査・開発用fixtureと記録であり、DB形式やネイティブ適用処理は変更していない。

[開発用の模擬IPC](../../app/tests/model-profile-browser-fixture.js)を用いたPlaywrightのブラウザ操作では、次を確認した。このfixtureは製品コードから読み込まず、モデルファイル・録音・ネイティブエンジンを使用しない。模擬DBの書込はネイティブ保存テストの代わりにはならない。

- 確認せず閉じる操作で適用APIを呼ばず、元のボタンへフォーカスが戻る。
- 標準に三つのエンジンを順に適用し、高精度も独立して適用できる。スレッド数・GPU等をCPU試行条件へ上書きしない。
- 競合時は構成版を増やさず、保存後の応答喪失では同じ操作IDで結果を確認して二重の構成版を作らない。
- 書込前の取消では構成が変わらない。保存が先に確定する競合では取消成功と断定せず、処理終了まで待って現在の構成を表示する。
- 改変された確認応答を表示せず、構成読込失敗時は適用確認を抑止する。保存後の設定読込失敗を保存失敗と誤表示しない。
- 画面を離れた後の遅い確認応答を表示せず、取消APIを対象の操作IDで呼ぶ。再表示・ブラウザ再読込後に模擬保存した構成を読み直す。
- 1440pxと760pxで長いパスの折り返し、表、モーダル表示を確認。初期フォーカスを見出しに置き、先頭から表示する。760pxでダイアログの横方向のはみ出しはない。
- 適用経路から互換性確認や解析開始のAPIを自動呼出ししない。

画面画像はGit管理外の`output/playwright/model-profile-application-wide.png`と`output/playwright/model-profile-application-narrow.png`に保存して目視確認した。Viteの開発用WebSocketが切れた際はブラウザを再読込し、最新版の見出しフォーカスと日本語ラベルを確認した。画面検証用ブラウザとViteサーバーは終了済みである。

## 残件

画面検証後の追加実装で、管理パッケージID・構成版を新規ジョブと自動解析計画へ固定し、適用後のモデル変更を開始・実行境界で拒否する処理を接続した。使用した構成のモデルなしの復元・再バックアップも検査した。範囲と制限は[ジョブ固定条件の検証記録](managed-model-job-binding-2026-10-05.md)を参照。通常条件での実モデル統合試験は未実施である。

ジョブで使用していない配置パッケージのメタデータ・プロファイル全体の構成の持ち運び、復元後の再配置・再結合と明示再試行、ダウンロード、途中配置の回収操作、実機での録音開始・終了との統合確認も残る。正式評価とWindows固有部分は保留し、Windows CIは再開しない。
