# 新規録音・録音中画面のコンパクト化（2026-10-25）

## 変更

- 最大936pxの外側カードに設定を集約し、内側のカード枠と重複する説明を削除。
- マイク／PC音声、話者数／入力確認を2列で配置。PC音声の範囲と対象アプリはインラインで選択し、重複する「録音の詳細設定」を撤去。
- 録音中は会議名とタイマーを同じ行に配置。入力・接続・入力レベル・書込みを2行の表に統合し、保存状況は同じ取得結果から表示する。
- 録音画面内のタイマー・戻る・開始／終了操作の重複を整理。他画面の共通録音操作は維持。
- 5秒テストの進行状況・試聴・取消・再テスト・一時音声の破棄を専用ダイアログに移動。閉じる操作は試聴を停止するが、テスト実行や結果は保持する。
- 幅760px以下は1列へ変更。警告・長い名称・小さい画面では縦スクロールを許容し、情報を隠して高さを固定しない。

## 検証

単体テストは `node --experimental-strip-types --test tests/*.test.ts`（appディレクトリ）で786件成功、失敗0件。専用ネイティブIPC fixtureを必要とするWindowsモデル選択の1件は既定どおりスキップ。

`tsc --noEmit` と `vite build` に成功。Viteは既存依存sonnerの `use client` と500kBを超えるチャンクの警告を出力する。

Chromeのヘッドレスブラウザーと本番Reactコンポーネント、既存の模擬IPCを使用。以下9本、合計111ケースが成功し、JavaScriptのpageerrorは0件。

新規録音の全体取得・アプリ指定、および通常の録音中画面は1280×720／1366×768のライト・ダーク双方で、カード全体と主要ボタンがスクロールなしで収まることをスクロール領域の寸法と画像で確認。960px・360px幅で横方向のはみ出しや操作欠落がないことも確認した。

テストダイアログの確認項目は、開始前の同意、二重送信防止、閉じる／再表示による結果保持と試聴停止、フォーカス復帰、明示的な再テスト・取消・破棄。既存ケースで応答喪失、取得対象の終了・再起動、再生準備取消、回収失敗、入力・書込みの鮮度切れも確認した。
