# 終了済み録音の入力履歴と通知台帳の保存先移動

終了済み録音の入力履歴・通知台帳・停止時の保存診断が、所有を確認した保存先変更と再起動後の読込みを越えて保持されることを確認した。移動前の通知受付は移動後の権限にせず、未表示通知だけを新しい受付世代へ引き継ぐ。

## 移動と通知の検証範囲

実際のBootstrapとStorageを使い、コピー・配置・起動設定の切替・元Storageの書込み停止・冷起動後の保存先承認を通す。表示確認を保存した場合と、受付だけを保存した場合の2通りで、それぞれ2回の保存先変更を行った。1つのRustテストで合計4回の所有付き移動を検査している。

対象は合成した終了済みの失敗録音で、音声ファイルは作らない。両入力に最新64遷移と2遷移分の保持不足を持たせ、保存診断は要求版201・確定版200の失敗とする。取得履歴の版と通知台帳の版は独立したまま扱う。

移動先で通知の書込みを開始する前に、コピーされた履歴・manifest・台帳のバイト列が移動元と一致することを確認した。移動前のコントローラー、書込み停止後のStorage、古い世代の受付は拒否し、拒否時に台帳を書き換えない。表示確認のある先頭通知は再提示せず、未表示の先頭通知は受取先を外し世代を進める。新しい受取先で受付・表示確認・終了を保存すると、次のマイク通知だけが進み、PC音声の未表示通知は保持される。

2回の移動後も両入力の保持不足、元の履歴、停止時の保存失敗を保持する。通知を閉じても保存診断は成功にならない。終了済み履歴に現在の入力状態や報告年齢を付けず、元の保存先の履歴と台帳も変更しない。

## 検証結果

重点テスト1件は成功した。関連する入力状態・履歴・通知の回帰検査は75件成功・専用4件ignored、起動設定の関連検査は19件成功となった。ログは以下に保持する。

- `/private/tmp/mon-input-companions-owned-moves-final.log`
- `/private/tmp/mon-input-companions-input-regression.log`
- `/private/tmp/mon-input-companions-bootstrap-regression.log`

最初の重点実行では、合成履歴が保持不足2件に対して最新64遷移を満たしておらず拒否された。検査用データだけを修正し、実際の履歴読出しAPIを通ることを前提条件に追加した。製品側の検査条件は緩めていない。最初の失敗ログは `/private/tmp/mon-input-companions-owned-moves.log` に保持する。

前段の全体 `make check` のRust1,622件成功などは、このテストの追加前のソースに対する結果である。今回の変更はテストだけで、上記の重点・関連検査を前段の全体件数へ加算しない。

## 残る検証と持ち運び対応

この検査は実際のネイティブ保存先変更を通すが、録音機器の取得・PCM保存・画面の実表示は検査しない。表示確認は通知APIへ保存した結果であり、Mac製品アプリで実際に表示した証明ではない。通常録音とMac実機での保存先変更、権限、長時間録音、電源断は別に残る。

バックアップへ履歴と通知台帳を収録する処理、新IDへの追加復元、復元先の通知権限、復元後の要確認一覧は未接続である。[停止時診断のバックアップ保持](portable-input-journal-diagnostics-2026-10-09.md)とは範囲を分ける。正式評価・10話者・Windows固有部分は保留し、計画全体は進行中を維持する。
