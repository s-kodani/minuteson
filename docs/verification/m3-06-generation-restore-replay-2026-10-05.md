# 復元時の保存済み生成結果の意味照合

2026-10-05に、計画M3-06の追加復元に向け、保存済みの議事録生成結果を再検証し、新しい参照IDに再構成する内部処理を追加した。通常の生成ワーカーと同じ処理計画・プロンプト作成・結果パーサーを使い、モデルは実行しない。一時DB・管理ファイルへの接続、最終検証と追加公開は未完成であり、利用者向けの復元機能はまだ使えない。

## 生成条件と保存内容の照合

元と再構成先それぞれの固定入力から処理計画を再計算する。会議・解析版・入力ハッシュ・進捗・総単位数・プロファイル・初回操作IDが条件と一致し、復元前後の計画・入力予算・モデルと実行バイナリのSHA・サイズ・推論設定が変わらないことを確認する。エンジンの配置先だけは変えられるが、利用可能なモデルとして登録せず、実行ファイルの起動やモデル検査を行わない。初回操作IDを再試行の祖先と照合する処理は、今後の復元コーディネーター側に必要である。

通常ワーカーの検証関数を共通化し、system.txt・prompt.txt・schema.jsonが実際の固定タスクとバイト単位で一致することを確認する。result.jsonは既存の厳密JSONパーサーで読み、抽出単位の根拠・担当者の裏付けや統合元IDの消費を、既存の結果パーサーと文書検証で照合する。items.jsonも、その生成原文から計算した項目と一致しなければ拒否する。

抽出原文では、型付きの担当話者IDと根拠発言IDだけを変更する。本文・担当者名・期限・項目順を文字列置換しない。新しい入力からプロンプトとschemaを作り直し、変更した原文をもう一度パースする。その結果が元の項目の参照だけを変更したものと一致した場合に限り、新しい成果物と参照・SHAを返す。

## 世代1と分割統合の途中再開

世代1の抽出・統合と、世代2の分割統合を扱う。統合の元項目IDは処理位置を表すため変更せず、担当話者・根拠の参照を変更した親項目から、新しい統合プロンプトとschemaを作る。元と新しいパーサーの結果を比較し、本文・メタデータ・根拠が一致することを検査する。

分割統合では既存のカーソルを復元前後で進め、保存済みの各バッチを順番に検証する。入力・出力予算、メタデータ別グループ、第2パスの並べ替えと元項目の一度限りの対応は変更しない。完了済みの統合は終端まで確認し、途中保存は同じ次の元項目IDへ到達することを照合する。過去のチェックポイントに記録された進捗も保持し、最新の進捗へ置き換えない。

成果物は各2MiB、チェックポイントは1MiB、分割統合は4096バッチの上限を維持する。取消は単位・バッチ境界と処理の開始・終了で確認し、途中で中断した場合は完了チェックポイントを返さない。

- 成果物のSHAとチェックポイント参照が一致していても、別会議の発言IDを根拠にした原文は意味照合で拒否した。

## 接続前の範囲と残件

今回の処理は内部の生成復元コーデックであり、[一時DB構築](m3-06-restore-workspace-2026-10-05.md)にはまだ接続していない。アーカイブの物理SHAと元の論理SHA、会議・ファイル・媒体種別、固定入力に所属する話者と発言の照合は、呼出し側の読出し・ID対応処理が行う必要がある。今回のメモリ上の検証は、その実ファイル接続を証明しない。

次に、検査済みアーカイブから元の固定入力を読み、新しい一時DBの既存読取り処理で再構成先の固定入力を検証する。成果物は操作専用領域へ排他的に保存し、過去の同じ参照が異なる内容を要求した場合は拒否する。エラー・取消時に専用領域だけを回収し、チェックポイントJSONと新しいSHAを一時DBへ登録する必要がある。

文字起こし・話者分離の途中成果物、解析フローと出力履歴、除外PCM・ログとモデル未配置時の再試行、永続台帳・二重追加防止・共通用語競合、トリガー再設定・全体検証・原子的な追加公開、UIと実プロセス停止との調停も未完成である。M3-06は進行中のまま維持し、正式評価・Windows固有部分・CIは保留を維持する。
