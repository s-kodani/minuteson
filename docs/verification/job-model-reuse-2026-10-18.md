# ジョブ中のモデル保持・再利用（2026-10-18）

## GPU試行後の `native inference exit 3` の修正

初版ではGPU自動設定が256層を試行し、実際にオフロードできた層数を保存した後、本処理がその実層数を指定するとワーカーが設定変更と判定していた。報告のログでは同一PIDでGPU試行（37/37層）が成功し、続く要求で停止していた。追加した実Metalテストでも256→29層の遷移で同じ `native inference exit 3` を再現した。

モデルの層数と出力層による実効オフロード数を用いて同一性を判定するよう変更した。モデル・コンテキスト長・実効GPU配置が異なる場合の拒否は維持する。Qwen 2.5とQwen3で、試行の256層指定から実層数による複数要求へ進み、同一PID・モデル初期化1回・単独実行との結果一致・正常終了を確認した。CPU・Metal・VAD・話者分離・特徴量抽出を含む実エンジン8件と、同梱・署名処理のPythonテスト33件が成功した。

固定済みジョブのランタイム識別子は変更しない。修正版は更新したアプリで新しく開始する議事録生成に適用され、既存ジョブの「再試行」は従来どおり固定された版を使用する。

## 当初の実装と検証

新規の文字起こし・話者分離・議事録生成をジョブ専用ワーカーへ接続した。各ワーカーは必要になるまで起動せず、処理単位を順に実行する。話者分離では分離器と照合用の特徴量抽出器をそれぞれ保持する。処理済み区間の登録・検証・チェックポイント確定は親側の既存処理を維持した。一時停止・取消・失敗・終了時には所有監視を通じて子プロセスを回収する。

固定パラメーターの任意フィールド `residentRuntime` にプロトコル版・エンジン・実行ファイル名・容量・SHA-256を保持する。フィールドのない既存ジョブとその再試行は従来方式のまま。操作応答の再送でも初回の方式を保持する。ランタイムはデータ領域のハッシュ別キャッシュへ保存し、アプリ更新で上書きしない。バックアップにはパスのない識別情報を保持し、復元先に同一の実行部品がない場合には別版へ切り替えず停止する。

Whisperとllamaは既存の固定コミットのCLI処理を再利用し、Whisper/VADのコンテキスト、llamaのモデルと推論コンテキストを保持する。要求ごとに認識履歴、KVキャッシュ、サンプラー、乱数、スキーマをリセットする。llamaではコンストラクターが行っていたモデル由来のサンプリング設定も各要求へ適用する。成功したGPU試行はそのモデルを本処理に引き継ぐ。Metalのキャッシュはバックエンドの静的デストラクターより先に明示解放する。

ビルド、アプリへの同梱、開発用署名、Developer ID署名後のインデックス再生成、通知本文の同梱まで接続した。既存のモデルパッケージやモデル重みは変更していない。ソース・バイナリーの照合とライセンス本文の収集は、配布許諾・公証の承認を意味しない。

## 検証

- 新規Rust 7件成功。PID再利用、実行中の停止と回収、未完了ジョブだけの遅延起動、応答ID不一致、実行ファイル改変、保存後のDB再起動・未完了区間だけの再開、復元時のランタイム識別情報の保持と差し替え拒否、再利用時のロード時間表示を検査した。
- Rust全体は1948成功・91除外・8失敗。8件はすべてループバックの `TcpListener::bind` に対する制限環境の `PermissionDenied`。通常環境で該当モジュールを再実行し41成功・8除外、失敗していた8件もすべて成功した。最終追加分を含む上記7件は、最新ソースをビルドして別途成功した。
- Python通常178件成功（実モデル等が必要な8件は既定で除外）。署名・同梱の検査33件を含む。実エンジンの検査は別途7件すべて成功した。
- 実エンジンはWhisper、Whisper + Silero VAD、Sherpa分離器、特徴量抽出器、Qwen 2.5 CPU、Qwen 2.5 Metal、Qwen3のテンプレートとサンプリングを検査した。音声→無音→音声、異なる生成要求を挟んだ同一入力で、従来方式との結果一致、同じPID、各推論インスタンスの初期化1回（従来3回）を確認した。VAD自体のロードも1回。Metalを含む終了コードは0だった。
- 最終ワーカー3種のarm64・最低macOS 15.0・静的リンク構成・署名・SHAと、ビルドレシピの一致を確認した。
- `git diff --check` は成功。今回変更したRustファイルは整形済み。全体の `cargo fmt --check` は、今回触れていないモデル管理などの既存変更の整形差分で未通過。

## 時間・メモリの記録

約7.9秒の合成日本語音声と同長の無音、または小さなJSON生成を3回実行した。既存の私的録音は使用していない。同じ端末・モデルで比較し、他のテスト実行後に取得した最後の測定値を下表と隣接JSONへ保存した。モデルロードの回数減少の接続検査であり、長時間会議での速度や品質を保証するベンチマークではない。

| 処理 | 従来3回の合計秒 | 常駐3回の合計秒 | 常駐ピークRSS MiB |
|---|---:|---:|---:|
| 話者特徴量抽出 | 1.132 | 0.806 | 214.4 |
| Qwen 2.5 1.5B・Metal | 1.828 | 1.424 | 1254.4 |
| Qwen 3 4B · Q4_K_M・CPU | 12.781 | 6.488 | 2945.7 |
| Qwen 2.5 1.5B・CPU | 5.163 | 3.738 | 1251.7 |
| 話者分離 | 0.550 | 0.247 | 135.3 |
| Whisper base・CPU | 5.269 | 4.933 | 344.0 |
| Whisper base + VAD・CPU | 2.474 | 2.133 | 346.2 |

常駐側は起動・推論・終了の時間を含み、比較のため間に実行した従来方式の時間を含まない。要求後のRSSもJSONへ保持した。特徴量抽出では初回の後に作業領域が増え、その後は安定した。各ケースで3回目のRSSが初回より128 MiBを超えて増えていないことを検査した。より長い連続実行・実会議での性能評価はこの短い検査の対象外。

再現手順と環境変数は `probes/inference-worker/README.md` と `tests/test_mon_inference_runtime_native.py` を参照。計測値は [JSON記録](job-model-reuse-2026-10-18.json) に保持する。
