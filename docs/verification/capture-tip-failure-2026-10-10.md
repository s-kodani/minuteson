# 原音声tip更新の容量・I/O異常と案内

- 対象: M3-01の原音声確定範囲と終端異常
- 更新日: 2026-10-10
- 状態: 最終Swift全体・最終全体`make check`終了コード0。M3-01と計画全体は進行中

## 実装

確定範囲tipを保持する共通のInputEventJournalFileは、実openat・write・fsync・renameatの失敗原因をPOSIXErrorとして保持する。初期作成と原子的置換の書込み・同期を、既定で実syscallを使う内部StorageIOへ分離した。故障注入は内部テスト専用であり、CLI・アプリ設定で同期・所有確認を無効にする機能はない。一般の通知履歴と診断の所有・実体・リンク・容量制限、保存先pin、現在／staging照合と原子的置換は維持する。

原音声writerはtipのENOSPC・EDQUOTを既存の`raw_segment_storage_full`、EIOを`raw_segment_storage_io_failed`へ分類し、確定時と閉鎖時の失敗を終端化する。書込み再開・finishの再試行から成功を返さず、既存音声やJSONを自動削除しない。初期tipの既知容量／I/O異常も案内へ接続する。EACCES・EEXISTなど別の初期原因や、確定時の未知原因の元診断は保持し、空き容量不足と推測しない。

置換後のdirectory fsyncに失敗した場合、現在のファイルに新しいtip・producerClosedが見えていても、その操作を確定成功のreceiptとして返さない。共通journalは新しい自分の実体IDを保持して同じ所属の再試行をできるが、原音声writerは失敗状態を固定して再試行しない。保存・取得終了を原子的置換の可視性から推測しない。

日本語案内は既存のTrackStats.requireWritable、原音声の排出／停止、既知の初期容量・I/O異常へ接続した。容量・クォータ、I/O、取得時計、書込み確認を区別し、録音停止を確認してから「中断録音の部分救出」で範囲を確認するよう案内する。既存の状態コードを保持し、正常終了・未確定末尾の保存・救出成功・損失時間を保証しない。元のmanifest errorsを既存の録音監視が有界に読み、既存の主画面・通知・録音確認表示へ渡す経路を使う。画面のDOM・状態遷移・自動操作は変更していない。

初期化失敗時にはpinしたdirectory descriptorを解放し、解放済み値へ変更する。既に解放したdescriptorをdeinitで再度closeせず、作成済みleafのdescriptorもdeferで解放する。初期作成に失敗した不完全なleafは削除・上書きせず保持する。

## 検査の範囲

実POSIX書込み・同期とAVFoundation CAF、合成PCMを使う。実ディスクを埋めず、内部のsyscall境界へ故障を注入する。

| 検査 | 条件 |

| 共通leafの初期失敗 | 3原因×4箇所（create・部分write・file fsync・directory fsync）の12ケース。POSIX原因、descriptor解放、既存leafの保持と排他的な再作成拒否 |
| 共通leafの置換失敗 | 3原因×5箇所（staging create・部分write・file fsync・rename・directory fsync）の15ケース。置換前の旧バイト不変、置換後の新バイト可視性、所有付き一時ファイルだけの回収、同じ所属への共通journalの再試行 |
| 原音声tipの確定／閉鎖失敗 | 3原因×5箇所×2段階の30ケース。確定済み実CAF・entryのバイト不変とPCM読戻し、可視tipと未確認状態の区別、閉鎖／再enqueue／再finish成功の拒否、故障解除後も終端状態と残ファイル不変 |
| 原音声tipの初期失敗 | ENOSPC・EDQUOT・EIOの案内とEACCES・EEXISTの元原因保持、計5ケース。既存音声を保持し、救出証拠を作らない |
| 案内と状態 | 既知6コードの日本語案内、UTF-8 1,000bytes未満、状態コード不変と実requireWritableのエラー文一致。未知コード・類似文字列を勝手に解釈しない |
