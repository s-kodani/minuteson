# 未確定本文の回復保存と確認画面

未確定の発言本文を、入力停止後約300msで専用の回復記録へ保存する画面を接続した。本文の確定保存とUndoとは分離し、再起動後は保存済み入力の確認を求める。編集再開・破棄・保存結果の確認・再試行を明示操作とし、旧下書きや変更後の本文へ入力を自動適用しない。2026-10-07時点の検証は単体テストと模擬IPCブラウザーであり、macOS実機の強制終了回復は残る。

## 保存順と入力の保持

発言の確定では、未確定入力の回復保存、本文の確定保存、確定した入力の回復記録からの除去を順に待つ。他の発言の未確定入力は、新しく保存した本文の版へ対応付けて保持する。本文保存中と結果未確認中は別の回復書込みを始めない。保存中に追加された入力を古い応答で置き換えず、確定・取消済みの入力を別の欄への入力で回復記録へ戻さない。

会議切替・終了・候補確認などの保存待ちは、本文と回復記録の確認が済むまで完了しない。同じ画面が残る場合は編集欄と入力開始時の本文を保ち、Escによる取消を新しい保存版として扱う。検索条件外の確定行はフォーカスが離れるまで保持する。編集開始後の遅いフォーカス移動で検索欄の入力を奪わないよう保護した。

同時編集128件、発言本文20000文字、回復記録のUTF-8容量4MiBを送信前に検査する。上限超過時は入力を保持し、不正な要求を再試行用の操作IDに固定しない。本文と回復記録の版番号もJavaScriptで安全に表せる範囲に限定する。

## 保存結果の確認と再試行

回復保存が失敗した場合は同じ操作ID・版番号・入力の要求を保持する。読み取りだけの結果確認では新しい入力を送らず、未保存と確認された場合も自動再送しない。明示再試行で旧要求を解決した後、新しい入力を別の版として保存する。

本文保存の応答喪失でも、保存した所有・版・内容ハッシュ・本文を照合する。結果確認は本文の読取りだけで行い、後から入力した内容を確定しない。本文が未更新なら入力と保存要求の区別を保ち、明示確定または再試行まで本文・回復の自動保存を停止する。取消は保存結果が進んでいないことを確認してから行い、別の更新を上書きしない。

## 保存済み入力の確認と破棄

現在の回復入力をプレビューし、入力開始時と未確定の本文を選択・コピーできる。旧下書きを含む会議別一覧は20件ずつ、入力のプレビューは10件ずつ表示する。明示的な編集再開は記録を再読取りし、操作ID・回復版・内容ハッシュ・入力と、現在の下書きの基底が一致した場合だけ許可する。旧解析版・非アクティブ・本文更新後の入力は閲覧と手動コピーに限定する。

破棄は表示した記録に対する確認モーダルを経て、現在の下書きと回復記録の版・ハッシュを固定して実行する。応答では空記録の形式版2と、破棄した記録の版・ハッシュを示す証拠を照合する。確定本文・話者名・Undo・解析版の採用状態は変更しない。応答未確認の要求はモーダルを閉じても保持し、新しい破棄と画面移動を止める。結果確認は読取りだけ、再試行は同じ破棄要求に限定する。

通常の編集破棄と再読込でも、先に読取りを完了し、本文が確認した版のままであることを照合してから回復入力を空記録へ進める。読取り失敗・保存失敗時に編集欄を消さず、再起動で破棄済み入力が復活しないようにする。

## 残る検証と実装

保存確認前の最後のキー入力まで回復できる保証はない。macOS WebViewとSQLiteを通した実際の再起動・強制終了・容量不足、保存待ちと録音・終了の統合は実機検証で確認する。別操作が本文や回復記録を進めた競合では入力を保持して上書きを拒否するが、すべての競合を画面から解決する操作は残る。

話者名の確定保存、固定プレーヤーと表示設定、ミニ画面の通知・説明、配布・更新と先行試用も残る。M3-08と計画全体は進行中であり、正式品質評価・10話者・Windows固有部分は保留する。Windows CIは停止したままとする。
