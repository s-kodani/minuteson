# M2-03 / M2-05 ローカル文字起こしワーカー接続

正式評価とWindows固有部分を保留にしたまま、whisper.cppの実行・進捗保存・候補版作成を実装した記録。話者分離と品質評価の完了を意味しない。

## 実装

- 保存済み録音のmanifest、トラック、各CAFのサイズ・SHA-256・フレーム数・時刻・形式を固定したジョブを登録する。実行ファイル、モデル、任意のVADモデル、プロファイル、用語ヒントも固定する。相対パス・変更済みファイル・別会議参照を拒否する。
- 同時実行1件のバックグラウンドワーカーをTauriへ接続。開始・一覧・一時停止・再開・取消のメイン画面専用コマンドを追加。起動時のqueuedジョブは実行対象、interruptedジョブは手動再開対象。
- 120秒区間の前後に最大2秒のコンテキストを付ける。元トラックを一度検証して保持し、区間だけPCMを読み、チャネル平均とアンチエイリアス低域通過フィルターで16 kHz・モノラル・PCM16 WAVに変換する。全会議のPCMをメモリへ展開しない。最大変換区間124秒、元音声の形式上限384 kHz・8チャネル。保持するモノラル配列は最大約182 MiB。区間所有は出力セグメントの中点で決める。
- シェルを介さずwhisper-cliへ引数を渡す。日本語・非翻訳・多言語モデル・モデルパスを出力JSONでも照合する。CLIのoffsetsはミリ秒として読む。空のtranscription配列は発話なしの結果として保持できる。
- 各実行のstdout/stderrはそれぞれ4 MiB、結果JSONは8 MiB、実行時間は30分を上限とする。100 msごとに一時停止・上限を確認する。停止・タイムアウト・エラーでは未完区間のプロセスをkill/waitし、子プロセスを残さない。起動前後で入力WAVをハッシュ照合し、実行中のモデル・実行ファイルの変更も検査する。
- 新しいUUID付き処理領域へ出力し、既存結果を上書きしない。完了区間のWAV・生JSONを管理ファイルとして登録し、そのID・ハッシュだけをチェックポイントに保存する。再開時は完了結果と元入力を再検証し、未完区間だけをやり直す。途中ファイルは削除しない。
- 全区間後に候補版とジョブ成功・出力版IDを同一トランザクションで保存する。確定版と編集下書きは自動で切り替えない。話者分離はpending、発言は話者不明、二系統の時間合わせはunverifiedとして保持する。
- 録音開始では解析停止・チェックポイント保存を最大15秒待つ。録音の終了・失敗後は録音理由で止まったジョブだけ再開し、ユーザー停止は維持する。通常終了でも解析の安全な停止を待ち、停止待ち失敗時は終了しない。
- SQLite移行9で出力解析版の会議・入力範囲と固定性を守る制約、および一時停止理由を追加した。

## 検証

- `make check`：Python 65件、フロントエンド12件、Rust通常54件、AVFoundation製CAF読出し1件が成功。正式評価前提の不足は従来どおり7警告。
- 音声変換：固定WAVヘッダー、チャネル平均、区間長、既存出力の上書き拒否、16 kHzの直接変換、セグメント境界をまたぐ読出し、一時停止を検査。8 / 44.1 / 48 / 96 kHzで1 kHz成分を保持し、12 kHz成分の折返しを抑制する合成信号テストを追加。
- プロトコル・寿命：終了コード0でもJSONなしは失敗、日本語以外・英語専用モデル・翻訳・別モデル・範囲外時刻は拒否。中断・タイムアウト後にテスト子プロセスが消失することを確認。
- 結合：124秒の合成CAF・2区間で1区間完了後の停止、DB再読込、途中からの再開、最初の結果ID保持、候補版保存、手動採用後の本文読出しを確認。再解析候補は既存の確定版と下書きを変更しない。元CAF・モデル・結果JSON・固定設定の改変をそれぞれ拒否。候補と成功状態の原子的保存、二重確定拒否、空発言候補、ユーザー停止の保持を検査。
- 実エンジン：公式[whisper.cpp v1.9.4](https://github.com/ggml-org/whisper.cpp/releases/tag/v1.9.4)のコミット`927cfce34f31707e17f2bff35c349632fb9e2c3a`を一時領域へ取得し、Apple Clang / CMake 4.1.2、静的ライブラリ、CPU＋Accelerate、Metalなしでビルドした。CLIのSHA-256は`ad4f0dde9e866567376c5e8b7e6df9ffff85bef468e576a87cfcc152f12f942a`。
- 実モデル：上流の[モデル取得手順](https://github.com/ggml-org/whisper.cpp/blob/v1.9.4/models/download-ggml-model.sh)にある配布元から多言語tinyモデルを取得。SHA-256は`be07e048e1e599ad46341c8d2a135645097a538221678b7acdd1b1919c6e1b21`。接続試験専用で、採用モデルや精度改善版ではない。
- 提供済みFLACの5分から30秒をCAFへ変換。CAF→本実装のWAV→実CLI→JSON検証で3セグメントを得た。同じ実音声を合成DBフィクスチャへ登録し、ワーカー実行→管理結果→チェックポイント→候補版→手動採用→内容ハッシュ検証も成功した（用語ヒント付き1発言）。件数は精度指標ではない。本文や原音をGitへ追加していない。

`npm run tauri -- build`も成功し、13.89 MiBの開発用`mon.app`を生成。`codesign --verify --deep --strict`に成功した。アドホック署名で公証はなく、実画面の録音操作を検証したものではない。

実エンジン試験は通常テストではignoreし、既存のCLI・モデル・30秒CAFを指定して次で再現する（このテスト自体は取得通信をしない）。

```sh
MON_WHISPER_CLI=/absolute/path/whisper-cli \
MON_WHISPER_MODEL=/absolute/path/ggml-model.bin \
MON_WHISPER_INPUT_CAF=/absolute/path/30-second.caf \
cargo test --manifest-path app/src-tauri/Cargo.toml --locked --offline real_whisper -- --ignored --nocapture
```

今回の一時検証領域は`/tmp/mon-whisper-integration.ibH0yg`。CLI・モデル・30秒音声をここに保持し、全編再解析と正式な採点は実行していない。テスト用DB・候補本文はテスト終了時に一時領域から削除される。
