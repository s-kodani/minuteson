# 未確定本文の回復保存基盤

2026-10-07に、仕様14.13の入力途中の回復に向け、文字起こし下書きに属する専用のSQLite保存領域とメイン画面専用APIを追加した。確定本文・編集履歴とは別に入力を保持する。画面からの保存・再起動時の復元操作は未接続であり、現在の本文入力は引き続き画面内メモリーに保持する。M3-08と計画全体は進行中である。

## 回復用の保存と版管理

移行28で `transcript_edit_recovery` を追加する。所有する下書きID、会議と解析版、保存時の下書き内容と版番号、編集開始時の本文・話者・上書きの有無、入力途中の本文を対応付ける。回復保存は現在の確定本文・下書き・Undo履歴を更新しない。

回復保存には独立した版番号と操作IDを使う。保存応答を失った同じ要求は同一結果として読めるが、同じ操作IDで内容を変更した要求や、古い版番号による上書きは拒否する。確定・取消後の消去は空の版付き記録として保持し、遅れて届いた古い入力で復活させない。異なる要求が同じ版へ競合した場合は一つだけを保存する。

下書きの確定保存やUndoで版が進んでも、回復記録には以前の基底内容と入力を残す。内容が同じに戻った場合も版番号が異なれば一致扱いにしない。保存済み下書きとの一致結果は、現在の解析版への採用許可ではない。画面側でも所有会議・解析版・下書きと現在版を確認する必要がある。

所有する発言・話者、JSON形式、内容ハッシュ、版番号を検査する。同時128発言、本文と開始時本文は各20000文字、基底を含む全体は4MiBを上限とする。入力途中の空本文も保存できる。壊れた記録を上書きして修復せず、書込停止中や旧保存先の停止後には保存を拒否する。

## バックアップと復元と完全削除

最新のバックアップには回復記録を含め、保存前と復元計画作成時に所有・参照・ハッシュを検査する。移行27以前の論理形式にはこの表を要求しない。復元では下書き・解析版・発言・手動話者・操作のIDを対応付け直し、基底と回復記録のハッシュを再計算する。本文中に自然文として含まれる旧IDは置換しない。進んだ下書きに対する古い入力も、その以前の文脈を保ったまま復元する。

完全削除の確認範囲には回復記録を明示的に含める。確認後の入力更新で対象の指紋が変わった場合は、以前の同意による削除を拒否し、その同意自体も上書きしない。正しい対象を確認した削除では、回復本文を含む行とDB・WAL内の本文を除去し、対象外の会議と端末設定を保持する。

表の追加によって完了記録が大きくなると、最初のVACUUM後の記録更新で空きページが生じる場合がある。共有の操作権限・保存先・完了記録を再確認した後、空きページがある場合だけ追加のVACUUMを行い、最終WALチェックポイント後に応答する。既存の同意・完了記録は変更しない。利用者の外部バックアップや物理記憶媒体からの消去を保証する処理ではない。
