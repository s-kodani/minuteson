# 音声取り込み画面と解析設定の引継ぎ検証

音声選択から確認、保存、会議詳細への移動を接続した。macOSの標準ファイル選択とネイティブのドロップを同じ取り込みコントローラーへ渡し、原本を変更しない既存の保存処理を使う。通常テストとブラウザの模擬IPCで操作・失敗時の入力保持を検査したが、macOS WebViewでの一連の実操作、長時間の性能と正式品質評価は未確認であり、M3-05は進行中とする。

## 確認画面と結果表示

「新しい録音」の隣に「音声を取り込む」を置いた。新しい録音は会議名入力へ移動し、勝手に録音しない。音声を選択すると、内容を検査してからファイル名、長さ、形式、チャネル、原本容量、保存に必要な容量、保存先の空き容量を表示する。会議名、標準または高精度の解析プロファイル、任意の会議別用語を確認して「取り込む」で開始する。動画抽出は対象外である。

共通用語と会議別用語を区別し、会議別用語は用語・読み・補足・有効状態を編集できる。空欄や重複は入力を残して開始を止める。共通用語の版が開始前に変わった場合は再確認を要求する。会議別用語は取り込み開始時に会議へ保存し、実際に解析ジョブを登録するときの共通用語と合わせて固定する。確認時の共通用語を、その後の全ジョブに永久固定する仕様ではない。

コピー・復号・FLAC変換・保存確定の段階を表示する。容量・形式・保存等のエラーは画面に残し、取消に失敗した場合も確認画面と入力を閉じない。開始応答やイベントを失っても、リビジョン付きのネイティブ状態を再取得する。古い応答で新しい状態を巻き戻さない。

保存後は同じ会議一覧・会議情報・解析・文字起こし編集・議事録導線へ移動する。AI未準備でも音声は保存済みとなり、選択プロファイルの準備待ちを表示する。会議の読込に失敗した場合は保存成功と区別し、「保存した会議を開く」で明示的に再試行する。音声を再取り込みしたり、候補を自動採用したり、議事録を自動生成したりしない。

## 排他と終了時の停止待ち

選択したファイルをネイティブで保持し、選択トークンと開始条件で重複開始を抑止する。古いトークンの取消は現在の処理を変更せず拒否する。検査・取り込み・起動時の回復は解析ワーカーと調停し、進行中の推論を安全に止めてから音声処理を始める。終了後は停止させた解析を再開できる。

録音開始は取り込みを取消要求して停止を待つ。取り込みが止まる前に録音を開始しない。通常終了も編集保存と取消確認の後に取り込み・解析の停止を待ち、15秒以内に停止を確認できなければ終了を拒否する。失敗した終了操作の後は終了ゲートを解除し、再試行できるようにする。OS等による強制終了の救出とは区別する。

manifest公開後の確定・回復検証も取消できる。検証を止めた場合は完了音声とmanifestを保持し、次の回復で再検証できる。保存のDB確定は原子的であり、確定後の遅い取消が成功済み音声を削除しない。

## 設定保存と移行

SQLiteの20段階目で、初期プロファイル・会議別用語・確認した共通用語版のJSONとSHA-256を保存する。設定は更新不可とし、読み出しと音声確定時にハッシュ・形式を再照合する。会議・取り込み・初期用語・設定の登録は同じトランザクションで行う。途中の登録失敗や共通用語の版の競合では、新しい会議や用語だけを残さない。

v19の既存の取り込みには標準プロファイルを追加し、音声、会議状態、既存用語を変更しない。高精度の選択はモデル未準備と再起動を経ても保持し、準備後の文字起こし・話者分離へ渡す。実際に準備したエンジンとモデルは従来と同じ解析工程へ固定し、後からの用語編集で過去の結果を変更しない。

## 検証範囲

Rustの追加7件で、コントローラーの選択トークン・取消・録音/終了ゲート・停止通知、初期用語と設定の原子的保存・重複開始、確定/回復の取消、v19からの設定移行、設定改変拒否、高精度の準備待ちと再起動後の解析を検査した。高精度の解析試験はプロトコル用の模擬エンジンであり、認識品質の実測ではない。フロントエンドの追加3件は開始条件、リビジョン、1件のドロップ受付を検査する。

ブラウザでは本番コードを変更せず、`app/tests/import-browser-fixture.js`を読み込むようにHTMLだけを差し替えて操作した。ファイル選択から確認、会議名と高精度の選択、用語の空欄抑止と「点検日」「てんけんび」の送信、取消失敗後の入力保持を確認した。開始応答喪失後の保存成功、会議読込失敗からの明示再試行、AI準備待ちと取り込みトラック表示、古い進捗イベントの拒否、複数ドロップの拒否、1件のドロップから同じ画面への移動、容量不足の開始抑止も検査した。スクリーンショットでモーダルの表示とスクロールを確認した。

通常の`make check`と別実行の署名済みヘルパーによる5形式試験を行う。詳細な実行結果は[実装状況](../implementation-status.md)に記録する。5形式試験は4秒の合成ステレオを実復号し、保存後に外部原本を移動して再起動・管理音声再生まで確認する。ファイルデコーダーの実検証であり、標準選択パネル・実ドロップ・WebView RPCを通した試験ではない。

最終の`make check`はPython 65件、フロントエンド64件、Swift 9件、Rust 229件に成功し、環境依存11件は通常実行でignoredのまま。AVFoundation製CAF試験1件と、別実行の5形式ファイル試験1件も成功した。locked・offlineのmacOS開発用アプリは18.81 MiBで、`codesign --verify --deep --strict`に成功した。署名はアドホック、公証なしであり、配布品質やネイティブ画面の動作確認を意味しない。

## 未確認事項と保留項目

macOS WebViewでの標準選択パネル、実ドロップ、終了確認、録音優先の停止待ちを一連の操作で確認する必要がある。容量不足は模擬IPCと見積もり検査で確認したもので、ディスクを実際に満杯にする試験ではない。4時間・16GBの速度とメモリ、録音のFLAC確定、共通のinfoポップアップ・確認モーダル、配布用ライセンス告知も残る。

正式評価とWindows固有部分は保留のまま。10話者やWindowsの合格を主張せず、Windows CIの`disabled_manually`を維持する。録音・マイク/システム音声の権限要求は今回行っていない。
