# 議事録Markdownの生成ワーカーと途中再開

2026年10月12日。[議事録簡素化仕様](../minutes-simplification.md)に沿ったMarkdown専用の生成ワーカーを追加した。生成結果を候補へ変換せず、一つの本文として直接保存する。今回は生成処理と成功通知の接続までで、本番の議事録画面はまだ旧経路を使う。会議バックアップの新しい生成ジョブへの対応、画面切替と不要経路の削除が済むまではQAを更新しない。

## 生成と途中再開

固定した文字起こしの表示名・本文・小数秒時刻をモデルへ渡す。発言ID、話者ID、根拠台帳、構造化議事録項目は求めない。出力は通信の枠として `markdown` 文字列一つのJSONを使い、復号したMarkdown本文をトリム・再構成せず保存する。既存のモデルと実行ファイルの照合、オフラインのローカル実行、実行時間制限と停止処理を再利用する。

入力が一度に収まらない場合はUTF-8の境界で分割し、全ての非空白発言の本文を順にモデルへ渡す。抽出結果を時系列で統合し、統合入力が大きい場合も切り捨てず複数回に分ける。分割数、統合単位数、統合回数には上限を設け、上限を超える場合は現在本文を変更せず停止する。入力の送信範囲の検査は、モデルが内容を正確に要約する品質の保証とは区別する。

処理済みの抽出と途中の統合結果について、システム文、入力、出力スキーマ、実際の生成出力の4ファイルを所有台帳とハッシュ付きで保存する。再開時に固定入力から同じ処理を再現して照合し、保存済みの単位はモデルへ再送しない。登録途中で停止した未確定単位を保存済みとして扱わない。生成の処理進捗は、置換前の人間の本文や旧版復元のバックアップではない。

完了時は開始時の本文の版とハッシュを照合し、本文とジョブ成功を一括保存する。生成中の人間の保存、生成失敗、停止・取り消しは現在の本文を変更しない。失敗・取り消し後の明示再試行では、元の固定入力と照合済みの単位を引き継ぐ。再試行の操作IDも本文保存で使える正規のUUIDとして検査する。

成功通知は保存した本文のハッシュ、ジョブ、操作、完了位置を照合してから表示する。後から人間が保存した本文が現在の正本になっている場合は、古い生成完了を再通知しない。候補比較や採用を案内しない。

## 検証範囲

追加の自動検査は合成実行ファイルと専用の一時DBを使う。短い本文の直接保存、再起動保持、生成中の人間の保存保護、不正モデル出力とモデル実体変更の拒否、抽出済み単位の停止再開、統合途中の再開と改変拒否、開始前停止、失敗・取り消し後の同一操作の再試行と保存済み単位の再利用を検査する。分割検査は日本語・引用符・改行・バックスラッシュを含む本文の全UTF-8バイトと小数秒、決定的な再開、収束しない出力の上限停止を対象とする。

先行Rust10件は8成功・2失敗。失敗は、素材の発言ID `utterance` の部分文字列がJSONのキー `utterances` に含まれていた検査と、上限停止へ到達するまでの反復回数が不足していた検査だった。正確なID文字列の検査と上限までの反復へ直し、製品の入力・成果物の検証は緩めていない。

最終の関連Rust60件は全て成功した。新しい生成処理7件と分割計画4件、既存のMarkdown保存、固定文字起こし入力、議事録保存、会議バックアップの本文保持、保存通知と再試行を含む。途中統合の再開で最初の追加実行までの呼出し数も照合し、保存済みの統合単位が再実行されないことを確認した。失敗した先行2条件も再検査に成功した。全Rustの再実行ではない。

最終フロント926件は成功し、型検査とフロント構築も成功した。フロントはMarkdown専用の保存通知、後続編集時の通知抑止、別処理・未完了・旧候補の証明の拒否を追加した。実LLMの生成品質、Mac本番画面の操作と実日本語入力は今回の合成検査には含まない。
