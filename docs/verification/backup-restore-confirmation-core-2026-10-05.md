# バックアップと追加復元の確認境界の検証

日付は2026-10-05。対象はM3-06の操作画面から呼び出す前段階であり、[モデル構成履歴の移送](portable-model-catalog-transfer-2026-10-05.md)に続く内部実装である。

出力先選択とバックアップ確定、検証済みバックアップの確認と追加復元を、それぞれ端末内の型付き操作としてまとめた。確認IDを照合し、確認後のファイル差し替え、共通用語の変更、別の保存領域への操作の流用を拒否する。復元は既存データを置き換えず、同じバッチの再試行で二重追加しない。

今回はRustの保存領域内部の境界を接続したものであり、Tauriコマンド、操作コントローラー、選択ダイアログ、確認モーダル、進捗表示、復元会議一覧はまだ接続していない。画面から利用できる機能の完成とは扱わない。

## 出力先の確認とバックアップ

選択した出力先の絶対パス、既存ファイルの有無、内容SHA、容量、実体識別子、親フォルダーの実体を保持したまま確定する。確定時に出力先を取得し直して、変更後のファイルを無断で上書きすることはしない。元の保存領域とMONバックアップ形式に属する選択だけを受理し、Markdown出力用の選択や別の保存領域の選択を拒否する。

確認用情報には対象のパス、上書きの有無、確認IDを返す。別の確認IDでは確定できない。成功した結果は端末内の操作へ保持し、同じ操作の応答が失われても、再試行でファイルをもう一度上書きしない。ファイル確定後にディレクトリ同期等が失敗した場合も、既存の `published` の結果を終端として保持し、未確定と誤認して再度上書きしない。ただし、この確定後エラーを実際に発生させる試験は行っていない。

## 検証済み入力と追加復元

選択する元ファイルは絶対パスのMONバックアップ形式、通常ファイル、単一リンクに限定し、開いた実体と選択時の実体を照合する。検証済みのコピーを保存先の非公開一時領域に保持する。元の外部ファイルが移動しても、確認した内容の復元は継続できる。元ファイルの新しい場所や別の内容へ入力を自動で切り替えない。

検証用DBの容量・SHA・実体識別子も保持し、確認と確定の再構築前後で照合する。確認を待つ間に会議データのコピーが改変された場合は、ライブDBへ書き込む前に拒否し、自動修復しない。

確認の準備では全会議、管理音声、下書き、根拠、固定条件、処理履歴、由来を一時領域へ再構築し、封印と最終検証まで行う。ライブDBには会議もバッチ予約も追加しない。通常の書込み遮断を保持し、参照対応のために必要な `table_info` と `foreign_key_list` だけを持ち運び対象の表に限定して許可する。会議INSERTや `foreign_keys=OFF` などの変更は拒否する。

確認用情報には会議名と件数、必要容量、空き容量、共通用語の追加件数、完全一致の重複件数、既存を維持する競合用語を返す。必要容量は封印済みデータ、モデル履歴、ライブDBとWALに加え、確認時にはまだ存在しない復元IDの予約行と索引の余裕を含む保守的な見積りである。見積りを正確な最終ファイルサイズとは表示しない。

確認IDは再確認ごとに生成し直すが、復元バッチIDは維持する。確定時は同じ検証済みコピーを再構築し、既存のバッチ予約があれば保存済みID対応を再利用する。共通用語の内容指紋と確認した容量上限を、ライブDBへの追加と同じトランザクション内で照合する。確認後の共通用語変更や容量上限の超過は、予約を永続化する前に拒否する。

公開済みの同じバッチは再構築や共通用語の併合を行わず、保存済み会議IDと確定済み状態を返す。この読戻しでは前回の共通用語追加件数を推定せず、結果の件数は未取得として区別する。別の入力選択は別バッチとして扱い、明示的に確定すると別会議として追加できる。

## 自動テストの範囲

追加した10件は実ファイルのアーカイブとSQLite、合成音声を使い、モデルの再実行は行わない。

- 全再構築を経た確認で2会議、必要容量、共通用語の追加・重複・競合を取得し、ライブDBの全行を保持する。確認中の会議書込みと設定変更を拒否し、操作を破棄すると所有する検証コピーだけを回収する。
- 新規バックアップの確認IDを照合し、成功後の再試行は同じ結果を返す。確定後に外部でファイルを編集しても再上書きせず、選択後に新しく作られた出力先も保護する。
- 追加先の会議フォルダーが実際に作成された時点で取消を要求する。既存会議と共通用語を保持し、未公開の所有ファイルを回収する。同じバッチで再確認・再試行し、一度だけ追加する。
- 元ファイル移動後の追加復元、別確認IDの拒否、同じバッチの終端読戻し、明示的な別バッチの別会議追加を確認する。
- 確認後の共通用語編集で確定を拒否し、全行を保持する。再確認でバッチIDを維持しつつ確認IDを更新し、古い確認IDを拒否する。
- 検証途中の取消と、検証済みコピーの音声改変を拒否し、既存行と通常編集の排他状態を保持する。
- バックアップの確認後の出力先変更、別保存領域、別形式、取消を拒否し、既存ファイルを保持する。再選択した正しい対象は確定できる。
- シンボリックリンク、複数リンク、相対パス、別拡張子、別保存領域への復元操作の流用を拒否する。
- 確認容量上限を故意に小さくした試験で、追加予約を永続化する前に拒否し、再確認後は追加できる。これは容量境界の注入試験であり、実ディスク容量不足の実測ではない。
- 検証用DBの会議名を変更した場合、再構築前に拒否する。確認ID、元の破損行、ライブDBを変更せず、通常の書込み遮断を解除する。

## 全体検証の結果

最終の `make check` は終了コード0で成功した。Python 65件、フロントエンド82件、Swift 9件、Rust通常482件、AVFoundation製CAF読出し1件が成功した。Rustの11件のignoredは通常検査の合格に算入しない。

初期の検査では書込み遮断が表構造の読取りも拒否していたため、対象表に限定した読取り許可を追加した。取消テストも初めは会議フォルダーの親を誤って観測していたため、実際の `meetings` 配下の新フォルダーを観測するよう修正した。修正後の10件と、最終状態の全体検査が成功した。検証用DBの実体照合を追加する前の全体検査も成功したが、最終確認として追加後に全体検査を再実行した。

Swiftのユーザー領域キャッシュへの書込み警告に加え、Rustテストのリンク時に `__eh_frame` がcompact unwindのオフセット上限を超える警告が出た。いずれも検査は終了コード0だが、この警告から例外処理の性能や配布成果物の動作を合格とは判断しない。
