# 議事録のMarkdown本文そのままの書き出し

2026年10月12日。保存済みのMarkdownを加工せず、標準の保存先選択から書き出せるようにした。未保存入力の確認と、書き出し結果が不明な場合の読取り確認を一つのダウンロードアイコンへ接続した。今回の証拠は専用の合成DB・一時ファイル・合成ブラウザに限る。使用中QAや既存会議、実録音、実モデル、OS許可、CIには触れていない。

## 書き出す本文と保存先

書き出し要求は会議・操作ID・保存済み本文の版とハッシュだけを持つ。高度編集用のJSON、議事録の旧版、根拠項目、生成時の文字起こしは不要。空の人間本文、改行コード、Unicode、HTMLのような文字列、リンク、末尾の空白をUTF-8のまま保存し、見出し・日時・注釈を付加しない。

保存先選択の前と、選択後の書込み受付時に本文を照合する。選択中に保存済み本文が変わった場合は外部ファイルを変更しない。受付後は固定した本文を書き出し、外部ファイルの永続書込み中はDBロックを保持しない。アプリ管理領域、リンク、変更された保存先等を拒否する既存の安全な保存処理を共用する。

結果記録には本文と出力のハッシュ、容量、保存先と成否を残すが、議事録の旧本文コピーは作らない。書き出し済み操作の再要求は既存記録を返し、外部ファイルを再書込みしない。公開済みか不確かな障害は成功とせず、失敗・未確定のまま保持する。再起動時の未完了書込みも成功扱いにしない。

## 応答が失われたときの操作

通常はダウンロードアイコンから書き出す。未保存の本文は、保存、破棄、取消を明示的に選んでから進む。二重クリックは同じ処理へまとめ、保存先選択中は競合する画面操作を止める。

応答が失われた場合は同じアイコンを「書き出し結果を確認」に変更する。この操作は結果の読取りだけであり、保存先ダイアログや書込みを再開しない。確認済みの成功だけを成功通知にし、不正な会議・操作・本文ハッシュ・出力ハッシュ・容量・状態の応答は受け入れない。

処理が終了し、結果記録もないと確認できた場合だけ、次の明示クリックを再試行に使う。同じ保存済み本文なら元の操作と条件を保ち、本文が更新されていれば新しい操作を新しい本文へ固定する。結果未確認の段階では条件を変更しない。結果照会の前後で処理中かを確認し、照会中に処理が終了して記録を見逃す競合では再照会を必要とする。

既知の応答が返り、画面が表示され、ボタンが有効で他のモーダルやフォーカス先を妨げない場合だけアイコンへフォーカスを戻す。タイマーやフォーカス処理からの自動書き出しはない。幅1280pxと360pxで隣接アイコンの32px高さと画面幅を確認した。
