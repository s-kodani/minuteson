# 未確定話者名の回復保存基盤と保存キュー

2026-10-07に、未確定本文と同じ回復記録へ入力途中の話者名を保存する処理と、名前に対応したクライアント側保存キューを追加した。確定済みの話者名・本文・Undoは変更せず、現在の下書きと独立した版番号で保存する。名前の入力画面と回復確認画面への接続は残り、実際の名前入力は引き続きメモリー内に保持する。M3-08と計画全体は進行中である。

## 保存形式と互換性

名前には話者ID、入力開始時の表示名と上書きの有無、現在の入力値を対応付ける。本文と名前を同じ要求・回復版番号へ保存し、名前だけの記録も扱う。同時100話者名、開始時の表示名と入力値はそれぞれUnicodeの文字数で200文字までとし、基底と本文を含めた全体の4MiB上限を維持する。空の名前や開始時の表示名がない入力も保持できる。

名前を含む通常記録は形式版3とする。本文だけの記録は形式版1、確認付き破棄は本文と名前が空の形式版2を維持する。名前がない場合は新しいJSONフィールドを省略し、旧形式の正本バイト列と内容ハッシュを変更しない。名前フィールドがない従来の保存要求も受け付ける。

名前の件数・長さ・重複・解析版への所属を検査し、ID順に正規化して保存する。形式版1に名前がある記録、名前がない形式版3、名前を残した破棄記録、未知の項目や所属不明な話者は拒否する。改変したJSONに新しいハッシュを付けても、通常読み取りとバックアップの整合性検査で拒否する。

## 保存と破棄の境界

同じ操作IDの再試行は本文と名前の両方を照合し、開始時の表示名・上書きの有無も含めて要求内容の変更を拒否する。空の記録へ版を進めた後は、遅れて届く古い保存要求で入力を復活させない。確認付き破棄は確認した記録のハッシュと版番号を証拠として残し、本文と名前を同時に空にする。

下書き保存・Undo・解析候補の採用後も、以前の基底と名前を読み取り用に保持する。版や内容の異なる旧入力を現在の名前へ自動適用しない。非アクティブな旧下書きも一覧・詳細・確認付き破棄の対象にできるが、旧版を有効化せず、現在の解析結果・下書き・回復入力を変更しない。一覧の入力件数は本文と名前の合計を返す。

書込み停止中は通常保存・同じ要求の再試行・破棄を拒否する。一覧と詳細は再起動後も読み取れる。回復保存自体は編集履歴を追加しない。

## 本文と名前を扱う保存キュー

保存キューは本文と名前を同じ版付き要求に固定し、送信中の入力で以前の要求を変更しない。新しい入力は確認した結果の次の版へ保存する。名前の開始時の表示名・上書きの有無・入力値まで結果を照合し、不一致なら要求と最新入力を保持する。名前がない要求と記録では新しいフィールドを省略する。

応答喪失時の結果確認は読み取りだけを行い、最新の本文や名前を送らない。明示再試行では元の操作ID・条件・入力を先に解決してから、新しい入力を次の要求へ進める。空にした名前を古い応答で復活させず、下書きが進んだ後も入力開始時の名前を保持する。件数・文字数・UTF-8容量の上限超過は操作IDを割り当てる前に拒否し、入力を保持して修正できる。

名前だけの回復記録も確認待ちにし、編集再開には所有・版・内容・現在の基底が一致する新しい読戻しを要求する。確認付き破棄の結果には名前が残っていないことも要求し、不完全な消去を成功として扱わない。

本番の編集コントローラーは、本文専用の回復画面が名前を含む記録を部分的に再開して名前を消さないよう、画面接続完了までその読み込みを拒否する。入力と記録を保持する保護であり、名前のプレビュー・再開画面が完成したという意味ではない。

## バックアップと追加復元と完全削除

名前を含む記録もバックアップと追加復元の整合性検査へ接続した。復元先では話者IDを再対応付けし、名前と開始時の表示名は変更しない。名前や本文に自然文として含まれる元IDも置換しない。基底と記録のハッシュを再計算するが、破棄証拠の元ハッシュは歴史的な証拠として保持し、新しい削除許可へ読み替えない。

完全削除の確認範囲は名前だけの回復記録も含む。名前の更新で対象の指紋が変われば以前の同意による削除を拒否する。正しい範囲への削除では回復記録を除去し、対象外の会議と端末設定を保持する。DBとWAL内の除去は検査対象とするが、外部バックアップや物理記憶媒体からの消去は保証しない。
