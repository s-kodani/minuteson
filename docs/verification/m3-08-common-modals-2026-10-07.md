# 確認モーダルの共通化と操作保護

2026-10-07に、既存のHTML確認ダイアログ13か所を共通部品へ接続した。仕様14.18.1の初期キャンセルフォーカス、Escapeと背景クリック、フォーカス保持、単一表示と小画面の余白を統一し、各操作の対象・同意・版番号・応答未確認時の保護を維持する。模擬IPCを使った実ブラウザ216ケースとフロントエンド189件が成功した。録音停止を含む既存の`window.confirm`の置換、通知・説明の共通化とmacOS WebView統合は残り、M3-08と計画全体は進行中である。

## 接続した画面

対象はバックアップと追加復元、保存先変更を共有する確認画面、中断データ対応、会議完全削除、音声だけの削除、モデル本体削除、音声取り込み、文字起こし候補、議事録候補、発言分割、話者追加、モデル対象の読み取り専用確認、モデル適用、再配置モデルでの再試行である。文字起こしの通常編集画面をモーダルへ移す変更ではない。

`CommonModal`はHTMLの`dialog.showModal()`を使い、背景を操作できない状態にする。共通キャンセルを本文より前に置き、長い一覧でも最初に操作できるようにする。キャンセルが読込中のため無効なら見出しへフォーカスし、読込終了後にキャンセルへ移す。利用者が既に入力欄へフォーカスした場合は移さない。TabとShift+Tabは表示中の有効な操作を循環し、見出し上のEnterで実行しない。

Escapeと背景から始まるクリックは既存の取消関数へ渡す。ダイアログ内の余白クリックや、内側から外側へのドラッグを取消と取り違えない。閉じた後は操作元へ戻し、操作元が消えた場合は元の画面の主見出しへ戻す。保存や共有操作で操作元が無効な間は、指定された完了条件を待つ。文字起こしと議事録のプレビューは閉じた後も共通部品を保持し、処理の終了と操作元の有効化を待ってから戻す。

HTMLモーダルは一度に一つだけ表示する。別の確認要求は既に開いている確認が実際に閉じるまで待つ。標準幅480px、最大幅560pxと24pxの余白を共通CSSで指定し、長い本文は内部で縦スクロールする。幅と高さの計算はスクロールバーを除いた表示領域を基準にする。候補比較は一列に並べ、現在版と候補版の見出しを保持する。

## 操作の同意と応答未確認時の保護

共通部品はネイティブ命令を発行せず、確認ID・操作ID・同意・版番号を生成しない。削除・復元・移動などの各コントローラーが既存の実行判断を保持する。実行中のEscape・背景クリック・共通キャンセルは拒否し、終了・取消完了を確認してから閉じる。

削除や共有データ操作の応答が未確認な場合は、従来の同一要求再送・読取り確認・書込停止を維持する。モデル適用と再配置モデルの再試行は、従来どおり未確認の操作IDを保持して確認画面を閉じ、後で元の要求を再確認できる。閉じることを新規操作や確認済みの結果へ変換しない。音声取り込みの入力破棄、生成版の採用などに残る`window.confirm`の判断も維持し、今回の共通化による省略は行わない。

共通部品では、初回検証でTabがブラウザの操作領域へ抜ける現象を再現して循環を追加した。実部品の検証では、採用後に操作元が消えた際の戻り先、復元後の無効な操作元への復帰、読込終了後の初期フォーカス、小画面のスクロールバーによる余白不足を修正した。モデル確認などの既存テストは、初期見出しフォーカスからキャンセルフォーカスへ期待値を変更した。命令・同意・ページングの制限は削らず、読み取り専用画面のボタンはキャンセルと前後ページだけであることも検査する。

文書・議事録の採用と取り込みの入力破棄に残る`window.confirm`は、検証用の決定応答で確認する。これらを共通HTMLモーダルへ置換済みとは扱わない。旧ブラウザfixtureには、現在の画面が必要とする読み取りAPIとウィンドウ情報を補った。検証入力の更新であり、本番のAPI保護は変更しない。

最終フロントエンドの型検査を含む`npm --prefix app run build`と`npm --prefix app test`は終了コード0。追加の背景座標判定1件を含む189件が成功し、スキップはない。既存の500kB超チャンク警告は残る。Rust・Swift・PythonとWindows workflowのソース変更はないため、今回の検査ではネイティブ側を再ビルドしていない。直前の全体検査は[テーマ設定の保存と編集状態の保持](m3-08-themes-2026-10-07.md)に記録した別実行の結果である。

## 残る実装と受け入れ条件

録音停止と明示終了、用語削除やラベル統合、再試行、生成版の採用等の`window.confirm`は今後置換する。ミニパネルの停止確認は小さなWebView内へ切り取らず、仕様14.19の独立した確認ウィンドウへ接続する必要がある。今回のHTMLモーダル単一表示の確認だけでは、この二画面間の仕様を満たしたとは言えない。

成功・注意・エラーのトースト、見出し横のinfoポップアップ、固定ヘッダーと本文スクロール、文字サイズと再生追従設定、ショートカット、全画面のキーボード操作とアクセシビリティ、macOS WebViewの実操作統合を続ける。長時間録音・異常履歴の解決・配布と手動更新・先行試用も計画全体の残件である。正式評価・10話者とWindows固有部分はユーザー指定により保留し、Windows CIは無効のまま実行しない。
