# PC音声が無音の場合の録音保存と議事録生成の修正

## 修正内容

通常録音の終了で、PC側から音声サンプルが届いていないことだけを保存失敗にしていた。PC音声の取得開始と停止が成功し、失敗や書込みがなく、同じ録音所有者の空の原音声記録が閉じている場合は、実際に取得したマイク音声だけを保存する。架空のPC音声ファイルや無音フレームを作らない。両入力の取得終了時刻、保存音声の共通原点、原音声とFLACの照合は維持する。

PC側が無音なのか、取得が許可されていないのかを、サンプル数だけでは判定しない。権限拒否、取得切断、停止失敗、書込み失敗、所有者の不一致、終了していない原音声記録、既存PC音声ファイルとの矛盾は引き続き失敗として扱い、マイク音声を自動削除しない。取得停止と書込み確定の両方が失敗した場合は、停止の原因も保持する。

議事録JSONの文字列内にそのまま入った改行、復帰、タブだけをJSONのエスケープ表現へ変換する。Markdownとしての文字列内容は変えない。その他の制御文字、不完全な出力、重複キー、別のJSONやログの混入は拒否する。報告と同じ制御文字エラーになる合成入力を自動テストで再現したが、使用中のモデルの実出力を確認したものではない。

設定画面のモデル選択欄は、隣接ボタンと同じ40pxの高さ・13pxのフォント・20pxの行高に揃えた。WebKitの標準セレクトが高さ指定を反映しない問題を避けつつ、選択欄自体の操作と強制色モードの標準表示は維持する。設定画面の「本文と再生の表示設定」を除去した。「編集の保存を確認中」「操作を実行中」の定型通知は表示せず、保存待ち・重複操作防止・失敗通知は維持する。その他のSonner通知と通知一覧は変更しない。

## 自動検証

Swiftでは音声機器を使わない取得ドライバーで、無音のPC取得の開始・停止、両入力の終了証拠、空の原音声記録の確定、停止と保存の失敗保持を確認する。Rustでは合成マイク音声の保存、マイクだけのFLAC登録と音声計画の読戻し、データベースを閉じた後の再起動相当の読戻しを確認する。PC音声の矛盾、取得失敗、所有者・終了・原点の不正も拒否する。

途中のRustテスト失敗は、合成録音の想定終了時刻と、再起動相当の確認で旧データベースを閉じず二重に開いたテストの誤りだった。Swiftの途中失敗は、合成ファイルの非正規パス、非同期処理の検査記述と、停止失敗が無音エラーに隠れるケースだった。停止原因を保持する本番処理も修正した。失敗した実行を成功件数へ加算しない。

ブラウザーはPlaywrightでWebKitとChrome系を確認し、モデル選択欄を明暗テーマと1200・800・390pxの幅で実測した。削除した設定と定型通知がなく、生成中の重複操作防止とヘッダーの高さが維持されることも確認する。これは合成IPCの画面検査であり、Mac実録音や実モデル生成の成功ではない。

最終Swift60件が成功した。フロント単体はQA用の確定済みソースで917件、未完了の再生成実装を含む作業ツリーで921件が成功した。型検査とフロント構築も成功。WebKitとChrome系は各10条件が成功し、結果は `output/playwright/model-height-quiet-ui-final-webkit/` と `output/playwright/model-height-quiet-ui-final-chrome/` に残す。

最終作業ツリーの関連Rust92件が成功し、専用子プロセス等の16件は通常実行ではignoreを維持した。生成JSON、録音時計、FLAC保存・検証・再起動・復元と解析工程が対象で、未完了の再生成実装に関する既存の関連検査も含む。Rust全体や実機録音の成功とは扱わない。

フロント検査の途中失敗は、除去した設定に依存するソース検査の期待値、QA専用領域に残っていた古い検査ファイルと一時的な構築スクリプトの差異だった。現在の操作とソースへ検査を揃えて再実行した。入力保護や保存・削除の内部検査を退役したわけではない。

## 工程時間

実装・調査・検査修正・記録は約45〜55分の概算で、個別計測していない。並行工程があるため、以下の累計を総経過時間として扱わない。

Rustテスト用構築は4回で409.54・59.96・382.04・377.53秒、計1229.07秒。QA構築は143.95・9.43（失敗）・152.13秒で計305.51秒。同梱ヘルパーの別構築15.20秒、フロントの別構築5.62秒。Swift検証の成功した構築は計20.45秒、構築前の制限と検査コードのコンパイル失敗は計5.59秒。計測済みの構築工程は計1581.44秒、約26分21秒。
