# 議事録生成の軽量化と工程内表示

対象: `plan/minutes-generation-performance.md` の段階0・1・3。

## 適用範囲

新規の製品ジョブを `compactEvidenceV3` に固定する。Legacy / InlineEvidenceV1 / InlineEvidenceV2 の指示文・入力形式・生成計画は保持する。進行中の `cc6948ca-e0cd-48d5-a300-d873fe3eb76b` のパラメーター、チェックポイント、プロセスには変更を加えていない。

V3では再生リンクの開始を秒未満切り下げ、終了を切り上げる。表示とURLを同じ秒単位にする。`start` / `end` と `partial:false` を省き、本文・話者名・`partial:true`・会議名・開始日時を保持する。発言分割は全文のUTF-8バイト列を漏れなく処理し、100発言上限・可変の最大出力配分を維持する。元の録音・文字起こしのマイクロ秒値は変更しない。

書式の警告判定は固定したプロンプト版のリンク一覧と照合する。旧ジョブの小数秒リンクも従来どおり判定する。書式不一致は本文を保存して警告し、不完全JSONは保存しない。

録音末尾を秒単位に切り上げたリンクは、終了が録音長の**ちょうど秒単位の切り上げ値**の場合に限り実際の終端まで再生する。開始が終端以降、さらに長い終了、超過した小数秒リンクは有効にしない。再生APIへ渡す値も録音長内に収める。

## 計測

`llama-completion` のログ詳細度を3にし、成功した各CLI実行のディレクトリーへ `performance.json` を新規作成する。

- モデルと実行ファイルのSHA、threads、gpuLayers、contextTokens、predictionTokens、入力バイト数。
- アダプター全体、検証・入力準備、プロセスspawn、初回stdoutまで、結果確認の各時間。
- 固定エンジンが記録する入力評価時間・実トークン数・tokens/s、出力評価時間・decode runs・tokens/s。
- b11533の `generate: n_ctx` 時点のネイティブログ時刻をエンジン初期化時間として記録する。読み取れなければnull。
- `nativeLoadMs` はエンジン報告の生値。今回のエンジンでは入力評価を含む値になり得るため、モデルをディスクから読む時間とは解釈しない。`spawnMs` は子プロセス起動の時間であり、モデル初期化時間ではない。
- 実際に選択したMetalデバイスと正のオフロード層数がログから読めた場合にだけ記録する。単なるデバイス列挙をGPU利用の証拠にはしない。
- ピークメモリとスワップ差分は現実装では未取得のためnull。推測値は入れない。

`unit-performance.json` では、管理モデルの照合を含む準備、推論、結果再検証、成果物登録を分離する。最後に使用した処理ディレクトリーの `attempt-performance-<uuid>.json` へ、今回の起動での事前検証・再生、チェックポイント保存、最終検証、本文公開、全体時間と終了状態を記録する。再開後は今回の起動分で、以前の時間を合算した値ではない。既に全工程が終わっていてCLIを起動しない復旧では新しい計測ファイルは作成しない。

診断ファイルに会議本文やプロンプトを複製しない。成果物の4ファイル・ハッシュ照合・保存成功判定には組み込まず、診断ファイルの書込失敗で正常な生成を失敗扱いにしない。未完成の生成を診断情報から復元・公開しない。

既存の `解析中 2 / 10` と20%を維持し、`3工程目：入力を解析中 · 経過 5分20秒` を追加する。初回stdoutの後は本文生成（統合なら下書き統合）、続いて確認・保存を表示する。経過時間は単調時計の実測と受信後の経過で表示する。エンジン内部の入力消化率は推定しない。停止・完了・別試行・完了済み工程の通知は表示へ適用しない。
