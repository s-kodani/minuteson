# 現行DBの検査と新規DBの初期化

既存DBに不足するスキーマ定義を追加する処理を削除し、空のDBの新規作成と現行DBの検査に分けた。旧形式を現行形式へ更新しない。現在のスキーマ31、保存された履歴の版とSQLハッシュ、新規作成時の単一トランザクションは維持する。旧構造化記録の読取りや別の一時台帳の旧更新は別の整理残件で、旧互換処理全体の削除完了ではない。

## DBの受付条件

通常起動は排他モードを指定し、DBの状態を検査してからWAL設定・録音と解析の回復・削除後処理・一時領域の整理を開始する。現行DBは不足分のSQLを追加せず読み取り検査だけとし、回復処理そのものは従来どおり行う。未完了の削除がある現行DBでは、その書込停止と保存済み同意の保護を維持する。

新規作成できるのは、内部オブジェクト以外がない空のDBだけ。履歴表だけのDB、既知の履歴がなく表があるDB、旧1〜30のDB、将来版・ハッシュ変更・欠番は修復・更新しない。未知のファイルやデータを自動削除しない。初期化のSQL定義は現行の新規DBを作るために残し、既存DBへ適用する途中開始位置は削除した。現行履歴に対応する各機能の構造・内容・所有の検査は従来どおり維持する。

## 検査の変更

旧会議・下書き・ジョブ・取り込み・配置を更新して成功する専用検査と、旧27の別リビジョンから生成した素材の更新検査を削除した。現在の本文・話者編集、資産、モデル履歴、復元記録・通知の保持を確認する検査は、現行DBの再起動へ変更した。旧形式の拒否とファイル保持の検査は残す。

新規初期化には、旧1〜30の拒否、未知の表・履歴の拒否、全テーブルの行と履歴の再呼出し後の一致、段階31のSQL拒否での全巻戻し、commit拒否と明示再試行、検証用子プロセスの段階1・17・31でのSIGKILLと正常な初期化再試行を加えた。SIGKILLは所有する合成DBの子プロセスだけで、実録音や既存会議の強制終了ではない。

関連Rustは主抽出で286件成功・失敗0件・子プロセス専用11件ignore、補足で143件成功・失敗0件・子専用1件と実素材が必要な3件ignore、合計429件成功。変更した検査名を実行ファイルの一覧とも照合した。当初の抽出指定の一部はファイル名と実際のモジュール名が異なっていたため、その範囲を補足している。素材が必要な3件はWhisper・Sherpa・ネイティブ音声形式の実実行であり、今回の合格に含めない。全Rust検査の合格ではない。

初回Rust構築は検査の定数参照が不足して失敗した。修正後、さらに旧更新を前提にする検査が見つかったため、テスト専用構築を明示的に中断してまとめて整理し、主抽出と補足を実行した。補足の待機プロセスもモジュール名を確定する前に一度取り消したが、その時点では構築・検査は未開始だった。

作業ツリーの初回・最終と構築用ソースの最終単体は各867件成功。構築用の途中検査は、一時的に録音・話者埋込みヘルパーを既存キャッシュへ参照させた構築設定のため865件成功・2件失敗だった。構築後に設定を戻し、検査を緩めず867件成功を確認した。型検査とフロント構築、2回のQA構築も成功している。未使用項目に関する警告は残る。
