# 録音開始とアプリ終了の共通確認

録音開始1か所とメイン画面の終了判断3か所を共通確認へ接続し、本番フロントエンドの `window.confirm` をなくした。録音中の明示終了は独立した録音確認ウィンドウを使い、保存成功後だけアプリ終了へ進む。正式評価とWindows固有部分は保留のまま、M3-08と実装計画全体は進行中である。

## 録音開始の対象と同意

確認には選択した会議名、マイクとPC音声の保存、参加者の同意と権限、解析の安全な一時停止を示す。取り込み中や音声選択の確認がある場合は、取り込みの取消範囲と元ファイル・保存済み会議の保持も示す。初期EnterとEscapeではキャンセルし、録音を開始しない。

開始の重複要求を防ぎ、未保存編集を保存した後に、会議ID・会議名・版番号・下書き状態・取り込みトークンと録音状態を再照合する。確認後の変更と編集保存失敗では開始を送らない。開始受付の応答喪失では同じ確認から再送せず、正準の準備中状態と失敗表示を保持する。Rust側も未完了の録音確認と別録音を拒否し、既存の録音開始・終了の共通ロックを維持する。

## 録音終了とアプリ終了の連携

録音中の明示終了はメイン専用の終了意図を録音確認IDに固定する。停止だけの既存確認を終了確認へ暗黙に変更せず、キャンセルと保存失敗では終了へ進まない。実際の保存成功を観測した同じ確認IDだけが、アプリ終了の継続通知を一度取得できる。フロントエンドもID・保存完了・終了意図と録音状態を検査し、停止命令を再送しない。

すでに停止・保存中の場合は、保存成功まで待つことを別途明示確認する。待機中はEscapeで閉じず、同じ録音を読み戻すだけで停止を追加送信しない。キャンセル後に保存が完了しても自動終了しない。保存失敗・古い状態・別録音・期限超過ではアプリと保存状態を保持する。

メイン画面を閉じるだけで録音を続ける既存動作は維持する。OSからのミニ画面閉鎖を録音確認へ接続すること、保存失敗からの再保存とmacOSの実際のウィンドウ操作は残件である。

## 取り込みとデータ処理の安全な停止

取り込み・バックアップ・追加復元・保存先変更・回収・会議削除・モデル削除・音声削除の終了確認を一つにまとめ、各操作の保持範囲と不可逆な損失を示す。解析やモデル準備がある場合も、安全な区切りでの停止と保存済み結果の保持を示す。

編集保存後に対象トークン・操作種類・確認内容を再照合し、同じ取り込みとデータ処理へそれぞれ一度だけ取消を送る。受付の応答ではなく、実際の停止を読み戻してから終了へ進む。停止より先に確定した公開結果は保持し、取消成功による巻き戻しとは扱わない。応答喪失・対象変更・読戻し失敗では再送と自動的な終了継続をしない。

メイン画面の終了要求は最終の取り込み・データトークンをRustへ渡す。解析の新規受付を封じた後、各コントローラーのロック内でトークンを検査し、不一致ならそのコントローラーの取消・選択破棄を始めない。既存の保存先切替後や削除回復後の専用終了ボタンは従来の経路を維持し、この追加トークン付き経路の検証とは区別する。

## 検証結果

実施日は2026-10-07。利用者の音声・モデル・設定・マイクと実際の録音プロセスは使用していない。画面試験は本番React部品と模擬IPCを使うPlaywright CLIで行った。

- フロントエンド単体テスト226件が成功し、失敗・スキップはない。
- 録音開始・終了の追加22ケースと、共通録音確認12ケースを含む25組・337ケースが成功した。既存の削除画面でも不可逆な損失表示と実際の停止待ちを確認した。
- Rust全体は1,251件成功、失敗0、既存の環境依存・親から起動する子専用35件がignoredとなった。追加7件で終了トークンの厳密な照合、変更された対象への取消なし、解析受付の封鎖と未確認処理の保持、保存後だけの単一終了継続を検査した。
- `npm --prefix app run build`、`cargo fmt --check`、`git diff --check`は終了コード0。500kB超のチャンクと `__eh_frame` の既存警告は残る。

ログは `/private/tmp/mon-confirm5-tests-final.log`、`mon-confirm5-build-final2.log`、`mon-confirm5-rust-full.log` と `output/playwright/application-close/regression/*.log` に保存した。テストの返却件数と結果配列を照合し、失敗した検証ランナーの形式処理・読み込み待ちと合成設定の不備を修正した後の成功結果を集計した。
