# 保存区間の話者特徴量抽出

保存済み音声の指定範囲から、話者の特徴量を別プロセスで実抽出するmacOS用ヘルパーと製品側の呼び出しを追加した。実モデルを使った合成音声で再現可能な抽出と元音声の不変を確認した。保存区間別ジョブ・再試行・追加復元・話者候補・自動工程への接続は残り、欠損付き話者分離全体の完了や話者精度を示すものではない。

## 音声範囲とネイティブ資源

`probes/speaker-embedding` の標準ライブラリだけのRustヘルパーは、16kHzモノラルPCM16の44バイトヘッダーを持つWAVから指定した半開区間だけを読む。最大30秒、空範囲・範囲外・異なる形式・切断・追加チャンク・リンクを拒否し、無音を補充せず音声を変更しない。

sherpa-onnx 1.13.8のC APIと同版のローカルヘッダーの構造・関数宣言を照合した。版と必須シンボルを確認した後、CPU推論を行う。埋め込みベクトル・ストリーム・抽出器・ライブラリを逆順に解放する。短い音声・有限でない値・ゼロのベクトルは取得不可として保持し、人物や本人識別の確率を作らない。

JSON形式版1は、エンジンと版、16kHz、開始・終了フレーム、次元、取得状態と理由を含む。有限な特徴量を小文字8桁のIEEE 754 binary32ビット列で保存し、丸めずに復元する。製品側は余分な項目・重複項目・必須項目の欠落・複数JSON・未知の状態や理由・範囲や次元の不一致を拒否する。

## 固定条件と子プロセス

`diarization/embedding.rs` は抽出ヘルパーを別の固定指紋として扱い、旧 `SherpaConfig` や管理モデルのファイル構成を変更しない。抽出ランタイムは固定エンジンの申告済みライブラリに一度だけ含まれる必要がある。ヘルパー・モデル・申告済みランタイム・WAVのSHA-256を実行前後で照合し、実行中のサイズ・更新時刻・実体識別子も確認する。

継承環境を消してロケールを固定し、入力を閉じた子プロセスを所有する。取消・制限時間超過・異常終了・出力上限ではkillとwaitを行う。標準出力64KiB・標準エラー1MiBの上限を実行中と終了後に確認し、開いた出力ファイルの実体を照合する。検証済みの出力だけを返し、取消後に部分結果を公開しない。

## 合成音声と実モデルの検証

ヘルパーの通常・模擬連携9件は先行検査と最終全体検査の両方で成功した。三秒の選択範囲の値・サンプル数、取得不可、nullハンドル、不正次元・準備状態、モデル改変、解放順、実ヘルパーCLIのビット列、版違い・必須シンボル欠落の拒否を含む。実モデルの別検査1件も成功し、同じ220Hzの合成PCMから二回とも同一ビット列を得た。先行記録は `/private/tmp/mon-native-embedding-fake1.log` と `/private/tmp/mon-native-embedding-real1.log`。同じ検査の再実行を重複加算しない。

製品側の最終実モデル別検査1件は成功した。署名済みヘルパーを二つの独立した出力領域へ起動し、同じ合成音声の範囲から同一出力を得た。保存JSONの読戻し、元WAVと固定したモデル・ランタイムの再照合も成功した。記録は `/private/tmp/mon-embedding-parent-real-final1.log`。先行する `/private/tmp/mon-embedding-parent-real1.log` と同じ1件の再実行であり、重複加算しない。実録音・実会議の特徴量や話者対応付けの品質を検査した結果ではない。

実モデルは以前取得した `3dspeaker_speech_eres2net_base_sv_zh-cn_3dspeaker_16k.onnx` を使用した。モデルのSHA-256は `1a331345f04805badbb495c775a6ddffcdd1a732567d5ec8b3d5749e3c7a5e4b`、C APIライブラリは `ae729669633008692c670d4e4c942db7ea5bdc38abc2f479516062d48849e9d1` で、ヘルパー直接試験の前後も一致した。

## 全体検査と生成物の整理

最終製品ソースの `make check` は終了コード0となった。記録は `/private/tmp/mon-embedding-full-check1.log`。通常Rust1,554件成功・失敗0件・専用51件ignored、Swift101件中100件成功・既存1件skip、フロントエンド504件と型検査・ビルド、Python65件、CAF全4800フレーム、既存の専用Swift/Rust連携9件が成功した。話者対応付けの前段20件と特徴量出力の6件も通常Rustに含み、別件として加算しない。検査実行ファイルのリンク時には既存の `__eh_frame` サイズの警告が出たが、検査は成功した。

新しい専用連携ではヘルパー9件と製品側の親呼び出し1件が成功した。親の1件には、実際の子プロセスの取消・タイムアウト・標準出力と標準エラーの上限・異常終了後のkill/wait、モデルとWAVの実行中変更、モデル・WAV・ランタイム・所有したヘルパー複製の実行前改変の拒否を含む。上限超過とタイムアウトは該当するエラー原因も照合し、子PIDが残っていないことを確認した。先行記録 `/private/tmp/mon-embedding-parent-fake1.log` とは検査時点を分け、最終の強化した条件は全体検査の結果を採用する。

全検査プロセスの終了と一時領域を使うプロセスがないことを確認し、再構築可能な専用Rust生成物2,221,608KiBとヘルパー・模擬ライブラリ・独立検査実行ファイル3,956KiBを削除した。ログとリポジトリのソースを保持し、製品targetは38,664KiBのまま。保持したrelease四成果物のSHA-256は前後で一致した。

WindowsワークフローはGitHub上でも `disabled_manually` を確認し、実行・有効化していない。MONアプリ起動・実録音・正式評価は行っていない。

## ビルドと後続接続

明示した出力先へビルドし、アドホック署名を検証するスクリプトを追加した。Mac用ビルドと通常の `make check` に録音しない模擬連携を組み込み、検査用実行ファイルと模擬ライブラリは専用一時領域で作成・回収する。署名とビルドはDeveloper ID署名・公証・配布バンドルへの組込みを証明しない。

次に保存区間別の話者分離を実行し、重複しない音声範囲の特徴量を保存済み区間間の対応付けへ渡す。区間・モデル・途中成果物の固定、検証付き再開・再試行・復元、元の会議時刻への対応、手動話者割り当てを保持する候補公開と自動工程への接続が必要である。

正式評価・10話者・Windows固有部分は保留のままにする。Mac実機の録音・権限・長時間性能と配布も残り、計画全体は進行中である。
