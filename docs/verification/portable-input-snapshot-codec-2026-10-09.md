# 入力履歴と通知台帳の不変な移送データ

入力履歴・通知台帳・停止時診断を、元の録音側の証拠と、受付権限を外した通知保持範囲に分ける移送データの生成と読戻しを追加した。この基盤の段階では、バックアップ公開処理や復元後の通知一覧には接続していない。後続の接続と検証状況は[録音入力履歴のバックアップと追加復元](portable-recording-input-snapshots-2026-10-09.md)を参照。

## 元の証拠と通知保持範囲

元の取得履歴と、ライブ形式または保存後形式の通知台帳を、それぞれの元バイト列から型付きで検査する。録音所有、履歴の保持範囲、受付と表示確認、終了記録、重複項目を確認する。取得履歴の版と配送の版の大小で新旧を推測せず、両者の重なる遷移の一致を必要とする。

元の台帳には表示確認・終了の証拠を保持するが、これは不変な由来の記録であり、書込み用の台帳や受付APIとしては扱わない。別に生成する通知保持範囲は、表示確認のある先頭通知を取り除き、未表示の先頭通知の世代を進め、古い受取先・受付操作・終了受付を外す。未表示の後続通知、観測済み範囲と保持不足は残す。読戻しでも元の証拠から同じ保持範囲を再構成し、一致を検査する。

元録音所有は書き換えない。現在の入力状態・新しい報告年齢・音声保存の成功は作らず、新IDの録音や画面を受け付ける権限も与えない。受付世代の上限に達した未表示通知は、世代を巻き戻したり削除したりせず移送を拒否する。

## 音声manifestのない録音の保存診断

失敗録音などで音声manifestが管理ファイルとして登録されていなくても、停止時の要求版・確定版・保存結果・終了状態と元所有を保持できる形にした。任意のネイティブエラー文は保存せず、停止時の未確定を真偽値で残す。旧形式で診断も履歴も台帳もない場合は記録を作らず、成功へ変換しない。現在の履歴がない場合にも、元台帳が保持している履歴と整合不良の診断は維持する。

元台帳と配送用保持範囲はそれぞれ128KiB、元履歴は65KiBの既存上限を維持する。全体の移送データはこれらを別々に保持するため512KiBを上限とし、manifestの256KiB上限を変更しない。

## 検証結果

最終ソースの新規9件を含む入力状態・履歴・通知の関連検査は84件成功・専用4件ignoredとなった。元の書込み所有者を開いたまま、移送データの生成・読戻しで元台帳を変更しないこと、元の表示確認・終了証拠の保持、配送用の古い受付権限の除去、保持不足、別々の版番号、重なる履歴の矛盾、不正な所有・重複項目・必須項目欠落・容量超過・受付世代上限の拒否を確認した。

製品側の `cargo check --locked --offline` と形式検査は成功した。同じ最終ソースの保存先移動の回帰1件も成功し、2通りの通知確認状態で各2回の所有付き移動を維持した。ログは `/private/tmp/mon-portable-input-codec-input-frozen.log`、`/private/tmp/mon-portable-input-codec-production-check.log`、`/private/tmp/mon-portable-input-codec-move-regression.log` に保持する。前段の全体 `make check` とはソース時点と範囲を分け、重点検査を全体件数へ加算しない。既存のRust unwindテーブルの大きさに関する警告は残る。

検査用の再構築可能なRustキャッシュ約2.8GiBは、全検査の終了とプロセス・開いたファイルの不在を確認して削除した。ソース・ログ・利用者のモデルと製品target約38MiB、既存releaseは保持する。製品アプリの起動・実録音・正式評価・Windows CIは行っていない。

最初の重点検査では、矛盾する履歴を作る検査用データ自体が不正だったため失敗した。個別には有効で重なる履歴だけが異なるデータへ修正した。続く構築では追加の証拠比較をテスト内の誤った場所へ配置したためコンパイルエラーとなり、そのテストコードを修正した。製品側の履歴・台帳検査を緩めていない。失敗ログは `/private/tmp/mon-portable-input-codec-focus.log` と `/private/tmp/mon-portable-input-codec-input-final.log` に保持する。

## バックアップと復元への残る接続

この段階はバイト列の検査と不変な論理データの生成だけを扱う。共有データ保守中のDB所属に基づくファイル取得、固定したディレクトリと実体の再照合、アーカイブへの収録・検査・公開、復元先の新IDへの論理的な所属対応、復元先が所有する書込み台帳と受付、再バックアップ、復元後の要確認一覧は残る。元の取得履歴の所有IDを復元先へ書き換えて録音証拠を作り直す方法は採らない。

[終了済み録音の保存先移動](closed-input-companions-owned-moves-2026-10-09.md)と[停止時診断のバックアップ保持](portable-input-journal-diagnostics-2026-10-09.md)の範囲とは分ける。正式評価・10話者・Windows固有部分は保留し、計画全体は進行中を維持する。
