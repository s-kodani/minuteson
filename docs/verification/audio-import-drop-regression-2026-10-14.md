# 音声ドロップから通常の取り込み確認へ進む回帰検査

2026-10-14。現行の取り込み画面に、Tauriの `tauri://drag-drop` 合成イベントを渡すブラウザー検査を追加した。1件のローカル候補パスが `select_audio_import` へ一度だけ渡り、会議名を持つ通常の確認画面を開くこと、確認前には `start_audio_import` を呼ばないこと、破棄を明示した後に同じ選択を一度取り消すことを検査する。固定パスは模擬IPC内の識別子であり、実ファイルの読取りや保存はしない。

最終検査はChrome・WebKitの既存 `import` スイートが各12件成功。フロント単体864件、型検査とViteビルドも成功した。計測時間はChrome 7.59秒、WebKit 7.82秒、単体4.14秒、ビルド8.25秒。最初のChrome試行はPlaywrightラッパーがnpmレジストリへ到達できず70.32秒で失敗した。導入済みのCLIを直接使う前に、制限環境のキャッシュ書込み拒否と既存セッション不一致も観測した。待受け可能な環境で新しくブラウザーを開いて再実行した結果を合格とする。これらの時間は工程別の実測で、並列実行した単体とビルドを経過時間へ加算しない。

Finderから専用 `MON Download QA` への実機ドラッグは、操作ツールではFinderの外までファイルを保持したまま運べなかった。そこで利用者に `/private/tmp/mon-synthetic-flow-audio.iAJXQT/QA-generated-meeting-valid.wav` を1件だけ手動でドロップしていただき、「確認画面が開いた」と回答を受けた。手動ドロップで確認画面へ到達する経路の証拠として扱う。対象ファイルはPCM16・16kHz・モノラルのWAVで、確認後のSHA256は `ccc3316f158ff9691267f176c32039f51eb49d5faf79b21908f43e6f328bfa93`。保存は依頼していない。後のQA画面をこちらで読んだ時点では確認画面は閉じており、会議一覧は0件だった。選択パスやネイティブの形式検査結果を画面上で独立照合したわけではなく、ドロップ後の保存・解析も今回の合格範囲に含めない。録音・モデル取得・権限変更・CIは行っていない。
