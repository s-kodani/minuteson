# 会議完全削除のファイル一覧と実体の再照合

2026-10-05に、M3-07の完全削除に向けて、一会議のファイル一覧を固定し、DB・パス・内容・実体の変更を再検査する内部処理を追加した。読取専用の確認材料であり、一覧や集計値を削除権限・所有証明として使わない。ファイル削除と永続的な回復、DB段階への内部接続は後続の[会議ファイルとDBの削除接続](meeting-deletion-compound-2026-10-06.md)まで追加済みである。メイン専用APIは後続の[ネイティブ操作と共有実行制御](meeting-deletion-native-controller-2026-10-06.md)として接続した。利用者向けの確認画面は未接続である。

## 起動時の実体と保守開始

Storageを開く際に会議領域のディレクトリーを開いて保持し、SQLite接続後のDB実体と、起動処理後のWAL・SHM・ロールバックジャーナルの実体または不在を固定する。デバイス、inode、生成時刻、権限を照合する。確認直前に観測した別inodeを、キャッシュされたSQLite接続の元DBとして採用しない。

SQLiteを開く前にも既存のDB・制御ファイルを非追従で検査し、シンボリックリンク、共有ハードリンク、特殊ファイル、別媒体を拒否する。初期化のWAL設定や移行処理が外部リンク先を変更する前に止める。保守開始時の検査が失敗した場合はSQLite操作を拒否し、書込停止を維持する。この開始検査は既存のバックアップ・保存先移動にも適用する。すべての通常SQL操作に実体検査を追加したわけではない。

起動時のファイル実体はStorageの生存中保持する。旧形式DBと所有された復元一時DBを直接組み立てる既存テストも、実際の対象ファイルへ同じ実体検査を結び付けた。テスト用の固定一時DB名を通常の会議DBとして採用する公開経路は設けない。

## 会議内のファイル一覧

既存のDB削除範囲を検査した後、DB接続ロックを保持して `meetings/{会議ID}` を非追従で列挙する。ファイルとフォルダーのパス、実体、権限、サイズ、更新時刻、変更時刻、通常ファイルの実内容SHAを記録する。登録資産のID・登録時サイズ・SHA・状態も対応付ける。登録済みでも実体が欠落している場合は欠落項目として残し、存在するファイルと同じ容量を表示しない。登録パスがフォルダーへ変わった場合は拒否する。

ディレクトリーの記述子に対するopenat・fstatat・fdopendirで操作する。リンクを追跡せず、通常ファイルのopenにもNONBLOCKを指定して、検査中にFIFOへ変わってもブロックする読込を始めない。ファイルの読込前後の実体と変更情報、フォルダーの前後の列挙と変更情報を照合する。列挙には新しいオープン記述を使い、共有オフセットによる二度目の列挙漏れを避ける。

全ツリーを二度検査し、DB範囲と起動時の実体を再照合してから一覧のSHAを返す。再確認時も同じ手順を繰り返す。上限は20万項目、相対パス256バイト、深さ32、manifest64MiB。読込バッファは再帰フレームへ積まずヒープに確保する。ファイル本文・音声・会議名はmanifestへ複製しない。録音・解析・取り込み・生成・書き出し等の実行中、旧保存先の停止済み状態、別の保守操作中は確認しない。

この一覧の64MiB上限は内部確認材料の上限であり、保守操作の64KiB固定intentへそのまま格納する設計ではない。対象パスの別表と固定SHAへの結合は[確認対象の永続化](meeting-deletion-intent-2026-10-05.md)で追加した。観測の保存であり、削除権限として使わない。

## 未登録物と由来候補

途中の録音、取り込み、AI処理には、未登録の原音声・PCM・プロンプト・全文を含む結果・ログが残り得るため、登録資産だけで一覧を終えない。対象会議のDBセッション・取り込み・ジョブID、既知の形式と固定ファイル名が一致する場合だけ由来候補を付ける。生成途中のプロンプトや結果も一覧に含める。

由来候補は所有証明ではない。未知のID、未知のファイル名、近くの処理IDだけが一致する追加物を登録資産へ採用しない。欠落を含む対象ファイル総数、フォルダー数、欠落数、登録時サイズ・SHAとの相違、由来候補付き未登録物、候補不明物、実在ファイルの容量を区別して集計する。この集計だけでフォルダーや未登録物の削除を許可しない。

対象外の会議、モデル、領域直下の制御ファイル、外部へ書き出したファイルは会議ツリーの一覧へ取り込まない。管理領域全体を再帰削除する処理は追加していない。

## 検証

追加の通常Rust13件で、一覧とSHAの安定性、本文を含まないmanifest、他会議と外部出力の保持、欠落・登録時内容との差異・未知物の区別、未登録の3工程入力・結果・ログ、DB IDと一致する未確定録音・取り込みだけの由来候補を確認した。改名、内容変更、同一内容の別inode、追加・消失、権限変更、葉と親のリンク、ハードリンク、登録パスのフォルダー化、不正パス、深さ上限、FIFO、取消、読込途中の変更を検査した。

起動前のDB・WAL・SHM・ジャーナルの外部リンクは、SQLite初期化前に拒否して外部内容を変えないことを確認した。起動後の領域・DB・WALの差し替えは採用せず、保守開始の拒否後に書込停止を保つことを確認した。既存のDB削除17件と親から実行するSIGKILL用fixtureも、この追加を含むコードで成功した。これは確認材料と開始保護の検証であり、実ファイル削除の安全性を証明するものではない。

最終コードで `make check` は終了コード0となり、Python 65件、フロントエンド100件、Swift 9件、Rust通常677件、AVFoundation製CAF読出し1件が成功した。Rustの環境依存11件と子プロセス専用3件は通常実行ではignoredである。既存のSwiftPMキャッシュ権限警告とRustリンカーのunwind警告は残るが、検査は成功した。

## 残件と制限

確認対象と同意時刻の内部保存・読戻し・未開始対象の再照合は追加した。2026-10-06に[確認後と冷再起動後の書込停止と未開始データの保持](meeting-deletion-fence-2026-10-06.md)を内部接続した。続いて、未登録物を含める明示判断、固定対象だけの非追従削除、部分完了と削除途中の再起動回復を[会議ファイル削除と中断後の再開](meeting-deletion-file-removal-2026-10-06.md)として内部接続した。DB削除と後処理は[会議ファイルとDBの削除接続](meeting-deletion-compound-2026-10-06.md)として内部追加した。共有コントローラーとメイン専用APIは[ネイティブ操作と共有実行制御](meeting-deletion-native-controller-2026-10-06.md)として接続した。利用者の同意画面は残る。一覧のJSONを読み込むだけで検証済みCensusや削除の許可を構築できない。

会議ツリー外の一時構築領域、移動前の旧領域と保持コピー、実機の容量不足・電源断・長時間確認、実機WebViewの統合は未検証である。悪意ある同一ユーザーによる同時変更への完全な耐性、物理媒体やOS・利用者のバックアップの安全消去は保証しない。今回の実装は利用者の音声・会議・モデル・設定を削除していない。

正式評価、10話者・16GB性能、Windows固有部分とWindows CIの停止を維持する。M3-07と実装計画全体は進行中であり、完全削除を完成扱いにしない。
