# 現行形式だけを使うMac起動設定

起動時の旧保存先の自動採用、schema 1の起動設定の読取り、移動開始・中止時に旧形式へ変換する処理を削除した。現在のschema 2の設定と、保存先変更の所有確認・排他・切替後の再起動義務は維持する。SQLiteの旧スキーマ更新や旧構造化記録の検査は別の整理残件であり、互換処理全体の削除完了ではない。

## 変更した受付条件

新規の会議保存先はアプリデータ内の `data`、モデルは `models`、起動設定と配置台帳は別の管理領域を使う。初期化済みの場合は、現在の設定に登録された保存先の実体を照合して開く。schema 2で保存先変更済みの場合は、従来どおりネイティブの配置証明が必須である。

schema 1と旧 `legacy` 選択元は受け付けない。移動の開始・取消・途中コピー保持で、証明のない選択元を旧形式へ書き換えない。初期化記録がないのに旧位置 `app-data/meetings.sqlite3` に物がある場合も、自動採用・変換・空DBへの切替をせず非対応として拒否する。未知のファイルを旧データと推定して自動削除する処理は作っていない。

フロントの保存先状態も `default` と `relocated` だけにした。旧形式を採用・再開する成功検査は、現行データの作成・配置・失われた応答の再照合と、非対応形式をDBを開く前に拒否する検査へ切り替えた。現行形式のハッシュ計算と設定ファイルの書き出しは変更していない。

## 構築と画面検査

初回のRust構築は、途中コピーの保持処理にも残っていた `Origin::Legacy` 参照により失敗した。そこに残る旧形式変換も削除して同じ関連範囲を検査し、143件成功・1件失敗・子プロセス専用7件ignoreだった。失敗したのは、別の配置履歴検査が旧保存先の自動採用を前提にしていたため。これも現行の分離した保存先へ更新し、最終の同じ範囲は144件成功・失敗0件・子プロセス専用7件ignoreとなった。正常な新規初期化・旧形式拒否・モデル保持・配置・取消・応答喪失・実際の検査用子プロセスのSIGKILLと再起動を含む。Mac実会議の録音や異常終了の検証ではない。

作業ツリーと構築用ソースの単体は初回・最終とも各862件成功した。Chrome・WebKitは各38条件で、バックアップ・追加復元24条件、受付保護3条件、保存先変更11条件が成功した。確認・容量不足・取消・応答喪失・切替後の書込停止・再起動義務などを確認した。ブラウザの通信は模擬であり、Mac実ファイルの移動成功を示すものではない。

Chromiumでは開発サーバーの自動更新用WebSocketがブラウザのローカル通信保護により拒否され、faviconも404だった。ページのHTTP読込みと検査は成功しており、保護を解除する設定は行っていない。製品QAは開発用WebSocketを使わない。最初の検査サーバー起動もサンドボックスのローカル接続制限で拒否され、同じ専用ポートで承認環境から起動し直した。最後に今回の専用ブラウザ2つとサーバーだけを終了し、ユーザーのタブとサーバーは操作していない。

## 新しいQAとMacの起動確認

新しい通常QAは `/private/tmp/mon-bootstrap-current-only-qa.ccjcn0/MON QA.app`。主実行ファイルのSHA256は `c48f413b82fe34fc54af7daafb46705595883992a3894629594b2597017210cc`、41.02MiB。deep strict署名検査と、構築元のバンドルからの全ファイル比較は成功した。開発用アドホック署名で、公証済み配布ではない。ソース・検査・構築設定も作業ツリーと構築領域で一致する。

通常QAの既存設定はschema 2・`relocated`・配置証明あり・未完了移動なしだった。録音も編集も進行していないことを確認して旧QAを正常終了し、新しいQAを起動した。会議一覧20件を表示でき、設定からWhisper tiny・標準話者分離・Qwen 1.5B Q4の選択と導入済み一覧、従来の会議・モデル保存先を読めた。ダウンロードや使用設定の変更はしていない。

その後、Cmd＋Qで正常終了してプロセス終了を確認し、同じ新QAを再起動して会議一覧を再表示した。最初の起動後と再起動後をそれぞれSQLiteの一貫した読取りスナップショットで比較し、47テーブルの全行が変更前と一致した。会議数は20件、DB整合検査はokだった。起動設定ファイルのSHA256も前後で `aa26004e6897602aa0d6d2dc07d2c10ef7f18db59eaf97d07ede6b8aab845020` のまま。データの初期化・会議・音声・モデル本体の削除はない。

## 残対応

SQLiteの旧スキーマの更新、旧配置台帳・旧構造化記録などの互換性専用処理の整理を続ける。今回の起動確認を、全ての配置・異常終了・中断削除のMac実機合格と扱わない。旧データは削除可能という方針を維持し、実際の破棄が必要な変更では保存先と範囲を特定する。

残る旧処理整理は1〜3時間、Mac異常時統合は1〜2時間、残モデル候補の取得・CPU実行・切替は2〜4時間を見込む。モデル取得量は既存承認の上限と照合する。短い実録音の再試験10〜20分と4時間検証は実施時間の合意が必要。配布署名・公証・先行試用は外部準備待ち。

実録音・音声再生・OS許可変更・モデル取得・実推論・VoiceOver・CIは今回行っていない。正式評価・10話者・Windowsは保留、VoiceOverは対象外で、開発目標全体は未完了。
