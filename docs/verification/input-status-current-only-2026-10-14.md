# Mac入力状態の現行形式への統一

2026-10-14。通常録音用の入力状態通知を、履歴付きの `schemaVersion: 3` に統一した。Swiftは履歴なしの版2を生成せず、Rustも版2の読取りと旧通知の一時的な受付処理を削除した。通知は現行の永続キューへ一本化し、WebViewへの表示と音声保存の証明を混同しない。

## 変更した境界

- Swiftの通常録音はマイクの状態と履歴が揃う場合だけ入力状態を公開する。PC音声を扱う場合は、その状態と履歴の一致も確認する。不一致や履歴欠落は通知を捏造せず、音声そのものの保存判定とは別に扱う。
- Rustは版3の全必須項目・所有者・取得世代・履歴の整合を検査する。版2を受け付けるサイズ制限、通知の揮発的な重複管理、旧受付応答と録音側の分岐を削除した。Rustが画面へ返す状態は版4のまま。
- `make check-input-status` と `make check-input-history` は、連携検査で作る永続通知台帳の既知ファイルを専用一時ディレクトリから片付ける。予期しないファイルが残れば `rmdir` は失敗する。
- 既存の録音・会議・モデルのデータは変更しない。旧形式の録音を変換・復元するものではない。

初回の関連Rust 79件は75件成功・4件が専用素材待ち。旧版2を拒否し、現行版3の読込み・古い同一heartbeat・リンク置換・所有者と履歴の検査が成功した。最初のSwift連携では旧版2のテスト用生成経路が残っていることが判明したため、Swift出力も現行版へ統一し、その失敗を隠さず修正した。次の連携では通知キューが「復帰」の前に未表示の「中断」を送る現行FIFOと古い期待値が異なったため、現行FIFOを確認する期待値へ修正した。
