# 未完了音声の再同意と確認画面

未完了の音声削除で対象が変わった場合、共有操作コントローラーとメイン専用APIから現在の残り範囲を確認し、新しい同意を保存して続行できるようにした。[内部処理](audio-remaining-reconfirmation-core-2026-10-07.md)と接続し、元の同意・対象証拠・中断位置を保持する。M3-07と実装計画全体は進行中を維持し、正式評価とWindows固有部分は保留する。

## 操作と保存

ファイル削除の途中と利用不可確定前では、保存した対象を検証できない場合にだけ、現在の全範囲を検証して再同意へ進める。確認は読み取り専用であり、新しい同意も削除も実行しない。保持するDB範囲・元の同意・保存先とDBの実体を検証できない場合や、安全上限・リンクの検査に失敗する場合は、自動削除せず保持する。

未完了の場合は元の操作IDを保ち、`native_audio_pending` として新しい確認IDを発行する。完了済み削除・復元元の利用不可記録から別操作を作る既存の経路とは区別する。サーバーに保持した確認を実際の共有保守leaseで再照合し、同意追記と現在計画への切替が確定してからファイル削除へ進む。元操作を未開始状態へ戻さず、保持・中止ボタンも提供しない。

現在の未登録音声には新しい独立した判断を求める。再同意を保存した後は、その判断を読み戻して同じ操作を続行する。応答喪失時は同じ確認ID・判断の要求を再送し、新しい同意を重複保存しない。冷起動では保存された同意だけを採用する。

## 確認画面

画面は未完了であること、既に消した音声を復元しないこと、元の同意・証拠・中断位置を履歴として保持することを説明する。「完了済み」「新しい削除操作」とは表示しない。再確認・更新で確認IDが変わると、対象理解と未登録音声の両チェックを解除し、古い一覧・遅れて届いた応答を流用しない。

同意保存後に停止した場合は、保存済みの方針を変更せず残りを再検査する。編集・録音・AI処理の書込停止を維持し、再起動が必要な場合は手動再起動を案内する。音声だけの削除では、会議・文書・編集履歴・外部原本を削除しない。
