# 未確定本文の回復保存キュー

2026-10-07に、未確定本文の回復保存APIへ接続するためのフロントエンド保存キューを追加した。保存済み本文の編集キューとは独立し、入力の保存順、未確認の要求と読戻しを扱う。入力画面への接続はまだであり、この追加だけで現在の入力が異常終了後に回復できるようになったわけではない。

## 入力と保存要求の保持

下書きの所有ID・解析版・保存済み版番号・内容ハッシュ・基底本文を固定し、回復保存を直列化する。送信中の入力変更は次の要求にまとめるが、先行要求の本文・版番号・操作IDは変更しない。要求と読み取った保存結果は複製して凍結し、呼出元が渡したオブジェクトや古い保存応答による新入力の置き換えを防ぐ。

保存結果は所有、操作ID、回復版番号、基底本文と内容ハッシュ、現在の下書き、通常保存の形式版と入力を照合する。異なる結果や応答喪失では入力と同じ要求を保持し、通常のflushや再読込で要求を消さない。明示再試行だけが同じ旧要求を送り、その確認後に新入力の別要求へ進める。JavaScriptで安全に表せない版番号、不正な操作IDや形式は書込み前または応答照合で拒否する。

## 読み取りだけの結果確認と編集再開

結果確認は読取りAPIだけを使う。先行要求の完全な保存結果を確認した場合はその保存だけを承認し、後から入力した内容は送らない。保存済みの先頭が変わっていなければ、未保存または処理中の可能性を残し、要求とエラーを保持する。別の保存や下書き更新があれば、入力と要求を保持して明示的な再確認を求める。結果確認と再試行が競合しても古い読戻しで新しい承認を置き換えない。

既存の非空記録は確認待ちとし、読込みだけで編集入力へ戻したり上書きしたりしない。明示的な編集再開はもう一度読取りを行い、確認した記録の操作・版・ハッシュ・内容と、現在採用中の解析版に属する下書きの基底が一致する場合だけ入力へ戻す。旧版・非アクティブ・変更後の記録は自動適用しない。破棄済みの空記録はその版番号を保持し、新入力の比較更新条件へ引き継ぐ。

## 本文保存との接続条件

画面側では確定本文の保存前に回復保存を待ち、本文の保存結果を確認した後で新しい下書き条件へ進める必要がある。残る入力は新しい条件で回復表へ保存し、確定・取消済みの入力だけを除く。本文保存中の別の回復書込みを始めない制御、応答喪失時の再確認、画面移動と終了の保存待ちへの接続は画面側の残対応である。キューを破棄した後の遅い応答は、追加要求を送らず拒否する。
