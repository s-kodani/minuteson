# 形式版1の全列固定と完全削除前の保護

## 発見した境界

旧移動由来の形式版1は、会議参照を含む削除操作の全列ハッシュが一致するときだけ読み取る。現行の形式版2／3は同意・対象等の固定ハッシュも持ち、型付き検査の下で会議参照の分離や進捗を再検査する。この違いを起動読取の許可から、旧形式の変更許可へ読み替えない。

完全削除のDB工程では、保守履歴の会議FKが `ON DELETE SET NULL` によって変わる。移動した形式版1の保持／完了記録が同じ会議を参照している場合、その全列固定条件と衝突する。DB工程の拒否だけでは、先行するファイル削除を防ぐ根拠として不足する。今回、対象確認とDB工程の直前にこの条件を接続する。修正前の実行による失敗再現は今回行っておらず、コードと既存の全列固定検査から特定した境界である。

## 実装範囲

生存する選択済み起動承認の履歴対応に属し、固定ハッシュのない旧記録だけを、会議参照を外す予定のSQL対象と照合する。該当する記録は元の全列ハッシュとの一致を検査した上で、完全削除の新しい確認・意図作成より前に拒否する。元の会議・音声・履歴を保持し、現行版による保存先変更で新しい所有付きコピーを作り、現在の範囲への別同意を行う案内を返す。

全会議の削除を禁止せず、無関係な会議・新しい現行記録・音声だけの削除はこのFK分離の拒否対象にしない。現行形式の削除許可、元の全列固定、型付き履歴、取消、所有・版・共有lease等を緩めない。対象確認・保存済みの確認／除去範囲再検査と、DB削除トランザクションの前の両境界で照合する。

再移動は既存の本番機能である。新しい実コピーと全履歴の再照合を経て現行形式の所有対応を作り、元の操作行・同意・対象・制御記録を書き換えない。古い保存先や音声を削除しない。新しいコピーでの完全削除は、新しい確認・共有lease・現在の保存先の範囲への同意で行う。画面・設定・ボタン・IPCは追加しない。

これは旧形式すべての修復・移行ではない。既に再出現・破損・変更されている履歴や、途中まで実行した削除、コピーに必要な容量不足は別の解決が必要で、未知データや古い同意を自動採用しない。

## 合成検証

通常Rust2件を追加した。

- 保持音声・完了音声・保持会議の3ケースで、形式版1を実際の所有付きコピー・配置台帳・本番切替・冷起動へ通す。完全削除の確認を拒否し、新しい意図を作らず、全保守行・対象行・会議ファイル・元制御記録を保持する。無関係な会議を新しい同意で完全削除し、次の冷起動も通常の書込みが可能であることを検査する。
- 形式版1の保持音声・保持会議を持つ起動選択で完全削除を拒否した後、現行版の本番再移動で形式版3と固定ハッシュを持つ新しい対応を作る。再移動前後で全操作・対象行が同一、現在範囲への新しい完全削除後も元の同意が同一、冷起動・通常書込みが可能、二つの古い保存先の元音声と旧制御記録を保持することを検査する。

旧形式の素材は、テストスレッドだけのRAIIで元状態へ戻るフラグにより、現行の保持済みSource観測を形式版1の形にする。初回移動のみを許し、履歴の再帰や古いコピーを捏造しない。製品にはこのフラグ・変換・入口を含めない。ただし、**古い製品バイナリが出力した素材ではない**。実際の旧版データでの互換性を、この合成検査だけで完了扱いにしない。

最終固定ソースの重点Rustは26件成功・0件失敗・専用子2件ignored。新規2件は内数であり、保持音声／保持会議の現行形式、起動承認、WAL読取と旧形式の全列固定も含む。同じ共有キャッシュの通常Rust全体は1,816件成功・0件失敗・専用／環境依存77件ignored、bin/doc各0件、終了コード0。重点の26件を通常全体へ二重加算しない。変更した製品／検査7ファイルのSHA-256はQA・重点・全体の前後で同一。フロント・Swift・Python・ブラウザの全件は今回は再検査しない。ネイティブWebView、実モデル、実録音、実時間4時間、電源断／ディスク故障の証明ではない。
