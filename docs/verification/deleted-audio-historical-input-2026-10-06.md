# 音声削除後の固定入力履歴の読取り

2026-10-06に、削除済み音声のバックアップから固定音声入力のメタデータを読む内部経路を追加した。音声本体を開かず、保存された区間・時刻・フレーム数・形式・容量・ハッシュ・トラックIDを保持する。復元の固定入力照合へ接続する基盤であり、削除済み音声を含む会議の追加公開と再バックアップは引き続き未接続である。

## 削除履歴と現在のDBの再照合

アーカイブ検査済みの型付き読取結果に、会議IDと音声資産・区間・トラックの3表の指紋を保持する。生のmanifestとは別に所有し、履歴読取りのたびに現在の利用不可状態と3表の全列指紋を再照合する。会議IDの一致や欠落状態だけでは履歴読取りを許可しない。検査後のフレーム数・形式・ハッシュ・保存先・状態の変更を拒否する。

履歴用の型には公開コンストラクターや逆シリアライズを設けない。復元以外の再生・解析開始・再試行・音声登録経路へ、この読取結果を渡さない。音声を消す権限や元端末のファイル実体識別子も持たせない。

## 固定音声入力と通常解析の分離

通常の音声入力は従来どおり削除完了の検査と利用可能状態を要求する。履歴用の入力だけが、検査済みの削除履歴に基づいてトラックの失敗状態と区間・資産の欠落状態を読む。状態の選択は非公開の内部型で行い、ユーザー入力や任意の真偽値による検査の省略を認めない。

manifestの利用可能状態とハッシュ、会議の音声種別・保存済み状態、録音セッションまたは取り込みへの所属、トラック数と区間数の制限は両経路で共通に検査する。既存の固定入力JSONの形は変えず、復元時は従来と同じ完全一致の検査とID・manifestハッシュの再構成を行う。音声サンプルのハッシュや容量を変更した入力には読み替えない。

## 検証範囲

所有する一時Storageと実アーカイブ、合成取り込み音声と2秒の合成CAFを用いる。取り込み・録音の履歴メタデータ、別会議と履歴なしの拒否、通常解析の拒否、3表の検査後改変、利用可能manifestと保存済み由来の独立した検査を追加した。改変試験は検証用DBに別の書込接続を作り、製品側の読み取り専用接続は維持する。

追加Rust5件と既存11件の計16件が16.02秒で成功し、終了コード0を確認した。ログは `/private/tmp/mon-deleted-audio-historical-check3.log`。先行試験では、既存録音fixtureの非UUID識別子と読み取り専用接続への書込みで3件が失敗し、その修正後は改変用保存先を複数行で重複させて1件が失敗した。正式UUIDの録音fixture、別書込接続、資産ごとに一意の改変先へ修正した。製品側の識別子・読み取り専用・パス一意性の検査は緩めていない。先行ログは `/private/tmp/mon-deleted-audio-historical-check1.log` と `/private/tmp/mon-deleted-audio-historical-check2.log`。

## 残件

音声本体なしでの取り込みmanifestと成果物の再構成、復元後の利用不可記録の原子的な公開、起動時・再生・再解析の制限、再バックアップ・再復元を接続する。追加復元のID領域を作る前の制限と、保存後画面の未接続表示を維持する。音声削除履歴を保持した会議完全削除と保存先移動、音声専用の共有操作・確認画面も残る。M3-06、M3-07と実装計画全体は進行中である。正式評価・10話者・Windows固有部分は保留し、Windows CIは実行しない。利用者の録音・モデル・マイク・設定は変更していない。
