# 会議ファイル削除と中断後の再開

2026-10-06に、M3-07の会議完全削除に向けて、固定した会議ツリーのファイル削除と中断後の再開を内部処理へ追加した。[確認対象の保存](meeting-deletion-intent-2026-10-05.md)と[永続的な書込停止](meeting-deletion-fence-2026-10-06.md)を使い、消す前の実体・内容検査、原子的な予約名への移動、限定削除、残りだけの再開を行う。DB行削除と後処理は[会議ファイルとDBの削除接続](meeting-deletion-compound-2026-10-06.md)として内部追加済みである。共有コントローラー、利用者の確認画面とAPIは未接続であり、完全削除機能全体の完成ではない。

## 削除範囲の明示確認

確認時のCensusから、シリアライズできないReviewedを構築する。元のDB範囲とファイル一覧が、保存した確認対象に一致することを開始時に再照合する。削除順は固定したパス列の逆順で、ファイルと子フォルダーを親より先に扱う。クライアントのJSONや任意のSQL・絶対パスから削除対象を構築しない。

登録資産だけの判断では、未登録ファイルが一つでもあれば開始しない。既知の録音・解析等の由来候補も所有確認には使わない。未登録物を含む判断は、確認時の全一覧を明示的に対象へ含める別の内部判断である。将来の確認画面は未登録物を表示し、この判断に利用者の同意を結び付ける必要がある。現在のテストでの内部呼出しは、実利用者の同意を得た証拠ではない。

元の確認記録・各パス観測・SHA・同意時刻は変更しない。別の削除判断、計画全体のSHA、ファイル段階の同意時刻、次の対象番号と移動中の実体を、既存の保守操作の進捗に保存する。DB移行は追加しない。開始確定後はinstalling状態のまま、通常書込みを引き続き停止する。

## 実体確認と予約名への移動

起動時に保持した領域・DB・制御ファイルを検査し、同じ媒体・リンクを追わない親フォルダーの記述子から処理する。各実在ファイルは確認済みの実体、容量、変更情報、リンク数と全内容SHAを照合する。フォルダーは元の実体と権限を保ち、空であることを検査する。子の削除によって変わるフォルダーの時刻・サイズを、元ファイル内容の変更と混同しない。

元の名前を直接unlinkしない。同じ親の操作ID・対象番号から決まる予約名へ、既存対象を上書きしない原子的renameで移す。macOSではrenameatx_npのRENAME_EXCLを使う。移動先の実体と内容を再照合してから、移動後実体を確定する。名前が直前に差し替えられた場合は削除しない。元の名前へ戻す試みも上書きなしに限定し、戻せない対象や確認できない対象は予約名で保持する。

削除する名前はこの予約名だけに限定し、削除直前にも実体を再確認する。フォルダーは再帰削除せず、空の対象だけをrmdir相当で削除する。移動・削除後に親をfsyncしてから次の進捗を確定する。途中取消・読込失敗・実体不一致で、消したデータを復元できたとは扱わない。

## 永続進捗と再開条件

進捗JSONは4KiB以内で、パスごとに全履歴を複製せず、固定列のカーソルと一件の移動中実体を保存する。固定パス観測は元のまま残す。

| 保存済み状態 | 現物 | 再開時の処理 |
|---|---|---|
| 移動前実体を確定 | 元の名前だけ存在 | 実体と内容を再確認して移動 |
| 移動前実体を確定 | 予約名だけ存在 | renameによる変更を区別して再検査し、移動後実体を確定 |
| 移動後実体を確定 | 予約名だけ存在 | 保存した実体と内容を確認して限定削除 |
| 移動後実体を確定 | 両方不在 | 削除と進捗確定の間の中断として、親を同期して進む |
| 移動後実体が未確定 | 両方不在 | 不明な消失を採用せず停止 |
| 任意の移動中状態 | 両方存在 | 元パスの再出現・衝突として停止 |

開始・再開時とファイル段階の終了前には、別会議を含む他の未完了保守操作がないこと、固定DB範囲と会議ツリー全体を照合する。削除済み登録資産の欠落観測を区別し、完了済みのパスの再出現や新たな未知物は削除しない。予約名の読み取り例外は、現在の一件に限る。会議フォルダー自体を移動した場合は、その正確な空の兄弟予約フォルダーだけを検査し、他会議を列挙しない。

元パスが長い場合も、移動中の正確な予約パスだけを512バイト以内で読み取れる。通常Censusの256バイト上限を一般的に緩めない。全一覧のSHA・構造検査は開始と再開にまとめ、実行中は接続ロックと検証済み制約の下で固定メタデータ・進捗遷移・個別実体を照合する。カーソルごとに全一覧を再読込みしない。大規模な実音声の性能を測定した結果ではない。

全対象の処理と終了前照合が済んだときだけfilePhaseをremovedにする。保守操作はinstallingのままで、会議と資産のDB行、下書き、文書版等はこの段階では残る。既存のDB削除を呼ばず、成功したファイル段階を会議完全削除の完了として表示しない。

## 検証範囲

追加の通常Rust21件は、固定ツリーの削除と対象外の保持、元の台帳・同意の保持、欠落済み資産、空の会議、登録・未登録の由来候補、異なる確認対象、開始前後の変更拒否、各境界の取消と冷再起動、部分削除中の未知物、予約名衝突と名前差し替え、リンク・ハードリンク・FIFO、親の差し替え、進捗改変と飛ばしたカーソル、完了後の再出現を対象とする。長い予約パス、多数の明示確認済みファイルと4KiBの進捗、DBを差し替えた後の次のファイル操作の拒否、別会議の未完了保守操作がある場合の再開拒否も検査する。

親テストから専用子プロセスを起動し、移動前実体の確定後、rename後、移動後実体の確定後、unlink後、カーソル確定後、ファイル段階完了後、子フォルダーのrename後、会議フォルダーのrename後の8箇所でSIGKILLする。冷再起動後の残りだけの処理、DB行と別会議・外部出力の保持を確認する。これは電源断や媒体障害の検証ではない。

最終コードの `make check` は終了コード0で成功した。Python65件、フロントエンド100件、Swift9件、Rust通常728件、別実行のAVFoundation製CAF読出し1件が成功した。通常Rustの17件はignoredで、環境依存11件と子プロセス専用6件を含む。今回の専用子プロセスは親テストから8境界で実行した。ビルド・型検査・書式検査も成功した。ログは `/private/tmp/mon-meeting-removal-final2-check.log`。既存のSwiftPMキャッシュ権限とRustリンカーのunwind容量の警告は残る。

## 残件と制限

複合intentと完了したファイル段階を使うDB行削除とDB・WALの後処理を[会議ファイルとDBの削除接続](meeting-deletion-compound-2026-10-06.md)として内部追加した。共有の実行排他、メイン専用API、確認・進捗・取消・再試行・部分失敗の案内画面は残る。未知物や変更を検出した部分削除の再確認手順も、利用者向け操作へ接続する必要がある。

構築用一時領域、移動前の旧保存先、保持コピーのデータは今回の会議ツリー処理に含めない。それらの案内と別の確認済み削除は残る。実機WebView、長時間・実音声・容量不足・電源断・媒体障害は未検証である。同一UIDの悪意あるプロセスが予約名を含む全ファイルと台帳を同時に書き換えることへの完全な耐性や、物理媒体・OSや利用者のバックアップの安全消去を保証しない。

削除と移動は一時テストデータだけで行い、利用者の会議・音声・モデル・設定は削除していない。正式評価・10話者・16GB性能・Windows固有部分とWindows CIの停止を維持する。M3-07と実装計画全体は進行中である。
