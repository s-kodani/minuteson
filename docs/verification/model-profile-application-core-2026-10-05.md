# モデルのプロファイル適用基盤の検証

- 日付: 2026-10-05
- 対象: M2-02 / M3-06のモデル構成保存基盤
- 状態: ネイティブ処理とメイン画面専用コマンドまで追加。適用画面は未接続

管理領域へ配置し、CPU互換性確認に成功したパッケージを、標準または高精度の既存解析設定へ適用する基盤を追加した。モデル選択と構成版の保存を原子的に行うが、実モデルでの品質・性能、GPUを含む通常条件での動作、利用者向け操作の完成は証明していない。

## 事前確認と適用

`preview_model_profile_application`は、最新の成功した互換性確認、配置パッケージ全体、試行入力・出力・ログの証拠を再照合する。成功記録の欠損、失敗、取消、新しい試行への置換は拒否する。事前確認や適用からエンジンを実行したり、新しい互換性確認を自動開始したりしない。

確認内容には対象プロファイル・パッケージ・互換性確認の操作ID、現在のプロファイルID・版・内容SHA、対象エンジンの設定版、変更前後の設定と確認内容SHAを含める。`apply_model_profile_application`はモデルと試行証拠を再照合し、DBトランザクション内で確認内容を再計算する。確認後に設定版・構成版が変わった場合や確認内容の改変は保存前に拒否する。

適用時に変えるのは、選択したプロファイルの実行ファイル・モデル・VAD・ランタイムライブラリーのパスだけである。他のプロファイルと他エンジンの設定、スレッド数・GPU設定・コンテキスト・生成予算・seed等は維持する。CPU互換性試行の1スレッド・GPUなし等の条件で通常解析条件を上書きしない。そのため、CPU試行の成功は保存した通常条件の互換性保証ではない。

## 原子的な保存と履歴

既存設定、`model_profiles`、`profile_components`、現在版参照を一つの即時トランザクションで保存する。途中取消、設定競合、DB書込失敗は全て巻き戻す。既存会議と既に固定済みのジョブは変更しない。

構成は一つのエンジンから保存できる。sherpa-onnxは分割・話者埋め込みの二つの役割を同じ設定に結び付ける。残るエンジンを追加するたびに既存選択を保持した新しい構成版を作る。v25移行では、版番号の重複、確定済み構成と構成要素の変更・削除、確定済み版への構成要素追加をSQL制約で拒否する。

同じ操作ID・同じ確認内容の再送は、現在版と設定が引き続き一致する場合だけ既存結果を返す。新しい明示操作では、同じ設定でも新しい構成版を保存する。古い操作IDで後の版を上書きしない。

`get_model_profiles`は標準・高精度の構成を再読込する。設定を手動変更した場合は`settingsMatch`、新しい互換性試行へ置き換えた場合は`compatibilityCurrent`で不一致を表示できる。元の構成履歴を自動修正しない。参照SHAや設定値の破損も黙って修復せずエラーにする。

`configurationComplete`は、三つのエンジンの選択が揃い、保存設定と最新の成功記録が一致するというDB上の状態だけを表す。構成表の`ready`も保存時点の同じ状態であり、現在のファイル健全性、GPU互換性、解析全体の準備完了、品質・速度を意味しない。構成取得ではファイル全体を読み直さない。

メイン画面専用の確認・適用コマンドには、既存の共有モデル準備ゲートと取消を接続した。録音開始・通常終了時の停止待ちと同じ経路を使用する。バックアップ中の設定・構成公開も拒否する。

## 検証結果

新規ネイティブテスト10件が成功した。

- 三つのエンジンの適用、標準／高精度の分離、既存数値条件・会議・固定ジョブの保持、再起動後の構成再読込。
- 新しい文字起こしジョブへ適用後のモデルSHA・スレッド数・GPU設定が既存の開始処理を通って渡ること。
- 同じ操作の再送、新しい構成版、設定版・現在版の競合、改変された確認内容、操作ID衝突の拒否。
- 最終書込失敗と書込後の取消で、設定・構成要素・現在版参照が全て巻き戻ること。
- 成功証拠の欠損・失敗・旧試行、変更されたモデル・試行成果物、モデルのシンボリックリンク、取消の拒否。確認・適用でエンジンが再実行されないこと。
- 手動設定変更・新しい失敗試行による不一致表示、履歴のSQL変更禁止、参照SHAや設定値の破損の拒否。
- v24からv25への移行と既存データ保持、バックアップ中の公開拒否、持ち運び用アーカイブへ端末内構成を混入しないこと。

全体の`make check`も終了コード0で成功した。Python 65件、フロントエンド69件、Swift 9件、Rust通常437件（11件はignored）、AVFoundation製CAF読出し1件が成功した。Rustテストは合成モデルファイルとシェル製の模擬エンジンを使用し、実モデルのロード試験ではない。今回はフロントエンドを変更しておらず、ブラウザ操作やmacOS WebViewの統合試験は実施していない。録音・実アプリ終了との一連の統合確認も未実施である。

## 残件

利用者向けの適用先選択、変更内容の確認、取消・失敗表示、適用後の設定再読込は未接続である。既存の新規ジョブは更新した解析設定を読むが、管理パッケージIDと構成版をジョブへ結び付ける処理、適用後に変更された管理モデルを新規解析前に拒否する専用ゲートは残る。適用後のファイル変更を防ぐ仕組みではない。

端末内のモデル構成と互換性証拠は持ち運び用バックアップの対象へ追加していない。モデルの履歴メタデータ・プロファイル構成の持ち運び、復元後の再配置と明示再試行への統合は未完成で、M3-06全体の完了とは扱わない。実モデル・実配布エンジン・保存した通常条件での統合確認、正式品質評価、16GB・10話者・Windowsの検証も残る。
