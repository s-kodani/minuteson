# 長時間音声の再生開始と事前ミックス

## 変更

会議全体・議事録の指定区間・発言の再生で、確定済み管理FLACを通常のファイル再生として開く。開始前の全体SHA256・全パケット索引生成・全PCMデコード／MD5を行わず、STREAMINFOを読み、再生位置へシークして必要なパケットをデコードする。短い最終ブロックもパケットの時刻と実フレーム数で扱う。

取り込み／録音保存時の完全検証と、文字起こし・話者分離等の解析入力の完全検証は維持する。再生時は管理領域・保存状態・ファイルサイズ・形式・DBのフレーム数／時計対応・準備中のDB変更を確認し、読出し時にはファイル変更、パケットCRC、PCM形式、時刻の不連続を確認する。未読区間の同サイズ破損やファイル全体のSHA256不一致を再生開始前に検出する契約ではない。古いCAFの再生は既存の完全照合を使用する。

短い定数FLACを末尾まで読んだ後、リサンプリングの重複窓を読み直すケースも検証した。FLAC demuxerのseekは、フレーム先頭に一致する場合にEOF時のparser状態を残すことがあるため、非連続読出しでは小さなreaderを再作成してからシークする。全体の走査・デコードは不要のままで、先頭・途中への繰り返し移動とMarkdown区間のPCM一致を確認した。

録音のマイク＋PC音声は、保存完了後および既存の録音会議の表示時にバックグラウンドで事前ミックスする。時刻補正・リサンプリング・固定ゲイン・欠損位置を既存の会議再生と共通にし、生成完了後だけキャッシュを公開する。通常再生とMarkdown区間再生の両方で利用する。準備中・失敗時・対象外では原音声を読みながら再生できる。

キャッシュはプロセス内で管理する匿名一時ファイルの48kHz mono Float32 PCM。原音声・会議DB・可搬バックアップ形式を変更せず、終了後は残さない。上限1GiB（1時間で約659MiB）・最大4件で、短い会議でも開いたファイルを無制限に保持しない。容量上限を超える会議は直接再生する。再起動後は会議表示時に再作成する。保存記録・時計対応・元ファイルの識別子と変更時刻をキーに含め、元ファイル変更後の古いミックスは再利用しない。バックアップ・復元・保存先変更・削除の排他取得時は生成を中止して終了を待ち、キャッシュを破棄する。

## 60分の合成音声測定

独立したffmpegで作った48kHz stereo、172,800,000フレーム、559,678,174 bytesのFLACを使用。製品の`audio.rs`と`audio/flac.rs`を一時ハーネスへコピーし、release構成で3回比較した。各回、先頭・30分・59分59秒から1秒分のPCMが従来の完全検証版とバイト一致した。

| 処理 | 3回の実測 |
| --- | --- |
| 従来の完全検証を含むopen | 10.604秒、11.056秒、10.358秒 |
| 直接再生用open | 0.121ms、0.165ms、0.122ms |
| 指定位置から1秒分の読出し | 1.44〜3.17ms |

再シーク修正後も同じ60分ファイルで再測定し、先頭→30分→59分59秒→先頭→30分の5箇所が完全検証版とPCM一致した。別ビルドが並行していたこの測定では、完全検証open 15.034秒、直接open 1.290ms、各読出し1.455〜2.196msだった。

OSファイルキャッシュを排出した測定ではない。Tauri IPC・UI操作・音声デバイス開始の時間を含まない。HRB_202604そのものの操作測定・聴取、実録音・機器間同期の評価ではない。
