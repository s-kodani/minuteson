# 取得済みQwen小型モデルのMarkdown診断

固定カタログのQwen 2.5 0.5B Q4_K_Mと同じ取得済みモデルを再利用し、公式llama.cpp b11533のCPU実行で短いMarkdown文字列を出力できた。追加ダウンロードと使用設定の変更はない。診断スクリプトの出力確認であり、製品のRust解析・保存・再生成・Mac画面からの導入の合格ではない。本文は素材に近い内容と末尾の依頼文を含んでおり、議事録の要約品質を保証しない。

## 使用したファイルと条件

カタログIDは `llama-b11533-qwen25-05b-q4km`。モデルは `/private/tmp/mon-real-ai-qa.T3hkeF/qwen2.5-0.5b-instruct-q4_k_m.gguf`、491,400,032bytes、SHA256 `74a4da8c9fdbcd15bd1f6d01d621410d31c6fc00986f5eb687824e7b93d7a9db`。元の承認済み取得と現行カタログの固定情報に一致する。

実行ファイル・共有ライブラリ・ライセンス本文は、以前の通常QA導入で配置された `jp.mon.desktop.qa.onboarding20261011` のパッケージ `107280ab-a410-4c90-b420-9e32fc157f5c` を読み取り再利用した。カタログの全13ファイルについてサイズとSHA256を再照合し、モデルは実行後も内容・inode・変更時刻が一致した。元の取得領域やモデルへ書き込まない。

確認対象は専用領域 `/private/tmp/mon-qwen05-markdown-probe.WxqZuM` の合成発言2件のみ。録音・会議データの読取り・ネット接続はなく、メインQAとOnboarding QAは起動しない。実行環境はPATHとLANGだけで、remote指定や認証情報などの環境変数を引き継がない。GPUモデル層・KV・演算オフロードは無効、CPU1スレッド、seed 1、temperature 0、context 4096、prediction 512、offlineとした。

日本語system指示は現行 `generation/markdown.rs` の文字列をそのまま取り出した。合成promptはこの診断専用で、製品の分割計画promptとは異なる。入力のUTF-8バイト上界940とテンプレート予約1024、出力512が実行contextに収まること、モデルの最大入力32768・最大出力8192・最大合計context32768に収まることを確認した。入力に余裕があることを理由にモデルの最大出力を増やしていない。

CLIのschemaはMarkdown文字列1つだけで、512-token予算からフレーミング余裕を取る現行の考え方に従って最大96文字とした。2MiBの出力制限、JSONの1つのrootフィールド、Markdownの非空・NULなしと重複rootフィールドなしを診断側で確認した。引用内の改行・タブのエスケープは文字列の内容を保つ処理に限定し、未完JSONや構造の修復はしていない。このスクリプトは製品の厳密なRust parserを呼んでいないため、その代用にはしない。

## 結果と途中事象

初回は取得原本側の非実行payloadを起動しようとしてEACCES、0.39秒で実行前に失敗した。取得原本の権限は変えず、通常QAで導入・CPU確認済みの実行用コピーに切り替え、全13件を再照合してから実行した。

最終は終了コード0、3.87秒。診断側の起動から後照合まで3517ms、stdout 241bytes、Markdown 202bytesだった。Rustの関連検査と並行しており、CPU性能の比較値ではない。本文は2発言と末尾の生成依頼に近い文字列であり、JSONを閉じられたことと要約品質を区別する。

診断スクリプトと原文・stderrは専用領域に保持した。生成結果を会議へ保存せず、使用モデルを変更せず、既存会議・設定・取得原本・モデルを削除していない。追加取得0bytesなので、既知の完成ファイル取得累計3,794,392,252bytesの4GiB枠は増えていない。累計は過去の記録に基づく完成ファイル量で、全通信量の実測ではない。
