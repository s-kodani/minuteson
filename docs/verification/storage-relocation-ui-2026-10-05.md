# 保存先変更の操作制御と画面検証

2026-10-05に、macOSの会議保存先変更をメイン画面のデータ操作へ接続した。親フォルダー選択、件数と容量の確認、同じ対象の再確認、コピーと履歴の検証、起動設定切替、終了して再起動する案内を含む。既存の[切替と初回起動の承認](storage-relocation-activation-2026-10-05.md)を利用し、旧保存先を削除せず、モデルと起動設定は元の領域に保つ。実機選択パネルとWebViewを通した一連の確認、中断コピーの解決、完全削除は残り、M3-07は進行中である。

## 選択と確認後の変更検査

メイン専用の既存データ操作APIに保存先変更を追加した。クライアントが送るのは操作種別、サーバー発行の操作トークンと確認IDだけであり、任意の移動先パス、manifest、コピー成功の宣言を切替入力にしない。システム選択パネルから得た親の正規化パス、開いたディレクトリー、実体識別子、現在の登録済みルートと起動設定版をサーバー内の非シリアライズ型で保持する。

選択した書込可能なローカルAPFSの親の下に、固有名の非公開フォルダーを確定時に新規作成する。親や既存物の権限を変更せず、同名物を採用・上書きしない。会議・モデル・起動設定と重なる新保存先、未完了の移動、新たな操作を始められない再起動待ちは拒否する。確認を破棄するだけでは移動先を作成しない。

確認時はネイティブスナップショットでDBと管理ツリーを検査して、会議件数、DBを含むコピー対象ファイル数、必要容量と空き容量を提示する。対象ファイル数には別途構築する制御台帳を含めない。必要容量はDBと管理ツリーの合計の2倍に64MiBの余裕を加える見積もりであり、任意の大きさの履歴台帳、競合する他アプリの書込み、ディスク障害まで保証する数値ではない。

確認後は一時スナップショットの書込停止を解除でき、通常の編集を許可する。確定時に共有排他を再取得して新たなスナップショットを作り、確認時のmanifest SHAと比較する。編集・会議・音声が変わったら、新規移動先の作成前に拒否する。同じ対象の再確認は操作IDを維持し、新しい確認IDと件数・容量を返す。古い確認IDでは切替しない。取消済み・失敗した確認の確定要求は画面だけでなくサーバー側でも拒否し、再確認を必要とする。

## 共有開始排他と再起動待ち

フォルダー選択から検査、確定の実処理まで、バックアップ・追加復元と同じ開始排他を使う。録音・解析・取り込み・モデル準備・書き出し・終了処理が進行中なら新しいデータ操作を開始しない。実行中の処理を勝手に停止・破棄せず、利用者が停止・完了を確認してから操作する。編集内容の保存を待つ画面制御も既存のデータ操作と共通にした。

処理はUIスレッドではなく所有されたワーカーで行う。RPCやイベントの応答を失っても、ワーカー・取消フラグ・選択・開始排他は残る。版付きの状態を読戻せ、同じ受理済み要求を再送しても新しいコピーを開始しない。取消後も実処理が終了するまで開始排他を解除しない。検査完了から終端状態を公表するまでの間に入った取消も判定し、取消済みの選択を確認待ちへ戻さない。既に公開した結果は遅い取消で破棄しない。

コピー、履歴引継ぎ、切替の進捗を区別して表示する。切替の前に既存の内部処理が旧Storageを不可逆に書込停止する。ワーカーは結果を公表し、一時的な開始排他を解除する前に、解析コントローラーへ再起動まで維持する開始禁止を設定する。新しい録音・取り込み・モデル準備・解析・書き出し・データ操作を再開しない。終了取消でこの開始禁止を解除せず、安全な終了の待機を永久に塞ぐ活動中処理としても数えない。

画面は選択済み保存先と現在開いている旧保存先を分け、切替後の編集・開始操作をロックする。「終了する（再起動は手動）」は既存の安全な終了処理へ接続した。自動再起動や旧データの削除は行わない。新起動での再照合と承認は、Storageを開く前に既存の起動経路で実行する。

## 取消と途中コピー

| 境界 | 設定とデータの扱い | 操作結果 |
|---|---|---|
| 確認まで | 移動先を作らず旧選択を維持 | 取消・選び直しができる |
| 移動intentとコピーの開始後 | 旧選択と途中コピー、所有台帳を保持 | 要確認として表示し、新たな移動を開始しない |
| 切替済み、または旧Storageの停止後に結果が未確定 | 旧Storageへ書込みを戻さず、コピーを削除・再上書きしない | 再起動を案内する。確定済み切替は遅い取消でも成功として保持する |

新規フォルダー作成後、intent保存前に失敗した場合も作成物を自動削除しない。同名物を採用せず、再選択を必要とする。保持した途中コピーの続行・保持確認・解決は今回の画面には接続していない。起動設定に未完了移動がある場合は途中コピーのパスと保持状態を表示するだけで、完了扱いや空DBへの切替を行わない。

## 確認した試験

追加Rust 9件で、確認のみでは移動先を作らないこと、同じ会議IDのコピー・切替・初回起動後の書込み、確認後の編集と再確認、誤った確認ID、親実体の差し替え・同名の未知物・設定版の変更・除外領域、intent前の取消とコピー開始後の取消・例外を検査した。コントローラーでは同じ要求と再確認応答の喪失、終端結果の保持、全種別の新規操作拒否、検査後から通知までの取消と再確認なしの確定拒否を確認した。解析の恒久的な開始禁止は一時排他の破棄と終了取消後にも残り、モデル・書き出し・データ操作を拒否しつつ終了待機を完了できた。

フロントエンドの追加5件で、サーバー確認のみの要求、容量不足・古い確認の拒否、移動元・先と操作に結び付く結果、再起動が必要な未確定状態、選択済みルートと現在のルートの区別を検査した。

ブラウザの模擬IPC 7ケースでは、根拠となるパス・件数と非移動範囲、明示確認前の実行なし、Escapeとフォーカス復帰、容量不足と同じ対象の再確認、二重実行なし、RPC・イベント応答喪失、取消完了待ちと途中コピー表示、変更後の再確認、遅い取消、異なる操作のレシート拒否を確認した。成功後はモデルの元パスと旧Storageのパス、再起動案内と編集ロックを確認した。既存のバックアップ・復元画面試験20ケースも別途再実行して成功した。これらは実際のシステム選択パネルやWebViewの統合試験ではない。

再現用のCLI起動スクリプトは`app/tests/storage-move-browser-bootstrap.js`、保存先変更の検査は`app/tests/storage-move-browser-check.js`、共通の模擬IPCは`app/tests/data-save-browser-fixture.js`に保存した。確認画面と再起動待ちの画像を`output/playwright/storage-move-review.png`と`output/playwright/storage-move-restart.png`に出力して表示を確認した。画像とCLI生成ログは追跡対象ではない。ローカルViteのHMR WebSocketがブラウザのローカル接続検査で拒否される警告は残るが、通常HTTPによる画面と模擬IPC試験とは区別する。

## 残件と保留

実機WebView、macOS選択パネルと安全な終了を通す統合試験、長時間・容量不足・電源断の実機検証は未実施である。所有不明・旧形式の途中配置と旧領域履歴の確認・解決、旧データの完全削除、古い版の整理、起動拒否時の利用者向け案内も残る。同一ユーザーによる悪意ある同時変更への完全な耐性は保証しない。利用者の音声・設定・モデルをこの検証で移動・削除していない。

正式評価、10話者・16GBの性能とWindows固有部分は保留したまま、Windows CIも無効を維持する。実装計画全体の完了とは扱わない。
