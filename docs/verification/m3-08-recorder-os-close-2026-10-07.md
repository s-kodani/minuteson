# 録音ミニ画面のOS閉鎖要求と共通確認

録音ミニ画面へのOS閉鎖要求を、独立した共通録音確認ウィンドウへ接続した。録音中にミニ画面だけを無通知で消すことや、閉鎖要求だけで停止することはしない。正式評価とWindows固有部分は保留し、M3-08と実装計画全体は進行中である。

## 状態に応じた閉鎖要求

OSイベントを受けた時点の録音セッション・会議・版番号を保持し、録音開始と停止に共通するロック内で最新状態と照合する。イベントループではロックを待たず、別スレッドで処理する。録音開始側がウィンドウ操作を待つ場合にも、イベントループをロック待ちで塞がない。

| 最新状態 | 閉鎖要求の扱い |
|---|---|
| 準備中・録音中 | 同じ録音であることを照合し、共通確認を要求する。明示的な同意までは停止しない |
| 停止中・保存中 | ミニ画面を維持し、新しい停止を送らない |
| 共通確認が表示中（確認中・停止保存待ち・確認内の失敗） | 既存の確認へフォーカスする。確認ID、最初の実行元、アプリ終了意図を変更しない |
| 待機中・録音エラー | 確認が開いていなければミニ画面を隠す。保存結果とメイン画面のエラーは消さない |
| 別の録音・古い読戻し・識別情報のない録音中状態 | 閉鎖と停止を拒否し、状態を保持する |

待機時に受けた古い要求が、その後始まった録音の確認になることも拒否する。同じ録音の準備完了や保存中への移行は最新状態で判断し、保存成功によって待機状態へ移った場合だけ画面を隠せる。

## 確認表示の失敗

確認の表示失敗や対象変更は、メインとミニ画面へエラー通知を送る。録音・保存結果を保持し、停止を自動再送しない。画面側は既存のエラー表示を使い、新しい明示的な確認IDを受け取ったときに古い要求エラーを消す。通知を受けたことを録音停止・保存成功・アプリ終了と解釈しない。

長い通知を小型WebViewで切れずに表示する専用通知領域、操作中のウィンドウに応じたトーストの振り分け、保存失敗からの再保存は残件である。
