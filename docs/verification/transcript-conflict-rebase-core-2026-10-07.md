# 保存競合の比較と編集再開基盤

2026-10-07に、別操作で同じ文字起こし下書きの保存版が進んだ場合の、読み取り専用比較とローカル編集再開の基盤を追加した。未確認の保存要求と手元の本文・話者名を保持し、確認した新しい基底へ切り替える操作を保存処理から分離する。以下は基盤追加時点の検証記録である。その後の画面接続と再起動後の古い回復入力への対応は[保存競合の比較画面](transcript-conflict-ui-2026-10-07.md)を参照。M3-08と計画全体は進行中である。

## 比較条件と入力の保持

比較できるのは、同じ会議・下書き・解析版に属し、ロック版番号が厳密に進んだ保存版だけである。旧解析の自動採用や別会議への入力転用はしない。本文の基底・最新保存版・未確認要求の本文と、ローカルの未確定本文・名前・完全な保存済み回復記録を凍結した比較情報として返す。読み取りで保存要求を解決したことにはせず、操作IDや書込みは発行しない。

編集再開は、その保存キューが発行した同一の比較情報だけを受け付ける。本文の所有・版・ハッシュ・内容と、回復記録全体を再度読み、比較後の入力・要求・保存内容の変更、別の比較情報への差し替え、読込み失敗、画面終了を検出した場合は基底を切り替えない。選択された本文・名前の件数・文字数・重複と4MiBのUTF-8容量上限も先に検査する。

成功時はローカルの基底と選択した未確定入力を切り替え、古い要求を外すが、本文も回復記録も書き込まない。後続の保存は新しい版番号を条件にした別操作になる。ネイティブの既存保存処理は、古い下書き版からの新しい書込みを拒否し、同一操作IDの再送は同一内容の既存結果を返すだけである。本文と回復記録の読込みは別々であり、単一のネイティブトランザクションによる一括比較ではない。読込み後に再度版が進んだ場合も、後続の条件付き保存で上書きを拒否する。

## 項目ごとの比較

純粋な三者比較関数は基底・手元・最新保存版から差分を作る。本文と話者割り当ては別項目として扱い、片側だけの変更を選択候補にする。同じ項目が両側で異なる値になった場合は自動選択せず、手元か最新保存版かを明示するまで解決結果を返さない。両側の同一変更は競合として扱わない。

話者名の明示的な不明と上書きの除去を区別し、手動話者・統合・分割も比較対象に含める。発言の保持・本文・割り当てが揃わない部分的な選択は拒否する。比較情報は不変で、解決結果の変更も元の入力を変更しない。

この比較結果はネイティブの下書き妥当性検査ではない。手動話者と統合の参照、分割の由来・時刻・本文などの依存関係は、画面接続時の再開前検査と既存のネイティブ保存検査へ接続する必要がある。構造比較のテストに使った仮IDや空の分割部品を、保存可能な実データの証明として扱わない。
