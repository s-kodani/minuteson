# 復元ジョブの同条件モデル再試行

2026年10月5日、再配置した同一モデルを使う確認付き再試行の内部処理を、文字起こし・話者分離・議事録生成の3工程へ接続した。元ジョブの論理条件と完了結果は変更せず、新しい試行に配置先の証拠を追加する。利用者向けの確認画面はまだ接続していないため、復元後の再試行機能全体の完成とは扱わない。正式評価とWindows固有部分は保留を維持する。

## 確認と原子的な登録

確認処理は対象会議、元ジョブの固定条件ハッシュ、状態、完了位置、チェックポイントの内容を検証する。配置先には最新の明示CPU互換性確認と、モデル・実行ファイル・全依存ファイルの同一性が必要である。元音声、固定した編集入力、保存済み出力も読み直すが、確認だけでは推論を実行せず、ジョブ・設定・成果物を更新しない。

プレビューには数値条件、トラックごとの人数条件、用語ヒントの文字数とSHAを含める。用語本文や文字起こし本文は追加しない。確認内容のハッシュは内容の一致判定用であり、認可用の署名ではない。登録時にはDBの固定条件から表示条件を再計算し、配置と試行証拠、入力と完了結果を再照合する。

SQLiteのv26移行で、再試行の入力・元版・パラメーター・単位数の不変制約を保ち、ネイティブ工程の再試行だけに`runtimeModel`の追加または再配置先の変更を認める。Rust側で型付きの全証拠と配置先の最新記録を検証する。新規の通常ジョブへこの証拠を注入する経路は拒否する。新しいジョブID・試行番号・元ジョブ参照と完了結果のコピーは単一トランザクションで確定し、確定直前の取消でも巻き戻す。

失敗・取消済みジョブに加え、追加復元によって準備待ちとなった中断ジョブを対象とする。一般の一時停止や中断を同じ扱いにはしない。再試行先が存在する中断ジョブは、元側を再開して完了履歴を別々に進められないよう、APIとDB制約の両方で拒否する。

同じ操作IDの応答が失われた場合は、確定済みの新ジョブを読み取り専用で確認できる。この結果照合は現在のモデルファイルやCPU試行に依存せず、モデル準備や推論の開始、別ジョブの登録を行わない。

## ワーカーの実行条件と保存結果

3工程のワーカーは、保存した元のパラメーターとは別に、同一内容のファイルを指す実行条件のコピーを解決する。モデル本体だけでなく管理パッケージの全依存を照合し、実行と公開の境界で再検査する。スレッド数、GPU指定、用語ヒント、話者分離の数値条件、生成予算とseedは変更しない。現在のプロファイルを読み直して差し替えることもない。

WhisperのJSONとsherpaのログには実行した物理パスが入るため、元の出力を上書きせず、別ファイルでモデルパスのメタデータだけを論理条件へ正規化する。正規化前後をそれぞれ検証し、文字起こし本文・時刻、話者区間・ラベルの一致を要求する。sherpaの未配置指紋参照は純粋な保存結果パーサーだけで扱い、ネイティブ実行では拒否する。

議事録の固定入力・処理計画・プロンプト・保存済み抽出結果の検証は従来のまま保持する。元の操作IDは再試行の由来から解決し、配置先の証拠だけが異なる複数試行も、同じ論理条件とパラメーターに結び付ける。

## 除外された一時ファイルと再バックアップ

一時PCMがない場合は、追加復元の除外記録が会議・ファイル・理由・容量・SHA・専用配置先と一致する場合だけ、元音声から私有の一時領域へ作り直す。その容量とSHAを保存済みの証拠と比較し、検証用ファイルは終了時に破棄する。元の欠損ファイル行、除外記録、チェックポイントは変更しない。通常の欠損・破損、除外証拠の不一致、予期しない保存先の実体を同じ例外として扱わない。

除外された話者分離ログは再生成したことにせず、ログ専用の除外記録と、復元済みの構造化結果に含まれる工程・入力・トラック・条件・時刻・話者ラベルを照合する。ログ本体がある通常の履歴では、従来どおりログのSHAとパーサー結果も照合する。本文を含むプロンプトや生成結果を、ログの例外として省略しない。

正規化した話者分離ログもバックアップではネイティブログとして除外する。再試行の`runtimeModel`は全役割のパスを未配置指紋参照へ変換する。実アーカイブの作成・追加公開・再試行・再バックアップ・2回目の追加公開を通し、元ジョブと新試行の由来がモデル本体なしで再構成できることを検査する。

## 検証範囲

合成音声・合成モデル・シェル製の偽CLIを用い、既存の照合基盤5件に次の検証を追加した。

- 元の配置を削除した状態で3工程の実ワーカーを実行し、候補保存と成功状態まで確認する。確認・登録はCLIを起動せず、元ジョブと設定を保持する。配置先を削除した後でも応答の再確認は新しい試行を作らない。
- 確認内容、元の状態、モデル、音声、最新CPU試行の変更と取消を拒否する。登録後・確定前の取消では、新ジョブとコピーしたチェックポイントをともに巻き戻す。
- 124秒・2トラックの途中結果を含む3工程を実アーカイブから追加復元し、除外証拠の改変と予期しない実体を拒否する。保存済み結果を再実行せず、未完了単位だけを処理して候補を保存し、2回目の追加復元でも由来を照合する。
- 正規化で本文・原時刻・重複発話・ラベルを保持し、異なる実行条件、翻訳指定、丸め後の重複区間を拒否する。出力の読込み上限、途中取消、リンクの拒否と上書き防止を検査する。

この検証は認識品質、話者精度、実モデルのGPU動作や長時間性能を証明しない。全体検査の最新結果は[実装状況](../implementation-status.md)を参照する。

再照合関連12件が成功した。最終の`make check`は終了コード0で成功し、Python 65件、フロントエンド77件、Swift 9件、Rust通常461件、AVFoundation製CAF読出し1件を確認した。Rustの実モデルなどに依存する11件はignoredのまま、評価前提の不足は7件の警告のままで、成功に算入しない。Swiftのユーザーキャッシュ警告は残ったが、Rustの未接続処理に対するdead code警告は解消した。
