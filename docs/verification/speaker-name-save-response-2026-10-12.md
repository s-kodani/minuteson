# 話者名モーダルの保存失敗からの復旧

2026-10-12。基準b10d9d2。M2-05とM3-08の限定修正。話者名の保存結果が未確認のままモーダルから復旧できない問題を再現し、エラー時だけ結果確認と再試行をモーダル内に表示する。正常時の表示と余白は増やさない。

## 入力保持と復旧操作

本文保存の成功応答を失うと、Escapeによる取消は保存済み本文が進んでいるため拒否される。一方、従来の復旧ボタンはnative dialogで操作できなくなる背景にしかなかった。入力保護は機能していたが、開いた話者名モーダルから先へ進めなかった。

既存の回復制御を使い、本文と未確定入力の結果確認、回復保存と本文保存の明示再試行を必要時だけ表示する。結果確認は読取りだけで、新しい名前を確定しない。未確認の元の要求を解決した後も、追加入力は保存ボタンを押すまで確定しない。会議・下書きID・基底版・版番号・hash・全文の照合、同じ要求の再試行、取消前の保存結果確認は緩めない。DB形式、RustとSwiftの製品コードは変更しない。

## 合成画面と単体検査

製品Reactと回復制御、合成IPCを使う新規12条件が成功した。成功応答喪失、未書込み、読取失敗、下書き消失、ID・会議・基底版不一致、新しい競合版、異なるpayload、狭幅の明示再試行、未確定入力の回復保存失敗・応答喪失を扱う。読取りで書込み件数が増えないこと、結果確認後650msを待っても新入力を自動再送しないこと、最新の入力と入力欄の同一性を保持すること、明示保存後に最新名が確定することを照合する。

360×640の画像を確認し、横方向のはみ出しがないことと隣接する回復ボタンの高さ・上端・文字サイズ一致を検査した。通常モーダルには復旧操作の空コンテナーもない。最終の独立ブラウザでは共通モーダル既存12条件を含め24条件成功。フロント単体905件成功、失敗・skipなし。実DBの通信障害、Mac WebView操作、全編集形態の合格へは拡大しない。

既存の文字起こし編集検査は、旧UIの「下書きがなければ編集ボタン無効」を期待して初期条件で失敗した。現在は発言・話者名の編集操作が下書き作成も開始する。後続の旧話者名・回復・競合検査はその一括実行では未実施で、通過扱いにしない。製品の直接編集導線を戻さず、残る検査ドライバーの更新が必要。
