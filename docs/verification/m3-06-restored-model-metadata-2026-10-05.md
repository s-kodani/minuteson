# 復元したモデル履歴と除外ファイルの再バックアップ

2026-10-05に、M3-06の追加復元後もモデルと実行依存ファイルの名前・容量・SHAを保持する内部基盤を追加した。復元済み会議の再バックアップで名前が未配置参照へ変わり、次の復元で文字起こし結果のモデル名照合に失敗する経路を修正した。あわせて、意図的に除外した一時PCM・ネイティブログの記録を残し、音声本体の欠損とは区別する。モデル導入と利用者向け復元操作は未完成であり、M3-06は進行中とする。

## 履歴と未配置状態の保持

SQLite v23で`model_packages`、`model_files`、`model_profiles`、`profile_components`の保存基盤を追加した。今回利用するのは、アーカイブの`fileReferences`にある名前・容量・SHA・役割を保持する履歴パッケージとファイル行である。プロファイルと構成要素の導入・選択はまだ接続していない。

履歴の`source_type`は`historical_snapshot`、パッケージとファイルの状態は`unavailable`にする。元端末のパス、本体、利用可能状態を引き継がない。元の記録にないエンジン版・モデル版・量子化・ライセンスを名前から推定しない。エンジンとモデル版は未記録とし、配布元の期待SHA・期待容量もNULLにする。観測されたSHAを配布元の真正性確認と表示しない。

会議の追加公開、共通用語の併合、公開済みバッチ、回収操作の完了、履歴メタデータを同じトランザクションで確定する。名称だけで重複判定せず、名前・容量・SHA・役割が一致する履歴だけを再利用する。同名で別SHA、別名で同SHA、同じ内容で別の役割を区別する。未配置の履歴を通常のUPDATEで準備完了へ昇格できない。

再バックアップでは、固定ファイル参照が正確に`mon-unavailable:<同じSHA>`で、容量と役割も一致する場合だけ履歴の名前を使う。現在のローカルファイル参照は現在のファイル名を使い、無関係な履歴はアーカイブへ追加しない。文字起こしの機械生成メタデータ`params.model`も、同じSHAに紐付くモデル名へ戻す。認識本文と時刻は変更しない。同SHAの別名が複数ある場合、このメタデータには辞書順で最初の名前を用い、参照記録には該当する別名を残す。

持ち運ぶ論理テーブルは31のまま、参照履歴は従来のmanifestへ記録する。端末内のモデルテーブルと、そのID・未配置状態を生の表としてコピーしない。現在はこの履歴の保持を実装した段階であり、導入済みパッケージの配布元・版・ライセンスやプロファイル構成全体の持ち運びを完成扱いにしない。

## 意図的に除外したファイルの記録

v23の端末内`restore_omitted_assets`は、追加復元で除外したファイルID・会議・理由・元容量・元SHAを保持する。会議公開と同時に登録し、該当するmissing行との一致をINSERT制約で検査する。PCMとログの理由を混ぜず、通常のUPDATEによる証拠の変更を拒否する。

再バックアップ時には、記録と会議・ID・正準復元パス・容量・SHA・メディア種別が一致する除外物だけを受理する。音声チャンク、取り込み原本・変換音声、取り込みmanifestとして参照されるファイルは除外しない。除外物の本体や架空の空ファイルを作らず、元の理由を次のアーカイブへ残す。一般の欠損・破損・削除待ちファイルは従来どおり拒否する。この記録も端末内専用で、次の復元では新しいファイルIDに紐付けて再構成する。

## ローカル検証の範囲

追加Rustテストは10件。合成CAFと偽の文字起こし・話者分離CLIを使い、実録音や実モデルの品質評価は行っていない。

- v22からv23へ移行し、既存会議を保持して履歴が空で始まることを確認した。既存のv20・v21アーカイブ互換試験も維持した。
- 同名の別SHA、同SHAの別名・別役割、繰り返し登録を照合した。トランザクション外の保存、取消と巻き戻し、パストラバーサル、不正SHA、過大な値を拒否した。未配置状態の昇格と指紋の変更を拒否し、破損・欠落した記録を名前の再利用前に検出した。
- モデルファイルの保存基盤ではパッケージ内のサブフォルダーを許可し、絶対パス・ドライブ指定・親への移動・空要素等を拒否した。履歴ファイルは元のファイル名だけを保持し、モデル導入が完了した証拠とは扱わない。
- 完了した文字起こしのモデルと偽CLIを削除してから、別の保存先への公開・再バックアップ・再復元を3回通した。名前・容量・SHA・役割の集合、認識本文と時刻、再起動後の閲覧、自動開始なしを確認した。
- 除外済みPCMの記録をトランザクション内で消すとバックアップ用の検査が失敗した。異なるSHAや音声本体を一時PCMとして扱わないことも確認した。
- 完了した話者分離の偽CLIと両モデルを削除して復元し、再バックアップ後もログの除外理由と参照メタデータを保持した。次の復元領域の封印も確認した。
- 既存の公開・取消・コミット失敗・二重追加の検査では、比較対象にモデル4表と除外記録も加えた。会議だけ成功して履歴が部分確定する状態を認めない。

最終コードの`make check`は終了コード0で成功した。Python 65件、フロントエンド64件、Swift 9件、Rust通常392件と別実行のAVFoundation製CAF検査1件が成功し、環境依存のRust 11件はignoredだった。型・書式検査とビルドを含み、評価設定の構造検査はエラー0件・警告7件。ログは`/tmp/mon-model-metadata-final-check.log`に保存した。

## 残件

モデル本体のダウンロード・手動導入・互換性検証、標準／高精度プロファイルの構成と選択、導入済みパッケージ全体のメタデータを持ち運ぶ経路、準備UI、元の固定条件を保った明示的な処理再試行は残る。履歴の保持だけでAI処理が利用可能になったとは表示しない。

v23より前の追加公開でDBに保存されなかった元のファイル名や除外理由は、今回の移行だけでは復元できない。原アーカイブには記録があるため、履歴を保持する新しい追加復元では利用できるが、欠けた証拠を推測して既存DBへ補う処理は追加していない。

利用者向け復元コントローラーと設定UI、編集保存・実プロセス停止の統合、構築用一時領域の起動時回収と要確認状態の解決、強制終了・長時間・容量不足の実機検証も残る。正式評価、Windows固有部分、GitHubのWindows CIは保留を維持する。
