# MON 開発タスク計画

- 作成日：2026-10-02
- 基準：初期仕様書 v0.8
- 状態：計画。進捗と検証結果は [実装状況](implementation-status.md) を参照

## 1. 進め方

OSごとの音声取得とローカルAIの性能を先に検証し、その後、会議1件を最後まで処理できる構成を作る。追加機能と異常時対応を仕上げ、両OSの統合検証を経て少人数の先行試用へ進む。工数・リリース日程は技術検証後に確定する。

## 3. 必須検証条件と開発目標

| 項目 | 条件 | 区分 |
|---|---|---|
| OS・CPU | Windows 11 24H2以降 x64、macOS 15以降 Apple Silicon | 必須検証環境 |
| 会議アプリ | Meet：Chrome・Edge、Zoom・Teams：デスクトップ版。両OS | 必須検証環境 |
| 録音 | 全体・アプリ選択、ヘッドセット・スピーカー、4時間 | 必須検証範囲 |
| 話者・言語 | 発言者10人、日本語中心、英語製品名・専門用語、重複発話 | 必須検証範囲 |
| AI性能端末 | メモリ16GB、独立GPUを必須にしない | 測定基準 |
| 標準解析 | 60分音声の文字起こし・話者分離を30分以内 | 実機検証する開発目標 |
| 議事録生成 | 文字起こし済み60分会議を5分以内 | 実機検証する開発目標 |
| 録音末尾の損失 | 異常終了時に5秒以内、保存済み部分は回復 | 実機検証する開発目標 |
| 議事録品質 | 決定事項・ToDoを根拠と照合。不明な担当者・期限は「未確認」 | 品質評価方針 |

CPU型番・モデル・電源設定・測定対象工程を固定して記録する。高精度プロファイルや4時間会議に60分の性能目標をそのまま適用しない。認識・話者分離の品質合格値はM1で評価データと実測に基づいて具体化する。未達は実測結果・代替案・影響を示して再確認する。

## 4. 各タスクの管理項目

各実装タスクには、対象要件、UI、バックエンド処理、保存データ、異常時の動作、依存タスク、受け入れ条件、検証結果を記載する。完了は画面の表示だけで判断せず、保存・回復・参照整合性まで含めて判断する。

各commit & push後に、変更内容とcommit ID、実装・ビルド・テスト実行それぞれの所要時間、残タスク別の想定所要時間を報告する。実測・概算・個別未計測を区別し、失敗・中止・再試行も含める。並行実行した工程は重複を明記し、工程時間の合計を実際の経過時間とは扱わない。保留中の正式評価・Windows固有部分と外部準備待ちは、残工数の見積もりから区別する。

### 2026年10月11日の検証範囲変更

初期開発中のため、ユーザー指定によりバックアップの旧形式互換は不要とする。現行DBスキーマのバックアップだけを受け付け、旧形式専用の復元処理・素材生成・復元成功テストを削除する。現在の通常バックアップ（format 2）と削除済み音声の履歴を含むバックアップ（format 3）は維持する。旧形式の復元評価は対象外であり、合格とは扱わない。非対応版を安全に拒否する検査と、保存済みDBの通常の更新処理は残す。既存データの削除・初期化は行わない。

ユーザー指定により、VoiceOverによる読み上げ・操作の実機検証は不要とし、以後の実施対象・完了条件・残工数から除外する。検証合格ではなく、対象外として扱う。日本語入力の変換・確定と通常のキーボード操作は引き続き検証対象とする。既存のアイコンの操作名・ラベルは削除せず、UIを単純化する方針も維持する。正式評価・Windows固有部分の保留と、他の実装・検証条件は変更しない。

## 5. 最初に着手する作業

1. 対象Windows PCとApple Silicon Macの端末条件を記録する。
2. 評価に利用できる日本語会議音声と正解データを準備する。
3. OS別の録音検証プログラムを作り、取得音声・同期・エコー・重複を測定する。
4. ローカルAIの評価処理を作り、品質・速度・メモリを比較する。
5. 結果をまとめ、モデル構成と本体の実装計画を確定する。
