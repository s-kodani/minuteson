# macOSのモデル導入

対象はmacOS 15以降・Apple SiliconのMON。モデルは全体設定で選び、未導入ならダウンロードして使用する。会議ごとのモデル指定、ローカルファイルの取り込み、取得定義JSONの入力、取得記録・配置記録の専用画面はない。

## 利用者の操作

1. 録音・取り込み・保存先操作が終了してから「設定」を開く。実行中のAI処理がある場合、モデル準備はその完了を待つ。
2. 「ローカルAI」で、文字起こし・話者分離・議事録生成それぞれのモデルを選ぶ。
3. 未導入なら「ダウンロードして使用」を押す。取得・容量とSHAの照合・管理領域へのコピー・短いCPU動作確認・全体設定への適用を同じ準備操作で進める。利用者がコピー・互換性確認・プロファイル適用の画面を順に開く方式ではない。
4. 導入済みなら「使用」で切り替える。同じエリアの「導入済みモデル」に「使用中」または「導入済み」が表示されることを確認する。すでに現在の設定と一致する使用中モデルは操作できない。

ダウンロード・配置などの工程間で待機中のAI処理が動き始めた場合も、モデル準備は「AI処理の完了待ち」として待機し、実行中の処理の終了後に続行する。準備が中断して結果が未確認の場合は、ジョブ一覧に「中断」として残る。「モデル設定を開く」→「現在の状態を確認」で元の操作の停止・保存結果を確認し、もう一度「使用」または「ダウンロードして使用」を押す。完了が検証された取得済みモデルは再利用するため、再起動や同じファイルの再取得は必要ない。途中までの取得を完了扱いにはしない。

モデルの変更は、その後に新しく開始する文字起こし・話者分離・議事録生成で使う。実行途中のジョブの固定入力や保存済み本文を自動で書き換えない。会議を開いて文字起こしを再生成する場合は置換を確認し、議事録は生成Markdownのプレビューとプレーンテキスト編集・保存を使う。

話者分離モデルを使用中の場合、「話者分離のCPU使用量」で「標準（4スレッド）」または「多め（8スレッド）」を選び、「CPU使用量を適用」で保存できる。モデルや話者判定の閾値・区間設定は変えず、次に開始する処理から適用する。開始済みの文字起こし・話者分離や再開待ちの処理は、開始時に保存した条件を使い続ける。速さは端末や音声に依存するため、必要に応じて標準へ戻せる。

## 現在の候補

| 用途 | 選択肢 |
| --- | --- |
| 文字起こし | Whisper tiny / base / small / medium / large-v3 / large-v3-turbo（多言語） |
| 話者分離 | Pyannote + ERes2Net base / Pyannote int8 + ERes2Net base |
| 議事録生成 | Qwen 2.5 1.5B · Q4_K_M / Q8_0、Qwen 3 8B / 4B · Q4_K_M、Qwen 3.5 4B / 9B · Q4_K_M |

合計14候補。選択肢と導入済み一覧には、導入前後で量子化形式を含む同じ名前を表示する。導入済みの同じモデルを選ぶと再ダウンロードせずに使用でき、同じ本体が複数ある場合も1候補にまとめる。Qwen 0.5Bは出力反復・未完成JSONのため新規選択対象から外している。以前の導入済み本体がある場合は一覧だけに「選択対象外」と出るが、予防的に本体を削除しない。

固定版の配布元・サイズ・SHA・必要な実行依存・利用条件資料はアプリの[モデル定義](../app/model-catalog/)に結び付く。モデル名だけから入力・出力トークン上限を推測せず、議事録生成は登録された能力上限に従う。入力の余裕だけで出力上限を増やさない。

Qwen3以外の従来候補は短い合成発話・設定切替の[Mac統合確認](verification/remaining-model-integration-2026-10-14.md)を行ったが、正式品質・多話者・60分性能の合格ではない。[Qwen3追加と表示修正の確認範囲](verification/qwen3-and-model-choice-labels-2026-10-16.md)には、実モデルの生成試験を含めていない。Qwen3 4Bも実モデルの生成品質・速度の評価は未実施。小さいモデルを品質保証付きの推奨と表示しない。Windows固有部分と正式評価は保留。

Qwen3 4Bは[公式GGUF](https://huggingface.co/Qwen/Qwen3-4B-GGUF)のQ4_K_Mを使用する。本体は2,497,280,256 bytes（約2.50 GB）、固定版は`bc640142c66e1fdd12af0bd68f40445458f3869b`、SHA256は`7485fe6f11af29433bc51cab58009521f205840f5b4ae3a32fa7f92e8534fdf5`。8Bと同様に非思考モードを使用し、共有コンテキスト40,960・最大出力32,768の範囲で入力量に応じて配分する。標準対応長32,768とYaRN拡張時131,072とは区別する。

Qwen3.5はUnsloth配布の[4B](https://huggingface.co/unsloth/Qwen3.5-4B-GGUF/tree/e87f176479d0855a907a41277aca2f8ee7a09523)・[9B](https://huggingface.co/unsloth/Qwen3.5-9B-GGUF/tree/3885219b6810b007914f3a7950a8d1b469d598a5)のQ4_K_Mを使用する。本体はそれぞれ2,740,937,888 bytesと5,680,522,464 bytes。SHA256・取得URL・公式Apache-2.0本文も固定する。[公式4B](https://huggingface.co/Qwen/Qwen3.5-4B/tree/851bf6e806efd8d0a36b00ddf55e13ccb7b8cd0a)・[公式9B](https://huggingface.co/Qwen/Qwen3.5-9B/tree/c202236235762e1c871ad0ccb60c8ee5ba337b9a)の設定とGGUFメタデータに基づき、共有コンテキスト262,144・最大出力32,768を登録する。既存の固定版llama.cpp b11533は`qwen35`に対応している。議事録のテキスト入力は非思考モードを使用し、画像用のmmprojは取得しない。2026-10-20時点の確認は固定メタデータ、生成引数・容量配分、合成IPCによる選択・導入・切替までであり、実モデルの生成品質・速度は未評価。

## 通信・保存と空き容量

初回のモデル取得には通信と空き容量が必要。準備済みモデルによるAI処理はローカルで行う。文字起こし実行ファイルはアプリに同梱し、利用者がCMakeやCLIを構築する必要はない。会議データとAIモデルの保存先は分かれており、会議保存先の変更ではモデルを移動しない。

取得素材はアプリデータ領域の `model-downloads/<取得ID>`、使用本体は別の `models` 領域に保持する。圧縮原本やコピーもあるため、モデル本体の容量だけで空き容量を判断しない。空き容量検査は予約ではなく、準備中に不足する可能性もある。SHAの一致は固定定義との照合であり、配布元署名の認証やライセンス全体の承認ではない。

## 失敗・応答不明時

準備に失敗すると同じエリアに原因を表示する。以前のモデル選択や保存済みの会議本文を成功扱いで置き換えない。録音中や他の準備中は新しい導入を開始しない。

応答が不明なときの「現在の状態を確認」は、元の処理の停止と結果を照合する。ダウンロード・コピー・設定適用を別の操作IDで無断再送しない。画面を開き直しただけでは取得を始めず、既存の確認済み取得や導入済み本体を照合して再利用する。未完了・破損・由来不明な素材を、完了または使用可能として採用しない。

停止済みと確認できた失敗後はモデル選択へ戻り、通常の「ダウンロードして使用」または「使用」から再試行できる。通信・取得準備・コピー・CPU確認・設定保存の失敗で、選択欄を永久に無効化しない。完了済みの取得は再利用し、未完了の取得しかない場合は、元の取得IDの取消・停止・記録照合を確認してから、新しく押された操作で再取得する。状態確認自体は再取得・コピー・設定保存を開始しない。未完了の素材は引き続き保持し、削除・部分ファイルの再利用は行わない。停止中・読取り失敗・記録不一致の場合は安全のため未確定状態を維持する。

## 開発者向けの形式と配布上の留保

取得定義は現行のアーカイブ版2と、同梱Whisper実行ファイル＋HTTPS重みを組み合わせる版3のみを受け付ける。旧版1や省略された形式情報へ補完しない。アーカイブ全体と選択した通常ファイルを照合し、危険なパス・リンク・過剰容量・SHA不一致を拒否する。取得したアーカイブ内のスクリプトは実行しない。

Macビルドの `tools/mon_whisper_runtime.py` は固定版whisper.cpp v1.9.4のCPU・Metal対応実行ファイルと構築情報・通知文をTAR/indexへまとめる。通常利用者はこのスクリプトを実行しない。再構築時は `.cache/whisper-metal-runtime/package` の実体を照合して再利用する。

新しく開始する文字起こしはmacOSでGPUの利用を要求し、デバイスがなければエンジンがCPUを選びます。以前のCPU専用エンジンで導入したモデルは、更新版アプリで同じモデルを「ダウンロードして使用」から準備し直すとMetal対応版になります。保存済みジョブの実行条件と既存のモデル素材は保持します。

QAのアドホック署名・CPU確認は、Developer ID署名・公証・Gatekeeper・配布条件の承認の代わりではない。外側アプリと内包実行ファイルの配布確認を分ける。詳細は[配布準備](macos-distribution.md)と[実装状況](implementation-status.md)を参照する。
