# macOSのモデル初回取得

対象はApple SiliconのmacOS版。設定の「AIモデル」→「モデルの初回取得」から、利用者が用意した取得定義を確認し、HTTPSでファイルを取得する。Windowsの取得は保留中。公式モデルカタログや推奨モデルの選定・配布元の認証を提供したことにはしない。

## 定義を用意する

JSONファイルは64KiB以内。手動取り込みの`mon-model.json`に使うmanifestと、ファイルごとの配布元を組み合わせる。全ファイルに配布元が公表した容量と小文字SHA-256を指定し、sourcesはmanifest.filesと同順にする。申告版・ライセンス参照・対象・量子化も実際の配布情報に合わせる。

以下は**構造だけの例で、そのままでは検査を通らない**。容量0・SHAの説明文・example.invalidの配布先を、利用を許可された実際のファイルの情報へ置き換えること。ローカルで算出したSHAだけでは配布元の真正性を証明できない。

```json
{
  "schemaVersion": 1,
  "manifest": {
    "schemaVersion": 1,
    "engine": "whisper.cpp",
    "engineVersion": "実行ファイルの配布版",
    "modelName": "モデル名",
    "modelVersion": "モデルの配布版",
    "quantization": null,
    "licenseRef": "配布元のライセンス参照",
    "target": "macos_aarch64",
    "files": [
      { "relativePath": "whisper-cli", "role": "executable", "expectedSize": 0, "expectedHash": "実ファイルの小文字SHA-256（64桁）" },
      { "relativePath": "model.bin", "role": "asr", "expectedSize": 0, "expectedHash": "実ファイルの小文字SHA-256（64桁）" }
    ]
  },
  "sources": [
    { "relativePath": "whisper-cli", "url": "https://example.invalid/whisper-cli" },
    { "relativePath": "model.bin", "url": "https://example.invalid/model.bin" }
  ]
}
```

whisper.cppは実行ファイル1件・ASR1件（VADは任意1件）、sherpa-onnxは実行ファイル1件・segmentation1件・speaker_embedding1件、llama.cppは実行ファイル1件・LLM1件。必要な依存ライブラリはruntime_libraryとして最大16件まで指定する。アーカイブを取得して展開する機能はないため、実行に必要な個々の配布ファイルのURLを指定する。初期URLの認証情報・query・fragmentは禁止し、初期URLと転送先ともHTTPSに限定する。私的な認証用リンクや秘密情報を定義へ入れない。

合計容量の上限は32GiB。取得前に将来の管理コピーの記録が64KiB以内に収まるかも検査する。長すぎる構成・パス・URLは、通信・ファイル作成前に見直す必要がある。

## 操作を分ける

1. AI処理・録音・取り込み・保存先の操作を停止する。定義のファイルを選ぶかJSONを入力し、「取得定義を確認」を押す。この段階では通信・ファイル作成・実行をしない。
2. モデル・版・対象・容量・各配布先・SHA・ライセンス参照を確認する。チェック欄を選択し、「確認した定義で取得する」を押す。
3. 受信表示が100%でも完了ではない。全実体の容量・SHA・manifestと記録の照合、同期を経た結果で「素材照合済み・未配置」になる。
4. 「照合済み素材のコピーを確認」から**別の確認**を行い、管理領域へコピーする。コピー直前にも取得意図・完了記録・全実体を再照合する。
5. 下の配置記録から**別の確認**でCPU互換性を検査する。この操作だけは取得した実行ファイルを利用者権限で起動する。隔離された実行ではないので、配布元と実行ファイルを信頼できることを確認する。
6. CPU成功後も、標準／高精度への適用は**別の確認**。取得・コピー・CPU成功は実会議の精度・速度・話者数の評価ではない。

素材はOSのアプリデータ領域の`model-downloads/<取得ID>/payload`へ非公開・非実行の状態で保持する。コピーは別UUIDの`models`領域。会議保存先と分離し、取得済みとコピーの両方が残るため、取得前に概ね合計容量の2倍＋記録分の空きを検査する。空き容量は予約ではなく、コピー時にも再確認する。

## 取消・応答喪失・再起動

「停止を要求する」は要求の送信だけ。通信子の終了待ち・同期・確定等が終わるまで準備の共有枠を解放しない。処理中の確認画面はEscapeや背景クリックでは閉じない。

応答が不明な場合は元の操作IDを保持し、取得・コピーを自動再送しない。「同じ操作の停止・結果確認」は元の操作の取消を送ってから実際の停止状態を確認する。まだ動いていれば、時間を置いて同じ操作を確認する。停止後、取得は新しい読取IDで全実体を照合し、コピーは取得ID・定義SHA・検査SHA・配置IDを束ねた確定記録を読む。コピーの歴史的な確定は、現在の本体や実行可能性の証明ではない。

画面移動で応答が失われても、プロセス内では同じ不明操作を保持する。アプリ再起動後は「保持している取得記録」を参照する。「完了記録あり（実体未照合）」はマーカーの情報だけで、配置・準備完了にはしない。選択して全実体を再照合する。途中・破損・由来不明物は自動再開・採用・上書き・削除しない。

停止完了を確認できたが読戻しができない場合に限り、一覧を再確認して「結果未確定のまま確認を終了」を選べる。成功や取消による巻戻しを意味せず、途中物・記録は保全する。新しい取得は利用者の別の明示確認が必要。保持物の自動回収はこの機能に含まれない。

実TLS／CDN・配布元／配布条件・実モデル・ネイティブGUIの統合は別途検証が必要。合成IPCのブラウザ検査と、Rustの合成素材／ループバック検査だけで仕様11章全体を完了扱いにしない。
