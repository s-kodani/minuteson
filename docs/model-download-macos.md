# macOSのモデル導入

対象はmacOS 15以降・Apple SiliconのMON。モデルは全体設定で選び、未導入ならダウンロードして使用する。会議ごとのモデル指定、ローカルファイルの取り込み、取得定義JSONの入力、取得記録・配置記録の専用画面はない。

## 利用者の操作

1. 録音・解析・取り込み・保存先操作が終了してから「設定」を開く。
2. 「ローカルAI」で、文字起こし・話者分離・議事録生成それぞれのモデルを選ぶ。
3. 未導入なら「ダウンロードして使用」を押す。取得・容量とSHAの照合・管理領域へのコピー・短いCPU動作確認・全体設定への適用を同じ準備操作で進める。利用者がコピー・互換性確認・プロファイル適用の画面を順に開く方式ではない。
4. 導入済みなら「使用」で切り替える。同じエリアの「導入済みモデル」に「使用中」または「導入済み」が表示されることを確認する。すでに現在の設定と一致する使用中モデルは操作できない。

モデルの変更は、その後に新しく開始する文字起こし・話者分離・議事録生成で使う。実行途中のジョブの固定入力や保存済み本文を自動で書き換えない。会議を開いて文字起こしを再生成する場合は置換を確認し、議事録は生成Markdownのプレビューとプレーンテキスト編集・保存を使う。

## 現在の候補

| 用途 | 選択肢 |
| --- | --- |
| 文字起こし | Whisper tiny / base / small / medium（多言語） |
| 話者分離 | Pyannote + ERes2Net base / Pyannote int8 + ERes2Net base |
| 議事録生成 | Qwen 2.5 1.5B · Q4_K_M / Q8_0 |

合計8候補。Qwen 0.5Bは出力反復・未完成JSONのため新規選択対象から外している。以前の導入済み本体がある場合は一覧だけに「選択対象外」と出るが、予防的に本体を削除しない。

固定版の配布元・サイズ・SHA・必要な実行依存・利用条件資料はアプリの[モデル定義](../app/model-catalog/)に結び付く。モデル名だけから入力・出力トークン上限を推測せず、議事録生成は登録された能力上限に従う。入力の余裕だけで出力上限を増やさない。

全候補の短い合成発話・設定切替の[Mac統合確認](verification/remaining-model-integration-2026-10-14.md)は行ったが、正式品質・多話者・60分性能の合格ではない。小さいモデルを品質保証付きの推奨と表示しない。Windows固有部分と正式評価は保留。

## 通信・保存と空き容量

初回のモデル取得には通信と空き容量が必要。準備済みモデルによるAI処理はローカルで行う。文字起こし実行ファイルはアプリに同梱し、利用者がCMakeやCLIを構築する必要はない。会議データとAIモデルの保存先は分かれており、会議保存先の変更ではモデルを移動しない。

取得素材はアプリデータ領域の `model-downloads/<取得ID>`、使用本体は別の `models` 領域に保持する。圧縮原本やコピーもあるため、モデル本体の容量だけで空き容量を判断しない。空き容量検査は予約ではなく、準備中に不足する可能性もある。SHAの一致は固定定義との照合であり、配布元署名の認証やライセンス全体の承認ではない。

## 失敗・応答不明時

準備に失敗すると同じエリアに原因を表示する。以前のモデル選択や保存済みの会議本文を成功扱いで置き換えない。録音中や他の準備中は新しい導入を開始しない。

応答が不明なときの「現在の状態を確認」は、元の処理の停止と結果を照合する。ダウンロード・コピー・設定適用を別の操作IDで無断再送しない。画面を開き直しただけでは取得を始めず、既存の確認済み取得や導入済み本体を照合して再利用する。未完了・破損・由来不明な素材を、完了または使用可能として採用しない。

## 開発者向けの形式と配布上の留保

取得定義は現行のアーカイブ版2と、同梱Whisper実行ファイル＋HTTPS重みを組み合わせる版3のみを受け付ける。旧版1や省略された形式情報へ補完しない。アーカイブ全体と選択した通常ファイルを照合し、危険なパス・リンク・過剰容量・SHA不一致を拒否する。取得したアーカイブ内のスクリプトは実行しない。

Macビルドの `tools/mon_whisper_runtime.py` は固定版whisper.cpp v1.9.4のCPU実行ファイルと構築情報・通知文をTAR/indexへまとめる。通常利用者はこのスクリプトを実行しない。再構築時は `.cache/whisper-runtime/package` の実体を照合して再利用する。

QAのアドホック署名・CPU確認は、Developer ID署名・公証・Gatekeeper・配布条件の承認の代わりではない。外側アプリと内包実行ファイルの配布確認を分ける。詳細は[配布準備](macos-distribution.md)と[実装状況](implementation-status.md)を参照する。
