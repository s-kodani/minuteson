# macOSのモデル初回取得

対象はApple SiliconのmacOS版。設定のローカルAI欄にある「モデルをダウンロード」から、文字起こし・話者分離・議事録生成の固定版を選び、確認後に準備する。JSON作成・パス入力・利用者によるCLI構築は不要。Macの独立したQA環境で3種類の通常GUIコピー・CPU動作確認・標準設定への適用と冷起動後の保持を確認した。LLMは今回の通常GUIで実HTTPS取得、文字起こし・話者分離は以前の実HTTPS取得素材を原本不変で再利用した。3種類をこの新規QAで連続ネット取得したという証明ではない。[実機で確認した操作と限界](verification/model-asr-onboarding-2026-10-11.md#3種類の通常guiコピーcpu確認標準適用)。完全なワンクリックではなく、取得・コピー・実行・適用は別の確認を行う。Windowsの取得、正式品質・性能の選定は保留中。正式署名・公証を含む一般配布は未検証で、SHAの照合は配布元署名の認証ではない。

## アプリ内の選択肢

「準備内容を確認」でモデル・取得容量・必要な空き容量・配布元・利用条件を確認する。JSON作成やパス入力は不要。配布先と版・容量・SHAはアプリ内の固定定義に結び付け、確認後だけ通信する。詳細なURL・SHA・構成は確認画面の折り畳みに収める。

現在のLLMはllama.cpp b11533とQwen2.5-1.5B-Instruct Q4_K_Mの固定版。取得約1.05GiB、コピーまでの空き容量目安約2.14GiB。アーカイブから必要な実行ファイル・共有ライブラリ・MIT本文、別途モデルとApache-2.0本文を取得する。推奨／品質合格／全Mac互換性の保証ではない。CPU動作確認と標準／高精度への適用は別の明示操作となる。

話者分離はsherpa-onnx v1.13.8、pyannote segmentation 3.0と3D-Speaker ERes2Net base。取得約62MiB、モデル本体等約72MiB、空き容量目安約184MiB。実行に必要なONNX Runtime、モデル2件、sherpa／segmentation／3D-Speaker／ONNX Runtimeの本文・ThirdPartyNoticesを保持する。モデルの人数推定／重複検出等の正式品質や10話者を検証したものではない。SHAが変わった配布物は自動採用せず取得を失敗にする。

手元の素材は「ローカルから取り込む」でファイル選択式の導入が可能。実行ファイル・モデル・必要な依存ライブラリは利用者が準備する。取得定義を自分で用意する場合は、詳細操作の「取得定義からダウンロード」を使う。

### 文字起こし実行ファイルの同梱（開発者向け）

Macビルドでは`tools/mon_whisper_runtime.py`が固定版whisper.cpp v1.9.4をstatic CPU＋Accelerateで構築し、約2.4MiBのTARとindexを同梱する。モデル重み・CMake・ソース・ビルド中間物はアプリへ含めない。通常利用者がこのスクリプトやCMakeを実行する方式ではない。取得画面には同梱indexから構成を作る文字起こし選択肢を接続し、Mac QAで通常の取得と再起動後の照合を通過した。同梱だけで実行／設定適用しない。

文字起こしの固定モデルはWhisper small多言語版。ネット取得はモデル487,601,967bytes＋モデルカード3,196bytes＋OpenAI MIT本文1,063bytes、計487,606,226bytes（約465MiB）。実行ファイル・MIT本文・構築情報はアプリ同梱TARから準備し、通信容量に加えない。空き容量目安は素材・管理コピー各約467MiB＋同梱TARの保持＋記録分で約0.93GiB。これは精度／速度の合格や標準・高精度の推奨選定ではなく、既存の使用設定を変更しない。

形式版3は同梱識別子 `mon-bundled://whisper-v1.9.4/whisper-runtime.tar` とHTTPS素材を組み合わせる専用形式。一般的なfile URLや任意のローカルパスを受け付けない。版・対象・CPU構築条件・member構成を固定し、確認時と取得直前にこのアプリのindexから作る全定義へ結び付ける。取得前に同梱TAR全体を再照合し、変更／リンク／容量超過／SHA不一致／取消ならネット通信・取得意図の作成前に拒否する。同梱分の処理も取消対象。由来の検査・再起動後の実体照合・バックアップの履歴検査は現在のアプリresourceを必要とせず、形式版1／2のcanonical SHAを保持する。

開発用の初回構築にはApple Silicon／CMakeが必要。未配置なら`MON_WHISPER_CMAKE`で開発用CMakeの絶対パスを指定する。取得済みの固定ソースアーカイブは`MON_WHISPER_SOURCE_ARCHIVE`で指定でき、容量・SHAの一致が必要。未指定の初回は固定公式ソースをHTTPS取得するが、モデルは取得しない。再構築時は`.cache/whisper-runtime/package`の全ファイルを照合して再利用し、開発用ツールなしでも再コンパイルを省略できる。source原本＋封印物の保持約11MiB、構築中は384MiBの空き目安。途中構築物は自分が作った私的領域だけを回収し、改変されたcacheや他のファイルは自動削除／上書きしない。

QAのアドホック署名と実CPU smokeは、最低OS全実機・GPU・正式品質／速度や正式配布の証明ではない。内包CLIのDeveloper ID署名／公証は別の残対応。正式配布準備の結果にも、外側アプリの署名と区別して`asrRuntime.runtimeSigning=ad_hoc_only`、未接続・未検証項目を記録する。

## 定義を用意する

JSONファイルは64KiB以内。手動取り込みの`mon-model.json`に使うmanifestと、ファイルごとの配布元を組み合わせる。全ファイルに確認した容量と小文字SHA-256を指定し、sourcesはmanifest.filesと同順にする。配布元が提供した値と、取得後に独立算出した値を区別する。申告版・ライセンス参照・対象・量子化も実際の配布情報に合わせる。

以下は**構造だけの例で、そのままでは検査を通らない**。容量0・SHAの説明文・example.invalidの配布先を、利用を許可された実際のファイルの情報へ置き換えること。ローカルで算出したSHAだけでは配布元の真正性を証明できない。

```json
{
  "schemaVersion": 1,
  "manifest": {
    "schemaVersion": 1,
    "engine": "whisper.cpp",
    "engineVersion": "実行ファイルの配布版",
    "modelName": "モデル名",
    "modelVersion": "モデルの配布版",
    "quantization": null,
    "licenseRef": "配布元のライセンス参照",
    "target": "macos_aarch64",
    "files": [
      { "relativePath": "whisper-cli", "role": "executable", "expectedSize": 0, "expectedHash": "実ファイルの小文字SHA-256（64桁）" },
      { "relativePath": "model.bin", "role": "asr", "expectedSize": 0, "expectedHash": "実ファイルの小文字SHA-256（64桁）" }
    ]
  },
  "sources": [
    { "relativePath": "whisper-cli", "url": "https://example.invalid/whisper-cli" },
    { "relativePath": "model.bin", "url": "https://example.invalid/model.bin" }
  ]
}
```

whisper.cppは実行ファイル1件・ASR1件（VADは任意1件）、sherpa-onnxは実行ファイル1件・segmentation1件・speaker_embedding1件、llama.cppは実行ファイル1件・LLM1件。必要な依存ライブラリはruntime_libraryとして最大16件まで、利用条件の本文はnoticeとして最大8件まで指定する。noticeも全バイトを検査・コピーし、実行ファイルや実行引数としては扱わない。初期URLの認証情報・query・fragmentは禁止し、初期URLと転送先ともHTTPSに限定する。私的な認証用リンクや秘密情報を定義へ入れない。

通常のファイルURLだけなら形式版1を使う。TAR内の選択ファイルがある場合は形式版2にし、そのsourceへ次のarchive情報を付ける。gzip・bzip2・非圧縮TARのみで、ZIP等は未対応。同じアーカイブURLの容量・SHAは全件一致し、memberPathは重複しないこと。同じURLを通常ファイルと混用しない。

```json
{
  "relativePath": "実行先の相対パス",
  "url": "https://example.invalid/engine.tar.gz",
  "archive": {
    "format": "tar",
    "expectedSize": 0,
    "expectedHash": "圧縮ファイル全体の小文字SHA-256（64桁）",
    "memberPath": "アーカイブ内の通常ファイル相対パス"
  }
}
```

これも構造例で、そのままでは検査を通らない。manifest.filesの容量・SHAは展開後の選択ファイル、archive内の容量・SHAは圧縮ファイル全体を表す。同じURLのアーカイブは1回だけ取得する。圧縮全体を再照合し、選択した通常ファイルだけを私的な新規ファイルへ保存する。アーカイブのリンク・デバイス等を選択して配置しない。不正パス・大文字小文字の重複・過剰な項目数／容量・欠落・SHA不一致は完了にしない。アーカイブ内のスクリプトを実行しない。

合計容量の上限は32GiB。取得前に将来の管理コピーの記録が64KiB以内に収まるかも検査する。長すぎる構成・パス・URLは、通信・ファイル作成前に見直す必要がある。

## 操作を分ける

1. AI処理・録音・取り込み・保存先の操作を停止する。「モデルをダウンロード」から種類を選び、「準備内容を確認」を押す。この段階では通信・ファイル作成・実行をしない。独自定義を使う詳細操作だけはファイル選択またはJSON入力を行う。
2. モデル・版・対象・容量・各配布先・SHA・ライセンス参照を確認する。チェック欄を選択し、「確認した定義で取得する」を押す。
3. 受信表示が100%でも完了ではない。全実体の容量・SHA・manifestと記録の照合、同期を経て取得素材の照合済みを表示する。取得の照合は、現在の配置・CPU確認・適用状態の判定とは別である。
4. 「照合済み素材のコピーを確認」から**別の確認**を行い、管理領域へコピーする。コピー直前にも取得意図・完了記録・全実体を再照合する。
5. 下の配置記録から**別の確認**でCPU互換性を検査する。この操作だけは取得した実行ファイルを利用者権限で起動する。隔離された実行ではないので、配布元と実行ファイルを信頼できることを確認する。
6. CPU成功後も、標準／高精度への適用は**別の確認**。取得・コピー・CPU成功は実会議の精度・速度・話者数の評価ではない。

素材はOSのアプリデータ領域の`model-downloads/<取得ID>/payload`へ非公開・非実行の状態で保持する。圧縮原本は同じ取得の`archives`に保持する。コピーは別UUIDの`models`領域。会議保存先と分離し、取得済みとコピーの両方が残るため、取得前に概ねモデル容量の2倍＋保持する圧縮ファイル＋記録分の空きを検査する。通信進捗はアーカイブを1回分として数え、展開後のモデル容量とは区別する。空き容量は予約ではなく、コピー時にも再確認する。

## 取消・応答喪失・再起動

「停止を要求する」は要求の送信だけ。通信子の終了待ち・同期・確定等が終わるまで準備の共有枠を解放しない。処理中の確認画面はEscapeや背景クリックでは閉じない。

応答が不明な場合は元の操作IDを保持し、取得・コピーを自動再送しない。「同じ操作の停止・結果確認」は元の操作の取消を送ってから実際の停止状態を確認する。まだ動いていれば、時間を置いて同じ操作を確認する。停止後、取得は新しい読取IDで全実体を照合し、コピーは取得ID・定義SHA・検査SHA・配置IDを束ねた確定記録を読む。コピーの歴史的な確定は、現在の本体や実行可能性の証明ではない。

画面移動で応答が失われても、プロセス内では同じ不明操作を保持する。アプリ再起動後は「取得記録」を参照する。「完了記録あり（実体未照合）」はマーカーの情報だけで、配置・準備完了にはしない。選択して全実体を再照合する。完了を確認すると記録モーダルを閉じ、結果の操作へ戻るが、コピーは開始しない。同じ取得ID・定義SHA・検査SHAに対応するコピー記録がある場合は「配置・構成記録を開く」で現在の状態確認へ案内し、再コピーへ進めない。コピー記録だけから本体の存在・実行準備・品質を保証しない。未完了・エラーは同じモーダル内で確認できる。途中・破損・由来不明物は自動再開・採用・上書き・削除しない。

停止完了を確認できたが読戻しができない場合に限り、一覧を再確認して「結果未確定のまま確認を終了」を選べる。成功や取消による巻戻しを意味せず、途中物・記録は保全する。新しい取得は利用者の別の明示確認が必要。保持物の自動回収はこの機能に含まれない。

文字起こし・話者分離の実HTTPS取得とLLMの実TLS取得、および独立QAの通常GUIから3種類の管理コピー・CPU試行・標準適用・冷起動保持を確認した。専用Storageの試験は、この通常GUIの証拠とは別である。高精度への通常GUI適用・全端末・正式配布条件・品質等は未検証。これらの限定証拠だけで仕様11章全体を完了扱いにしない。
