小型モデルの全文精度が低いとのユーザー評価を受け、同じ音声を大型 `faster-whisper-large-v2` とVADで再処理。1655.156秒、最大RSS約7.33 GiB、557セグメントのドラフトを生成した。ユーザーは「一部用語に誤りはあるが大きく改善」と定性的に確認。正解データがないため精度値と正式な達成判定は出していない。
ユーザーの原音確認で「天気ビー → 点検日」の1件のみ確定。他の用語は判別不能との申告。確認済み用語リストと1箇所だけ修正した別版ドラフトをGit管理外に保存した。同じ30秒音声でホットワードと初期プロンプトを試したが、どちらも該当語を修正できず、用語登録効果は未検証。
録音解析では各音声セグメントと両OSの録音マニフェストのハッシュを保存し、集計時の差し替えを検出する。
両OSの録音マニフェストを解析入力にして条件ID・モード・要求時間を合否集計と照合し、別条件の録音の流用を拒否する。
必須16GB端末のベンチマークにはエンジン設定JSONを要求し、ファイルの改変を検出して構成指紋へ含める。コマンドと申告設定の一致は人手レビューが必要。
録音失敗を不合格として集計する場合も、両OSのマニフェストに記録された条件ID・モード・要求時間・対象PIDを検査する。
macOSのScreenCaptureKit停止が失敗しても受信済みCAFの確定を試み、停止エラーとともに失敗として記録する経路を追加。実機での切断・停止失敗再現は未検証。
macOS録音プローブに、アプリからの停止要求ファイルを約200ms間隔で確認してCAF確定へ進む`--stop-on-file`を追加。ビルドと署名済みバンドル生成は確認したが、権限を使う実録音・Tauriからの起動停止接続は未検証。
Tauriの録音操作は静的ビルドと単体テストまで確認。単体バイナリの非録音起動はmacOS Launch Servicesのエラーが出て画面一覧に現れず、GUI操作の実機確認は未達。試験プロセスは終了済み。録音は行っていない。
macOSの`npm run tauri -- build`はフロントエンドと録音プローブをビルドしてから、プローブをResourcesへ含めた`.app`を生成する。親アプリ・入れ子のプローブとも`codesign --verify --deep --strict`に合格。現時点の署名はアドホックで公証なしの開発用成果物であり、配布可能性・画面起動・実録音の確認は未実施。
録音プローブ終了後のDB確定だけが失敗した場合は、失敗扱いで元音声を見失わないよう中断状態に残す。再起動後に保存完了manifestと両CAFの検証に成功した録音のみ非同期で確定し、UIの会議一覧を更新する。ファイルの破損や保存途中の録音は保全するが、音声の部分救出は未実装。再起動より後にプローブが保存完了した場合も次回起動まで再試行されない。

このコマンドは評価設定の構造検査、Pythonとフロントエンドの自動テスト、Swift/Rustのフォーマット検査、macOS録音プローブとフロントエンドのビルド、Rustの自動テスト、AVFoundation製CAFとRust区間読出しの統合テストを行う。評価前提の不足は警告として表示される。通常の終了操作は保存完了を待つが、OSや外部からの強制終了前に未保存の入力を救出する機能はまだない。
